- `dotx scope add` writes a bug bounty program's scope — its hosts, its page and its rules — in one command, `dotx scope list` shows them, `dotx scope remove` drops one, and `dotx scope check <host>` answers which program covers a host, so nobody hand-edits a toml block (item 1888).
- The scopes live in `scopes.toml` in Dot's home and every call reads it by its stamp, so a scope added in one run holds for the next without a restart; `recon`'s port scan and `security_scan` read it through the same one gate, and their refusal names the command (item 1888).
- A `scopes.toml` that cannot be read is named with what is wrong instead of losing a scope without a word: the port scan and `security_scan` wait for it, the passive audit goes on; `dotx scope add` with a bad host says why in one line (item 1888).
