- Security: `write_notes` writes its own file in the workspace's notes folder or nothing: a link at the folder or at the
  file, which a command of a run could make to lead the write to Dot's own code or any file, is refused, never followed
  (item 556).
- The file tools: a file `write_file`, `edit_file` or `write_notes` makes gets the permission bits any program's new
  file gets (`0666` less your umask) instead of `0600`, and one that was there keeps its own; `edit_file` refuses an
  empty text to replace, which with `replace_all` filled the file with copies of the new text; `read_file` reads an
  iPhone's HEIC and HEIF photos, turned the way they are held; and `use_tools` no longer says a group is on that the
  run was not given (the browser off in Settings, an agent's tool list) (item 556).
- Office files: a workbook whose rows run far to the right with little in them is read in part, and the text says
  where it stops, instead of keeping a worker busy for minutes; a package that is damaged, locked or packed in a way
  Office does not use is refused as a file that cannot be read, in the tool, an upload and the file panel, not as a
  fault in Dot (item 556).
- The database: a store that cannot be opened (a file that is no database, one locked by another process) ends the
  worker thread and says why, so the daemon or the command exits (and launchd starts the daemon again) instead of
  hanging; a note deleted while its rewrite waits on the embedding leaves nothing in the search index; a history read
  during a compaction is never found empty; the search for the first event of a replay no longer skips events after a
  run closed late (item 556).
- `dotx prune --apply` keeps what the events it deletes said that nothing else records: that a run ended after reading
  outside content (a run that resumes it, or a schedule's firing that builds on it, starts as it did) and that you
  saved a lesson from a run's page (the nightly reflection keeps leaving it alone); `dotx prune` reports the earlier
  versions of chats' histories that it keeps for rewinding (item 556).
- Logs: a line the disk will not take is dropped without an error in the code that logs it, and the next line says how
  many were lost; two processes that find the log full together no longer move the new file over the old one
  (item 556).
