- Every screen of the web interface in words that someone who knows no software reads at once (item 625). Dot says
  **Dot**, never the daemon; a run is a **task**; a sign-in token is a **key** and the code for a phone the **sign-in
  code**; a model's tool is an **action**; an MCP server is a **connected app**; a provider is an **AI service** (the
  tab Settings › Providers is now **AI services**); the preset is the **safety level**; the config file is the
  **settings file**. A failure says what happened and what to do, in a sentence ("Could not reach Dot. Is it running?
  Open Dot again, or restart your Mac."), and the code or the raw message stands under **Details**. The words of the
  expert are not gone: they stand under a fold that is shut until it is opened, with a setting's key, a command or a
  code. The sign-in screen asks for the sign-in code first, with **Other ways to sign in** under it; Settings › System
  shows how Dot stands in three tiles and keeps its health checks and facts under **Details**; Settings › Browser has
  **Advanced** (how Chrome stands, a port for programs) and Settings › Channels has **Advanced** (what Dot sees in
  Messages); a schedule reads "Every day at 08:00"; an approval card and "Why it ran" say what the policy found in words
  ("Sends a message for you"); the refusals that a toast shows, and a schedule's status, say task, action and
  connected app too. A test (`tests/smoke/test_plain_words.py`) opens each screen, menu and dialog and fails
  when a word of the program comes back; `CONTRIBUTING.md` says the rule in four lines.
