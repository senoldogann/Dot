- Safety, from the deep audit of 2026-10-23 (item 561): a page that comes back from a click, an upload or a login's
  fill marks the run untrusted, as one that was opened does; a script run in a page (`browser_eval`) is read for a key
  or a secret Dot holds before it runs, in every mode, in a run that read outside content; an AppleScript or JXA
  script that Dot cannot read (a raw Apple event such as `«event ichtsend»`, text it runs or builds through the
  Objective-C bridge, a script file, an `osascript` line whose script the shell puts together as the line runs, a
  shell line a script builds as it runs) asks as a message sent for you; so does one that types keys or presses a
  button through System Events, in whatever application (a script that only copies or pastes through keys asks too),
  and one that builds a name or code as it runs, calls a method through `.call` or uses the bridge, when it can
  reach Mail or Messages; a Mail rule that forwards, redirects or replies by itself asks as a send; `Dot.app`, the
  program that starts the daemon, and the folder it is built in can no longer be changed by a run's commands; an
  upload carries the flag of an upload, so a run that read outside content is asked before it does one; a batch of
  browser steps takes one payment at most; a rule drafted from words never lets Dot act in the shell or the
  AppleScript tool; a Keychain that refuses the lookup is told as that and not as a missing key, and does not stop Dot
  from starting when the key is one it can start without; the daemon starts only on `127.0.0.1`, `localhost` or `::1`;
  `dotx undo` keeps one history for a file named in two letter cases; and the desktop shell's pages no longer get
  Tauri's whole set of core commands (they could read a PNG from disk), only notifications and the window's bars.
