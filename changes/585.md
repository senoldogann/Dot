- Learned skills have a higher bar, versions, rest and merging (item 585). A skill is written only from a run whose
  steps the review model judges a procedure you will likely ask for again (a question answered or a job done once gives
  none), never from a chat-mode run, and never from a run that changed Dot itself (a step that acts which the policy
  flagged as a change of Dot's own files or as reaching a secret or the clipboard, an MCP call whose arguments name its
  configuration, keys, code, skills or program, `dotx`, or the daemon's address, or a step whose words do, in the run
  itself or in a run it delegated); the skip is logged with why. A rewrite by a later run, a restore and a merge keep
  the file they replace as a version: Customize › Skills shows **Versions (N)** with how each was made, its mark of
  outside content and the steps it changed, and **Restore** puts one back as a new version (`dotx skills versions` and
  `restore` do the same). A learned or taught skill that no run read for `[agent] skill_rest_days` (60) rests: no run is
  offered it, the page shows it as **Resting**, and **Wake** or **Pin** (it never rests) are yours; nothing is deleted,
  and only you drop a skill. A read is dated when it happens (the `skill` tool, a skill picked in the composer), in a
  chat, a helper's run or a run that is stopped as in any other. Each night the review model is asked which pairs of
  close skills are one procedure; each yes waits as a card under **Waiting for your yes** with everything it would write
  (name, description, kind of work, when, steps and parameters, each against the first skill), and your **Merge** makes
  exactly that a new version of the first skill and rests the other; the merged skill is shared with every agent only
  when both were (`dotx skills proposals`, `accept` and `dismiss`). A run that reads a skill that may carry outside
  content is untrusted from the read, as one that read a web page, and so is a run started with such a skill picked. The
  records gain fields and folders (`.versions`, `.proposals`) and no skill is rewritten; a Dot from before this cannot
  read a record written after it.
