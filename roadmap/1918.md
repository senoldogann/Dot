### 1918. A run reads what it starts with at once, before its first model call

**Status: done (2026-11-26).** The owner (2026-11-26): after a message, 10 to 15 seconds pass before the agent even
starts thinking.

Measured on the owner's store (read-only; the last 15 chat runs, seconds from the run's creation): the `memories`
event came at 1.8 to 13.5 s (median 4.7), the first model call began at 2.2 to 18.2 s (median 5.9), and its first
word came 1.1 to 107 s later (median 5.1; the provider's time to first token). Before the first call a run read,
one after another: the model's profile over its newest 30 finished runs' events (1.3 s, 5.4 s cold, on an 880 MB
store), the skills' files with their YAML parsed anew (1 s for 190 skills), the notes' recall with its embedding (0.4
to 1.1 s; bge-m3 on the local Ollama answers in 0.1 to 0.4 s warm), and smaller reads.

What changed:
- `start_reads` reads the profile, the agent and the team, the accounts, the skills, the goal's query and its notes,
  the chat's last call and the harness's texts at once (`await_together`: the first that fails cancels the others and
  is raised as it was, not wrapped).
- The store keeps each finished run's profile counts by how many events the run holds: a run that finished since, or
  whose events were added or pruned, is read again, the others not. `read_model_profile` sums the same per-run counts,
  so the profile is what it was (24 profiles of the owner's 12 models, old and new read, equal).
- A skill's frontmatter is parsed once per file and text (`lru_cache`; an error is never kept).
- No recall, skill or note changed; the embedding of the goal is not shared with the skills' search, whose text differs.

Measured on a copy of the owner's store, the same four runs, three times each, on a loaded Mac: the reads before the
notes took a median 7.4 s one after another with nothing kept, and 2.2 s at once with the newest run just finished;
alone and warm the profile reads in 0.08 s and the skills in 0.06 s.

Not changed: the first model call's time to first token (DeepSeek v4.1 Flash on OpenCode Go, 1.1 to 107 s, median
5.1 s), which is the provider's; it shows in `model_call`'s `first_token_seconds`.

Checked: `tests/unit/test_start_reads.py` (the reads wait for each other, so reads one after another never end; a
failure is raised as it was and stops the others), `tests/unit/test_scaffold.py` (only the changed runs are read again,
and the profile equals a whole read), `dotx eval check`, `test_freedom_contract.py`.
