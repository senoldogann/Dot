### 1088. A file named in a chat is found in a big workspace

**Status: done (2026-11-09).** Asked by the owner: a file named in a chat often opened "This file cannot be shown:
there is no such file in the workspace."

Found in the daemon's log (`workspace_search_cut`, 2026-11-09): every miss searched 20,109 entries and found nothing,
while the files were there (`video-lab/storyboard-A.json`, `aino-pilot/episode.py`, `job-pipeline.md`). The owner's
workspace holds about 245,000 entries, most of them in the `node_modules` of four copies of a web project; the search
went down folder after folder (`os.walk`) and spent its 20,000 entries in one of them before it reached the agents'
own folders. One more miss was the prose: `~/Library/Application Support/Dot/workspace/job-pipeline.md` written in
words was cut at the space, so the panel asked for `Support/Dot/workspace/job-pipeline.md`.

Now:
- The search goes folder by folder from the top (breadth first), so files near the top are reached first, and never
  into hidden folders or the packages and builds of a project (`node_modules`, `__pycache__`, `venv`,
  `site-packages`, `Pods`, `DerivedData`, `target`, `bower_components`). The owner's workspace is about 13,600 entries
  without them; each name of the log is found in under 0.3 s.
- A path from `~/` or `/` in words may go through folders whose names are capitalised words after spaces, as the
  Mac's own are (`Application Support`, `Mobile Documents`). The pattern is no longer case-blind (that would take any
  word for a capital); the suffix is matched in lower or upper case instead.

Checked: `tests/unit/test_previews.py` (a workspace whose `node_modules` and deep folder fill the search before the
file; fails on the old walk in any order of the disk), the names of the log against the owner's workspace (read
only), `npm run check`, `tests/smoke/test_changes_panel.py`.
