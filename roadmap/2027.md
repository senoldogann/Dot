### 2027. What Dot resumes on its own is marked by the run its chain began with: the asks of items 850 and 860 hold

**Status: built (2026-11-27), waiting on the owner's look.** The owner approved it on 2026-11-27, from the pre-push
review of item 2016: the marks a run's gate takes as it starts (`owners_word`: a chat of Dot's own initiative, item 850;
`owners_chat` and `owner_there`: the owner's chat and whether they are there to answer, item 860) were read from the
source of the run itself, which for a run that resumes another is `resume`, and for a resumed helper whose parent ended
is that parent's. So a schedule's firing the daemon resumed after a restart counted as a run of the owner's, there to answer: in
yolo its mail and posts in the owner's chat asked the owner, where the firing's are judged by the review model.

## Approach (written before the code)

For what Dot resumes on its own, the three marks are read from the origin of the run's chain (item 2016's
`RunManager._origin`: a resume followed back to the run it resumes, a resumed helper to the run at the top of its
delegations): a helper whose parent ended, and a run the daemon resumed as it started (`Resumption.automatic`). A run
the owner resumes by hand stays theirs, there to answer, as docs/safety.md has said since item 860: pressing Resume is
their word. When the origin cannot be read, the marks are read as before, from the run's own source: an unknown origin
is not taken as a run nobody watches, which would hand its messages to the review model.

What must hold: a run the owner started, what resumes it, and any run the owner resumes by hand, are marked exactly as
before: nothing it did unasked asks now, nothing it asked goes unasked. A run of a schedule, a watcher or Dot's own
initiative that Dot resumes on its own is marked as the run it resumes was, so in yolo its payment is the owner's, its
message or post in the owner's chat is judged by the review model, and in a chat of Dot's own a message, a post and a
release ask the owner (items 850, 860: no new ask, the ones they designed).
