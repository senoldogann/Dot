### 1875. A push to main runs only the parts its files can affect; the whole suites run at night

**Status: done (2026-11-25).** The owner, the evening of 2026-11-25: "no need to be that strict; don't keep running the
long tests; on GitHub only when really needed". Every push to main ran the gate whole (`gate`, `gate (part 2)` and the
three browser parts: 42 to 76 macOS minutes each, 55.5 on average over the 29 pushes before 25 November evening), and a
push that changed `ios/` ran the whole iPhone suite (about an hour on two runners).

What must hold: a push to main runs `gate`, `gate (part 2)` and each browser part only when a file changed since main
was last green can affect it (`scripts/python_ci.py`, `scripts/browser_ci.py`, as for a pull request); a decision that
cannot be made (no green run found, a base that does not fetch, a check that fails) runs everything; a release and a
run started by hand run everything; what main no longer runs is run each night: `browser.yml` every browser test (it
did already), `ios.yml` the whole iPhone suite.

What was built (`.github/workflows/gate.yml`, `ios.yml`): the `changes` job runs for a push too. Its base for a push is
the commit of the gate's last green run on main, read from the API (the job reads `actions`): runs of main that wait
replace one another (item 1011), so the push just before may never have run, and the files changed since main was last
green are those this run must test. The jobs' conditions no longer ask whether the event is a pull request: a job whose
decision was not made (the `changes` job skipped, as in a release or a run by hand) or failed runs. `ios.yml`'s whole
run (the long UI parts and `e2e`) is the night's, a run by hand and a pull request labelled `ios-full`; a push to main
runs the short set as a pull request does. CLAUDE.md "Checks", docs/development.md and ios/Next/README.md say so.

Measured: the 29 pushes to main of 22 to 25 November read by the new rule against the same files (the files changed
since the previous green run): 4 of 29 would have skipped every macOS job, the others changed `src/` and run all as
before; 1,609 macOS minutes would have been 1,400, 55.5 a push on average would have been 48.3. A merge of several
pull requests at once, which is most of main's runs, almost always holds a file of the package.

Checked: `tests/unit/test_release_workflow.py` (the jobs' conditions, the `changes` job's events); actionlint and zizmor
on the workflows.
