### 1582. Tests and docs for a cut program that goes on: the stand-in dies mid-run and the run is continued, once and twice, never after a stop

**Status: done (2026-11-24).** The tests of items 1580 and 1581 end to end, on the real runtime, manager, bridge and gate
with the stand-in program (`tests/fixtures/claude_standin.py`), and the pages that say what a cut program does now.

The stand-in kills itself as a goal asks (SIGKILL, SIGTERM, exit 1 with a line on stderr: `die by sigkill`, `die by
sigterm`, `die with exit 1`) and, started with `--resume` of its session after the cut, reads what is sent up to the note
about the cut, writes it to `continued.json` and finishes (`once`), dies again (no `once`) or answers an API error that says
the session cannot be taken up again (`refuse the resume`; the new session that follows, without `--resume`, finishes). Each
start is a line of `starts.log`. Five more modes cut it at the moment that matters: `die in a step` (half a sentence, then the SIGKILL), `die after finishing` (a `finish` that worked, then the SIGKILL), `die while sending` (SIGKILL half a
second into a call of `shell`, which the test makes an action the policy keeps for the owner), `die after sending` (the
call returns, a step says it went, then the SIGKILL) and `die with a message waiting` (a SIGKILL after a 2 s call, before it
reads its input again).

What is asserted (`tests/smoke/test_claude_code_run.py`):

- The run is continued in place and ends `done`, for a SIGKILL, a SIGTERM and a crash: one run record in the chat (its id
  is the started run's), 2 steps (one of each program), `run_started` and `run_finished` once, the `assistant` events of steps
  1 and 2, one `claude_code_continued` event with attempt 1 of 2, the exit and `cut_at`; the second program was started
  with `--resume` of the first one's session and read the note in the words of the brief; the chat keeps the session.
- A second cut ends the run when `continue_cut = 1` (both exits in `cuts`, `continued` 1, why in `not_continued`, the
  chat's session forgotten); with the default 2 the third cut ends it, with the three exits.
- The owner's Stop is never continued: during the wait before the new start (a 30 s wait cut short, the program not
  started, the run `cancelled`), and a Stop that comes with the death (the run's stop event set as the exit is read: the run
  ends `cancelled`, not failed, nothing started again).
- The plan's limit is not continued (one start, no event).
- A call of an outward action in flight is not continued, with the owner's free mode off and on (the gate asks nothing in
  the second, and the rule does not depend on it); one whose result the model read (a step began after it) is.
- A delegated helper whose program is cut once gives its parent, through `delegate`, the final result of the continued run:
  the same run record, `done`, 2 steps.
- A program cut after the model's `finish` ends the run as the finish said (done, with its answer), not failed, and is not
  continued; the chat keeps no session.
- The step a cut interrupted is dropped from the page: the half sentence it had shown gets a `reset` for its step, and the
  program that goes on begins that step number again.
- A resume the API refuses is met with a new session whose first message has the goal, the chat, "What the cut session had
  done" (its first words) and the note; the third program has no `--resume` and the chat keeps its session.
- What the owner sent that the cut program never took in is the first thing the next program reads, then the note.
- Item 1580's: the exit in the event, the context and the log lines for each way of dying (with continuing off, which
  `continue_cut = 0` is), two runs cut together are one line, a Stop that ends the program is no cut.

Each of these was put red once by putting the fault back (the list is in item 1581's record). Docs: `docs/models.md` (the
Claude plan's page, with item 1581), `docs/runs.md` (the run's page: a run that goes on in place), `docs/configuration.md`
and `defaults.toml` (`[providers.claude_code] continue_cut`).
