### 1037. The speed set: what Dot's browser use takes, measured the same way every time

**Status: done (2026-11-07).** **Asked** by the CI/CD session on the owner's approval: make Dot's browser and computer
use finish the same tasks in less time at the same success, each step measured against one baseline. The eval catalog
had two browser tasks and no desktop task, and no report said how many model calls a run made or how long its first
token took.

**Built.**
- `evals/speed_tasks.py`: four browser tasks on a local site (no network, no account), kept out of the catalog the
  weekly score plays (`all_tasks`) and checked with it by `dotx eval check`: `speed-signup-wizard` (a sign-up over three
  pages of GET forms, every field the goal names shown on its last page), `speed-shop-search` (a search, eight results, the one item to open),
  `speed-stock-list` (a table of 120 rows to read to its end), `speed-daily-check` (a status page, its alerts and today's
  orders). Each answer is judged by what the pages say; `dotx eval check` proves each can be passed and not by nothing.
- `evals/metrics.py`, `evals/results.py`: a run's model calls, the mean time to the first token of its steps' calls,
  the most input tokens a call was sent, and its calls of the browser's tools (a pass with none read the pages another
  way, and the table says so).
- `evals/speed.py` and `dotx eval speed [--model] [--repeat] [--report]`: plays the set and prints the table per task
  and over all; with two saved reports, the change task by task. Docs: `docs/development.md`.
- No desktop task: an eval attempt runs with the desktop off (`evals/runner.py`), and a task on macOS's own
  applications would act on the owner's screen; the desktop is measured from the owner's runs instead.

The report: `evals/20261107-203030-ollama-deepseek-v4-1-flash-1017-cloud.json` in the owner's Dot home. Each later step
compares against it: `uv run dotx eval speed --report <baseline> --report <later>`.

**The owner's runs** (the store, read only, the last 30 days): 1,277 `browser_act` calls, 68% of one step, median 0.55 s,
p90 5.7 s (the mean, 8.0 s, is approvals waited for: 46 calls over 15 s, the longest 906 s); 857 `browser_open` at 3.6 s;
6,277 step calls of runs that used the browser on the main model, 3.4 s each, 1.4 s to the first token, 115k input
tokens on average; 17 `desktop_act` calls (35% of one step, 1.7 s) and 19 desktop screenshots (0.7 s). Real flows carry
about five times the context of the set's (115k against 24k): a change that shrinks context shows less on the set than
on real work, and the report of each step says both.
