### 1195. A cloud model Ollama retired is left out of the menu of models, not the menu with it

**Status: done (2026-11-15).** The owner saw "provider answered HTTP 410: mistral-large-3:675b was retired on November
9, 2026. Try glm-5.3-flash:cloud." and could not change models in Settings › Models. The model was in no setting of
Dot's: the owner's Ollama still listed `mistral-large-3:675b-cloud` (`/api/tags`), and Ollama answered every `/api/show`
for it with that 410. `OllamaProvider.list_models` asked for every listed model at once with `asyncio.gather`, so the
one refusal failed the whole list, and the menu showed none of Ollama's models.

- `llm/ollama.py`: `described_models` sets apart a model refused with 410 (with the server's words) and raises any
  other failure as before; `list_models` lists the rest and logs `ollama_model_retired` with the `ollama rm` that
  removes it.
- On the owner's Mac the stale model was removed with `ollama rm mistral-large-3:675b-cloud` the same day.

Checked: `tests/unit/test_ollama_retired.py` (a 410 is set apart and the other models listed; a 500 still fails the
list), `tests/unit/test_ollama_finish.py`.

Log:

- 2026-11-15: item 1195, a retired Ollama cloud model no longer empties the menu of models.
