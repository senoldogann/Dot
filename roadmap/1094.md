### 1094. A name that only ends in "sk" is not taken for a key

**Status: done (2026-11-10).** Asked by the owner: in free mode, a run's `cat >> …/vk46_muistiinpanot.md <<'MD'`
(notes written to a file on the Mac) was "Blocked by Dot's safety rules: this run read outside content, and the step
would send a secret out of the Mac".

Found in the step's record (`run_mwa06621_f7a799`, `secret_egress_refused`): the notes named a transcript,
`flask-callers-ensure-sync__B__1.jsonl`, and the key pattern of `policy/elements.py` took
`sk-callers-ensure-sync__B__1` inside "flask" for an `sk-` key. No secret was in the step. The refusal itself is meant
for every mode (item 525), so the pattern is what changes.

Now an `sk-` key is found only where it starts a word (no letter or digit before it). A key a run writes into other text
on purpose is not what the pattern finds, as one cut in two never was; the keys Dot holds are still found word for word
wherever they stand.

What must hold: a key in the form `sk-…` standing alone, after `=`, `:`, `_`, a quote, a space, a percent escape (`%3D`)
or a backslash escape (`\n`, `\t`, `\x3d`, `\u003d`) is still
refused; the other forms (`AKIA`, `ghp_`, `xox?-`, a private key) are unchanged.

Checked: `tests/unit/test_egress.py` (the owner's line passes, a key after `token=` and a bare `sk-` key are still
refused, and so is one after `%3D`, `%22`, `%20`, `\n`, `\t`, `\x3d` or `\u003d`), the whole unit suite.
