### 557. Learning and memory: search keeps visible notes, rejected or unapproved lessons stay out of memory, the learning alarm after sleep, learned skills' counts and names

**Status: done (2026-10-23).** From the audit of 2026-10-23 (at `96e8c750`), whose findings an independent read of the
code confirmed one by one: memory search, the nightly reflection, the record of how learning fares, learned skills, the
catalog's names and the docs that describe them.

**As built.**
- F20, memory search drops visible notes (`memory/service.py`, `store/db.py`): both rankers cut to the best
  `candidate_pool` notes among every note, and only then dropped the resting, expired and other agents' ones, so 40
  lessons put aside that mention a word left a note that mattered out of the start notes, `memory_search` and the
  lesson writer's check. `_recall` now asks the store for the cut among the notes that may be found
  (`AwakeNotes`: not tagged `rest`, not run out of time, and with `recall_for` Dot's or the agent's own):
  `search_memories_terms` and `all_memory_vectors` take it as a condition before their `LIMIT` and their cosines, which
  also leaves out a vector that has no note. The check on the records that came back stays.
- F21, lessons the second look rejected, and ones the owner has not approved, reach memory through the nightly
  journal (`agent/reflection.py`): `_learn` reads which of the drawn lessons are saved now (`run_lessons`, from the
  lesson events) and the journal names those alone, and carries the mark of a tainted run only when one of them came
  from it; `lessons_written` still counts the lessons drawn (proposed or saved), as `Reflection` says.
- F65, a note saved while reading outside content can make the reflection rest a clean note: `outdated_pairs` never
  pairs a tainted newer note with a clean older one, and `duplicate_pairs` never lets a tainted note fold away a clean
  older twin (no pair, rather than folding the tainted one into the clean one, whose tags would take the tainted note's).
- F66, a false "learning has stopped" after the Mac slept 48 hours: `check_learning` takes `reflecting` and tells
  nothing while a reflection is under way (`Scheduler._check_learning` passes `self.reflecting()`), so the tick that
  starts the catch-up no longer says that no reflection went well; one that fails is told as before.
- F67, a rewritten learned skill keeps the failure count of its old steps: `meta_of` clears `failing` when a run that
  ended done rewrites the steps.
- F68, a retired skill moved aside to `<name>-2` can no longer be read or listed: `_renamed` rewrites the name in its
  SKILL.md (frontmatter and heading) and in `playbook.json` to the new folder name, and logs a skill it cannot read
  instead of failing the retirement.
- F69, skill work reads only the first 2000 events of a run: it reads the newest 2000 tool calls and results
  (`Store.events_of_kinds`) for the steps, the digest and the main site, and counts every `skill` call of the run
  wherever it was (`Store.tool_calls_named`), so a skill read at the start of a long run still counts. `learn_playbook`
  and `save_playbook` use both.
- F70, the prompt grants `taught-` skills the owner's authority by name alone: the three prefixes
  (`learned-`, `taught-`, `playbook-`) moved to `skills/catalog.py` (`PLAYBOOK_PREFIXES`; `playbooks.py` imports them),
  and `load_catalog` leaves out, and reports, a skill of any root but the playbook folder whose name starts with one,
  so a plugin's or a folder's skill neither speaks as the owner nor shadows a real learned or taught skill.
- F22, `docs/extending.md` describes a learned-skill check and a record field that do not exist: the paragraph says
  what the code does (the model sees a tainted run's own steps only, the record's `tainted` and `tainted_runs`, lines
  withheld when it is offered, secrets masked, and the model told, not checked, about e-mail addresses and home paths).
- F71, `docs/memory-and-schedules.md` pointed to a Reflection section it does not have: it links to Autonomy.
- The docs say the rest: the search's cut, the clock alarm and the reflection, the journal and the tainted notes
  (`memory-and-schedules.md`, `autonomy.md`), the newest steps, the count that starts again, and the reserved names
  (`extending.md`).

**Left.**
