### 650. The Run tab keeps the whole chat's context, and Web reading scrolls inside itself

**Status: done (2026-10-25).** The owner wrote, with a screenshot of the Task tab (Recap, Files made): "Her mesajda
burası sıfırlanmamalı, o sohbetin başından devam ettiği sürece hep kalmalı; ayrıca web reading alanı kendi içinde
scroll olmalı eğer 8'den sonra göstermiyorsa." In short: it should not start again with each message but keep the
chat's context from its start, and Web reading should scroll rather than stop at eight.

**Why it reset.** Each message of a chat is a new run, with a page of its own. The Run tab's context sections (items 539
and 546) were fed by that run's own tool calls only (`timeline.js` `onTool` for `scope.runId === rootRunId`).
The recap (item 536) was that run's alone. Files made already listed the chat's files, from the Changes. Web reading
kept the newest 8 readings, and Memory updated the newest 6.

**The change.**
- **`GET /runs/{id}/chat-context`** (`server/chatcontext.py`) gives the tool calls of the chat's turns before the run
  that succeeded, oldest first. Each comes with its arguments, every string cut at 300 characters but an address,
  which the panel's row opens and which stays whole (the pre-push review's finding). For a change of
  the memory with its result's text and summary. The run's own calls are left out, and so are a failed call's, a
  rewound turn's and a delegated run's, which has its own page. `Store.tool_events` reads them through the run's own
  events.
- **The panel** (`contextpanelview.js`): each section keeps the open run's rows and the earlier turns' apart and shows
  the open run's first.
  - Skills count a skill's calls across the chat (`chatUsage`).
  - Readings and notes are told once each, the open run's over the earlier ones (`chatMemory`).
  - `memoryChange` moved from `timeline.js` to `contextpanel.js`, which both use.
- **The recap.** A run with no recap of its own shows the recap of the chat's turn before, saying "From the task before
  · … This task's own comes once it has taken a few steps". It only reads that recap and never writes one, and the
  run's own recap paints over it.
- **The lists.** Web reading keeps up to 100 readings and Memory updated up to 40. Each is a list that scrolls inside
  itself past about eight rows (`.context-scroll`).

**Tests.**
- `tests/unit/test_chat_context.py`: the earlier turns' calls in order, the cut, the memory text, and none for a
  failed call, the run's own, a rewound turn, a delegated run or a first turn; a long address kept whole.
- `tests/js/contextpanel.test.js`: `chatUsage`, readings in their order, `chatMemory`, `memoryChange`.
- `tests/smoke/test_context_panel_page.py::test_a_new_message_keeps_the_chats_context_and_web_reading_scrolls_past_eight_rows`,
  in a real browser. A chat's first turn saves a note, reads ten pages and gets its recap. Its second turn only
  answers. The second turn's page shows the first's recap as the turn before's, the ten pages newest first in a list
  that scrolls, and the note.
