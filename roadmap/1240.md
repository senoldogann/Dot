### 1240. A notification's title is a value of its script, never a word of it

**Status: done (2026-11-19).** The code review of 2026-11-19 (finding S3-01) found that `core/notify.py` handed a
notification's title to `osascript` after the script's lines with no `--`: `osascript` reads its options up to the
first argument, so a title that starts with `-e` was one more line of the script, and a `property` line runs a command
as the script is compiled (shown with an empty marker file in a temporary folder). The `notify` tool is offered in every
run mode and its title is the model's, and `osascript` is started by the daemon, outside a run's sandbox.
`show_notification` now runs its script through `desktop/script.py`'s `run_osascript`, which puts `--` before the values
(item 314's fix of the same kind), and says its failure as the notification's, keeping the runner's words, which
speak of an application's Automation dialog, as the reason (the pre-push review); a sweep of the other 61 places Dot
starts a program found no other such argument.

Checked: `tests/unit/test_osascript_argv.py` (the title and the text reach the script as its values),
`tests/unit/test_watchdog.py`.
