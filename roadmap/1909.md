### 1909. DotNext's work log reads like a coding agent's: tool calls grouped in plain words, each helper its own row, and one quiet line while the run waits

**Status: done (2026-11-26).** The owner likes another coding agent's desktop work log and wants its logic in DotNext's
chat: consecutive tool calls folded into one muted line in plain words, a helper as its own row with its face, title,
latest line, time and a chevron to its chat, a finished thought as one "Thought" row, and one quiet line while the run
waits on something.

What changed (the app only):
- Two or more consecutive tool calls that ended well are one line, "Ran 3 commands and read 2 files", "Used 1 tool and
  searched the web 1 time" (`toolGroupWords`: the kinds in the order they came, each counted; "and" before the last),
  with the terminal's symbol when all are commands and a hammer otherwise; a tap opens each call as its own row. Before,
  only consecutive commands were grouped ("Ran 3 commands"). A call at work or one that failed stands alone.
- A helper is its own row where the run started it: its face with a dot while it works, its title, one quiet line of
  what it does now (the work line's words) or the last line it said, its time at the right, and a chevron; a tap opens
  the helper's own chat. Item 1880 had taken the helpers out of the stream for the pill's people segment, which stays.
- While the run's step waits on something (a wait or a watch), one quiet line under the stream says on what, "Waiting ·
  <on what>", in every tool mode, with Details (the run inspector) as a plain text button. A wait on helpers is the
  pill's "Waiting on 2 helpers" and their rows.
  It has no Stop: the pill's Stop is on the screen at the same time, and one Stop where the run's state already is
  reads clearer than two.
- A finished thought is already one "Thought" row (item 1904); while it streams it shimmers "Thinking".
