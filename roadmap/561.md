**F6, the structural rule.** What the guard reads of a script is its words. It tells a send by the verb (`send`, `make
new outgoing message`), and a script that spells the verb another way (a raw Apple event `«event ichtsend»`, a name that
JavaScript builds as it runs: `m["se"+"nd"]`, `m["s\x65nd"]`) says nothing the guard can read. So, instead of one more
pattern for each spelling: a script that the guard cannot read asks as a message sent for the owner when it can reach
Messages or Mail. "Cannot read" is a short list of what hides a word, the same for every spelling of it: a raw Apple
event, text the script runs as code (`run script`, `load script`, `eval`, `Function`, the Objective-C bridge), a
JavaScript name built by a bracket whose key is not a number, keystrokes, and a script file (`osascript file`). "Can
reach" is: it names Messages or Mail (by name, by bundle id or by path), or it calls `Application(…)` with a name that
is not one string. A raw Apple event and text run as a script ask whatever they name, since nothing else can be said of
them and they are rare; the rest is how JavaScript for every application is written, so it asks only for these two. A
plain read of Mail (`get subject of messages of inbox`, `messages[0].subject()`) names no hidden word and goes on
without a question. The independent review (below) kept the rule and widened what it reads: the same few things by
what they are called and not by how they are called, and the words a command line puts together as it runs.
