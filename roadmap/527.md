### 527. A blob decoded and run asks once the run has read untrusted content

**Status: done (2026-10-22).** An outside code review of 2026-10-22 (its K1, marked critical) found that the shell guard
rated a line that decodes a blob and runs it (`base64 -d x | sh`) low, though it reads that code no more than it reads a
download piped into a shell (`curl | sh`). Item 523 had made `install` a flag the taint turns into a question, so this
item gives a decode the same flag as a download.

**As built.**
- `policy/shell.py` judges a decode as it judges a fetch. `_fed_a_decode` catches a decoder piped straight into a shell
  or an interpreter (`base64 -d x | sh`, `cat x | base64 -d | bash`) as `_fed_a_download` catches `curl | sh`: high, with
  `install`, so once the run has read untrusted content the line asks, in the default preset too.
- The two-step form is caught as a download's is (item 385). Every file a decoder names — its operands and option
  values (the words that are not options), the value of `-o`/`--output` in any spelling (`-ox`, `-o x`, `--output=x`),
  the text glued after `=` in a long option, and its `>` redirects (`_decoded_writes`) — joins a new `decoded` set in the
  line's scope, the twin of `downloaded`, so a later line that runs the file (`base64 -d blob > x.sh; sh x.sh`) is
  caught by `_runs_download` and `_fed_a_download`, which share `_names_one`. Which word is the output file differs by
  decoder and by option spelling (`base64 -o`, `openssl -out`, `xxd`'s second operand), too many to read one by one, so
  taking them all is the safe side: marking an input file too only costs a question if the line later runs it. A decoded
  file is matched as written, not by the folder it lies in (`_names_one(..., under=False)`; only the folder `git clone`
  made holds scripts), so a decoder that names `/` marks nothing under it.
- A program named by its path (`/usr/bin/env ...`, `/usr/bin/sudo ...`) that the line downloaded or decoded still has
  what it is read: `_assess_simple` adds the finding of running it to the judgement of the command (`_assess_named`)
  instead of returning with it, so a wrapper or a privilege command at that path is still looked through to what it
  runs (the early return skipped that, which `main` could only reach by a download, a write that asks anyway).
- A decoder is `base64`, `base32`, `basenc` (and the `g`-prefixed coreutils) given a decode switch, `xxd -r`, `gpg` given
  `-d`, `openssl` given `-d` or `-decrypt`, and `uudecode` and `b64decode`, whose only work is to decode. A short
  switch is read among a word's leading letters, where a value glued to it (`-dox.sh`) cannot reach.
- A decode reaches no network, so, unlike a download, running what it wrote does not mark the run's output untrusted
  (`fetches` stays false: its findings use `_finding`, not `_fetching`). `_carried_download` still carries only
  downloaded files.
- Encoding (no decode switch), a decode written to a file that nothing runs, and a plain file piped into a shell raise
  nothing; a run that has read nothing from outside is judged as before.
- `docs/safety.md` lists a blob decoded and run among what asks after untrusted content.

Checked by `tests/unit/test_shell_policy.py`: each line that decodes a blob and runs it, in one step and in two, with
every decoder and the spellings of its output (`-o`, `--output=`, `-ox`, `-out`, `xxd`'s operand, `-ps`), is allowed in
a clean run and asks in a tainted one (they fail without the change); the lines that run no decoded code stay allowed in
both; a test pins `fetches` false for a decode and true for a download; and the unit suite.

Later item (read by the reviews, not built): a decode inside `eval` (`eval 'base64 -d b > x'; sh x`), process
substitution (`sh <(base64 -d x)`), `eval "$(base64 -d x)"`, compression piped into a shell (`gzip -dc x | sh`), a blob
decoded inside an interpreter's own inline code, a decoded file carried by `cp` or `mv` and then run, a decoder that
names no output on the line (`uudecode` takes the name from the blob's own `begin` header, `gpg blob.gpg` decrypts with
no switch, `gpg --decrypt-files`), and long options written shortened (`--deco`).
