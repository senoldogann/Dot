### 646. A finished chat opens with one read of its record, its bill and its Changes

**Status: done (2026-10-25).** This item comes from the same request as item 645.

**What was measured.** The owner's longest chat (7 runs, 357 steps) was opened in a headless browser on their daemon,
read-only. The run's record (`GET /runs/{id}`) was read 3 times as the chat opened, its bill (`/stats`) twice, and its
Changes (`/changes`) twice. The Changes of that chat take 250 to 770 ms to make: the two sides of 21 files are diffed,
and every secret in them is masked. A wrapped `fetch` with its call stacks named the readers:
- the replay of the stored events reached the run's end, which the page took for an end under the reader's eyes
  (`onRunStatus` → `reconcile` and `refreshChanges`);
- after the replay the page read the record again "for the lessons, the questions and the cost" (`attempt(reconcile)`),
  though it had read the record just before;
- each replayed result of a file-changing tool asked for the Changes again (`refreshChanges`).

**The change.** In `static/js/views/run.js`:
- `reconcile` reads the record and draws it with `drawRecord`, then reads the bill.
- After the replay, the record this open read is drawn again (`drawRecord(detail)`) rather than read again. A run
  drawn as it was kept from an earlier visit, over when it was kept, still reads its record again (`reconcile`), so
  lessons, questions and a title changed while the reader was away show (`showRun`'s `readNow`). The first push
  dropped that read and the pre-push review found it. On the owner's chat, open, leave and come back read the record
  once each time.
- An end whose time is not after the end of the record read at the open is the replayed one. A run's end event is never
  after its record's end, as the owner's 169 runs show. That end reads nothing. A run that went on again ends later, and
  its end reads them as before.
- The events put in while the page is drawn ask for no Changes. The Changes read at the open stand for theirs.

**Measured after,** the same chat, with the new page code served in place of the old: the record, the bill and the
Changes are read once each.

**Not changed.** The masking of secrets is 86 % of the Changes' own time. A check for a secret's word before the field
patterns would have skipped 0.1 % of the text, so it was not done. The proof of the daemon before each burst of requests
(`/api/proof`, item 267) is a defence, and it stays.

**Tests.** These browser tests pass: the Changes panel, the lessons, the bill, the helpers, a stopped delegation, a kept
live run, ended calls kept, handoffs kept, the opening and a chat that follows. That is 46. `test_phone_return`'s test
of the network waking fails on main too, and CI leaves it out.
