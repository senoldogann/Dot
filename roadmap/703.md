### 703. The tabs a Dot that did not end cleanly left are closed by the next

**Status: done (2026-10-26).** The docs said it: if Dot crashes, the tabs it opened in the owner's Chrome stay open.

**The change.** `browser/ledger.py`: `<home>/browser-tabs.json` holds, by process, the ids Chrome gave the tabs each
Dot has open in the owner's Chrome (written under a `flock`, as tabs open and close). A session that attaches takes
the entries of processes that no longer run and closes those ids through Chrome's DevTools (`Target.closeTarget`),
when this Chrome still has them: a Chrome that restarted gives no tab the same id. A tab of the owner's, and a tab of a
Dot that still runs (the daemon while `dotx browser` attaches beside it), is not touched.

**The review** (the independent security review of the first push): Dot writes and reads the ledger outside the
sandbox, so a link a run planted at `browser-tabs.tmp` made Dot overwrite what it named (and set it to 0600), and one at
`browser-tabs.json` copied a file the run may not read into one it may. The ledger's files are now opened with
`O_NOFOLLOW` (the staged one made anew with `O_EXCL`, after what was there is unlinked), and all three are among the
files the sandbox guards from every run (`runtime._guarded_files`).

**Checked.** `test_browser_attach.py` (scratch Chrome): of a crashed process's tab, a living process's tab (pid 1) and
the owner's, only the first closes; the session's own tab is in the ledger while open and gone after. `test_browser_ledger.py`: a link at the staged file is
replaced and its target untouched, a link at the ledger is not read, a link at the lock refuses the change, and the
three files are guarded; without the change the first three fail.
