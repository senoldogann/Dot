### 697. A login after a script makes the chat's tabs new itself

**Status: done (2026-10-26).** **Measured:** `browser_fill_login` failed 3 times of 3 in the owner's month; two were
the refusal "a script of this run ran in a tab of this chat", after the run had used `browser_eval` (299 calls). The
rule is right (a script may leave a listener that copies what is typed); the run had to close each tab and open the
page again itself.

**The change.** `BrowserSession.fresh_for_login`: when a script ran in a tab of the chat, every tab of the chat closes
and the current tab's address opens in a new tab, a new document with no history, so no scripted page can come back
from Chrome's cache. `browser_fill_login` calls it before it reads the secret: nothing is read or filled, and the
result is that page with "Nothing was filled yet ... fill again with the refs of the fields below". The refusal in
`fill_from_vault` stays for a script that runs between the two calls.

**The review** (the independent security review of the first push): a popup a page of the chat opened, still being
registered while the tabs were made new, joined the chat that was clean now. `_adopt_popup` now takes a popup in only
while its opener is still a tab of the chat; one whose opener left meanwhile closes, as its opener did.

**Checked.** `test_vault_fill.py`: after a script, with two tabs open, the fill reports nothing filled and one tab,
shows no value, and the fill with the new page's ref goes in. The vault suites pass (29). `test_browser_tabs_tidy.py`: a popup whose registering
is held while the tabs are made new is closed and not in the chat; without the change it is.
