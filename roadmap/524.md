### 524. An MCP server offers every tool it lists, however many

**Status: done (2026-10-22).** Reported by the owner: servers they added showed "Left out".

- **What was in the way.** `select_tools` (`mcp/hub.py`) left out a server that listed more than
  `MAX_UNFILTERED_TOOLS` (30) tools and had no allow list, until the owner chose 1 to 30 of them on the Plugins page
  (item 426). A server of many tools never reached a run without that choice.
- **What it does now.** A server without an allow list offers every tool it lists. The limit is gone from the hub, from
  `chosen_tools` (any number of the tools a server lists, at least one) and from `GET /mcp/servers/{name}/offered`
  (no `limit`). Choosing every tool keeps no allow list, so the server offers the tools it adds later too.
- **Choose tools stays, as a choice.** `picks_tools` is true for a server that runs, to cut its tools down, and for one
  left out with an allow list, to choose the list again. The dialog opens with every tool ticked when the server has no
  list, counts "N of M", and has **All tools** to tick or untick them at once. On a server that runs the button is a
  plain one; on one left out it stays the primary.
- **What it costs.** With the default `[agent] tool_surface = "full"` every step carries the definition of every tool,
  so a server of many tools makes every request longer. `tool_surface = "grouped"` keeps a server's tools out of a run
  until the run turns the server's group on. `docs/extending.md` says so.
- **A run of more than 128 tools starts grouped** whatever the setting (`surface_for_tools`, `MOST_TOOLS_AT_ONCE` in
  `agent/scaffold.py`): some providers take no more in one request (Gemini documents 128 function declarations, and
  OpenAI's API has answered more with a 400), and without the old limit an MCP server could bring a run past it. The
  pre-push review found that every request of such a run would have been refused. A single server whose group alone
  brings a request past its provider's limit still fails there, with the provider's error; Choose tools cuts it down.

Checked by:
- `tests/unit/test_tool_groups.py`: a run of 129 tools starts grouped with the reason, one of 128 keeps its surface.
- `tests/unit/test_mcp_pure.py`: a server of 120 tools hands them all over; an allow list hands over its own.
- `tests/unit/test_mcp_connect.py`: any number of tools may be chosen, and all of them keep no list.
- `tests/smoke/test_mcp_tool_choice.py`: a server of 32 tools added on the page is ready with all of them; the chosen
  two come back alone, every one chosen keeps no list, a choice that cannot connect leaves the server as it was; the
  page's dialog opens all ticked, All tools unticks them, and the two saved are the server's tools.
- `tests/smoke/test_mcp_sign_in.py`: a server that signs in and lists 40 tools is ready with all of them, and the tool
  chosen connects with the sign-in the try gave.
