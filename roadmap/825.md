### 825. The plan reaches the model after the history, so that a change of it keeps the provider's cache

**Status: done (2026-10-29).** **Asked** by the owner ("bu sistemi token caching, daha usage limit dostu fakat
kaliteden ödün vermeyen bir sisteme nasıl çeviririz?").

What the owner's store said of 2,068 model calls (2026-10-28 23:22 to 2026-10-29 20:00): the providers already read
92.3% (Ollama Cloud, `deepseek-v4.1-flash`) and 83.1% (OpenRouter) of the input from their cache. Ollama Cloud now
bills by token, cached input at $0.006 a million against $0.30 uncached, so the 7.7% read uncached was about two thirds
of the input's cost. Each miss was set beside what came just before it in the run:

| Why a step read more than its new messages uncached | Share of what was read uncached |
|---|---|
| nothing found in the run: another of the provider's machines, a cache gone | 34% |
| the new messages themselves (no avoiding them) | 34% |
| **the plan changed** (`update_plan`, `mark_plan_step`) | **19%** |
| a tool group turned on (the tools sent change) | 6% |
| a compaction | 2% |
| the run's first steps | 1% |

The plan stood at the end of the system message of every step (item 87), before the whole history, so that every
change of it had the provider read every message of the run again: in the run of 171 steps of 2026-10-29 (job
applications), the steps after the plan's five changes read 364,000 tokens uncached, a third of the run's.

- `dotagent/agent/loop.py`: the open plan is a stored note after the history (`[system note] Your plan now:`) when it
  changed since the last note, or that note is 20 steps old (`plan_due`), so that a long run has it near as item 87
  wanted; once every step is closed, a note says so, so that neither the run nor a later one of the chat takes the last
  note's open steps for open. The system message is the same at every step, and every step's messages begin with the
  previous step's. The budget counts the note as part of the history it is.
- Weighed and left: the plan after the last message of every step, not stored. It moves every step, so that each step
  reads the message before it again uncached; with few changes of the plan, that costs more than it saves.

**Checked.** `tests/smoke/test_plan_cache.py`: a scripted run that writes a plan, marks a step, searches and marks the
last: every step's system message is the first's, every step's messages begin with the previous step's, the plan is
handed when written and when marked, not when unchanged, and its closing is said. `dotx eval check`.
