### 1219. How a run was started leaves the system prompt, which stays the same across a chat's sources

**Status: done (2026-11-18).** The system prompt told a run how it was started: by a schedule nobody watches, by a
message on the owner's phone, by another run, and whether the owner answers questions while it works. A chat whose
runs come from the app and from a schedule changed those lines from one run to the next, and the provider read the
whole prompt again at full price: 5 of the 26 cold first steps within an hour on 2026-11-17 had the size signature of
those lines (400 to 650 characters, `reports/agent-capabilities-2026-11-18.md`, ARC-04). Item 1217 took the phone's
state out for the same reason.

- `agent/prompt.py`: `started_note` gives the lines, under a lead that says they hold for this run in place of what the
  chat's earlier runs were told about theirs (their notes stay in the history). A run the owner's own message started
  is told so in one line, so that an earlier schedule's "nobody is watching" never stands as the newest word. The
  system prompt keeps no line that depends on the run's source.
- `agent/loop.py`: the note is stored under the goal with the turn note, and handed again after a compaction that
  folded it away, like the recalled notes (item 404).
- The words to the model are the same as before; only where they stand changed. Dot's own loop only: the Claude plan
  and OpenCode paths build their own prompts.

Checked: `tests/unit/test_prompt_cache_stable.py` (one system prompt for a run from the app, a schedule, iMessage and
another run; four different notes), the prompt tests of the moved lines, `tests/smoke/test_scaffold.py` (a page is the
newest tool result of a step, which a note handed again after a compaction may follow), `dotx eval check`.
