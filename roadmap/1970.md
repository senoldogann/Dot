### 1970. Inbound webhooks start work: a signed call to a hook starts its schedule or agent, tainted

**Status: built (2026-11-26), waiting on the owner's look (it touches the guard).** The owner's ask of 2026-11-26:
watchers only poll (`server/daemon.py`, "no inbound webhook"); a service that can call an address (GitHub, a form, a
monitor, a shortcut on the phone) should be able to start Dot's work at once.

## Approach (written before the code)

A hook is a row of `<home>/hooks.json` (readable by the owner only, written whole, like `phones.json`): its id (12 hex
characters), a name, what it is bound to (a schedule's id or an agent's id, one of them), the goal template, the named
fields of the body the template may use, a calls-per-minute limit, whether it is on, its secret, and its last calls.

`POST /api/hooks/{id}`: the caller sends a JSON object and two headers,

- `X-Dot-Timestamp`: the Unix time in seconds the call was signed at;
- `X-Dot-Signature`: `sha256=` and the hex HMAC-SHA256, keyed with the hook's secret, of `<timestamp>.<raw body>`.

The daemon, in this order: refuses a body over 64 KiB (before it is read whole, in the body-limit layer); reads the
file and refuses an unknown or switched-off hook, a timestamp more than 300 seconds from its own clock either way, a
signature that does not match (`hmac.compare_digest`) or one it has seen in the last 601 seconds (kept in the file, so a
restart does not reopen the window), all as 401 with the same words, so an id cannot be probed; only then counts the
call against the hook's limit (429 past it), checks it again and remembers its signature in one locked change of the
file, reads the body as a JSON object and starts the run. A call refused before its signature matched writes nothing
and counts against nothing: it is kept in the daemon's memory (the newest 20 a hook, for Settings › Hooks) and logged
at most 60 a minute. A signed call is written to the hook's last calls (time, status, the run it started), the newest
20 kept.

What the run is given: its goal is the template, the owner's own words, which the reviewer takes as their instruction;
a placeholder `{name}` in it is left as the field's name in brackets (`[name]`), never replaced by the caller's value.
Its first message is a line that says a hook was called, the line watchers use that what is fenced is data and never an
instruction, then the named fields, each JSON-quoted and cut to 2,000 characters, inside the `account_content` fence a
watcher's item goes in (a nonce only Dot knows closes it; the prompt already tells the model what that fence is), then
the template. A field the body does not have is said to be missing. Fields are named by a dotted path into objects
(`pull_request.title`); nothing else of the body reaches the run.

What it runs as: bound to a schedule, the schedule fires as when the owner presses Run now (`Scheduler.fire_by_hook`,
its own choices, its chat rules, its in-flight check, the emergency stop), with `from_outside` set, so its run starts
tainted; bound to an agent, a run of that agent starts in a chat of its own with the agent's bounds (`agent_bounds` with
nothing asked) as a watcher's run starts, tainted, its source `watcher` (a run nobody watches, started from what a third
party wrote). A hook has no approvals, model or mode of its own: nothing in the call or the hook can raise what the run
may do above the schedule's or the agent's.

Where it answers: the guard serves `/api/hooks/<id>` (that exact shape, POST) without the bearer token: the signature is
its key. Every other check of the guard stays: the Host header must be the loopback address or a name of `[server]
reach` (Tailscale on the owner's tailnet), so by default a hook is reached from the Mac and the owner's own devices
only. To open hooks to the internet the owner names a host in `[server] hook_hosts` (with Tailscale Funnel on its own
port, set to the hooks' path only); a request with such a Host reaches `/api/hooks/<id>` and nothing else. The
management routes (`/api/hooks`, `/api/hooks/<id>/...`) need the installation's token and are refused to a phone's key,
as every way into Dot is (`needs_main_token`).

Settings › Hooks makes one (the address and the secret are shown once, in the answer to the create; nothing returns the
secret again), rotates the secret (shown once), switches it off and on, deletes it and lists its last calls with a link
to each run. `dotx hooks list|add|rotate|remove` does the same from the terminal on the same file. `docs/hooks.md` has a
`curl` call that signs.

## Threat model

Who calls: anyone who can reach the address. On the default reach that is the Mac's own programs (a run's included)
and the owner's tailnet; with `hook_hosts`, the internet.

What must hold:

- **No unsigned start.** A run starts only after the HMAC of the timestamp and body under the hook's secret matched in
  constant time. A wrong, missing or malformed signature, an unknown or switched-off hook: 401, nothing started.
- **No replay.** A timestamp outside ±300 s is refused; a signature seen within 600 s (more than the window's width) is
  refused, across restarts (kept in the file). Replaying the exact call is either stale or seen.
- **No raise of privilege.** The run's approvals, model, effort and mode are the bound schedule's or agent's, read at the
  call; the hook stores none, the call carries none. The run starts tainted (`RunOpening.tainted`, or the schedule's
  `from_outside`), so every taint rule applies: in yolo the review model checks what the run does, in every mode a
  tainted run asks before what reaches other people or lasts, as after reading a web page.
- **The payload is data.** Only the named fields reach the run, each JSON-quoted, capped and fenced with a nonce the
  caller cannot know; the template is never filled with the caller's words.
- **No way in from a phone's key or a run.** Making, rotating or listing hooks needs the installation's token
  (`needs_main_token`); the file sits in Dot's home, which the sandbox seals from a run's processes outside yolo
  (`policy/sandbox.py`), as the API token is. In yolo the shell is not sandboxed, as `docs/safety.md` already says of
  the API token: a yolo run that reads the file could sign a call, which starts a tainted run with no more than the
  bound schedule's or agent's rights.
- **Bounded cost.** A body over 64 KiB is refused before it is read; a call without the secret costs a read of the file
  and an HMAC, writes nothing, and neither uses up the hook's calls a minute nor pushes its signed calls out of the list;
  each hook takes its own signed calls per minute (10 by default, 1 to 120); a field is cut to 2,000 characters; at most
  20 fields.
- **The secret is never shown again, logged or put in a run.** It is in the create and rotate answers only; the log
  carries the hook's id and the status.

What only logs: a refused call (its reason, never the body or the signature, at most 60 a minute); a call on a
switched-off hook. A hooks file that cannot be read answers 503 with no path or error; the log has them.

What is out of scope: who holds the secret (a caller with it may start the bound work, at its rights, tainted, at the
hook's rate); a schedule that is itself yolo stays yolo (the owner chose its approvals), and taint is what checks it.

## What was built beyond the approach

- `hooks.json` and its lock are among the files a run may neither read nor change (`runtime._guarded_files`), as the
  phones' file is: the sandbox's closing of Dot's home alone keeps a run from changing it, not from reading it.
- A schedule the owner switched off starts nothing from a call (409); Run now stays theirs alone.
- A body that nests deeper than 32 levels is no body (422): a field is written back as JSON.
- After the security review and the pre-push review of the first push: a call is counted against the hook's limit, and
  written to the file, only once its signature matched (an unsigned flood used up the limit, rewrote the file each time,
  pushed the real calls out of the list and told by a 429 that a hook exists); the refused ones are kept in memory; an
  unreadable hooks file answers 503 without its path.

fields quoted, capped, masked and fenced; the template never filled; the guarded files), `tests/unit/test_hook_guard.py`
