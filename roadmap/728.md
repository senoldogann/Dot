### 728. A config.toml or .env kept elsewhere and linked is changed where it leads

**Status: done (2026-10-27).** From the outside review of 2026-10-27 (its finding 4, a nit): a `config.toml` or a
`.env` linked into Dot's home from a dotfiles repository became a file of its own at the first change Dot made
(`set_setting`, `write_env_value`): the atomic write (`os.replace`) replaced the link, the repository's file kept the
old values, and the next edits went where the owner did not look.

**The change.** `core/files.link_target`: the file at the end of the links at a path. `config_edit` and
`secrets._write_env_file` write there, beside the file the link leads to (the temporary file in its folder, so the
move stays atomic), keep its mode (the env file's 0600 from its first byte), and leave the link as it was; the env
file's lock stays at its own name, where both writers take it. Dot's other files (`write_whole`: playbooks, sign-ins,
a browser profile's preferences) are still written in place of whatever stands at their name: following a link there
would let a link put in Dot's home move a write of Dot's elsewhere.

**Checked.** `tests/unit/test_linked_settings.py`: a linked `config.toml` changed by `set_setting` and a linked `.env`
by `write_env_value` are changed where they lead, stay links, and the env file keeps 0600; both fail on the code before.
