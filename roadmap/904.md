### 904. The improvement loop makes the owner's worst run into a task of its own

**Status: done (2026-11-01).** **Asked** by the owner (2026-11-01): "self improving hiç çalışmıyor", and research on how
self-improving agents are built. The records of the owner's Dot showed why: from 2026-10-29 to 11-01 every night
proposed a candidate written for the run that went worst (a page on a local port the browser refused, an agent's failed
part left undone), and scored it on tasks of the catalog that a capable model passes under any text (32 attempts of 34).
Nothing could come out better, and the base was kept every night. The research (Reflexion, Voyager, GEPA, ACE, the
Darwin Gödel Machine, Anthropic's guide to agent evals) agrees on one thing: improvement needs a signal from real
failures, checked by something other than the model that proposes.

**Built.**
- A fifth role, the task writer (`write_harness_task`, `agent/review.py`, on the proposer's model), makes the run into a
  small task of files that tests the habit the run lacked (`harness/tasks.py`: goal, at most six files, checks of files
  and of the answer with no pattern and no command, a reference of file tools ending with `finish`, the habit).
- Code admits it: paths inside the workspace, only the file tools and `finish` in the reference, every text through the
  gate for learned texts (`draft_problem`); three scripted plays in throw-away homes prove it fair: its reference
  passes, a run that does nothing and claims it is done fails, and so does one that gives up (`harness/own.py`,
  `fairness`).
- A run that read content third parties can author gives no task, and the writer is not asked; a run is asked about once
  (`harness_task_tried:` in the store).
- The independent security review found that a reference's own paths (`~/.zshrc`, `$HOME/...`, `/tmp/x`, `../`) were not
  confined, and the scripted play runs with the owner's `HOME` under their preset: one draft could have overwritten a
  file in the home folder. Now every path a call names stays inside the workspace and no text of a task names a home
  folder, a variable, an absolute path or a climb; and a task of the loop plays under the balanced preset at least
  (`held_to_workspace`, `evals/runner.py`), where a write or command outside the workspace asks and the attempt
  declines.
- Tasks are kept in `harness_tasks` (the newest 24), given whole to the probe process (`ProbeAsk.own`), and join the
  pool the step plans on (`plan_scoring(..., own)`). The task made tonight is scored on first by the base and each
  candidate. A night that only tries the pool still makes the worst run into a task and tries it, without taking the
  run.
- The page's night row says `Own test:` with the task kept or why none was.

**Left for later.** Edits as small rules with counters of what each did, rather than whole texts (ACE's finding that a
model rewriting the whole text collapses it); a count per night of proposals written, valid, scored and adopted; a task
that a model fails under every text for a month set aside as too hard.

**Checked.** `tests/unit/test_harness_tasks.py` (what code refuses, the twins, fairness, the pool);
`tests/smoke/test_harness_step.py`: a night makes the run into a task that is played for real, kept, tried first and
planned on the next night; a task an idle run passes, or its reference fails, is not kept; a task with a link is asked
again; a run that read outside content gives none; a night that proposes scores its candidates first on the task;
`tests/unit/test_harness_tasks.py`: a task naming a path outside the workspace anywhere is refused, prose with a slash
or an ellipsis is not, and a task of the loop plays under the balanced preset at least.
