### 763. Dot trades crypto on Coinbase, paper or live, under limits no run can change

**Status: done (2026-10-27).** **Asked** by the owner: Dot should trade, as Grok Bot does on Coinbase (its leading agent
venue) and on Interactive Brokers (where each order is approved in the broker's own tab). The owner chose Coinbase, a
paper account first and the live one on their word, and orders placed without asking in yolo, within hard limits.
Coinbase's own sandbox answers with set replies and has no paper trading, so `paper` is Dot's own account at Coinbase's
real prices.

**The approach (CLAUDE.md: what must hold, and what only asks).**

What must hold is in code, before any market sees an order, in every approval mode, yolo's too:
- `[trading]` (config file, which no run can write): `mode` off/paper/live (off by default: no trading tool exists),
  `products` (all priced in `quote`), `max_order`, `max_day`, `max_day_loss` (buys stop for the day, sells do not),
  `max_position`; `trading.limits.refusal` judges each order against them and the account's cash and holdings.
- `trading.service.Trading.place` judges and places one order at a time under a lock, keeps the order before it is
  sent (it counts against the day at once; one sent with no answer stays counted as `unknown`), refuses every order
  while the `STOP` file exists, and reads the settings on each call.
- `trading_order` is placed in the account it was judged for: the action names it (`trading:<mode>:<product>`) and the
  run refuses when the mode changed while the call waited for its approval.
- No tool withdraws or transfers; `trading.coinbase.CoinbaseBroker.check_key` refuses before each live order a key that
  may transfer (`/key_permissions`), and Settings refuses to keep one.

What only asks is the policy: a live order is `network`, risk `high`, flag `trade` (new, `policy.engine.trade_guard`, as
`vault_guard` is): a question in every mode but yolo that no rule lets through, routed to the owner in `auto` too, whose
yes runs the order; a yolo run asks nothing, and one that read outside content has the review model check it (item 525:
`trade` is a taint escalation flag). The first cut gave it `financial`, whose hand-off leaves a step to the owner's own
hands: the pre-push review found that the owner's yes then placed nothing and the run went on as if it had bought. A
paper order is `network`, risk `low`, no flag. The prompt's Trading section tells the run to trade only with
`trading_order`, never by the browser or the shell, to read prices and the account first, and never to split or repeat
an order around a limit; that is guidance, not a guard: the browser's own payment steps keep their money hand-off, and
Dot's tools never show the Coinbase key (a run's own program can reach it, below).

**The reviews.** The pre-push review found that `financial` made a live order a hand-off, which the owner's yes did not
place (now `trade`), that a cancelled order stayed `pending` (now `unknown`, counted) and that a phone could raise
`paper_start` in two steps (any rise is now a widening). The independent security review found that an order approved
for paper could wait for the lock behind another and go live if the owner switched meanwhile, and that an order was
judged against the account of the mode read again mid-way: `place` now takes the account the action was approved for,
reads the settings once inside the lock and judges against the account the order goes to; that an order Coinbase took
was recorded `failed` when the key failed while it was followed (now `unknown`, counted; only "filled nothing" is
`failed`); that the `STOP` file was looked at once before several reads (now again just before the order is sent); and
that a run's own program can read the key from the Keychain, as it can Dot's other keys (docs/safety.md): the docs say
so, and say that a key limited to a Coinbase portfolio holding only what Dot may lose is the bound that holds. The
second pre-push round found that Settings › Rules' replay counted an allow rule as letting live orders through (`trade`
is now among the sources settled before rules, as `vault` is), and that a fill Coinbase told with no usable price was
read as 0 and counted for nothing (now an error: the order stays `unknown`, counted as judged; a candle's volume is
checked too). The third found that Start again kept the day's start from before, which could lift the day's loss limit
or hold every buy (it starts the day again too), that an error before an order is sent counted it (a refusal now), and
that the live account read the Keychain of the start rather than the trading's store (now read as it stands).

**The change.** `src/dotagent/trading/`: `market.py` (Coinbase's public market data: ticker, product rules, candles,
each number checked before use), `limits.py`, `service.py` (the paper account: `paper_start`, fills at the ask or the
bid, `paper_fee_rate`, holdings from its filled orders since its last start; the day's start equity kept per mode and
day in the owner's zone), `coinbase.py` (the Advanced Trade API: an ES256 JWT of two minutes per request from the
owner's ECDSA CDP key, balances, market IOC orders sized to the product's increments and followed until Coinbase says
what they filled). The `trading_orders` table; `tools/trading.py` (`trading_market`, `trading_portfolio`,
`trading_order`, `trading_history`, the `trading` group, which exists only while the mode is not off at Dot's start);
the prompt's Trading section; `routes_trading.py` (`GET`/`PATCH /api/trading`, `PUT`/`DELETE /api/trading/key`, `POST
/api/trading/paper/reset`: what widens — trading on, live, a higher limit, another product, a key — refused from a
phone's key, what narrows open to it; a switch to live checks the key with Coinbase first; changes kept in the config
file through `config_edit`, which writes `[trading]` and numbers with decimals). The key is kept in the login Keychain
(account `trading-coinbase`). `cryptography` (already installed through `pywebpush`) is declared for the signing.

**Checked.** `tests/unit/test_trading.py` (every limit and its message, a sell after the day's loss let through, the
config's own checks; the paper account's fills, fees, round trip and start again; the day's cap and the next day; the
`STOP` file; off and live with no key; a price Coinbase did not give; the order tool's flags and the account guard),
`tests/unit/test_trading_coinbase.py` (the JWT verified with the key's public half; the key read as pasted and other
kinds refused without echoing it; a buy and a sell in Coinbase's sizes, followed to the fill; a transferring key places
nothing; a refused order did nothing and does not count), `tests/smoke/test_trading_settings.py` (a served daemon: a
phone narrows and only the Mac widens; the file keeps each change; a change the config refuses changes nothing). No
test reaches Coinbase or the Keychain. Not measured: a live order on the owner's account, which waits for their key and
their word; the paper account's results, which the owner looks at before going live.
