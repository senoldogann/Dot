### 997. Dot on the iPhone as an app: the live task on the lock screen and in the Dynamic Island

**Status: in progress (2026-11-06).** **Why.** The owner's word of 2026-11-05/06: the phone shows nothing of a task
at work while it is locked, no Dynamic Island, no lock-screen answer. A web app on iOS cannot: Live Activities,
notification actions and a Share extension are native. Two independent reviews (iOS practicality, red team) agreed
with a thin native shell around the same web UI, with changes that this item keeps: Swift and WKWebView (not Tauri
iOS: no code to reuse, remote push only through community plugins), the tailnet's HTTPS address only, the APNs key out
of the runs' reach, alerts that carry no content, a bridge limited to the daemon's own pages. Apple's side was set up
with the owner on 2026-11-06: team `79DZ4AA4DW`, App ID `dev.dotagent.phone` (push, app groups), APNs key
`UMHD6682PT` for the sandbox environment and that topic alone, kept at
`~/Library/Application Support/Dot-keys/AuthKey_UMHD6682PT.p8` (0600, outside Dot's home).

**What must hold.**

- The app opens one address, the daemon's tailnet name over HTTPS (`https://<mac>.<tailnet>.ts.net`), which the
  owner types once; nothing else is loaded in its web view (`WKAppBoundDomains`, no App Transport Security exception,
  no plain HTTP). Pairing is the web UI's own (Settings › Phone code); the phone's key stays what it is.
- The web page tells the app the phone's key through one message (`dot.paired`), taken only from the main frame of
  the daemon's own origin; the app keeps it in the Keychain, where only this app (and later its extensions, through
  its access group) can read it. No other message passes the key, the APNs key or anything of the Keychain back.
- The app registers with the daemon what Apple gives it (`POST /api/phone/apns`, with the phone's key alone): the device
  token, the Live Activity push-to-start token, the environment (`sandbox` for an Xcode install) and, as one is
  started, each activity's update token (`POST /api/phone/apns/activity`). A token is kept with the phone that sent
  it, and goes when the phone is removed or when Apple says it is gone (410, `BadDeviceToken`, `Unregistered`).
- The daemon signs with the APNs key it reads from the path in `[apns] key_path`, never from the store or the
  settings' text, and never logs, returns or masks it into a prompt. The key file is among the files no run reads or changes (the guard and the sandbox).
- An alert carries one of Dot's fixed titles ("A task is done"; a message Dot wrote goes as "Dot has a message for
  you"), the line "Open Dot to see it." and the route to open; no question, draft, result or summary.
- A Live Activity of a run: started when a run of the owner's starts (push-to-start, `run_started`), updated as the
  run's status line changes (the step, how long, waiting for you), ended when the run ends (it stays 15 minutes); a helper's, a schedule's, a watcher's
  or Dot's own run has none; a stale-date so that a lost end does not leave it standing for ever.
- Tests call no Apple service: the sender takes a transport the tests replace.

**Not in this item (next ones):** Approve and Deny on the lock screen (a single-use token per approval), the Share
extension, a widget, a production key for TestFlight.
