### 1673. Dot knows which versions of the `claude` program it works with, refuses a broken one and says when one is unmeasured

**Status: done (2026-11-24).** The `claude` program updates itself, and what Dot relies on (the stream-json protocol,
`--resume` of a cut session, its init line, how it ends on a signal) was measured on given versions (2.1.330 and
2.1.331, items 1580 to 1582). Nothing in Dot read the version, so a change in a new one showed only as runs failing.

What changed (`claude_code/versions.py`, `llm/claude_code.py`, `core/errors.py`, `doctor.py`, the stand-ins):

- `CLAUDE_VERSIONS`, a table of ranges: `supported` 2.1.330 up to 2.2.0 (measured), `graceful` 2.0.0 up to 2.1.330
  (runs, not measured: a cut program may not be continued as item 1581 expects). No version is listed as `broken`: none
  is known to be, and the table says a broken one is added with what broke. A version in no range is `unknown`.
- `ClaudeCodeProvider.program()` (every run, single question and model listing finds the program through it) asks
  `claude --version` once for each program file (its path and time of change: a self-update is asked again), refuses a
  `broken` one with `ClaudeCodeBrokenVersion` ("Claude Code X is known not to work with Dot: why. Install another
  version ..."), and logs a `graceful` or `unknown` one once (`claude_code_version_not_measured`). A program that says
  no version, or does not answer within 15 s, is an unknown one, logged.
- `dotx doctor` has a **claude code** row: where the program is, its version and the verdict; a broken one is a failed
  row. On the owner's Mac: `/opt/homebrew/bin/claude: 2.1.331, supported`.
- The test stand-ins of the program answer `--version` with 2.1.331.

Checked: `tests/unit/test_claude_versions.py` (the version read; the table's verdicts at each edge; a stand-in program
of a version a test table lists as broken is refused, an unmeasured one is logged once across two finds; without the
refusal the test fails), `tests/smoke/test_claude_code_run.py`, `test_claude_code_ask.py`, the doctor's unit tests, and
`dotx doctor` against the installed 2.1.331.
Not done: older versions were not installed to fill the table with measured ranges.
