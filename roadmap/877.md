### 877. An agent has its own folder, which its runs read first and keep their state in

**Status: done (2026-10-31).** **Asked** by the owner, after the review of Dot against an agent-template article
(0xRafy, "GrokBot Templates"): an agent that runs on a schedule needs a place of its own for what it did, so that the
next run picks up rather than starts over.

What Dot had: ten templates told their agent to keep a file "in the workspace" (`prospects.csv`, `candidates.csv`,
`metrics.csv`...), one workspace for every run: two agents of one template wrote one file, and a run of Dot's saw them
beside its own scratch files. Nothing told a run to read its last state first.

- `core/paths.py`: `agent_folder(workspace, agent_id)`, `agents/<id>/` in the workspace (by id, so a rename keeps it).
- `agent/loop.py`: the run of an agent makes its folder at the start and hands its path to the prompt.
- `agent/prompt.py`: `AgentBrief.folder`; the agent's section says the folder is its runs' alone, to list it and read
  what the last run left before starting, and to keep there what the next run needs, never a secret.
- `agent/templates.py`: the nine templates that kept a state file keep it "in your folder".
- `docs/agents-and-campaigns.md` says so, and that the folder is a convention, not a wall.

**Checked.** `tests/unit/test_agents.py::test_the_prompt_names_the_agents_own_folder_and_a_teammate_has_none`,
`::test_the_templates_keep_their_files_in_the_agents_folder`; the agent run smoke tests.
