### 1563. Free mode asks no run's owner anything: `ask_user` no longer waits in a run that is not `yolo`

**Status: done (2026-11-24).** Found by the freedom-contract test (item 1561, `tests/unit/test_freedom_contract.py`), which pins every place that still asks as a known ask. Item 922: with `[policy] free = true` "no run asks anything, whatever its mode".
The gate honoured it (`RunGate` reads the switch, `gate.py`), but `can_ask_user` (`agent/progress.py`) took the run's own mode only, so a watched run in `ask` (or `auto`, `supervised`) with free mode on still raised an approval for `ask_user(wait=True)` and stayed `blocked` for the owner, while the same
call in a `yolo` run left the question in the chat and went on; the stall ladder kept its asking rung too.

What changed: `can_ask_user` takes `free`, and no run can ask while it is on. The loop (`run_agent`), the context a handed-over run is given (`agent/handover.py`) and the one a resumed run is given (`agent/resume.py`) pass `runtime.approvals.free`; what a run that cannot ask does with its question is
`[agent] questions`, as for a `yolo` run. Two places keep the run's own mode on purpose: a message sent with **Plan first** is the owner's own word that this run should ask him before it acts (item 318), so its run can ask, and a start that cannot ask is still refused only as before (`picks_problems`);
and the trust given to an answer (`vouches`, `agent/manager.py`) stays as it was, so no answer clears a mark of untrusted content that did not before.

Checked: `tests/unit/test_progress.py` (the new case: no mode can ask with free on; with it off the old table holds) and, through the real loop with a scripted model, `tests/unit/test_freedom_contract.py` (`test_in_free_mode_the_agents_own_question_is_left_whatever_the_runs_own_mode`, shown red against the old loop, and its twin `test_outside_free_mode_a_run_in_an_asking_mode_still_waits_for_its_question`); `docs/freedom.md` no longer lists the gap as a known ask. `ask_secret` reads the same flag (`tools/meta.py`, `ctx.questions == "leave"`): with free mode on its card is now LEFT on the chat and the run goes on, as in a yolo run, instead of waiting for the card; the card still waits for the owner's value, and what saving it does for the run that parked it is the ask-a-secret work's (the run is not resumed by it today). The docs, the known-asks table and the freedom page say so, and a test pins it.
