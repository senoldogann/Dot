### 1108. A lock screen row whose run ended unseen is ended within a minute

**Status: done (2026-11-10).** From the review of the implicit state machines: the phone's Live Activity (item 1093)
ends a run's row on its `run_finished` event. A run closed by the store alone (`mark_interrupted_runs` as the daemon
starts, `close_runs_of` when a command's process is found gone) or whose event the feed dropped sent none, and its row
stood "Working" until the daemon started again, as `settle` only adds rows.

Now the watch's flush reads the rows still at work against their runs every `CHECK_EVERY_S` (a minute): a run that
ended ends its row with its own status and end time, as its event would have; one that is gone takes its row off; the
activity is told at once.

Checked: `tests/unit/test_apns.py` (a run finished in the store alone is a failed row at the next minute's flush, not
before).
