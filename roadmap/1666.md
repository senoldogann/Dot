### 1666. DotNext speaks Turkish from its first string, and its screenshots come from a harness

**Status: done (2026-11-24).** The owner reads Turkish only (the lead's steer from G2 #1 and #10).

What was built:
- Every user-visible string of DotNext is `String(localized:comment:)` and lives in
  `ios/Next/Resources/Localizable.xcstrings` (218 keys, English source, a Turkish translation and a translator comment
  each; English plural forms where a count needs them). `ios/Next/scripts/translations_tr.py` holds the Turkish,
  `apply_translations.py` writes it into the catalog and refuses a key it has no Turkish for.
- Two checks: `StringCatalogTests` fails on a key with no Turkish, no comment, or marked stale, and proves the built
  app shows the Turkish words; `ios/Next/scripts/check_strings.sh <derived data>` syncs a copy of the catalog with the
  keys the compiler extracted (`SWIFT_EMIT_LOC_STRINGS`) and fails on a string of the code the catalog lacks, on a
  stale key, and on a raw literal in a SwiftUI call (which would bypass the comment). The repository's CI does not build
  Swift, so the script runs on a Mac with the other iOS checks (`ios/Next/README.md`).
- The screenshot harness: a debug build opens a scene with `-DotNextScene <name>` (the gallery pages, the tabs, the
  chat and its two sheets) and writes `Library/Caches/dotnext-ready.txt` once it is drawn;
  `ios/Next/scripts/shots.sh <app> <out> "<languages>" <udid>...` waits for that mark and captures every scene in light
  and dark, at Large and AX3, on each simulator, with a fixed status bar.

How it was checked: both checks pass; each was made to fail once (a Turkish entry removed: both tests failed; a new
string added to the code: the script named it and the missing Turkish). The harness produced the 120 shots of item 1665.
