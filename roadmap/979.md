### 979. A run that read a page adds no tags to a clean note

**Status: done (2026-11-05).** **Found** by the security audit of 2026-11-05 (the owner's ask; run-1 lead
`dotagent/memory/service.py:saved-again:tainted-tags-merged-into-untainted-note`): `memory_save` of a note's exact text
merges the saver's tags into the note that has it (`_saved_again`) and leaves the note's mark as it was, since the
same words bring nothing new. The tags do: a run that read outside content could add up to six tags of its own words
to a clean note, which every run is then handed as trusted, and a `core` tag made an owner's note stand for every run.
The approval card of the save shows its text, not its tags.

**Built.** `memory/service.py` `save_memory` gives a save from such a run no tags to merge into a note that is not
marked (`_tags_taken`); the note is still woken, and its own tags and time stay. A clean run's save, or one into a
note already marked, merges as before.

**Checked.** `tests/unit/test_memory_taint.py` (a marked run's re-save with `core` and a tag of its own leaves the clean
note's tags as they were; it failed before the change; the owner's re-save still adds its tag), the memory unit tests.
