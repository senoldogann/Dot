### 1147. The state set: browser tasks that pass by what their site took

**Status: done (2026-11-13); played by a scripted model only.** **Found** while reading how the eval tasks judge a
browser run. The speed set judges the answer's words: the reference of its job application opens the page and
finishes with the sentence a sent application shows, without sending one, and the sign-up's opens the last page
directly. That times a run. It does not show that a form was sent.

**Built.** A task's site may take POSTs (`SiteEndpoint`, `evals/site.py`): it keeps every request an endpoint was
sent, as it arrives, and answers after the endpoint's delay. A new check, `site_recorded`, holds when the site took
exactly so many requests at a path, each with the fields it names; the records are read once the run is over and
handed to the checks beside the run's events. `eval_config` is untouched. Two tasks
(`evals/state_tasks.py`): an application whose answer comes 1.5 s late, and a settings form whose button takes its
first press and does nothing. They are checked by `dotx eval check` and played by id; they are not in the catalog's
own list, so the weekly score stays the set it was.

**Checked.** `tests/unit/test_eval_state.py`: the site keeps what it was sent and nothing for a page; the check holds
for exactly one request with the right fields, not for none, two or other fields; a check that names no endpoint is a
mistake of the task. `tests/smoke/test_browser_state_tasks.py`, a scripted model through the real loop, tools and a headless
Chrome: both references pass, and each way of seeming done fails on the site's record with the answer a run that did
the work gives: saying so, opening a page that looks like the answer, pressing the button once, sending the form
twice. No model was played: whether one passes them, and at what cost, is `dotx eval run --task state-apply-once
--task state-save-second-press`.
