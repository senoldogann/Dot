### 795. MCP: a sign-in keeps where its tokens are renewed, and a modern session is not pinged

**Status: done (2026-10-28).** **Asked** by the owner, the third round of the review of every module ("Bir sonraki
yapılacaklara geç"). The owner's daemon printed, at every start, a traceback ending in "the MCP server asks you to sign
in again" for Stripe, and a warning that MCP's ping is removed. A review of `mcp/`, each found point checked in the code
and in the mcp SDK 2.3.0:

- **A token renewed at the wrong address.** Dot kept a sign-in's tokens and client but not the authorization server's
  metadata the sign-in found. A restart's sign-in had none, and the SDK renewed a token that ran out at `/token` of the
  MCP server's own origin; a server whose token endpoint is elsewhere answered 404, the SDK dropped the tokens and Dot
  asked the owner to sign in again at every start after the first hour. The metadata and the authorization server's
  address are kept with the tokens (`StoredSignIn.metadata`, `auth_server_url`) and given back to every later sign-in.
  A sign-in made before keeps none: Stripe asks once more, then stays signed in.
- **The SDK's tracebacks on stderr.** The SDK logs with Python's logging, which Dot does not set up, so each refusal
  printed a traceback to the daemon's stderr; its logger has a null handler, and Dot logs the outcome itself.
- **A ping to a modern session.** The ping before a quiet session's call was sent under the modern protocol too, which
  has none (the SDK warns it is removed): a server that refused it read as a session gone and was connected again
  every quiet minute. A session of the modern protocol is not pinged (a call that fails reconnects, as before); one of
  the older protocol is, without the warning.
- **A server left running.** A call cancelled while its server started (a stop, a tool's time) left the server's task
  running, kept nowhere, until the daemon ended; it is stopped with the call.

**Not changed:** a ping another call sends while a slow call is in flight on the same older-protocol server may cut that
call; a sign-in the server refused is tried again at each start (one line in the log now, not a traceback).

**Checked.** `tests/smoke/test_mcp_sign_in.py` (the metadata kept and given back), `tests/smoke/test_mcp_http.py` (a
modern session not pinged; the older one's ping as before), every MCP test.
