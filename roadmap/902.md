### 902. Let it help: the helper works, and its answer reaches the run at work

**Status: done (2026-11-01).** **Asked** by the owner (2026-11-01): "I press Let it help and nothing happens. When a
feature is added you must make sure it works, with tests."

What happened on the owner's Mac: two presses, at 16:14 and 16:15, reached `run_mvxwmfu7` (a run of Dot's own
initiative on senoldogan.dev) as item 896's notes ("hand a part over with message_agent if one fits, else go on"); the
run was near its end, went on and finished 28 seconds later, and no helper did anything. Item 896's tests had checked
that the press sent its request, not that help came of it.

- `POST /api/agents/offers/help` starts the helper's run as a helper of the run at work (`manager.delegate`, as
  `message_agent` makes one, so that it answers the policy's questions as that run does, an initiative's asks of
  item 850 included, and starts as untrusted as it is: the pre-push review; `delegate` takes `on_start` to give the
  run's id at once) with
  `help_goal`: fixed words that name the one it helps and the run at work, read where that run stands with
  `read_agent_chat` (its new `run`, which reads that run's chat, only one of that agent's own, rather than the newest:
  Dot often has more than one at work, the pre-push review), do the part its role fits, end with what it found or
  made. The run at work is told so (`help_note`, Dot's note via `manager.tell`),
  and when the helper ends its answer goes to the run at work as another note (`help_answer_note`, the reply as
  `message_agent` renders it, fenced when the helper read outside content), while that run still works; one that has
  ended is left (logged). An answer of a helper that read outside content also marks the run at work as having read
  it (`UserInput.taints`, `manager.tell(..., taints=True)`, `gate.taint()` in the loop), as a reply through
  `message_agent` does (the pre-push review). Only a free agent helps (409 for one at work, waiting or paused); the run
  at work is told once the helper has started (a start refused tells nothing, a run that is itself a helper is 409),
  and one that ended meanwhile has its helper stopped and is refused (409); a relay that fails is logged
  (`help_answer_failed`); the helper's run is returned (201). The office's button is off while its press is on the way,
  and a helper being started is refused a second start (409). The helper lives no longer than the run it helps: the
  relay races the helper's run against that run's end and stops the helper when that run is stopped or ends first, as
  the run that sends a `message_agent` does. What a message does to a run's trust is taken in one place,
  `RunGate.take`, by Dot's loop and OpenCode's alike (OpenCode's had missed the new mark).
- `office.js`: the helper is shown at work at once, the toast says it is helping, the button says **Helping**.
- `docs/agents-and-campaigns.md` says so.
