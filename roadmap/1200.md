### 1200. The `word` skill says that Word's `open` returns no document, so a script takes `active document` instead

**Status: done (2026-11-16).** Dot's record showed `apple_script: osascript failed` four times. One was a Word script,
`set theDoc to open POSIX file "…docx"` and then `save as theDoc …`, that failed with *theDoc is not defined (-2753)*:
Word's dictionary gives `open` a result (the opened document), but Word returns nothing, and the `word` skill named
`open` without saying so while pointing the run at the dictionary. The skill now says that `open` returns nothing,
whatever the dictionary says, and to take the document as `active document` after opening it.

The other three are not a defect of this change's to fix: two were scripts sent to the owner's Google Chrome to run
JavaScript in a tab, one refused by Chrome (*Allow JavaScript from Apple Events* is off, the owner's setting) and one
failing with -609 after a run found Dot's browser profile held by another Dot process and reached for the owner's Chrome
instead (item 1198 fixed that hold); the `apple_script` tool already tells a run to use `browser_eval` for a web page.
The fourth's script is not in the record any more.

No test: the change is the skill's words to the model, and Word is not driven in tests.
