### 729. The daemon starts without the libraries of single tools

**Status: done (2026-10-27).** The owner's word of 2026-10-27: Dot is to be so fast and so light that people ask how.
Measured with `-X importtime` and the resident size of a fresh Python (M4, macOS 26.6): importing
`dotagent.server.daemon` took 1.2 s and 190 MB, and python-docx, openpyxl and python-pptx were among them at every
start (`agent/attachments.py` imports `office.py`; `harness/probe.py` imports the eval catalog, which imports
`evals/office_tasks.py`), with numpy, which openpyxl loads; so were Vision (`desktop/session.py` -> `shots.py` ->
`ocr.py`) and pywebpush with aiohttp (`notify/push.py`). Each is used by one tool or one moment.

**The change.** `office.py` keeps the models, the checks of a package and the text; the readers that need the libraries
are `office_read.py`, which `office_content` loads on the first Office file. `evals/office_tasks.py` names the libraries'
types for the type checker only and loads them in the check it runs in a process of its own. `desktop/ocr.py` loads
Vision in `read_lines`, `notify/push.py` pywebpush in `_send`.

**Measured.** The import of the daemon's module: 190 -> 150 MB. With item 730, a daemon started on a copy of the owner's
database: 184 MB after start before, 132 MB after.

**Checked.** `test_startup_imports.py` imports the daemon's module in a fresh Python and finds none of the seven loaded;
`test_office.py`, `test_previews.py`, `test_evals.py`, `test_screen_text.py`, `test_push.py` (its fake now takes
pywebpush's own place).

**Not done.** AppKit (23 MB), the MCP client (23 MB) and FastAPI (19 MB) are what the daemon uses from its start.
