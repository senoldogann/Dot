### 687. A nightly reflection whose lesson draw failed tries those runs again and says it failed

**Status: done (2026-10-26).** The whole-project review found that `_learn` of the reflection kept only the lessons of
`learn_from(...)` and dropped its error, and that `_asked_already` counted a `lessons_failed` event as the run asked, so
a run whose draw failed (at the loop's own draw at its end, or in a reflection) was never drawn from again; and the
scheduler recorded such a night as learned and cleared the failure counter, so nothing told the owner. The reflection
also read only the runs that ended since the last one, so a run that failed on one night was out of the next night's
window.

**The change.**

- A run whose lessons were never drawn (no `lessons_proposed` or `lessons_none`) and whose draw failed fewer than
  `MAX_DRAW_FAILURES` (3, the loop's own try counted) times is asked again by the next reflection, so a model that is
  down one night is asked the next, and a run that always fails costs no model call for ever. A run whose lessons were
  drawn and whose deciding failed is not drawn again: its lessons stay proposed.
- `Store.runs_with_failed_lessons` finds such runs of the last seven days; the reflection reads them beside the runs
  that ended since the last one, without telling them twice in its journal.
- `_learn` returns what failed; `Reflection` has `lessons_failed` and `lessons_error` (the first error, and how many
  more). The scheduler records a reflection with a `lessons_error` as failed: the Activity list and `dotx stats` show
  the failure, and the record of how learning fares counts it, so three such nights tell the owner that learning has
  stopped. `reflection_failure` keeps a failure recorded at the time of the reflection it came with (`<=`), as that
  reflection is done and failed at once.

**Checked.** `tests/smoke/test_reflection.py` with a review model that is down: the loop's draw fails, the first night
asks again, fails and says so (failure kept, health counts one), the next night with the model back draws the lesson
and clears both; a model that stays down is asked for the loop's try and two nights and no more.
`tests/unit/test_reflection.py` holds the bound and the store's query. `docs/autonomy.md` says it.
