### 1760. A run no chat is told in is not offered a command in the background

**Status: done (2026-11-25).** A repair of a problem Dot found in its own record (tool_error, seen 22 times):
"terminal_open: A command in the background is told to its chat when it ends, and a delegated run or a campaign's
session has none".

Cause: `terminal_open` refuses `background` in a delegated run and in a campaign's session (item 437: no chat of their
own is told of the end), yet both were offered it: the field stood in `terminal_open`'s parameters, and `shell`'s
description sends a long command there. On the owner's Mac, 22 delegated runs on `claude_code:sonnet` (and one team run
on DeepSeek) set it once each, were refused and spent a step on it.

What must hold: a run that `tells_no_chat` (a parent run or a campaign) is offered neither the field nor the sentence;
every other run is offered the tools as before, word for word; the refusal stays for a model that sets the field anyway.

What was built (`tools/terminal.py`, `tools/shell.py`, `agent/loop.py`, `claude_code/run.py`):
- `shell`'s sentence about the background is `BACKGROUND_HINT`, its description unchanged (checked equal to the old one).
- `chatless_specs` (pure): `terminal_open` without `background`, `shell` without `BACKGROUND_HINT`, others as they are.
- Dot's own loop applies it to the specs of such a run, beside the delegated run's and the campaign's own filters, and
  Claude Code's door to the specs it hands the program.

Checked: `tests/unit/test_terminal.py` (the specs offered), `test_claude_code.py`, `test_freedom_contract.py`, the smoke
tests of the terminal and the background commands, `dotx eval check`.
