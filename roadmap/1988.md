### 1988. A search pattern ripgrep cannot read is told as the call's own error, with the syntax it reads

**Status: done (2026-11-27).** Dot's record held `search_files: ripgrep failed` five times: each a pattern the model
wrote in Python's or PCRE's syntax, which ripgrep's default engine does not read (a look-ahead `(?!…)`, a `\n` across
lines, a `)` with no group open). The tool did not say which syntax it reads, and on such a pattern it failed as a
failure of ripgrep's own, with ripgrep's words, which advise passing `--pcre2` or `--multiline`: flags `search_files`
does not take, so the model could not act on them.

What changed: the `pattern` argument's description names the syntax (Rust regex as ripgrep reads it: no look-around, no
backreferences, a match within one line, and what to escape to match as text), and a pattern ripgrep cannot read fails
as an error of the call's input (`ToolInputError`): "The pattern has a regex syntax error (<ripgrep's reason>).
search_files reads <the syntax>.", without the advice on flags. Every other failure of ripgrep is told as before.

How it was checked: `tests/smoke/test_sandbox.py::test_a_search_with_a_pattern_ripgrep_cannot_read_is_the_calls_own_error`,
with the three kinds of pattern of the record, fails without the change and passes with it; the file's other tests,
`tests/smoke/test_mcp.py`, the freedom contract and tool tests, `dotx eval check`, ruff and mypy pass.
