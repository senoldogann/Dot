### 1402. A run whose goal check could not run has an ending of its own, and is no longer "refused"

**Status: done (2026-11-24).** Found by the autonomy audit (`workspace/autonomy-audit-2026-11-23.md`, finding 9). When
no model could answer the goal check, `loop.py` ended the run `failed` with "the check could not run (...); this answer
is not verified" under the answer, after the mark `Goal check: ` that a real refusal carries too, and
`store/endings.py` read that mark as `goal_check_refused`, "refused by the goal check". Of the seven runs in the
owner's database that carry it, at least five were never judged: `dotx stats` told a spent quota as the check's no.
Item 1354 made the case rare (the check goes down `[models] standby`); it did not make the word true.

What changed: a new ending, `goal_check_unavailable` ("goal check could not run (answer not verified)"), which
`classify_ending` reads from the note under the mark: one that starts with `GOAL_CHECK_UNAVAILABLE` ("the check could
not run", the words `loop.py` writes, now one constant for the writer and the reader), as the owner reads it unchanged,
is the new ending; any other note is the check's own word and stays `goal_check_refused`, which is now for a refusal
alone. A run closed before the change was stored as `goal_check_refused` whatever the note said: a stored refusal whose
note says the check could not run is read again as the new ending, so the owner's five runs are told as they were (no
data is rewritten, so no migration; every other stored ending still wins over the text).

The readers: `dotx stats` (`ENDING_LABELS`, which `store/stats.py` orders its endings by and `cli_stats.py` prints; a
test holds that every ending has its words), `docs/development.md` and `docs/models.md`. The others that name an ending
read none of the two: `scheduler/recovery.py` tries a task again only for a cut, a stall, a passing error and the plan's
limit, so a check that could not run is not tried again (its work may be done and a try would do it twice), as before;
`agent/resume.py`, `agent/orders.py` and a campaign's follow-up read other endings. The web UI never read the ending
(the timeline hides the `goal_check` events and the answer carries the note), so no script changed, and the answer text
stays as it was: "this answer is not verified".

Checked: `tests/unit/test_endings.py` (the new text is the new ending, a refusal that says a step "could not run" stays
a refusal, a stored refusal with the unavailable note is read as the new ending and every other stored ending stands,
every ending has its words), `tests/unit/test_run_statistics.py` (`dotx stats` counts two runs as "goal check could not
run (answer not verified)", one of them stored the old way, and one as "refused by the goal check"),
`tests/unit/test_schedule_recovery.py` (not tried again), `tests/smoke/test_evals_runner.py` (a real run whose review
model has no key ends `failed`, says "not verified" and is classified as the new ending),
`tests/smoke/test_run_limits.py` (a real refusal is still `goal_check_refused`). `ruff`, `mypy`, `npm run check`, `dotx
eval check`. Not done: the five runs of the owner's database keep their stored word; they are read as the new ending,
not rewritten.
