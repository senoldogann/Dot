### 746. A run reads its tab's console and opens a page at a phone's size

**Status: done (2026-10-27).** **Why.** The owner's agents build websites and check their own site after a deploy.
Chrome DevTools' MCP has what that takes and Dot did not: the console messages and uncaught errors of a page
(`list_console_messages`), and a page at a phone's width (`emulate`, `resize_page`).

**The change.** Each tab keeps what its page wrote to the console and the exceptions no script caught, the last 100
(`browser/console.py`, `Tab.console`, kept as `browser_requests` keeps the background calls, from the page's `console`
and `pageerror` events; a new document of the tab starts the list again). `browser_console` lists them newest first,
by `level` and `limit`, each cut to 400 characters with its script line; the list is fenced as the page's text, the
run marked untrusted, secrets named in a message or an address hidden outside `yolo` and what the password manager
filled in held back, as for `browser_requests`. `browser_viewport` gives the current tab a `width` and `height`
(`BrowserSession.set_viewport`, a DevTools session of the tab's own laying `Emulation.setDeviceMetricsOverride` over
Playwright's; the size the model sees, `_viewport`, follows it) and, with no width, the size every tab has: the window's,
where pages fill it, or that of Settings › Browser. Both are observations in every mode. The viewport is a size alone: no touch and no
user agent, which Dot's browser has no way to put on one tab, and no heavier emulation layer. In the open Chrome of the
owner it fails with a clear message: its window is theirs and Playwright puts no emulation on it.

**Checked.** `tests/smoke/test_browser_console.py` in a real headless Chrome: a page that logs, warns, writes an error
with a token and throws late is read newest first, by level and limit, cut, its token hidden outside `yolo` and shown
in it, the list starting again on a new page; a page whose layout depends on its width reports the phone's width and
layout after the change, a screenshot of 390x844, the size kept across a load and not given to another tab, and the old
size back; a scratch Chrome attached as the owner's refuses the size and still reads the console; as tools both are
read-only for every preset and a research run has them, the console is untrusted. Each fails on the code before, and
the new page's reset of the list and the refusal in `attach` each fail when removed.
