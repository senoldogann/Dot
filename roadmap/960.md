### 960. web_fetch reads a site that closes the plain request's TLS handshake in the browser

**Status: done (2026-11-03).** **Found** by Dot's self-repair in its own record: `web_fetch: the request failed in
transit`, seen four times. Three of the four were the sites: `witted.fi` and `access2finance.eu` refuse port 443
(their port 80 redirects elsewhere), and `suomenyritysrekisteri.fi` did not answer in 15 s, to `curl` too. The fourth,
`www.businesskitchen.fi`, closed the TLS hello (`SSLEOFError: UNEXPECTED_EOF_WHILE_READING`) of Dot's plain client
only: measured on 2026-11-03 with Python's `ssl`, closed four times of four with ALPN `http/1.1` (what httpx offers
without HTTP/2) or none, open four times of four with `h2` first, and with TLS 1.2. Chrome offers `h2` first.

**Built.** `WebHandshakeRefused` (`core/errors.py`), a `WebTransportError` the web client (`web/client.py`,
`_refused_handshake`) raises when a connection failed on an `ssl.SSLError` that is not a certificate that did not
verify; it is still tried again as any failure in transit. `web_fetch` (`tools/web.py`) remembers the host as refusing
and reads the page in the run's browser, as it does a page that turns the plain request away (item 98); when the
browser cannot read it either, the result says so and names the next rung. HTTP/2 in the plain client would need the
`h2` package, a dependency the owner adds.

The browser's way exposed a hang of its own: in a Chrome that had read a page before, as a running Dot's has, a quiet
read whose navigation failed in transit three times (`ERR_CONNECTION_CLOSED`, `ERR_EMPTY_RESPONSE`) never came back,
`page.close()` waiting on a tab Chrome was still committing its error page in (measured 2026-11-03: each such second
read hung; a pause of a second before the close let it through). `BrowserSession._close_scratch`
(`browser/session.py`) now closes the tab the way `_background_tab` made it, through `Target.closeTarget`, and waits up
to `action_timeout_s` for Playwright to see it closed, else raises (0.02 s each in the same sequence).

**Checked.** `tests/smoke/test_web.py` (a listener that closes each hello: `WebHandshakeRefused`; a refused
connection stays a plain failure in transit); `tests/smoke/test_web_fetch.py` (browser: after a page the browser read
first, the same listener, which closes Chrome's hello too, gives a result that names the browser's failure and the next
rung, and the host is remembered; without the change to `_close_scratch` that call hangs). By hand against the site:
`web_fetch` of `https://www.businesskitchen.fi/en/home` now reads it in Dot's headless Chrome (HTTP 200); `witted.fi`
still fails in transit, as `curl` does.
