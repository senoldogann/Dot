### 679. An extraction's address that could carry data out is flagged as a fetch's is

**Status: done (2026-10-26).** The whole-project review of 2026-10-26 found that `web_extract` weighed only the files
among its sources (`_source_flags` called `read_flags` on them) and named only its first source as its target.
`web_fetch` and `web_crawl` give an address the flags of `checked_address` (`exfiltration` for one that is very long or
holds a key, which the policy refuses in every mode but `yolo`); an extraction of
`https://collector.example/?k=sk-ant-…` passed with none, and the daemon sent the key in the address. An owner's rule
read the first source alone.

**The change.** Each web source of an extraction is weighed by `checked_address`, as a fetch's address is (refused
where Dot does not go, flagged when it could carry data out), and the action's target holds every source, one per line,
so a rule reads them all. `docs/safety.md` names the extraction among the tools whose addresses are judged so.

**Checked.** `tests/smoke/test_crawl.py`: an extraction whose second source holds a key has the flags of a fetch of it
(`exfiltration`) and names it in its target; one of a plain address has none; the file test of item 174 as before.
