### 1316. What the code imports is declared in pyproject.toml

**Status: done (2026-11-22).** Eight packages the code imports directly were in `uv.lock` only as the dependencies of
other packages, so a release of `mcp`, `fastapi`, `httpx` or `pywebpush` that dropped one would have broken Dot with
`uv sync` saying nothing. Found by reading every import under `src/dotagent` (grep, `uv tree` and the lock): `starlette`
(the server's middleware, streams and the OpenCode bridge), `httpcore` (`web/client.py`), `pydantic-core`
(`agent/review.py`, `themes.py`), `httpx2` and `mcp-types` (`mcp/connection.py`, `mcp/hub.py`), `py-vapid`
(`notify/push.py`), and `objc`/`PyObjCTools` and `CoreMedia` (`desktop/ax.py`, `flight.py`, `live.py`, `vault/ocr.py`),
which are `pyobjc-core` and `pyobjc-framework-coremedia`. The PyObjC ones carry the same `sys_platform == 'darwin'`
marker and `>=12.2.2` as the other `pyobjc-framework-*` lines; the others take the version `uv.lock` holds as their lower
bound. The tests import `httptools` (`test_daemon_http_stack.py`), which uvicorn's extras bring: it is in the `dev`
group. `uv.lock` records the new names and changes no version.

`tests/unit/test_declared_imports.py` walks `src/dotagent` with `ast` and fails for a third-party import that is not in
`dependencies`, an optional group or a dependency group of `pyproject.toml`, is no standard module and no part of
`dotagent`, unless a short allowlist (empty today) gives the reason. `pyproject.toml` dependencies are under "Always
needs a human" in REVIEW.md; nothing of what Dot does at run time changes.

Checked: the new test (and that it fails on the eight names before they were declared); `uv lock --check`.
