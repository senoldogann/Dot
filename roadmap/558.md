### 558. Setup, the command line, config, MCP and accounts: an early line never answers a prompt, setup picks working helpers and embeddings, MCP re-adds drop old tokens, drafts report Mail's failures, tests never use the owner's keys

**Status: done (2026-10-23).** From the deep audit of origin/main `96e8c750`: 32 findings in setup and the command line,
config, the routes of MCP, the system and the gallery, drafts, the accounts and the tests, each one read again by a
second reader before it was fixed. Each is named below by its number and title.

**As built.**

The terminal and `dotx setup` (`cli_ui.py`, `cli_setup.py`, `cli_daemon.py`, `cli.py`, `cli_desktop.py`):
- F39 *A line typed before a terminal approval prompt answers it.* A prompt for a decision (approval, question, hand-off)
  discards what was typed before it appeared (`termios.tcflush`) and says so, and the line typed at it answers it; the
  chat's own `you>` prompt keeps what was typed ahead, as does standard input that is no terminal. A hand-off is done
  only on Enter or a yes (`done`, `y`, `yes`); any other answer skips it, and the prompt says that.
- F40 *`dotx setup` with a provider other than Ollama leaves the embeddings on Ollama.* With the models of another
  provider setup asks the Ollama of this Mac for `[memory] embed_model`; with none, or without that model, it writes
  `[memory] embed_enabled = false` (`config_edit.set_embeddings`), says why, and says the ways back (Ollama and `ollama
  pull bge-m3`, or `embed_provider = "openai"`, to which the text of every note goes). An embedder the owner chose
  already stays. The vision, fast and review lines say when the model they keep is an Ollama model that does not answer
  here. `doctor.model_is_installed` is public for it.
- F43 *`dotx setup` with OpenCode Zen makes the free model the fast, review and vision model.* A pick of Zen is the main
  model alone (`_write_models` writes no role), the output says why the roles keep their models, and warns where a kept
  model is itself one of Zen's, as an earlier setup wrote it.
- F44 *`dotx run --standing --browser own|attach` is refused for every value.* `get_args(BrowserMode.__value__)`.
- F145 *`dotx prune --help` hides what `--apply` deletes.* The help of `prune` and `--apply` names the old run events, the
  orphan screenshots, the old undo journals and the database's free space.
- F117 *`dotx service uninstall` is not refused inside a run.* It is, as install and restart are.
- F119 *Dead copies of the run flags' help in `cli_desktop`.* Deleted.

The desktop shell (`desktop/src-tauri/src/lib.rs`, `desktop/ui/down.*`):
- F118 *The down page tells the user to start Dot when something else holds the port, and its command works only in a
  clone.* `Seen::Unproven` carries the address; the page says "Something else answers at <address>" with the `lsof` line
  and none of the advice to start Dot. The command is `dotx service install`, with a line for a clone (`uv run dotx`).

Config and the models (`config.py`, `config_edit.py`, `defaults.toml`, `llm/router.py`, `runtime.py`, `doctor.py`):
- F112 *Count settings accept 0 or negatives that disable the browser* and F147 *Some `[agent]` numbers that break the
  loop are accepted.* `navigation_attempts` and both `max_batch_steps` at least 1; `stall_limit` and `revisit_window` at
  least 2, `failure_streak` at least 1, `finish_nudges` and `goal_patience` at least 0; and the others the review found
  below what means anything: the desktop's `jpeg_quality` (1 to 100, as the browser's), `screenshot_max_edge`,
  `ax_max_nodes`, `ax_max_depth`, the settle waits and `paste_settle_ms`, `reminder_every`, `keep_recent_*`, Ollama's
  `num_ctx` and `num_ctx_cloud`.
- F114 *Settings cannot change `[models] standby` or `[server] reach` once the list runs over several lines.*
  `config_edit` finds where the array closes (brackets in a string or a comment do not count) and replaces the lines
  whole, a comment after the `]` kept.
- F115 *`defaults.toml` comments contradict the settings they describe.* The budget comment names
  `context_elide_share` and `context_summarise_share`; the standby comment lists what moves a run on.
- F110 *Web-search rungs use key presence frozen at daemon start.* `Runtime.search_keys` (a holder, with the old
  `search_key_present` and `anthropic_key_present` as properties) is read again when Settings › Providers saves or
  removes the Ollama or the Anthropic key, which retires the provider's connector: the router tells what listens
  (`ModelRouter.on_retire`), so `server/routes_keys.py`, which needs the owner's review, is not changed. The keys of
  the services the daemon starts without (Ollama's, Anthropic's, TypeSafe's) are read so that a Keychain that does
  not answer or refuses is no key there and the daemon still starts (`_optional_secret`); `dotx doctor`'s key rows
  read it the same way. Tested in `tests/unit/test_search_keys_refresh.py`.
- F111 *The router's single lock is held while a connector is built.* A connector that exists is returned without a
  lock; one is made, retired or registered under a lock of its provider alone, and made once for the calls that wait for
  it; one made while the router closes is closed.
- F113 *`harness.md` states the selection rule wrongly.* Better on at least one task and worse on none.

The routes (`server/routes_mcp.py`, `mcp/masking.py`, `mcp/hub.py`, `server/routes_system.py`,
`server/routes_gallery.py`, `server/views.py`, `static/js/views/plugins.js`, `server/app.py`, `server/callback_page.py`):
- F34 *Re-adding an MCP server under a connected name keeps the old server's OAuth tokens and sends them to the new
  URL.* An add of a name whose server is another address (or command), or which no server has any more, forgets the
  sign-in kept under the name first; an address left as it was keeps it.
- F98 *MCP address and failure detail returned and logged unmasked.* `mcp/masking.py`: a URL is shown without its user
  and password, its query and the path segments that read as keys; a command line with its secret options masked; the
  context of an error (the URL, the arguments, the causes, the tail of what the server printed) with the URL's own key
  and the secrets of known forms masked. `McpServerView.address`, `McpFailure.detail` (stored, so `GET /api/status`,
  the terminal and the log have it so), the log of a try that failed.
- F99 *Choose tools during a running try orphans the try.* `PUT .../allow` is a 409 while Dot tries the server.
- F100 *`PUT /judge` switches the live provider before the config write.* The previous provider is put back when the
  write fails.
- F101 *A gallery plugin shows "installed" after the pin moved.* State `outdated` with `installed_commit`; the card says
  **Older version** and the page which commit is installed; Remove, then Install, takes the new pin.
- F96 *Unexpected exceptions are answered outside LocalGuard.* `_AnswerFaults`, inside the guard, answers them (the
  guard's headers and `no-store`), logs `request_crashed` once and raises nothing again; the handler of `Exception` is
  gone, so only a failure outside every middleware reaches Starlette's last resort.
- F97 *The failed sign-in page sends the owner to Customize › Plugins.* Connectors.

Drafts and accounts (`drafts/`, `oauth/`):
- F72 *A Mail draft is marked sent even when Mail's `send` reports failure.* The script ends in
  `if not (send theMessage) then error "Mail did not send the message"`.
- F73 *An iMessage to several recipients that fails partway is marked failed and Send again sends it twice.* A message
  is handed over one recipient at a time (`send_calls`); a failure partway names those reached, and says to take them
  off before sending again.
- F74 *Signing out during a token refresh writes the tokens back.* `forget` takes the account's refresh lock.
- F75 *OAuth scopes grant sending and writing though every account tool only reads.* Google `gmail.readonly` and
  `calendar.readonly`, Microsoft `Mail.Read` and `Calendars.Read`.
- F77 *Sign out leaves the refresh token valid at the provider.* Google's refresh token is given back to its revoke
  endpoint (best effort, logged without the token); Microsoft has none for a client like Dot's, which the docs say.
