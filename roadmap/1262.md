### 1262. A whole-file write is synced before the name moves

**Status: done (2026-11-20).** The code review found that `write_whole` moves a temporary file over the target without
flushing it to disk. A crash or a power loss after the name moves can leave the file empty or cut short: a skill, a
theme, a sign-in, a phone, the watchdog's state, a browser profile's preferences.

Now the new bytes are written beside the target, flushed and synced, then moved over it, and the directory is synced
so the name survives too. A failure while writing or syncing the new bytes removes the temporary file and leaves the
original as it was. The file stays readable by this user only (mode 0600, as `mkstemp` makes it). The signature is
unchanged.

Other writes that open a file with `"w"` were left. Each one follows a link, copies a mode, or creates a file that
must not exist yet, which `write_whole` does not do.

Checked: `tests/unit/test_write_whole.py` (a failure mid-write and a failure while syncing leave the original and no
temporary file; the file is synced, with its full bytes, before it replaces the original, and the directory after).
The two durability tests failed first (`DID NOT RAISE`, and the only step was `replace`).
