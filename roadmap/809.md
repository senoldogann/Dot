### 809. Aggressive autonomy, corrected: the other agent's ideas, with the bugs fixed

**Status: done (2026-10-28).** The direction of `feature/aggressive-autonomy` is kept: a run moves fast on low-risk
work, recovers from a failed action through its chain, lets urgent things jump a busy Mac, and the goal checker asks
for the best result. This fixes the bugs that made the first implementation unsafe or false, without turning it into
a cautious system.

- **Speculative read-only work.** A read-only tool (`web_search`, `web_fetch`, `read_file`, `list_dir`,
  `search_files`, `find_files`, `browser_snapshot`, `browser_read_text`, `desktop_snapshot`, `desktop_read`) skips
  `wait_free` in `auto`/`yolo`, so a takeover does not stop a lookup or a read. Approval and a tool that acts still
  wait; the old code called `wait_free` "approval" but never skipped the actual approval. The test checks both.
- **Tool-chain failover, with a truthful answer.** `browser_act → browser_find` and
  `desktop_act → desktop_snapshot` are back. The first implementation called an empty `ToolRegistry()`, so it could
  never find the alternative; it also did not authorize the alternative and silently called its read result a success.
  Now the alternative comes from the run's registry, is prepared, authorized and taken like any step, and the result
  starts with `[fallback] … The original action was not performed.` It shows the page or window; it does not lie about
  the click. A read-only failure is still retried once; an acting tool is tried once before the chain; cancellations
  are never retried.
- **Urgent initiative.** Any `[URGENT]` title or reason can start while another run is active or the Mac is in use, as
  the other agent intended. `_urgent_todo` reads the list without side effects, so a busy tick cannot drop or finish
  anything; `_next` runs only after the idle decision and puts urgent things first.
- **Outcome maximization.** The goal checker keeps the broad rule: when the goal is reached but a clear better result
  is reachable (better price, a missing valuable detail, more research), it says continue and describes what to do.
- **Measured.** `tests/unit/test_aggressive_autonomy.py` (6), `tests/smoke/test_initiative.py` (21, including four
  urgent cases), `tests/unit/test_request_gate.py`, `tests/unit/test_tool_errors.py`,
  `tests/smoke/test_context_budget.py`, plus the full unit suite. `ruff` and `mypy` clean.

**The independent security review (2026-10-28), and what changed after it.** The owner said yes to the change; the
review that REVIEW.md asks for under "Always needs a human" found that two of the three parts did nothing and the third
let outside content start runs. All three are fixed, with tests that fail on the code before:

- **The hold was never skipped.** The test built its context with `mode="auto"`, but `mode` is the run's kind (task,
  chat, research), so `ctx.mode in ("auto", "yolo")` was never true. It reads `ctx.approvals` now, and only for the
  reads that touch neither the browser nor the screen (`_HOLD_FREE_TOOLS`: `read_file`, `list_dir`, `search_files`,
  `find_files`): a snapshot of the page while the owner types a password in it would have handed the password to the
  model (nothing is masked in `yolo`). A page or screen read, `web_fetch` and `web_search` (each may open a tab of its
  own in the run's browser: a page that refuses a plain request, the browser at the foot of the search ladder) and
  every acting tool wait.
- **The failover never ran.** The reader was prepared with the act's arguments, which a tool refuses
  (`browser_find` also needs its own text). `browser_act` falls over to `browser_snapshot` with no arguments,
  `desktop_act` to `desktop_snapshot` of the app it named (`_failover_arguments`), and the reader is checked against
  the other runs (`peers.conflict`), decided by the gate and waits for the owner's hold like any step.
- **`[URGENT]` came from anyone.** A run can put a thing on the list (`todo_add`), a run that read a mail or a page
  included, and its `[URGENT]` started runs on a Mac the owner worked on. Only a thing the owner put on the list
  (`OWNER_SOURCE`), untainted, is urgent; and when macOS cannot say how long the Mac has been idle nothing starts, as
  `docs/proactive.md` promised. The test that had a run's urgent thing jump another run now checks the opposite.
- The comments of `executor.py` the change had taken out (items 301, 305, 525, 551 and the approval note) are back, and
  `docs/autonomy.md`, `docs/daemon.md`, `docs/runs.md` and `docs/proactive.md` say what Dot does now.

**Checked after the review.** `tests/unit/test_aggressive_autonomy.py` (reads away from the screen go on in auto and
yolo, page and screen reads wait even in yolo, every tool waits in ask and supervised, the readers take their own
arguments and wait), `tests/smoke/test_initiative.py` (a run's or a tainted urgent thing never jumps, an unknown idle
starts nothing); six of them fail on the code before the fixes.
