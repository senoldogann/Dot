### 791. The vault without 1Password: an import brings changed passwords, and 1Password says what it needs

**Status: done (2026-10-28).** **Asked** by the owner: "Op is signed in to no 1Password account … Ayrıca Vault varken
1Password'e gerek var mı? Eğer gerek yoksa vault sistemini geliştiririz, yoksa 1Password kalır." The answer, measured on
their Mac: 1Password's app is not installed, only its command line `op` (Homebrew's), which signs in to no account
without the app, so Connect can never work there; and Dot's own vault already holds their 387 logins, in the Keychain,
and fills them. 1Password is not needed: it stays a choice for whoever uses it (its one-time codes, which the vault
does not keep by design), and the vault is made better:

- **An import brings changed passwords.** A file exported again from the browser counted every login already saved as
  "already in the vault" and kept the old password, so a password changed since could never reach the vault but one by
  one. A login already saved whose password the file has changed takes the new one, the report
  says "Updated the password of N logins already in the vault", and the same file again changes
  nothing. Each saved login is renewed on its own, after the new logins are kept, under the lock an edit of it takes,
  read again there and left alone when it was changed in any way since the import began, so an edit of the owner's is
  never undone; it keeps its own notes, not the file's (the third review of the first approach: a batch written from a copy read at the start could bring
  back the Keychain item of a login removed meanwhile, which no record would name, or undo an edit): one removed or
  changed to another site or username meanwhile is left alone and counted so. The first Keychain read or write that is
  refused or not answered ends it (a locked Keychain is not asked again for each login, at fifteen seconds each), and a
  Keychain that ended the new logins is not asked at all: the saved logins left are counted "its password not
  compared", so every row of the file is in the report. A browser's file has no dates, so the file's password may be
  the older one (a password changed through Dot after the browser saved its own): the one it replaces is kept in the
  login's notes, "Password before the import of <date>: …", which the eye shows, and the report names the logins
  it changed (the first 50); a login whose notes have no room for it is not changed, and counted so. A row of the
  file is one login of the report: of two logins the owner saved by hand for one site and username, the first is
  renewed and the second left as it is.
- **1Password says what it needs.** Connect with `op` and no 1Password app said to turn on a setting of an app the Mac
  does not have; it says the app is not installed, that the vault keeps the logins and 1Password is not needed, and the
  two ways to use it all the same (its app, or a service account's token). Settings › Connectors says the same before
  Connect is pressed (`app` in `GET /api/vault`), and so does docs/extending.md.

login removed while the import reads left removed, one unread password ending the comparing),
