### 539. A run's context under its recap

**Status: done (2026-10-22).** Asked by the owner: the side panel of another agent shows what a task is made of in a few
rows. The Run tab had the recap of the run and its details; what it read, wrote and remembered lay only in the
conversation's steps or in other tabs.

**As built.**
- `static/js/contextpanel.js`: what a tool call read, as plain values — a search's words, a page's host and path with
  the address it points at (`web_fetch`, `web_crawl`, `browser_open`, `browser_new_tab`, and an extract's sources; an
  MCP tool by the name after its server's), and the notes a memory change saved, corrected or forgot. Each list keeps
  the newest first, each item once (a page read again moves to the front, a note corrected again stands as it is now)
  and never grows past its limit: eight readings, six notes.
- `static/js/contextpanelview.js`: four sections under the recap in the Run tab, each hidden until it has something to
  say, in the reference's order: **Skills & MCP** (`GET /palette`, the skills and servers a run can use, a row each,
  the rest counted into Customize), **Artifacts** (the files the chat wrote, with their added and removed lines, a row
  opening the Changes tab where the diff is), **Web reading** (the searches and pages the run read as it goes, and
  again from its history, so an ended run shows them), and **Memory updated** (the notes it saved, corrected or
  forgot, each opening its note in Settings › Memory).
- `timeline.js` gives a root run's calls to the panel (`onTool`) and a memory change as values (`onMemory`), the line
  in the conversation built from the same change; `changes.js` gives its files (`onFiles`); `recap.js` adds when the
  recap was written to its line ("Updated 17:27"), from `written_at`.
- `run.css`: the panel is one borderless card on the composer's corner, no hairline dividing its sections or framing
  it, and the sticky strip of tabs is a translucent pane of the surface over a blur, so what scrolls under it shows
  faintly through; a row is its mark on a quiet tile, its name and what stands beside it, the name cut at the panel's
  edge, in the theme's own colours. A skill wears an upright hammer, a page a globe (a search its lens), a note the
  memory mark, and a file the letters of its kind ("MD", "TS") on the tile in a mark's blue rather than a theme's
  accent (themes.css tokens `--file-kind`, `--on-file-kind`), so that a file reads as a file in every look. The rows
  wrap nowhere and keep the panel no wider than a phone.
- `timeline.js` hands a call to the panel only once its result says it succeeded, so a page the policy refused or the
  network could not reach is not one the run read; `docs/daemon.md` describes the four sections and the time the recap
  says it was written.

**Tests.** `tests/js/contextpanel.test.js`: a page's line and address, a bare host read as the browser's tools read it
(https, http for a loopback one), a crawl's root, an extract's pages, a search's words trimmed, and nothing for another
protocol, a local file, a malformed address or a tool that read nothing; the newest first, each once, at the limit; a
note corrected again told once as it stands now. `tests/smoke/
test_context_panel_page.py`: an ended run's Run tab shows the recap with the time it was written, its artifacts each
wearing its kind on a tile, the loopback page it fetched under Web reading with a globe and the address it points at,
and not the page whose fetch got 404, and the note it saved, in that order; a row of artifacts opens the Changes tab
where the diff is, at 1280 beside the conversation and at 390 in a phone's sheet, no wider than the screen.
