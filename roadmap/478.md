### 478. The standby models are chosen in Settings › Models

**Status: done (2026-10-21).** The owner's word of 2026-10-21: a run whose model hit a problem went straight to
`anthropic:claude-sonnet-5-5`, the one standby model of the owner's config file, and the owner wants to choose it. The
standby models (`[models] standby`, a run's move when its own model answers with a quota, rate-limit, key or access
error, or its content filter stops the reply) could be set only in the file, and read when the daemon started.
**As built.** `ModelRoles` (`llm/roles.py`) keeps the standby models beside the models of Dot's own work and
`choose_standby` changes them while the daemon runs; `_to_standby` (`agent/loop.py`) reads them from there at each
move, so a choice holds from the next move on with no restart, and a run that moved already keeps its model.
`PUT /api/models/standby` takes the whole list (eight at most) and refuses a model named twice, one that cannot call
tools and one of Zen's free models, which answer only as OpenCode's own agent; `set_standby_models` writes
`[models] standby` into the config file with the rest of it as it was. Settings › Models lists them in their order
under the models of Dot's own work: **Add a model…** (the models that call tools, Zen's left out), the arrows, ×, a
"no key" badge where a run would pass one over, and a note when there are none (the error ends the run). Yolo is
untouched: the move is the loop's, in every mode. Tests: `tests/smoke/test_helpers.py` (a standby model chosen while
the daemon runs takes the next run over, though the config the runtime was built with names none) and
`tests/smoke/test_standby_models.py` (refusals change nothing; the card adds, moves and removes; the status, the
runtime and the file say it, the owner's comment kept; wide and light, and on a phone and dark). Docs: models.md,
daemon.md.
