### 1141. An owner edit is not lost while Dot is writing memory

**Status: done (2026-11-12).** Two writes of memory each read a copy and wrote the whole record back.

The nightly reflection read what it knows about the owner, asked the model, then stored Dot's new lines together with
the owner's lines from the start of the night. A save of the owner's lines while the model answered was put back to
the old lines. The Memory page did the same the other way: it wrote the Dot lines it had read when it opened, so a
reflection that finished while the page was open lost the night's new lines. Each write now changes only its own
lines, read and stored in one write, so the other side is whatever stands at that moment.

A note a run saved keeps that run as its author when the owner corrects it on the Memory page. The run's next step
skipped every change whose author was the run, which is also how the run's own save stays out of the next step, so
the correction never arrived. The note is now marked as the owner's correction. The run is handed it. The run's own
save and its own rewrite are still not handed again. A correction brought back from the trash keeps the mark.

Checked: `tests/unit/test_memory_owner_edits.py` (lines saved while the reflection writes; a page save keeping Dot's
lines written since it was read; both writes at once; the running run handed an owner correction and not its own
rewrite; a restored correction still handed), and `tests/unit/test_memory_lifecycle.py`,
`tests/unit/test_memory_saves.py`, `tests/unit/test_reflection.py`, `tests/unit/test_memory_recall.py`,
