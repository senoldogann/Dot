### 1691. A run on the owner's Claude plan is told Dot's own system prompt

**Status: done (2026-11-24).** The audit of 2026-11-24 (harness parity, A1) found that a `claude_code:*` run was told a
3.9 KB prompt of its own (`_PROMPT`: who it is, the door, `THOROUGH_AND_BOLD`, `CHARACTER`, the owner's lines) instead
of the ~25 KB Dot's own loop builds: no "How to work" (verify each step, the plan, ask_user rules), no ending rules, no
"There is always a way", no Web/Browser/Desktop/Memory guidance, no trust and safety fences, no learned habits or tool
guidance, no skills list. Measured symptoms on the owner's store: `shell` 73 % of its calls against 38 % in the loop,
the browser in 3 % of runs against 52 %, no skill used in 124 runs, 29 % of `memory_save` calls refused.

What changed:

- `agent/loop.py`: what the loop's prompt is built from is gathered by `gather_prompt_facts` (questions, chat, the team
  it leads, the skills listed by the chat's title and those that fit the goal, browser, MCP purposes, agent, team,
  accounts, helpers, harness texts, held secrets) into `PromptFacts`, and turned into `PromptInputs` by
  `run_prompt_inputs`; the harness texts by `run_harness_text` (which records the version and the trial's arm, as
  before), the free-mode line by `free_mode_line`, the skills handed under the message by `turn_skills`. The loop calls
  them where it built them inline; what it builds is unchanged.
- `claude_code/run.py`: the run gathers the same facts for the door's tools and is told `build_system_prompt` of them
  plus the free-mode line, then `_HARNESS`: the door and its tools' names, the look-up rule (item 1201), that Claude
  Code's own tools are off and Dot's skills are on, the language and workspace lines and what Dot knows of the owner
  (item 1055). It goes with `--append-system-prompt-file` at every start, a `--resume` and a continuation after a cut
  too, so Claude Code's compaction keeps it: a 0600 file in the run's private folder, removed as the run ends, as the
  prompt now holds what Dot knows of the owner and `ps` shows the arguments to every process (the pre-push review). The first message carries, under the owner's words, the `started_note` (how
  the run was started, item 1219), the recalled notes and the skills that fit the goal that the prompt does not list.
  `_PROMPT`, `_team_text` and `_brief` are gone: the team is in Dot's prompt.
- Size: 3,899 characters of the plan's own before (the audit's measure, without the owner's lines); 31,855 in the
  smoke test's runtime (107 door tools named) after. Claude Code's own prompt stays first (appended,
  not `--system-prompt`): replacing it on a plan login was not tried.

Checked: `tests/smoke/test_claude_code_run.py::test_a_run_on_the_plan_is_told_dots_own_system_prompt_and_the_skills_of_its_goal`
