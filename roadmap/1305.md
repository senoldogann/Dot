### 1305. A skill that cannot be read is logged once, a plugin whose skills cannot load is not proposed, and a SKILL.md may begin with blank lines

**Status: done (2026-11-22).** The log held 398 `skill_skipped` lines for one plugin, twilio-developer-kit, whose
`SKILL.md` does not start with the `---` line: `run_skills` reads every skill again at the start of each run and logged
each problem each time. The same plugin had got past the scout, which only checked that a `SKILL.md` exists in a folder
(`skill_folders`), never that Dot can load it.

- `skills.catalog.unreported` hands out a problem once per process, by its path, reason and the time its file changed;
  `run_skills` logs through it. The problems stay in the catalog, so Doctor's `skills` row, `dotx skills list` and
  the plugins' left-out lines keep showing them (Customize has no list of its own for them): nothing is hidden, the
  log stops repeating.
- The scout calls the skills parser (`parse_skill`) on the `SKILL.md` of each skill folder of a plugin it examines
  (`loadable_skills`, read straight from the archive). A skill the parser refuses is left out of the proposal, with the
  reason in the log; a plugin none of whose skills loads is `Unusable` with the first reason, so it is counted, written to
  `looked` and not downloaded again under that commit.
- `split_frontmatter` reads past blank lines before the opening `---` line. Anything else there (a title, a comment) is
  still the error.

Checked: `tests/unit/test_skills.py` (blank lines before the `---`, and only they; a broken skill is told once, again
after its file changes, and the other skills load as before), `tests/unit/test_scout_night.py` (a plugin with no
loadable skill is unusable and recorded once, the others of the night are proposed as before; `loadable_skills` keeps
the good, the blank-line-led one, and says why each other cannot load).
