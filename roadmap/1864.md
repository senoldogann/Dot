### 1864. Every note says where it came from: an `origin` the store sets from the run that saved it

**Status: done (2026-11-25).** The study of OpenClaw of 2026-11-25 (`reports/refs-2026-11-25/clawdbot.md`, item 2) found
that its memory keeps each fact's provenance class and decides by it what may become lasting memory; Dot kept only
`source_run`, the id of the saving run. The runs are pruned and the notes are not: on the owner's Mac on 2026-11-25 the
run of 1,083 of the 1,272 notes was gone, so who saved those notes could no longer be read anywhere. Items 1865 and 1866
decide by this origin.

What must hold: no model writes the origin (no tool argument reaches it); it is set where the note is written, on every
path (a run's save, a lesson, the owner's note, a reaction's note, a merge, a restore from the trash, a rewrite).

What changed (`store/provenance.py`, `store/db.py`, `store/models.py`, `server/static/js/views/memory.js`):

- `MemoryRecord.origin`: `owner`, `chat`, `schedule`, `watcher`, `helper`, `initiative` or `reflection`, `None` when it
  is not known. A nullable `origin` column on `memories`, added at open as the other columns are (the schema digest is
  pinned again). The store reads it in `_insert_memory` from `source_run` and that run's `source` and `parent_run_id`
  (`note_origin`, `run_origin`: a run with a parent, or of a delegate or a team, is a helper's; then a schedule's, a
  watcher's (a watched item, a reply to a mail, a notice), Dot's initiative; any other run is a chat's). A merge keeps
  the kept note's origin, a restore keeps the note's, a rewrite by another run takes that run's, the owner's correction
  keeps the one it had.
- Filled once, as the column is added, from the runs still stored; a note whose run is gone keeps none.
- The Memory page says it in the note's line ("Saved 2 hours ago by a scheduled task"), and `GET /api/memories` and the
  other note answers carry it, which the phone reads.

Design choices: (1) A column, not a join on `runs` at read time, since the runs go and the notes stay. (2) Derived from
the run in the store, not passed by every caller, so a new path that writes a note cannot leave it out or set it.
(3) No `import` origin: Dot has no path that imports notes (`dotx memory add` and the Memory page are the owner's).
(4) The run sources are written out in `store/provenance.py` (the store sits below the modules that name them), and a
test holds each to its constant.

Measured on the owner's notes (read only, 2026-11-25), by the origin the fill gives them: 3 the owner's, 1,083 none
(run gone), 106 chat (`ui`), 39 schedule, 28 code review (chat), 5 resume (chat), 4 `dotx` (chat), 2 delegate
(helper), 1 team (helper), 1 reply (watcher).

Not done: the text a run is handed (`render_note`) does not name the origin; the phone app shows it once it reads the
field (`ios/` is not changed here).

Checked: `tests/unit/test_memory_origin.py` (each source's origin and the constants, the owner's, the reflection's, a
gone run; the store sets it on a save, keeps it through a correction, a trash and a restore, a chat's rewrite takes its
own; an older database is filled once from the runs it has), `tests/unit/test_store_schema.py` (digest pinned).
