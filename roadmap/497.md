### 497. What other sources gave Dot is removed in one place

**Status: done (2026-10-21).** Asked by the owner: the MCP servers and plugins added from outside should be easy to
remove. Customize › Plugins removed only the servers added on the page itself. One added from another agent of this
Mac was taken back only on Customize › Skills › Found on this Mac, and kept running until Dot's next start. A plugin's
had no way out but its folder.

**As built.**
- `DELETE /api/mcp/servers/{name}` takes back a server added from another agent, as Found on this Mac does
  (`help/added.remove_server`, by its Dot name), and stops it at once. One of a plugin is refused, with the plugin it
  goes with. One of the config is refused with where to take it out.
- `DELETE /api/installed-plugins/{name}` (new):
  - stops the plugin's servers and moves its folder in Dot's plugins to the Trash (`plugins/removal.py`), from
    which it can be put back;
  - its skills leave the runs that start after, as a missing skills root does;
  - a plugin read from a folder of `[plugins] dirs` is refused.
  - The servers listing leaves out the servers of a plugin whose folder is gone.
- `McpServerView.plugin` names a plugin server's plugin.
- The page's buttons (`views/plugins.js`, which Connect apps' service pages share): Remove for a server added from
  another agent, Remove plugin for one of a plugin, each asking first in its own words. A config server says how it
  is taken out.

**Tests.** `tests/smoke/test_remove_plugin.py`:
- a plugin's server is not removed on its own;
- a plugin of `[plugins] dirs` is refused;
- Remove plugin stops the server, moves the folder to the Trash (one made here) and leaves it out of the listing.

Taking back a server from another agent through `DELETE` is not tested here: it is the take-back that
`tests/smoke/test_found_elsewhere.py` covers, followed by the hub's disconnect that the page's Remove already used.
