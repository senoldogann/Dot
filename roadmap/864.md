### 864. A run makes a team of agents, not only the agents one by one

**Status: done (2026-10-31).** **Asked** by the owner: "ajana bana bir takım oluştur agentler ile dedim ama tek tek
oluşturabiliyor, oluşturduğu ajanları 1 takım olarak oluşturamıyor, bunu mümkün kıl".

A team (item 610) is a record of the owner's agents that lists under Agents › Teams and in the sidebar, where a chat
with it is started. Only the Agents page and a ready team's Use made one. A run had `create_agent` and no way to make
the team.

- `tools/team.py`: `create_team(name, purpose, agents)`. It takes two to twelve agents by name or id: the owner's own,
  or ones a run made, which are theirs too. They are kept in the order given, a name given twice once.
  - It is refused, with nothing made, for an agent nobody made (the result names the agents there are), for fewer
    than two agents, for a name a team has already, and for a third team in one run.
  - It is a `persistence` step, as `create_agent` is, so it is judged the same way under the approvals.
  - It is in the `team` group.
  - A delegated run and a run that answers a message are not offered it (`_NOT_FOR_DELEGATED_RUNS`), and refuse it,
    as they make no agent. The first draft had it there, so an agent a run messaged could make the owner a team: the
    pre-push review.
  - A run's teams are counted from all its calls of the tool (`tool_calls_named`), whose names stand among the teams.
    A run makes at most two, in four tries.
- The page's label ("Make team") and the progress words of a channel ("made a team", "bir takım oluşturdum").
- A run makes at most six agents (it was three), so that it can make the team asked for.
- `agent/prompt.py`: the Team section tells a run asked for a team to make its agents, then the team with
  `create_team`.
- `docs/agents-and-campaigns.md` and the tools table of `docs/runs.md` say so.
- A fresh run's first step grows by about 180 tokens. `test_context_budget.py` raises its budgets by 200, saying why.

**Checked.** `tests/smoke/test_create_team.py`, on a scripted model and a real store:
- a run makes two agents, then the team of them and an agent the owner had, in that order;
- a second team under the name, a team of an agent nobody made and a team of one agent are refused, with what
  went wrong.
