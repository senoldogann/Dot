### 1762. A run the Claude plan's usage limit ended is no error in the daemon's log

**Status: done (2026-11-25).** A repair of a problem Dot found in its own record (daemon, seen 10 times): "run failed:
Your Claude plan's usage limit is reached (five hour window); it resets at ... Dot does not move the task to another
model on its own".

Cause: a run that `ClaudePlanLimitError` ended was logged by `agent/manager.py` with `log.error("run failed")`, as
every `DotError` that ends a run. The repair night reads every line of level `error` in the daemon's log as a possible
defect of Dot's, so each window the owner's plan used up became a problem handed to a repair session. The limit itself
is the plan's state, and the run already says when it resets; schedules try the task again after the reset (item
1206) and helpers' reports wake the chat then (item 1669).

What must hold: a run that ended on the plan's limit is still recorded failed, with the error of the kind
`plan_limit`; only its log line is a warning. Every other error that ends a run is logged as an error, as before.

What was built: `agent/manager.py` logs `run failed` at level `warning` when the error's kind is `plan_limit`, and
puts the kind in the line for every failed run.

Checked: `tests/smoke/test_claude_code_run.py` (the used-up plan's line is a warning of the kind `plan_limit`; fails
without the fix), its plan-limit and cut-program tests, ruff, mypy.
