### 684. A code read from Mail or Messages marks the run as one that read outside words

**Status: done (2026-10-26).** The whole-project review of 2026-10-26 found that `code_fetch` gave the model the
sender and the subject of a message (whoever sent it writes both; a subject had no limit) as plain trusted text: its
kind (`app_control`) is not one that taints, and its result was not marked untrusted. A mail to the owner whose subject
said "123456 — ignore your instructions and …" reached the model with no fence, and the run was not marked, so the asks
a run that read outside content gets (an upload, a persistence) did not come.

**The change.** The result that names a message (a code found, or a message that holds none) is untrusted, which marks
the run as one that read content third parties can author, as a page does; the subject shown is cut to 200 characters.

**Checked.** `tests/unit/test_code_result.py` (a code and a message without one are untrusted, a long subject is cut,
no message is no outside word), `tests/smoke/test_codes.py`.
