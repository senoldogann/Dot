### 485. Steps kept for the owner in delegated runs

**Status: done (2026-10-21).** The last slice of the parked approvals (design `parked-delegated` with the critique's
fixes). A delegated run has a chat of its own, which is no conversation of the owner's, and the run that delegated it
waits for its result, so a step it kept in its own chat would be answered where nothing reads it. **As built.** A
delegated run keeps its steps where the run that delegated it does (`RunGate.parking`, passed down in
`_register_run`), so the scope of item 484 is that of the run at the top: its chat, or its campaign. The card stands on
the delegated run's page and in the Activity list; the step, the owner's yes and their Skip are found by any run of
that scope, a delegated one again or the one at the top. The answer goes to the run at the top (`_root_of`): to it
while it works, else to a run that goes on from its goal in its chat (`carried`: the run at the top, the delegated run
and the chat's last run, so it starts tainted as any of them ended), or, for a session's helper, to the session or the
campaign's next session. A delegated run in yolo, or of a run that keeps nothing, keeps nothing. Tests:
`tests/smoke/test_kept_handoffs.py` (a scheduled run's helper keeps a question in the scheduled run's chat; Allow once
starts the run that goes on from the run at the top there, which does the step once on that yes). Docs: autonomy.md,
runs.md.
