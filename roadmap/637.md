### 637. Web-research 1.4.6 in Dot: the address guard holds Camoufox too, and a list of sites starts no download

**Status: done (2026-10-25).** The owner made web-research read a walled page once more in Camoufox (1.4.2), made
`camoufox` a dependency (1.4.3), and moved Google's search into Camoufox (1.4.4). They pinned their own Dot to each,
in local commits on their main.

The security review of 1.4.1 (round B) was still open. Neither Camoufox path was held to the address guard, which
refuses this Mac, the private networks and the cloud metadata addresses. A page read in Camoufox could reach them with
its scripts, its windows and its web sockets. 1.4.5 (web-research PR #14, on PyPI) closes it, and 1.4.6 (PR #15) leaves
Camoufox out on an Intel Mac (below). This item pins 1.4.6 with the lock, and it takes the place of the owner's four
local commits, as they chose ("Ben taşıyayım").

**The change.**
- `pyproject.toml`: `dotagent-web-research==1.4.6`.
- `playwright>=1.62.0`, from `>=1.63.0`. `camoufox` 0.5.8 asks for `playwright<1.63`, so the lock takes Playwright
  1.62.0, as the owner's did.
- `uv.lock` adds `camoufox` and the 25 packages it brings (numpy, cython and others), each but on an Intel Mac. Its
  hashes of `dotagent-web-research` 1.4.6, `camoufox` 0.5.8 and `playwright` 1.62.0 were checked against PyPI's.
- `mcp/builtin.py`: while the owner has a list of sites set, Dot starts the server with
  `WEB_TOOLS_BROWSER_STEALTH_FETCH=off`. 1.4.5 fetches Camoufox's browser, its fingerprint model and its ad blocker by
  itself (from GitHub and `addons.mozilla.org`) the first time a page needs it. With a list set, the server reaches no
  host of its own accord, as items 623 and 630 hold it. A walled page is then read in Camoufox only if its browser is
  on the Mac already.
- `docs/safety.md` and `docs/extending.md` say what 1.4.2–1.4.5 do:
  - the search order: DuckDuckGo, then Google in Camoufox, Yahoo, DuckDuckGo lite;
  - Google's two consent cookies, set in the code, the same for everyone, in memory, sent to Google only;
  - the second read in Camoufox after a wall, and the fetch, once in the background;
  - what the guard holds since 1.4.5, and what it does not: a redirect the browser follows, a worker's requests, a web
    socket in Camoufox, and the browser's own name resolution;
  - a map or a crawl that redirects to another site, which reads only the one page it leads to.
- `docs/development.md` names the pin.

**Checked.**
- `tests/unit/test_builtin_mcp.py`: with a list set, Dot sets the fetch off, and the installed 1.4.6 reads it as off,
  so a later rename shows. Without a list it is not set.
- The web-research tests of Dot, unit and smoke: 103 passed with 1.4.6 (and with 1.4.5 before it).
- That smoke run includes the check of the server's tool schemas against what Dot judges. It found no new argument.
- Dot's own browser code on Playwright 1.62 (run against the owner's lock of 1.4.4, which has the same Playwright and
  camoufox):
  - `mypy src` is clean;
  - 112 of the 114 driver tests pass. The two that fail start Playwright's own bundled browsers, which that machine had
    not downloaded for 1.62.
  - Dot drives the installed Chrome, and so does web-research's headless browser.
- On the owner's Mac the Camoufox browser is in `~/Library/Caches/camoufox` already (2.5 GB), so this pin starts no
  download there.

**An Intel Mac (the pre-push review's BLOCK of the first push, with 1.4.5).**
- The chain is camoufox → fpgen → `indexed-zstd`, and `indexed-zstd` has only one macOS wheel, `macosx_15_0_arm64`.
- On an Intel Mac, which the app's universal build serves, the installer's `uv tool install` would build it from its
  C++ source. A Mac without Xcode's tools cannot do that, so the install stopped.
- I had first left this for the 0.2.0 release. The review was right that the regression arrives with the pin.
- **The fix is in web-research 1.4.6** (PR #15): `camoufox>=0.5.8; python_version >= '3.10' and (sys_platform !=
  'darwin' or platform_machine != 'x86_64')`. Its test evaluates the marker for both kinds of Mac and for Linux.
- In Dot's lock, `camoufox`, `fpgen` and `indexed-zstd` carry that marker. `uv pip compile` for `x86_64-apple-darwin`
  takes none of the three, and for `aarch64-apple-darwin` takes all three.
- On an Intel Mac a walled page stays walled, and Google is searched in the headless Chrome. `docs/safety.md` and
  `docs/extending.md` say so.
