### 1212. `watch_video`: a video file or a link, seen in frames and heard in a transcript, for any model

**Status: done (2026-11-17).** The owner asked that Dot watch, hear and understand the videos of the Mac and of the
links they give, with every model they choose (DeepSeek among them), and asked whether a skill or another system is
the way. A skill only tells the model what to do: a model that takes no video still takes none, and the skill's script
would run as a shell command each time, its result unfenced and the run unmarked. The skills that give Claude Code a
video (bradautomates/claude-video, jordanrendric/claude-video-vision) cut it into frames and a transcript, since Claude
takes pictures and text and no video; Dot does the same as a tool of its own, so it holds for every model (one that
cannot see has the frames described by the vision model) and under Dot's rules.

- `video/watch.py` (pure): the part a call looks at (at most an hour), the moments of its frames (the middles of equal
  slices, at most one a second), the minutes its sound is written down in, the caption track of a link (the uploader's
  in the language spoken, else the site's recognition of the original sound: `<lang>-orig`, or the track in the
  video's own language; never a translation, which YouTube lists among its automatic tracks), and WebVTT read once per
  line (YouTube writes each line twice).
- `video/media.py`: ffprobe, ffmpeg and yt-dlp, each with an argument list, a time limit and the run's sandbox. ffmpeg
  reaches no address (`-protocol_whitelist file`) and opens no list that names other files (`-format_whitelist`:
  measured, an ffconcat list named `.mp4` opened and read the file it named before). Frames and sound come back on its
  output; a link's video is downloaded at most 480 lines high and 2 GB to a folder of the call's own.
- `tools/video.py`: `watch_video` in the group `video`. A file is read as `read_file` reads one (a protected location
  is refused); a link is an address as `web_fetch`'s, and its host must resolve to public addresses. What is said in a
  file, or a link with no captions, is written down by the Mac's own dictation model, a minute at a time: the
  runtime's `Transcriber` (item 626), which the voice routes now share. The result marks the run untrusted, fences the
  title and the transcript, and carries the frames as images.

Measured on the owner's Mac: the dictation model wrote 63 s of speech in 2.3 s (an hour in about 2.5 minutes); a
54-second Turkish video word for word in 4.5 s with the build; a 3:33 YouTube video with six frames and its captions in
9.1 s. The live daemon lists DeepSeek v4.1 Flash as seeing on every provider, so its frames go to it as pictures.

Checked: `tests/unit/test_video_watch.py`, `tests/smoke/test_watch_video.py` (a real video ffmpeg makes, run in the
sandbox, with a stand-in dictation program; skipped where ffmpeg is not installed), the tool-group tests, `dotx eval
check`, and the real dictation model and real YouTube links by hand.

The pre-push review found, in a first round, that a second look in another language read the first language's caption
file, that a kept folder of a link's downloads had no lock and could take a stream yt-dlp had not merged for the video,
and that its sweep dropped errors; in a second, that the kept folders sat under the temporary folder, where a run's
command could put a link to the owner's home that the daemon's sweep would then empty. The structural answer: nothing
is kept. Each call downloads into a folder of its own (`mkdtemp`, mode 0700) and removes it as it ends, with an
`rmtree` that removes no link's target and a failure that is logged; the caption file is read by its exact name; only
the file yt-dlp names after it merged and moved it is the video, and the daemon writes nothing in the folder. A second
look downloads again (9 s for a three-minute video). A frame that fails stops the others, a dictation stopped by one is
awaited, a dictation model held by two other recordings is waited for (five minutes at most), and its errors are said
for a run. A third round found that a caption track's name comes from the page (yt-dlp's generic reader takes a
`<track srclang>`) and reached Dot's own line before the fence, an error and the caption file's path: a name that is
no language tag is dropped as yt-dlp's answer is read, and the caption file must be in the call's folder.

The tool's definition is counted in every run's fixed part, so it is kept short (the language's pattern is checked in
the code, not in the schema): the fresh home's first step went from 27,620 to 27,904 tokens (budget 27,950, tools
19,500), and the scaffold tests' small windows by 1,000 each, as for every tool before it.

Not in this item: a video sent in iMessage (the channel still says it cannot read one); frames chosen at scene changes
rather than evenly.
