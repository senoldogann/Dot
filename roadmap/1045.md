### 1045. A run ends once

**Status: done (2026-11-08).** The first item of the owner's ask to make the implicit state machines explicit.

What must hold: a run's end is written once. `runs.status` is a state machine (queued, running and blocked work; done,
failed and cancelled end it) whose transitions were plain `UPDATE ... WHERE id = ?`, so a late writer could move an
ended run:

- An end after an end: a `dotx run` whose process seemed gone was closed (`close_runs_of`, `mark_interrupted_runs`),
  then its process ended the run again, storing a second `run_finished`, scoring its notes twice, following its queue
  and campaign twice.
- A working state after an end: an approval answered as the run was cancelled set it `running` again.
- A start after an end: a queued run closed before its task began started anyway, called its model and acted, while
  the store said it had failed (shown by `test_a_run_ended_while_queued_does_none_of_its_work`, which failed before).

The fix is in the store: `_set_end` and `set_run_status` write only from a working state and say whether they did;
`end_run` returns `None` for an ended run. `_record_end` then follows nothing (orders, queue, campaign, lessons) and
`_drive` raises `RunAlreadyEnded` before any work when its start did not move the run.
