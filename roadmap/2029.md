### 2029. MCP resources and prompts: Dot reads a server's resources and offers its prompts as starters

**Status: done (2026-11-27).** Dot's MCP client only used a server's tools. A server also advertises resources
(documents, records) and prompts (ready-made starting messages).

What changed:
- `mcp_resource` is one small tool: `list` shows a server's resources, `read` returns one. What a resource holds is
  content from outside, so a read taints the run like any other untrusted tool result; the prompt rule for untrusted
  content names it. A server with no resources adds nothing to the prompt (measured: with one, the group line adds 11
  words and the rule 45).
- A server's prompts are listed and fetched through the hub (`mcp/starters.py` turns the messages into an editable
  text draft, refusing images and other non-text content), shown as starters in the composer's slash menu on the web
  and in the iPhone composer. The owner edits the draft and sends it; nothing is sent by itself.
- Settings (web Connectors, iPhone Connect apps) show a read-only list of each server's resources and prompts.
- `docs/extending.md` and `docs/safety.md` say it.

How it was checked: `tests/smoke/test_mcp_catalogue.py` (a stdio server with resources and prompts: list, read, get,
taint), `test_composer.py`, `test_freedom_contract.py`, `test_context_budget.py`, `dotx eval check`.
