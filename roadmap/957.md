### 957. A run sends a note to the run at work in another chat

**Status: done (2026-11-03).** **Asked** by the owner with item 953: the chats should know of each other and the
agents talk across them, as the threads of another agent's app the owner uses do. Item 953 built the reading part
(`chats`, `read_chat`); this is the sending part.

**What must hold (the approach, before the code).**
- A run sends to another chat only a note to the run at work there now, the way a work order tells its lead
  (`agent/orders.py`, `RunManager.live_run_in` and `tell(..., "note", taints=...)`): Dot's words, never the owner's. The
  note vouches for nothing (it clears no mark of untrusted content) and is no instruction to the review model (`said` is
  empty), so that the run that reads it judges what it asks as it judges a page.
- A note starts nothing. A chat where no run is at work is refused, and the error says so: new work goes to an agent
  with `message_agent`, which keeps the agent's bounds and its one chat (item 952), and never to a chat of the owner's,
  where only the owner starts work.
- A note always marks the run that reads it as content third parties can author does (`taints`, item 902), whatever its
  sender read: what the reader does after it is judged as after a page, in every mode, until the owner writes in its
  chat. The owner chose it on 2026-11-03, after four pre-push reviews each found a way a run that asks the owner less
  does for the sender what the sender asks first (its approval mode, the owner's chat in yolo, Dot's own initiative,
  a chat's "don't ask again" yeses): the mark brings every check of outside content to bear, without a rule for each.
- None goes to a run whose approval mode asks the owner less than its sender's (`supervised`, `ask`, `auto`, `yolo`, in
  that order), and a run of Dot's own initiative, which asks before a message, a post or a release in every mode (item
  850), sends none to a run that does not.
- The note says where it comes from (the sending chat's id, which `read_chat` reads; not its title, which may be a third
  party's words) and stands fenced as a note, so that the reader tells it from the owner's message; the page of the
  target chat draws it as Dot's note from that chat, never as the owner's message. The known secrets Dot holds are
  masked in it, as `read_chat` masks them. It is no answer to a question the run waits on (it carries no question's
  id): a run that waits on the owner reads it once it goes on.
- Only chats `chats` lists are targets (the owner's, the agents' and Dot's own; not a helper's, which its parent
  tells), never the sender's own. A run that may only read (research) sends none, as it moves no other run to act, nor
  does a helper, whose run tells the other chats.
- Bounds: a run sends at most a few notes (a constant in the tool, about six), so that two runs that answer each other's
  notes stop; a run whose end is being recorded or that was stopped takes none (`tell` refuses it), and an emergency
  stop ends both sides as it ends every run.
- Both sides are recorded: the sender's call in its run (`tool_result`), the note in the target's (`steer` with
  `vouches: false`, the tainted flag and the sending run's id). A run's notes are counted by a query of its results
  (`store.calls_that_worked`), however many other calls it made.

**What only asks.** Nothing new is asked of the owner: a note sends nothing out of the Mac, and what the reader does
with it goes through the reader's own gate, with the reader's approvals, marked when the note marked it.

**Not in this item.** Starting work in Dot's own chats from another run: later, if the owner wants it.

**Built.** `tools/office.py` `send_to_chat`, in the group office and every agent's core tools, for the acting modes
alone and no helper (`_NOT_FOR_DELEGATED_RUNS`): refuses the run's own chat, a helper's and a seventh note, masks the
known secrets and fences the words under the sending chat's id (`note_text`). `RunManager.note_chat` reads the sender's
approval mode (`Gate.approval_mode_now`) and whether it asks what a run of Dot's own initiative asks from its handle, not
from the tool, tells the chat's own run before a helper's (`tell(..., "note", taints=True)`, which no hold is released
by) and records `chat_note` on it,
which the run's page and the chat's history draw as a line that leads to the sending chat (`chatNoteLine`). The context
budget of a fresh home's first step rises by 100.

**Checked.** `tests/smoke/test_chat_notes.py` (a scripted run at work reads the note as a `steer` that vouches for
nothing, marked though its sender read nothing from outside, and its `chat_note` line; its own chat and an idle chat
are refused, and nothing starts there; a seventh note is refused after 600 other calls; a run in Ask mode and a run of
Dot's own initiative are refused a note to a yolo run of the owner's chat). The tool groups, an agent's
core tools, its helper's, the known-secrets callers and the context budget.
