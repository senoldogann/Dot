### 815. A restart that waits for the runs waits for the night's learning too

**Status: done (2026-10-29).** **Asked** by the owner ("tamam düzelt hemen") once they had heard that the restart queued
after the deploy of items 808-811 waited for their two runs only: had those ended between 03:30 and 05:30, it would
have cut off the first reflection and the first step of the harness since the fresh start of Dot's store.

- `dotx service restart --when-idle` (item 441) waited until no run was queued, running or blocked. The reflection
  (`[agent] reflection_time`, 03:30), the harness's step (`[harness] step_time`, up to `step_minutes`) and the plugin
  scout's night are no runs: tasks of the daemon's scheduler, each of which records nothing until its end. A restart
  cancels them (`Scheduler.stop`), and the next try is the next night.
- The scheduler names the night's learning under way, `Scheduler.night_work()`: `reflection`, `harness_step`,
  `plugin_scout` (the scheduler's night, or a Look now, which holds the scout's lock). `GET /api/status` carries it as
  `night_work`.
- Once no run works, the restart asks `GET /api/status` with the API token every 5 seconds, and waits while it names
  anything; it logs `restart_when_idle_waits_for_the_night` once for each new set. It gives up after 2 hours of runs at
  work, as before, or 3 hours of the night's learning (`RESTART_NIGHT_LIMIT_S`; a step takes up to 90 minutes by
  default).
- What it cannot learn counts as no night's learning, and is logged as `restart_when_idle_night_unknown` (a token that
  cannot be read, an answer refused or unreadable; a daemon that does not listen is not logged): a night cut off is
  done again the next night, and a daemon that answers badly is the one a restart mends. A daemon from before this
  item does not name its night, so the restart that deploys this item cannot wait for it.
- `dotx service status` and the line `--when-idle` prints say what it waits for; docs/daemon.md describes it.
- The owner's own Dot: the restart queued at 03:05 (the program from before this item) was cancelled at 03:13
  (`cancel_restart_job`, which `service uninstall` uses), so that tonight's learning ran whole; the daemon restarts onto
  808-811 and this item once the night is over.

**Checked.** `tests/unit/test_restart_when_idle.py` (the wait goes on while the night learns and asks only once no run
works, it gives up on a night longer than its time, the question carries the token, and an old daemon, a refusal, an
unreadable answer and no daemon read as no night; the program waits for a step of the harness before it restarts;
the status line), `tests/smoke/test_reflection.py` (the scheduler names the reflection while it is under way, and
nothing after), `tests/smoke/test_server.py` (`night_work` is empty on a daemon that learns nothing now).
