### 525. Outside content in yolo: the review model checks what a planted instruction is after, and no secret goes out

**Status: done (2026-10-22).** Asked by the owner: runs go out to the web and to social media, and content written by
someone else must not steer them into sending the owner's secrets away or running the wrong thing, without taking the
quality of the work or the freedom of yolo away.

- **Where it stood.** Pages, screens, MCP results and mail were fenced as data (items 214 and 424), and a run that read
  them was marked untrusted: its outward-facing and lasting steps asked, and secrets and data sent out were refused
  (items 243 and 433). A yolo run waived all of it (item 443): a run that read a hostile page could send, post, upload,
  pay or read a secret without any check.
- **The taint check.** A yolo run marked untrusted has the review model check a step a planted instruction would be
  after before it does it (`policy.engine.checked_when_tainted`: the flags that escalate on taint but a follow or a like,
  a read of a secret or data sent out, an install, a change of Dot's own files, a login filled from the password
  manager, a deletion outside the workspace). The model judges it against the owner's instructions with the run marked
  untrusted, as in `auto` (`RunGate._check_taint`). Its refusal stands: the step is refused, the run is told why and
  goes on, and the refusal is recorded as the review model's. Any other answer, `escalate` too, leaves the step to
  yolo, which does it, so nobody is asked. A review model that cannot answer fails the step with its error.
  `[policy] yolo_taint_check` (on) turns it off.
- **No secret out.** In every approval mode, yolo too, whatever the preset or the owner's rules say, a run marked
  untrusted refuses a step that sends out (a request, a page's address or field, a message, an MCP tool, a step that
  uploads, posts or sends, and what runs code or types into an application: a command line, an AppleScript,
  keystrokes) and carries a secret Dot holds (`secrets.known_secrets`) or text in the form of a key or a private key
  (`policy/egress.py`, `RunGate.refuse_carried_secret`, called by the executor before the step is authorised). The
  arguments are read as the tool reads them, not as JSON. A command line counts whatever flags its words raised: the
  pre-push review found that a plain `curl` of an address that holds a secret raises none.
- **What it costs.** One call of the review model per checked step of a yolo run marked untrusted; nothing for a run
  that read nothing from outside, nor for its steps that only read or work in the workspace.

Checked by:
- `tests/unit/test_egress.py`: which steps send out, which carry a secret, and which a yolo run checks.
- `tests/smoke/test_taint_check.py`: on a real store, a checked step of a tainted yolo run runs when the review model
  approves or escalates and asks nobody, its refusal stands and is recorded, an untainted run, a step that only reads
  and the check turned off ask the model nothing, and a tainted run of every approval mode refuses a secret going out.
- `tests/smoke/test_approval_modes.py`: the question untrusted content raises, which a yolo run waives, is checked by
  the review model first, and nobody is asked.
- `tests/smoke/test_secret_egress.py`: a scripted yolo run reads a local page that tells it to send a key away; the
  step that carries the key held in the home's `.env` is refused, the key is masked in its record, and the address
  never gets the request.
