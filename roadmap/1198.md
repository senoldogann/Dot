### 1198. A Dot process that must start Dot's own Chrome asks the other Dot process whose idle Chrome holds the profile to let go of it

**Status: done (2026-11-16).** Dot's record showed `browser_open` failing five times on 2026-11-15 with *the Dot
browser profile is open in another process; close that Chrome window and try again*. Every holder was a Chrome
Playwright's driver of another Dot process had started: a `dotx run` (source `cli`, its own process with its own
browser session) found the daemon's Chrome on the profile, idle since its run ended but not yet closed by the idle close
(which also waits while that Chrome's window is in front), and once the daemon's run found the `dotx run`'s Chrome at
work. Told to close "that Chrome window", the runs waited in shell loops for 20 minutes and in the end quit every Google
Chrome by AppleScript, the owner's too.

- `browser/profile_lock.py`: `ask_handover` writes a request file `handover-<pid>` in the profile folder,
  `withdraw_handover` takes it back, `handover_asked` says whether a live process asks (a dead one's is deleted).
- `browser/session.py`: `_start_own`, finding the profile held by a Chrome Playwright's driver started
  (`started_by_dot`), asks for it and waits up to 20 seconds for the profile to be free. Each session with Dot's own
  Chrome watches each second for a request and lets go of its Chrome when no work uses it now (`_free_now`, the idle
  close's own test without the idle time and the front window). A Chrome a run works in is kept, and the asking start
  fails with *Dot's browser is in use by a run of another Dot process … wait and try again, and do not quit Chrome*. A
  window no Dot process started keeps the message it had.
- `docs/browser-and-computer-use.md` says so.

Checked with a unit test of the request files and two browser smoke tests of two sessions on one profile: an idle
holder lets go and the asker starts its own Chrome (the first fails without the change, with the old message), and a
holder in use keeps its Chrome while the asker is told to wait.
