### 1144. An upload reaches the see-through file field over a dropzone below what shows

**Status: done (2026-11-13).** **Found** by Dot in its own record (`browser_upload: uploading the files failed`, five
times in a week, kind `tool_error`). Of the five, two were the model's own wrong ref (a heading beside the field on an
SAP form whose field was in the view, an unnamed icon of a webmail toolbar), and two runs have no events left to read.
The one Dot could have done: a Teamtailor application form in a dialog, where the ref named the text of the CV
dropzone, a see-through `<input type=file>` laid over it, and the dropzone lay below the part of the dialog that
showed. Item 754 takes the field a click at the element's middle reaches, but it read that point before anything
scrolled the element into view: outside what shows `elementFromPoint` reaches nothing, so no field was found. Then
the click scrolled, met "`<input type=file>` intercepts pointer events", the forced click was rightly not made, and
the page had two file fields (CV and others), so none was the only one.

**The change.** `_CONTROLLED_FIELD_SCRIPT` scrolls the element into view (`block: 'nearest'`, nothing moves when it
shows already) before it reads the point, as the click that would follow does anyway.

**Checked.** `tests/smoke/test_browser.py` (real headless Chrome): a page with two file fields whose dropzone, with a
see-through field over it, lies 3000 pixels down a scrolling dialog takes the file by the dropzone's ref; on the code
before it failed with the error of the record. The other upload pages of the test still pass.
