### 926. A reply to a mail Dot sent goes to the chat that sent it, which the code finds by the sender

**Status: done (2026-11-02).** **Asked** by the owner, the first of the gaps they took from the DeepSeek Harness
"Super-agent" article: thread pass-through, an event that belongs to a thread goes to the worker of that thread with
its context. Measured on the owner's Mac (2026-10-28 to 11-02): no watcher (the owner's mail is webmail.zone.fi, which
the watchers cannot read); their mail is read by a schedule, "Müşteri postası", every two hours, in a chat of its own,
which knew nothing of the applications and offers its replies belonged to. The owner chose to adapt the item to that
schedule.

- `agent/gate.py`: when a message is sent (a step with `message_send` let through, in any mode), the mail addresses the
  step and the run's newest 20 calls named (but for a sender a search names) are kept by the run's chat
  (`correspondents`, `Store.note_correspondents`).
- `tools/replies.py`: `pass_reply(sender, what)`. The chat other than the finder's that wrote to the sender last in 60
  days is found by the code; a run starts there (`RunManager.hand_reply`, source `reply`: nobody watches it, its goal is
  Dot's words, it starts tainted, and it takes the chat's model and approval mode). The same sender is handed once in 12
  hours; one no other chat wrote to stays with the finder; a chat with a run at work is handed later. Only a run of a
  schedule or a watcher that is not of Dot's own initiative hands one (`PolicyDenied` for any other): the reply's run
  sends as the owner's chat does, so an initiative run, whose messages ask the owner in every mode (item 850), would
  have its mail sent unasked (the pre-push review).
- `agent/prompt.py`: a schedule's or a watcher's run is told to hand such replies with it.
- `proactive/__init__.py`: `UNWATCHED_SOURCES` (a schedule's, a watcher's, Dot's own initiative's and a reply's runs),
  which every rule of a run nobody watches now reads (no question that waits, no window of the owner's taken, no
  reaction, the prompt's line; `agent/progress.py`, `agent/manager.py`, `agent/loop.py`, `agent/prompt.py`), so that a
  reply's run is one in all of them (the fourth pre-push review: it was in one list of four).
- `docs/memory-and-schedules.md` says so.

**Checked.** `tests/smoke/test_pass_reply.py`: the address typed in To kept by the chat when its Send goes through;
the reply handed to that chat once, untrusted, not while a run works there, and a sender no other chat wrote to kept by
the finder; a real run of a schedule hands it to a run nobody watches, in the chat's mode, untrusted though its finder
read nothing marked so (a command's output marks nothing: the third pre-push review),
and a real run of Dot's own initiative is refused. `tests/unit/test_unwatched_sources.py`: every such rule counts a
reply's run. An address only searched (`from:`) is kept for no chat.
