### 789. A model that cannot answer hands the run on: Ollama's month spent, and replies that hold nothing

**Status: done (2026-10-28).** **Asked** by the owner, from the review of every module. On 2026-10-26 the owner's
schedules failed with "provider answered HTTP 429: you … have reached your monthly usage limit" (Ollama's cloud) and
"The model returned empty replies and did not finish" (gemma4:cloud). A review of `llm/` and the loop's model switch,
each found point checked in the code:

- **Ollama's month spent was a burst.** Only "used all included" was read as a spent plan; "reached your monthly usage
  limit" fell to a plain rate limit, which the connector asked again six times on every call (about 30 s) and a run
  without a standby model waited for up to `quota_wait_s` (six hours) by polling. A 429 that says a usage limit was
  reached is spent for the month, or a window (hourly, weekly) that is waited for, as OpenCode Go's is.
- **Empty replies ended the run whatever the standby list.** A model that answered with nothing as often as a run is
  nudged ended it with "The model returned empty replies"; it now hands the run to the first standby model that can
  take it over, as a content filter's stop does, and the timeline says "it answered with nothing, again and again".
  The model is paused for no other run.

**Not changed:** a model the router paused is not remembered across runs, nor across a restart (an hourly schedule asks
the spent model first each time, then moves); a long Retry-After is slept within the step's time. Both cost time, not a
run; they are written here for a later item.

**Checked.** `tests/unit/test_provider_errors.py` (the month spent and the week's window), `tests/smoke/test_helpers.py`
(empty replies hand the run to its standby model; the test failed before), `tests/smoke/test_model_wait.py`.
