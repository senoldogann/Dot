### 552. A run ends honestly: a finish beside a failed call, a compaction whose fast model fails, OpenCode's cut-off replies and limits, a model's refusal

**Status: done (2026-10-23).** Found by the audit of 2026-10-23 at `96e8c750` (F14, F15, F48, F50, F51, F37, F38, F109),
each read again in the code by a second reader. Each is a place where a run, a compaction or a resume told the owner
something that was not so: done for work that did not happen, a failure where a fallback was promised, a call said to
only read, a bound that was not kept.

**Fixes.**
- F14, *a finish in the same reply as a failing or refused call ends the run done with an answer written before the
  failure was seen*: the loop sends the run back once when the calls ahead of an accepted finish in its reply include
  one that did not work (`_failed_before_finish`: an error, a refusal of the policy, a step kept for the owner; the
  plan's tools and `use_tools` are left out). A note names the calls and asks the model to read their results and end
  again, saying what did not happen or doing it; a `finish_after_failure` event keeps it, and the timeline draws it as
  its other reminders. It comes after the run's limit (a run past it ends with its finish as before) and before the plan
  reminder, and is sent once per run.
- F15, *a compaction whose fast model is an Ollama model that cannot be read fails the run*: `_compact` reads the fast
  model's window inside a guard; a provider error or a missing key there is the fast model's problem, named in the
  `compacted` event as any other, and the run's own model writes the summary.
- F48, *a step cut by the desktop fail-safe or by an error outside a tool loses the results of the calls that had
  ended*: the loop keeps them for any `BaseException`, not only a cancellation, and an error of keeping them is logged
  and does not hide the one that cut the step.
- F50, *auto-resume treats every `meta` call as read-only*: `meta` is out of `REPEATABLE_KINDS`; the meta tools whose
  second call sets what the first set are named (`REPEATABLE_META_TOOLS`: the plan, `use_tools`, `skill`,
  `schedule_list`, `find_help`, and `ask_user`, which a shutdown closes and a resume asks again, as docs/autonomy.md says
  and the resume smoke test has it). A cut-off `create_agent`, `notify`, `show_page`, `consult` or `campaign_targets` is neither resumed
  on its own nor said to only read. A test checks that each name is a tool that exists.
- F51, *the summary prompt asks for DECISIONS, and the check never does*: `SUMMARY_SECTIONS` holds it, between STATE and
  PROBLEMS, as the prompt orders them; a summary without it is asked again and, still without it, kept with an empty
  heading, as docs/runs.md says of every section.
- F37, *a run on OpenCode ends done when the agent's reply was cut off*: `_Follow` keeps how the newest step ended in
  OpenCode's words; `length` and `other` (as Dot's own loop counts them) end the run failed with the loop's own words
  ("The model's replies were cut short and the run did not finish (the last one ended with 'length')"). The empty
  closing message stays done with its line, the design of the module; the content filter was refuted by the second
  reader (OpenCode raises its own error for it, which already fails the run).
- F38, *a run on OpenCode skips `run_max_minutes` and `run_max_tokens`*: after a step that the agent goes on from, the
  follow reads the limits as the loop does (`limit_reached`, the tokens of the run's family): the first step that ends
  past one emits the `limit_reached` event and prompts the agent to stop and answer, and an agent that still goes on two
  steps later (the step under way when the note came has not read it) is stopped and the run ends failed with
  `limit_result`, the loop's words. The agent has no `finish` to be told to call, so the words of the note are its own.
- F109, *an OpenAI refusal is read as a normal answer (Responses) or dropped (Chat Completions)*: the chat codec reads
  `delta.refusal` into the text; both codecs end a reply with a refusal and no call as the Messages codec ends
  Anthropic's, `finish` `other` and `raw_finish` `refusal`, so that the loop does not end the run done with it and the
  review model's refusal is known for one (`_DECLINED_FINISHES`).

**Left.** Nothing of the item's findings. Noted, not changed: a refusal now takes the loop's cut-short path (nudged,
then "The model's replies were cut short ... 'refusal'") as Anthropic's already did, and the words of the refusal stay in
the thread and the timeline but not in the run's result; a model that declines to answer with plain text (most refusals
of a model without strict outputs) still reads as the answer it is.
