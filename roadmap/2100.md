### 2100. Verification guards: a red main blocks merges, a weakened test says why, a commit without the hooks is seen

**Status: built (2026-11-28).** The owner's direction of 2026-11-28: "Verification is the new bottleneck: build checks a
coding agent cannot shortcut." That day main went red several times because one pull request changed a test's words
while another changed the code it checks; three fixes concluded "the test was wrong" with nothing but the agent's word;
one helper committed with `git -c core.hooksPath=/dev/null`; and pull requests were merged while main's macOS run was
red, a rule that was prose alone. Each of those is now a check that fails, not a sentence to follow.

## What it does

- **A red main blocks merges.** `scripts/merge_pr.py` reads main as `scripts/main_macos_green.py` reads it
  (`red_now`: its newest commit's runs of the gate, the last iPhone run, the last finished browser run; while those are
  still to come, the open issue "main is red on macOS" and the runs its latest report links) and refuses to merge, or
  to bring a
  branch up to main, over a red one. The pull request that fixes it says so with a line `Fixes-main-red: <run id>` (or
  the run's link) in its body, naming a run that is red now; an older red's id does not open the way. A main whose
  state cannot be read is not merged over (no fallback). Pending is not red: the train keeps merging while main's runs
  of the last merge are still going, as before, but not over a red the issue still holds. Only this script asks: the
  repair night's merge and Dependabot's do not (docs/development.md says so).
- **A weakened test says why.** `scripts/weakened_tests.py check` reads the branch's diff from where it leaves main:
  in a test file (`tests/`, the Swift files of `ios/`'s test folders), an assertion line removed or changed with no
  identical line added back anywhere in the tests (whitespace aside: a moved one, or one its hunk wraps over lines, is
  not a weakening), a test removed (a function, a `Test` class, a Swift `@Test`), a skip, xfail, fixme, rerun or
  `pytest.mark.timeout` added to a test that was there (not one guarding a new test, in a new file or in the hunk that
  adds it, nor one moved, nor one written in a string or a comment), a timeout raised within a hunk under the same name.
  Each such file must be named, with a reason of three words at least, in a `Test-change:` line of a commit's body.
  The gate's new `guards` job runs it on every pull request, prose alone included (main's own copy, so that a branch
  cannot loosen the check that reads it; the pull request that adds it runs its own), and the pre-push hook before the
  review.
- **The review answers for each test edit.** `weakened_tests.py brief` gives the pre-push review a section listing the
  test files the change edits (when it changes code too, or weakens one), what was seen weakened in each, and the
  commits' `Test-change:` lines; REVIEW.md's new "Test changes" says the review must say for each why it changed and
  what the old assertion caught, and that a weakening with no reason the code bears out, a test bent to agree with
  wrong code, or one changed for another pull request's code is Important (a BLOCK).
- **A commit made without the hooks is seen.** The commit hook `.claude/hooks/commit-msg.sh` adds the trailer
  `Dot-Hooks: commit-msg`. `scripts/hook_stamps.py` lists a branch's commits that lack it; the pre-push hook refuses to
  push one, and the gate fails a pull request that holds one, which catches a push made with `--no-verify` as well.
- What the two checks find stops the push before the model review, written to `.git/claude-review/<commit>.checks.md`
  and named as a review's BLOCK names its file, so that Dot's repair night hands it to the session to answer, as it
  does a review's findings (`push_branch` reads that sentence); it carries no verdict, so it is no round of the three.

## Approach

- The pre-push hook runs the two scripts from the checkout it is linked from (the owner's, like the hook itself), on
  that checkout's `.venv`, never from the branch pushed, and stops with what to run when that Python is missing.
- Who is not held to the stamp, so that nothing legitimate breaks: GitHub's own commits (committer
  `noreply@github.com`: the merge `gh pr update-branch` makes for the merge train, and the rebase and squash merges
  onto main); a commit made on a tree without the hook file (branches older than this item); a commit written before
  2026-11-28 12:00 UTC by its author date, which a rebase keeps (a branch begun before, rebased onto a main with the
  hook). `git rebase` (the train's and a repair session's bringing a branch up to main), `git cherry-pick` and `git
  commit --amend` keep the message and its stamp; `git merge` runs the hook. Repair sessions commit in worktrees of the
  owner's repository, whose hooks folder the stamp hook is in, and Dot pushes them through the pre-push hook: they are
  stamped. Checked on git 2.x by the tests below: a rebase with the hook removed keeps the stamp. `git revert
  --no-edit` runs no hook; the message says to amend it.
- The hook is installed as a copy (`cp .claude/hooks/commit-msg.sh "$(git rev-parse --git-path hooks)/commit-msg"`), not
  a link: it reads nothing of the checkout, and a copy stamps every worktree's commits at once, before the owner's
  checkout pulls this change. It was installed in the owner's repository on 2026-11-28 at 11:58 UTC. The pre-push hook
  does not install it: a repair session's push through the hook would change the hooks folder the session's
  checkout print guards (`checkout_print`), and end the session.
- What these checks cannot see, said in docs/development.md: an assertion spread over lines is seen by its first; a
  looser comparison on a line that asserts nothing; a stamp or a `Test-change:` line written by hand without the
  reason being true (the review's to judge). The checks make skipping visible, not impossible.

## Independent review

One reviewer agent, given the branch alone, before the pull request. It found three Important problems, all fixed
here: the pull request failed its own check (`'@pytest.mark.skip'` held as data in the new tests read as a skip); a new
test's ordinary guard (`skipif` on another platform, a live test's `XCTSkip`, `pytest.importorskip`) was flagged, 31 %
of main's last 120 commits by its measure, 7 of them by a skip; and a refusal before the review ended a repair night's
session as failed instead of handing it the finding. Its nits taken: a reflowed assertion, timeouts compared across
names (`timeout=5` against `timeout_ms=5000`), a `.bak` path naming a file, a later round's brief missing the earlier
commits' reasons, `self.assertRaises`, removed Swift `@Test`s and `Test` classes, prose-only pull requests not checked,
and every old red in the issue counting as red now. Left, and said in the docs: the other merge paths, a skip in
`conftest.py` or a rerun in `pyproject.toml`, a reason that answers for its file over the whole branch, and a red night
of `browser.yml` holding the train until it is run again.
