### 1949. Custom providers: any OpenAI- or Anthropic-compatible API as a provider of its own

**Status: built (2026-11-26), waiting on the owner's look** (it touches `server/routes_keys.py`, an "Always needs a
human" path). The owner's request: Dot had a fixed set of providers, and adding another meant code; they want to add
any provider easily, if need be from its documentation.

What it is: `[providers.custom.<name>]` in `config.toml`, a server that speaks one of the three wires Dot already speaks
(OpenAI Chat Completions, OpenAI Responses, Anthropic Messages), through the same codecs and streaming plumbing as the
built-in connectors (`llm/custom.py`; no new HTTP stack). `<name>:<model>` is then a model in every role, schedule,
agent and picker. Settings › AI services gets **Add provider** (name, base URL, protocol, key, models with what each can
do or "list them", extra headers), **Test** (one small real call, only when pressed), **Fill from docs** (the page read
with Dot's own web reader, the fast model asked once only for what the page does not state plainly), **Change** and
**Remove provider**. `dotx doctor` and `dotx models` list them; the phone lists them read only in Settings › Models.
[Models](../docs/models.md#custom-providers) says what is and is not supported.

#### Approach (written before the code, as CLAUDE.md asks of a key-storage change)

What must hold, by structure rather than by a check of spellings:

- **A key goes to its own provider's address and nowhere else.** The connector's client follows no redirect
  (`llm/http.build_client`); the address is `https://`, or `http://` to this Mac's loopback alone, with no user info
  (`config._custom_base_url`). A custom provider cannot name the key of a built-in provider (OpenAI's organization and
  project included), the typed judge's, or another custom provider's (`ProvidersConfig._own_keys`, `_custom_names`,
  `AppConfig._models_of_known_providers`).
- **The API cannot point a provider at a secret of another service.** A provider added or changed through
  `PUT /api/providers/custom/{name}` does not choose its key's name: the daemon gives `DOT_CUSTOM_<NAME>_API_KEY`
  (`routes_providers.key_name`), which no built-in provider, search engine or app of Dot uses. Only a table written by
  hand in `config.toml` names another variable: that is the owner's own file, as every provider's `api_key_env` is.
- **A saved key does not follow a provider to another server.** A change of the address (scheme, host, port) of a
  provider with a key drops the key Settings saved for it, so the owner types it again for the new address; for a key
  from the environment, the Keychain or a name `config.toml` chose, such a change is refused through the API. Test uses
  the saved key only at the address it was saved for; elsewhere it takes a typed one.
  The independent security review of the first push found that a table could stop taking a key and take it again at
  a new address, the saved key following it, and that the key was dropped only after the new address was in service:
  now the key Settings saved is dropped, before the router takes the change, by every change but one that keeps the same
  key at the same server, and by every removal (`keeps_its_key`). It also had the header check take bearer, credential
  and pass; the docs say it is a check of names.
  The pre-push review of that push found the same hole, and that a custom model in `[models] standby` or `helpers`
  raised "unknown provider" in the roster (`agent/helpers._key_name`): the roster now reads a custom provider's own
  key, or none, from the router's providers in use, and a provider removed while a setting still names it counts as
  having no key (`tests/unit/test_custom_providers.py::test_a_custom_model_stands_in_the_standby_and_helper_roster_by_its_own_key`).
  Its second round: a key in the environment or the Keychain under the name Settings gives could still be attached to a
  new address through the same toggle, or to a new provider; Save now refuses any key it would newly send to an
  address unless it is the name it gives and is kept in Dot's `.env` (where it drops it for the owner to type again);
  the `.env` copy is dropped after the config file is written (a file that cannot be changed changes nothing), never
  when another table names that variable by hand; and the header check takes password, passwd and passphrase rather
  than any "pass".
  Answered, not changed: a schedule's or an agent's model is checked by its shape when saved, so a mistyped lower-case
  provider is refused at its first run with "unknown provider" (the router alone knows the custom providers in use,
  and the save paths do not hold it); `dotx models` lists the custom providers' models with the others, and
  `dotx models <name>` takes the built-in names only, as its subcommands are made before the config is read.
- **A key is written once and never read back.** It is saved through the existing `POST /api/keys/{name}` route
  (`secrets.write_env_value`, mode 0600) and shown as its last four characters like every key. The one change to
  `routes_keys.py` is that its map of key names is read per request (`providers_by_key(config, router.custom)`), so a
  provider added while the daemon runs has its key row, and Check asks a custom provider as Test does. `secrets.py` and
  `server/guard.py` are unchanged.
- **No secret in the config file.** A header whose name speaks of auth, a key, a token, a secret, a cookie, a password,
  a session or a signature is refused, as are the headers Dot sets itself; the key is `api_key_env` alone.
- **A built-in name cannot be shadowed.** A custom name is lower case, from a letter, up to 32, never a built-in
  provider's nor `typesafe` (`llm/types.custom_provider_name`); the router refuses `set_custom` of a built-in name.
- **A phone only reads.** Add, change, remove, Test and Fill from docs are refused from a phone's key
  (`refuse_from_a_phone`); `GET /api/providers/custom` carries whether a key is set, never the key.
- **Nothing is saved unasked, and nothing is called unasked.** Fill from docs proposes; Save writes. Test and Check are
  the only calls the owner's page makes, each on a press. A key typed for Test is used for that call and kept nowhere.
  Fill from docs reads the page through `WebClient` (public addresses only, the browser's host lists), and an address or
  a model id the fast model proposes that the page does not hold is dropped.
- **The configuration stays loadable.** A model a setting names of a custom provider not configured is a configuration
  error naming the setting; removing a provider a setting still names is refused; the config edit is checked after it
  is written in memory (every other setting unchanged, the table as given) before it replaces the file.

What it does not do: anything of a particular service beyond its protocol (prices, routing, a usage page, fast mode,
embeddings, web search's relay). A schedule or an agent that names a removed provider's model fails at its next run with
"unknown provider". The freedom contract is untouched: no tool, gate or policy changed.

Built and checked:

- `tests/unit/test_custom_providers.py`: the configuration's rules (names, addresses, secret headers, shared and
  built-in keys, models), the config file's edit written, changed and removed with the rest kept, `<name>:<model>`
  routed through the router to its base URL on each of the three protocols against recorded streams (headers, key,
  path, model, reply and usage), a provider without a key sending none, an unknown model refused before any call, a
  provider added and removed while the router runs, a refused key said by Test, and Fill from docs on three saved
  pages (OpenAI-compatible, Anthropic-compatible, and one that needs the model, whose invented address is dropped).
- `tests/smoke/test_custom_providers.py` (browser): Add provider on a wide dark window and a phone-sized light one,
  Test's failure said, Save into `config.toml` and the running router, its model listed, Change filled, Remove; the
  API refusing a header that carries a key (the key not echoed) and a built-in name, and naming the key
  `DOT_CUSTOM_ACME_API_KEY`.
- `tests/unit/test_config_bounds.py`: an unknown provider's model is refused by the setting that names it.
