### 1367. The Claude plan's models are those Claude Code lists, not a list written into Dot

**Status: done (2026-11-23).** The owner's word of 2026-11-23: the newest models do not show up on the Claude plan.

The plan's models were written into `llm/claude_code.py` (item 1054, measured on 2.1.319 on 2026-11-08): `fable` was
shown as "Fable 5.1" while Claude Code ran it on Fable 5.2 (measured), `claude-fable-5-2` by its id was refused, and
fast mode was a set written next to them.

- Dot asks the `claude` program for its models as an SDK host does: an `initialize` control request on a
  `stream-json` input, no prompt, no model called (`claude_code/models.py`). Its answer gives each model's id, the model
  it names, its name, its reasoning levels and whether it has fast mode; the `default` entry is left out.
- The program fetches the full list only while its non-essential traffic is allowed: with
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` (set for runs) it listed 5 models, without it 14 (measured on 2.1.330).
  The request goes without that variable; runs keep it.
- The answer takes 6-11 s (measured), so the list is kept in `claude_code/models.json` for six hours; the models page,
  a run's check of its model, fast mode and the names of the models read it.
- A family's alias the list names by id (`fable`: a chat of 2026-11-23 chose `claude_code:fable`) answers by the newest
  model of that family it lists.

`tests/fixtures/claude_models_response.json`: ids, fast models, levels, the alias, names),
`tests/smoke/test_claude_code_run.py`, `test_claude_code_ask.py`, `test_plan_roles.py`, `test_repair_page.py` (the
