### 740. A new account's password is made by Dot, filled and kept in the owner's vault

**Status: done (2026-10-27).** **Asked by the owner:** when a run makes an account somewhere, its password and login
should go straight to where Dot keeps logins. In their runs a model had made up a password and written it into a
script (`setter.call(pw, 'Wq7-…')`), which stood unmasked in the run's events: Dot masks the secrets it holds, and a
password a model made up is none of them.

**The change.** `browser_create_login` (`tools/browser.py`): given the refs of a sign-up form's password field, of the
field that repeats it and of the username's, and the account's username, Dot makes a password (`new_password`: 20
characters drawn by `secrets`, one at least of lower case, upper case, digits and signs, none of l, 1, O, 0, I), holds
it as a secret from that moment (`hold_filled`, masked wherever it would stand), keeps the login in Dot's vault (its
website the page's origin, `website_of`, a note of when it was made), then fills it through `fill_from_vault`, the path
and the rules of a vault login (a password only into a password field, on the login's own site, a chat a script ran in
reopened first), and takes the login back out of the vault when the fill fails. The model gives the username and never
chooses, sees or records the password; the prompt's lines on logins tell it never to make one up. It writes the
owner's vault and types a password into a page, as a fill does, so it is asked as a fill is (high, `vault_fill`): outside
`yolo` it waits for the owner's own yes, and in `yolo`, which the owner runs with no approval, it runs at once.

**Checked.** `tests/smoke/test_vault_items_fill.py` (a stand-in for the Keychain, a real headless Chrome, an https
site): a sign-up form gets the same made password in both fields, the vault keeps the login of the page's origin with
its username and a password of 20 characters, which is among the secrets Dot holds, in no result or view, and is what
the form sent. `tests/unit/test_create_login.py`: 200 passwords all differ and each holds every kind of character; the
website is the page's origin over https or loopback http and none otherwise. Each fails on the code before.
