### 2047. Drafts in the owner's own Gmail and Outlook

**Status: done (2026-11-28); the owner approved the scopes on 2026-11-28, asked apart per account.** From Grok Bot's
review (backlog GK2): `mail_search` and `mail_read` read Gmail and Outlook, but an answer went only to Mail.app
(`draft_message`) or the browser.

- `mail_draft` (tool group `accounts`, tasks and chats) makes a draft in the account's own Drafts: Gmail's
  `drafts.create` (a reply gets the thread and `In-Reply-To`/`References` of the message `reply_to` names), Graph's
  `messages` or `createReply`. With `draft` it writes a waiting draft of its chat again (`drafts.update`, `PATCH`).
- The draft is the chat's draft card of item 314 (`drafts.mailbox`, a JSON column added in place): the account it
  goes from and **Open in Gmail** / **Open in Outlook** (Gmail's `#drafts?compose=<message id>`, Graph's `webLink`,
  https only), on the web (`drafts.js`) and the phone (`DraftCard.swift`). Send on the card writes the card's words into
  the mailbox's draft and sends it (`drafts.send`, Graph's `send`); Discard deletes it there (a 404 means it is already
  gone and the card is dropped all the same).
- Sending stays the owner's press, whatever the approvals: the tool is classified like `draft_message`
  (`notes_write`, `safe`, a key in it flagged `exfiltration`), no new ask in any mode (freedom contract row), and no run
  can send a draft. A write is retried only after a 429; a lost answer to a send says whether it went is not known.
- Scopes: a sign-in still reads only (item 558). **Allow drafts and sending** beside an account in Settings ›
  Connectors › Accounts (on the Mac, `POST /api/accounts/<provider>/<address>/drafts`) signs it in again, named by
  `login_hint`, with Google's `gmail.compose` or Microsoft's `Mail.ReadWrite` and `Mail.Send` added; the account
  keeps `drafts` while its token holds them (`granted`, Google lets the owner untick one). Neither provider has a
  drafts-only scope, so only an allowed account's token could send mail (and at Microsoft change or delete it); a
  draft in another account is refused before any call, with that advice.
- A draft changed in the mailbox is not written over: Dot keeps the version it last wrote (Gmail's message id,
  Graph's `changeKey`), reads it again before Send writes the card's words, and refuses on the card ("it was changed
  in Outlook after this card was shown…"); a run's rewrite is refused the same way. Send's own write keeps the new
  version, so Send again after a failed send is not taken for the owner's change.
- One writer per draft in the daemon's process (a lock Send, Discard and a run's rewrite hold), dropped once the draft
  is sent, discarded or gone, a conflict too.
- Context: the tool is in the `accounts` group, withheld without a signed-in account and off on the first step with
  one; `tests/smoke/test_context_budget.py` passes unchanged (fresh home). The full tool surface grows by ~530 tokens
  (`tests/fixtures/prompt_surface/summary.txt`).

How it was checked: `tests/smoke/test_mail_drafts.py` (a real sign-in against stand-ins of both APIs and a keychain in
