### 1863. A merge no longer sends the other pull requests back to main for Markdown no test names

**Status: done (2026-11-25).** `scripts/merge_pr.py` (item 945) brought a pull request up to `main`, and so ran its 20
to 30 minutes of checks again, whenever `main` had changed one of its files since those checks began. Nearly every pull
request writes `roadmap/INDEX.md` and a page under `docs/`, so each merge sent every other open pull request back (on
2026-11-25 #1109 went back for `docs/daemon.md`, `docs/runs.md`, `ios/Next/README.md` and `roadmap/INDEX.md`).

What was built (`counts`, `asks_the_tests`): `roadmap/INDEX.md` never counts (the gate's item-records check fails a
stale one, and rows two pull requests add at the same place conflict, which makes the second unmergeable rather than
wrong). Any other Markdown file counts only when a test names it, its file name in quotes in a file under `tests/` of
`main` or of the pull request's head, read with `git grep` at the merge: `tests/unit/test_css_tokens.py` reads
`docs/daemon.md` and `docs/dot-ui.md`, `tests/unit/test_ui_map.py` `docs/dot-ui.md`, `tests/unit/test_freedom_contract.py`
`docs/freedom.md`, `tests/unit/test_harness_docs.py` `docs/harness.md`, and those keep counting, as does a page a test
added tomorrow names, with no list to keep. An item's records and every `SKILL.md` always count. Of the example above,
`roadmap/INDEX.md` and `docs/runs.md` no longer send #1109 back; `docs/daemon.md` still does, and `ios/Next/README.md`
too (tests name files `README.md`, so every README counts). Checked by `tests/unit/test_merge_pr.py`.
