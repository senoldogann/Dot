### 738. A script of the page gets the elements of the snapshot's refs

**Status: done (2026-10-27).** **Asked by the owner:** they moved Slack's buttons that did not answer a click only
with "run JavaScript in the page" (Chrome DevTools' `evaluate_script`), and asked for it in Dot. Dot has had it since
item 263 (`browser_eval`); what it lacked of DevTools' is `args`, the elements a script is called with: a script had to
find its element again by a selector the model wrote, which a page that renders as Slack's does (generated class names,
many alike) makes a guess.

**The change.** `browser_eval` takes `refs` (at most 20) from the latest snapshot; the script is then a function called
with their elements, in that order, in the frame they are in (`driver.run_script`, `_elements_of`): `(el) =>
el.click()`, or the event the control listens for. Each ref is checked as a step's is (`live_locator`: of the snapshot's
shape, not gone since it, the page not navigated), refs of two frames are refused, and a script that is not a function
fails with the page's own words. Nothing else of the tool changes: a click of medium risk, which the cautious preset
asks about and a research run does not have; refused on a page that holds a password, code or card field outside `yolo`;
the cookies hidden; the value fenced as the page's and the run marked untrusted; its words read for a secret.

**Checked.** `tests/smoke/test_browser_eval.py` in a real headless Chrome: a page whose button answers only its own
event (as some of Slack's) is moved by a script given its ref, and two refs come in their order; a script that is not a
function, a ref not in the snapshot, a ref of another shape and refs of two frames are told, a ref inside a frame
works, and the page stays usable; as a tool it is the same click of medium risk, its summary names the refs and its
value is untrusted. Each fails on the code before.
