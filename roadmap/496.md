### 496. The accounts signed in are in the at menu

**Status: done (2026-10-21).** Asked by the owner: the Google and Microsoft accounts signed in on Customize (item 422)
did not show when they typed @. The at menu (item 447) listed the MCP servers alone, and a run's picks (item 318) had
no field for an account.

**As built.**
- `GET /api/palette` names the accounts signed in (`accounts`: address, provider, what of it a run reads, the
  provider's mark).
- `slash.js` gives them a group of their own under the MCP servers, each wearing its provider's logo.
- `picks.js` makes an account picked a chip, sent as `accounts` with the message: in `POST /api/runs`, and in a
  message the queue holds.
- `RunPicks.accounts`: the picks kept before this name none.
- A run picked an account:
  - it starts with the accounts' tool group on (`picked_groups`);
  - its first message names the account for `mail_search`, `mail_read` and `calendar_events`;
  - an account that is not signed in is refused before the run starts (`picks_problems`), with the accounts that are.
- The `picks` event names the accounts, and a sent message's chips show them.

**Tests.**
- `tests/unit/test_picks.py`: an account picked opens the group, is named to the model, and is refused once signed out.
- `tests/smoke/test_composer_picks.py`: the menu shows the account with Google's logo, and the picks events name
  `accounts`.
