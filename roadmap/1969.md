### 1969. Dot makes pictures: `generate_image` draws a logo, diagram or card in its own browser, or asks Google's picture model for a photo, with no key of its own

**Status: done (2026-11-26).** The owner's word of 2026-11-26: Dot should make images, with no new API key.

What was built:
- **Drawn** (the default): the run writes an SVG or a static HTML page and Dot's own browser draws it at the size asked
  (`BrowserSession.render_image`, a quiet tab: scripts barred by a content security policy put first in the page, every
  request refused, an SVG drawn as an `<img>`), saved as a PNG in the workspace. Works for every model, needs no key.
- **Photo**: Gemini's picture model on the `GOOGLE_API_KEY` the owner already has (`[providers.google] image_model`,
  `image_base_url`; `GoogleProvider.generate_image`, retried like the connector's other calls, recorded on the run as a
  `model_call` of purpose `image` with the tokens Google reports). Pictures are not on the free tier: Google's refusal is
  told to the run with its own words. With no key the tool says so and names drawing; it never draws instead and never
  asks for another key.
- The tool is a write of its `path` for the policy (no new ask: a row of the freedom contract), in the group `images`,
  and the picture shows in the web chat where it was made (`pictureCard`, also in a chat's history).

Not done: the rich cards work (`feat/chat-cards`) has not merged, so no `image_gallery` card is emitted; the phone shows
the run's images already. The model id and the request shape come from the Gemini API's reference of 2026-11-26; no live
call was made (no key on this Mac in the helper's session).

Checked: `tests/unit/test_google_image.py`, `tests/smoke/test_generate_image.py` (`browser`),
`tests/smoke/test_generate_image_photo.py` (a stand-in of the API on this Mac), `tests/unit/test_freedom_contract.py`
(rows for both ways), the prompt surface fixture and the context budget, `dotx eval check`.
