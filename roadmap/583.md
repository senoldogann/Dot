### 583. web-research comes with Dot: a dependency and a built-in MCP server, on by default

**Status: done (2026-10-23), waiting for the owner's review.** The owner's decision: the web-research MCP server
(`senoldogann/web-research-stack`, its pull request #6) becomes part of Dot, so that every install has it ready and on.
Before, an owner who wanted it wrote an `[[mcp]]` table for a checkout of their own. Now Dot's package depends on
`dotagent-web-research==1.2.0`, and the daemon starts its server `web-research` with the servers of the config, unless a
server of that name is set up somewhere else or `[builtin_mcp] web_research` is `false`. The change touches the
dependencies of `pyproject.toml`, which REVIEW.md lists under "Always needs a human" (the owner reads it, and an
independent `/security-review` reads it from the first push), and adds one folder to what a run's commands may not
write. The PyPI upload of `dotagent-web-research` 1.2.0 comes with Dot 0.2.0, not with this item. It stands on a branch
of its own, from `main`, apart from the desktop installer (item 575, on another branch): the two meet only in the order
of the PyPI uploads (`docs/development.md`, Releasing), since the installer's `uv tool install dotagent-macos` brings
this dependency too.

**The approach, in short.**
- One module, `mcp/builtin.py`, decides what comes with Dot: the package can be imported (looked for, not imported:
  the server runs in a process of its own), its name is not taken, and the switch. It gives the server as a
  `McpServerConfig` that the hub starts as it starts the others, so that the tools, the policy, the log, the failure
  report and the Connectors page need no code of their own for it; what they are told is only that it is Dot's.
- Where the others are read (`runtime._open_services`), the built-in is added last, with the names the others hold as
  `taken`, so that every other source wins. The runtime keeps the names it started as built-in
  (`Runtime.builtin_names`), which the page reads: an earlier version of the page recognised the running server by
  comparing its config with the one made now, and the test of Try again showed it to be fragile.
- The switch lives in a table of its own, `[builtin_mcp]`: TOML cannot have a table `[mcp]` beside the `[[mcp]]` tables
  (`mcp = []` is the array of tables in `defaults.toml`), which is where the brief put `[mcp] web_research`.
- The page's switch acts at once through the hub (`connect`, `disconnect`) and writes the file through `config_edit`:
  on, the file is written once the server answered; off, before it stops, so that a server that cannot start or a file
  that cannot be changed leaves the switch as it was.
