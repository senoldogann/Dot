### 1317. The roadmap from item 459 on has an index, and the gate keeps it current

**Status: done (2026-11-22).** ROADMAP.md is 17,308 lines and stops at item 458 (its last commit is of 2026-10-21), yet
its own first lines tell an agent to read it first; the 812 files under `roadmap/` (and the `changes/` files) had no
list, so the work from 459 to 1316 could be found only by guessing a number. `scripts/roadmap_index.py` reads each
`roadmap/<n>.md` (the `### <n>. <title>` line, the `**Status: ...**` line, the status's first clause and the date in it,
as far as the closing `**`, which a long status puts on a later line) and writes `roadmap/INDEX.md`: a table, newest
item first, each number linking to its file. It reads the files that exist and not git, so whatever a branch adds, the
table gains that row and no other; `--check` fails when the file is not what the files make. A file whose title line
names another number is an error, not a guessed row. The 815 files of today (456, 459 to 1317, with this item's) give 815 rows, and all have a status.

`scripts/check_item_records.py`, which the gate already runs on a pull request, runs the check too, so no workflow
changes. The per-item commit flow says to run the script before the commit (CLAUDE.md, CONTRIBUTING.md,
`roadmap/README.md`), and when two branches that added items side by side conflict in `INDEX.md`, to run it again rather
than merge rows. ROADMAP.md, CLAUDE.md and `roadmap/README.md` begin with the pointer "for items after 458 use
`roadmap/INDEX.md`". ROADMAP.md is not moved or cut. Nothing of what Dot does at run time changes.
