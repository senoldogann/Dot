### 1013. Dot's runs on the owner's Claude plan, as Dot

**Status: approach reviewed, building (2026-11-06).** **Why.** The owner's ask of 2026-11-06: use the limits of their
own Claude plan (Pro/Max) for Dot's runs, fully autonomous inside Dot, the model "feeling itself Dot" as T3 Code's
integration of Claude Code does, as OpenCode's free models are used today. Built on the recommendations put to the owner, which they
have not answered yet (they said "do what you can"): the plan through the `claude` program's own sign-in; when the
plan's window is used up, the run stops and says so (no switch to another model on its own). The merge waits on their
look.

**What Anthropic allows** (read 2026-11-06, code.claude.com/docs/en/legal-and-compliance and agent-sdk/overview): third
parties may not offer claude.ai login or route requests through a plan's credentials for their users; an end user may
sign in to the unmodified Claude Code program with their own plan. Dot is the owner's own program on their own Mac, run
by them alone, and it runs the unmodified `claude` program signed in by the owner, never reading, storing or passing its
credentials (as item 919's worker does, `repair/claude.py`). This is a judgment, not a documented exception: the docs say
plan limits assume ordinary individual use, and an always-on agent may be held to more. Dot does not offer it to anyone
else, and the docs page says so.

**What must hold** (after an independent red-team review and a practicality review, both AGREE WITH CHANGES, and
the flags measured on `claude` 2.1.318 on 2026-11-06).

- The model sees Dot's tools alone, served by Dot's bridge (`opencode/bridge.py`, item 284) at the chat's door. The
  program runs with `--tools ""` (no built-in tool at all: an allow-list, not a deny-list a new built-in would slip
  past), `--strict-mcp-config` with the door as the only MCP server, `--disable-slash-commands`, `--permission-mode
  dontAsk` (refuses whatever `--allowedTools` does not name; never `auto`, whose classifier decides on its own),
  `--allowedTools mcp__<door>` (the door's own name), `--permission-prompts none`, never
  `--dangerously-skip-permissions`. Measured: the `system`/`init` line then lists the door's tools alone. The run reads
  that line and fails at once if it lists any tool, MCP server, slash command or skill that is not the door's.
- `--setting-sources ""`: no settings file of the owner, the project or the workspace is read, so no hook runs and no
  CLAUDE.md or AGENTS.md is loaded. Measured on 2026-11-06: a workspace CLAUDE.md, a workspace AGENTS.md and the owner's
  `~/.claude/CLAUDE.md` did not reach the model, and a workspace `.claude/settings.json` hook did not run.
  `--safe-mode` is not used: measured, it drops the `--mcp-config` server too, so the model would have no tool.
- Every call goes through the run's gate as a call of Dot's own loop (`agent/executor.execute_calls`): the owner's
  rules and preset, yolo's asks (item 860), the initiative's asks (item 850), the sandbox, the shell guard, the
  timeline. Nothing a run does reaches the Mac but through a tool of Dot's. `<workspace>/.claude` and `.mcp.json` are
  paths a run may not write (defence beside `--setting-sources`).
- The door's secret is in a 0600 file in a private folder of the run (`--mcp-config <path>`), removed as the run ends:
  in the argument list `ps` would show it to every process of the owner, other chats' commands among them.
- The program's environment: `worker_env` of item 919 (no API key, so the plan is billed; no secret-named variable), no
  `DOT_*` or `GIT_*`, the owner's `HOME` (its sign-in), `DISABLE_AUTOUPDATER=1` and
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (no updater, telemetry or error reports; its only network is Anthropic's
  API). Never `--plugin-url` or `--plugin-dir`.
- Dot never reads `~/.claude/` credentials or Claude Code's Keychain item; whose plan a run used is read from
  `~/.claude.json`'s `oauthAccount` (no secret), as item 919 does.
- The plan's window used up (`rate_limit_event` with no room, or the program's limit error) ends the run failed with
  that reason and when the window resets; nothing switches model. A program silent past a limit (no line on its
  output) is ended and the run fails, saying so.
- A step of the run is shown as Dot's own are: the text and thinking as they stream, each tool call and its result, the
  tokens, the plan's window. Claude Code keeps the session's transcript under `~/.claude/projects/` (it needs it for
  `--resume`): the tools' results are written there in plain text, outside Dot's store; `docs/safety.md` says so.

**What only asks / later.** Claude Code's own tools (Bash, Edit, Read) gated through `--permission-prompt-tool` by Dot's
gate are a later item: v1 keeps the model to Dot's tools, whose gate and sandbox exist already.

**How.**

- `llm/types.py`: provider `claude_code`, models `claude_code:opus` and `claude_code:sonnet` (the program's own aliases;
  `haiku` is not one in 2.1.318); the models page lists them once `claude` is found and signed in.
- `claude_code/run.py` (beside `opencode/run.py`; the bridge's helpers it shares are made public, not
  copied): a run whose model is `claude_code:*` goes whole
  to `claude -p --input-format stream-json --output-format stream-json --include-partial-messages --verbose --model <alias>
  --append-system-prompt <Dot's system prompt>` and the flags above, a session per
  chat kept for `--resume`, the owner's messages while it works sent on its input, a stop of the run ending the
  process.
- `agent/manager.py`: the run goes to `run_in_claude_code` as it goes to `run_in_opencode` today.
- Docs: `docs/models.md`, `docs/safety.md` (what leaves the Mac: to Anthropic through the owner's plan).

**Checked (to be).** Unit tests of the stream-json reading and the arguments built (no API key, no built-in tool, the
bridge alone); a smoke test with a stand-in `claude` program that streams a tool call and reads it back through the
bridge and the gate; a live test (marked `live`) of one real run on the owner's plan.
