### 556. Files, office documents and the store: write_notes never follows a link, hostile workbooks are bounded, a failed open exits, prune keeps what protects runs and lessons

**Status: done (2026-10-23).** From the audit of 2026-10-23 (at `96e8c750`), whose findings an independent read of the
code confirmed one by one: the file tools, `office.py`, `store/db.py` and `core/logs.py`.

**As built.**
- F0, `write_notes` follows a link at its fixed path, so a run could overwrite any file, Dot's own code included, as a
  `low` notes write that is never asked (`tools/notes.py`). The tool keeps its kind (`notes_write`, so a research run
  and Supervised treat it as before) and writes the one file it names or nothing: the notes folder is taken from the
  workspace as the kernel names it and refused when that leads into Dot's own files or a protected place; it is opened
  through no link (`O_NOFOLLOW_ANY`), so a link at the folder, or at any folder above it, is refused; the file in it is
  looked at in that open folder, and refused when it is a link or not a regular file; an append reads it through
  `O_NOFOLLOW`; and the new text replaces it by its name in the open folder (`files.replace_in`: a temporary file
  beside it, then a rename), so a link made after the checks is replaced, never written through. The journal notes the
  path that was written, as before.
- F161, `edit_file` with an empty `old` and `replace_all` inserts `new` between every character: `old` has
  `min_length=1`, so the call is refused before it runs.
- F162, `read_file` lists `.heic` as an image that Pillow cannot decode: a HEIC or HEIF photo is drawn by macOS's
  ImageIO (full size, turned the way it is held, as an iPhone stores a portrait photo on its side) as PNG before
  `encode_image`; `.heif` is listed too.
- F163, `use_tools` says a group is on that the run does not have: it reads the tools the run was given
  (`ctx.run_tools`, the registry outside a run of the loop), so a group the loop left out (the browser off in Settings,
  an agent's tool list, no account signed in) fails as no group of this run, and the groups it lists are the run's own.
- F164, a file `write_file` creates gets mode 0600: `replace_in` makes the temporary file with `0666`, which the umask
  cuts as it does for any program's new file, and a file that was there keeps its own bits. `write_notes` and
  `edit_file` write through it too.
- F23, a small hostile .xlsx keeps a worker busy for minutes: a row is read as wide as its last cell, empty or not, so
  rows ending in column XFD cost 16,384 places each however little the file weighs. `read_workbook` charges every place
  of every row walked against a budget of 50 places for each of the cells it may read (`MAX_CELLS`), and stops where it
  is spent, saying so in the text as it does at the cell limit. A sheet of real data never comes near it.
- F76, `office_content` lets `zlib.error` and `NotImplementedError` from a corrupt package escape: the package is
  looked at first, and a part that is locked, or packed in a way no program writing Office uses (only stored and
  deflated are), is refused as a file that cannot be read; `zlib.error` and `EOFError` are caught with the other errors
  of a package.
- F35, a failed `Store.open` leaves aiosqlite's worker thread running, so the daemon or `dotx` never exits: the
  connection is closed on any error after it was made, and a `sqlite3.Error` becomes a `StoreError` (a locked database,
  or one that cannot be opened), which `cli.main` prints without a traceback.
- F36, `dotx prune --apply` deletes the events that record a run's taint: before it deletes them it records, in a new
  table `run_taints`, each ended run whose newest event of the taint kinds (`TAINT_EVENTS`, passed by `cli_prune`, read
  as `tainted_after` reads them) leaves it tainted; `RunManager._ended_tainted` (`agent/manager.py`, one line) reads
  that record when the run has no events left, so a resumed run, or a schedule's firing that builds on an old run,
  starts as it did. A chat's deletion takes the record of its runs.
- F102, prune deletes the `lesson_saved` events that protect the owner's lessons: it leaves the owner's (the events
  `owner_saved_memory_ids` reads), small as they are, and the count of what it would delete leaves them out.
- F103, `message_archive` is never pruned and keeps every screenshot it names: `dotx prune` now reports how many
  messages the archive holds and their size, and `configuration.md` says that they stay until their chat is deleted or
  rewound.
- F104, reads on the shared connection see a unit's half-done writes: `load_messages` waits for the write under way
  (the store's write lock), so a `/btw` question during a compaction never reads an empty history.
- F105, `first_event_id_since` assumes ids grow with the time: the halving search does not probe `run_finished`
  events, the only ones stored with an old time (`mark_interrupted_runs`, `close_runs_of`), which a replay does not
  read.
- F106, log write errors and the rotation race surface in the code that logs: `RotatingLog.msg` drops a line the disk
  would not take, counts it, and the next line that is written says how many were lost (`log_lines_dropped`); a file
  that is gone as it is moved is no error; and the process that holds an exclusive lock of the file moves it, one that
  finds the lock held leaves the moving to it, and one that takes it after finds the file moved, so the new file is
  never moved over the older one. A new handle is opened before the old one is closed.
- F107, stale comments: the dangling comment before `_RECENT_IMAGE_S` is gone, `HARNESS_ADOPTED_KEY` stands above the
  run columns' comment, and the `ApprovalStatus` comment says when a `left` question expires.
- F108, a rewrite of a note deleted in the meantime commits index and vector rows for it: `_rewrite_memory` raises
  `NotFoundError` when its `UPDATE` finds no note, before it touches either, so `_whole` rolls the write back.
- `docs/runs.md`, `docs/safety.md` and `docs/configuration.md` say what changed: the notes file and links, the new
  file's permission bits, an empty text to replace, HEIC, the bound on a workbook's rows and a damaged package, what a
  prune keeps and reports, and what the log does on a full disk.

**Left.**
- F76's optional bound on the size of a package's parts (zip bombs in `.docx` and `.pptx`): a limit that never refuses
  a large real workbook or deck is a choice for the owner; the damaged and unusable parts are refused now.
- F35's locked-retry for the migration and the index refresh: the open now ends with an error, the process exits, and
  launchd starts it again; a retry loop at open would hold a daemon that cannot serve anyway.
- F103's thinning of old archive versions: a chat could no longer be rewound to before a thinned version, and the
  rewinding would have to refuse it clearly; only the report and the page are done.
- F104's other readers: only `load_messages` reads the history on the shared connection while a unit may be open; the
  scan of `referenced_images` also runs under the write lock in `_release_images`, where a second take would wait for
  itself.
- A run pruned before this change has no record of its taint, and starts as it did (unmarked).

**Tests.** `tests/unit/test_notes_file.py` (a link at the file, a link at the folder, a workspace that leads into Dot's
own files: refused, what they lead to left as it was, nothing in the journal; writing and appending as before),
`test_file_tools.py` (an empty `old` refused before it runs, a HEIC photo and one stored on its side, a new file's
permission bits and an old file's kept), `test_tool_groups.py` (a group the run was not given), `test_office.py` (rows
that run to the last column, empty or valued, are read in part; real data is read whole; a damaged, otherwise packed or

and no worker thread left), `test_retention.py` (taint outlives the events, the owner's lessons stay, the archive is
counted and reported, the halving search past a late end), `test_store_writes.py` (a read waits for the unit under
way), `test_memory_saves.py` (a note deleted while its rewrite waits leaves nothing), `test_log_rotation.py` (a lock
held, a vanished file, a full disk). Each of the store and office tests fails on the code before. `ruff`, `mypy`, the
unit tests of the files changed, the smoke tests of rewind, resume, undo, research notes, the tool groups and the
approval modes, and `dotx eval check` pass.
