### 801. Tool health is a table, not a sentence hidden in an average

**Status: done (2026-10-28).** The owner asked what remains in the system; an audit of 30 days of runs found 5,193 tool
calls and 255 failures (5 %), but `dotx stats` showed only the tools whose calls took the most seconds, with their
failed count. A tool that fails four calls in five was invisible under an average.

- **`dotx stats --by tool`.** New view: every tool by failure rate, with calls, failed calls, fail % and median call.
  The highest failure rate comes first; ties break by failed count and call count.
- **The table is honest.** It is computed from the same `ToolStats` the rest of `dotx stats` uses, so it needs no new
  event or column; the real 30-day database shows `browser_wait_text` 59/153 (39 %), `calendar_events` 5/15 (33 %),
  `apple_script` 11/40 (28 %) and `browser_fill_login` 4/5 (80 %) that the old table would not rank first.
- **`--by all` is unchanged**, and `--by tool` skips the models, sites, days, learning and reflection sections; the
  tool table is the answer to the question it asks.
