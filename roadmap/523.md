### 523. Installing software asks once the run has read untrusted content

**Status: done (2026-10-22).** An outside code review of 2026-10-22 (its Y3) found that the default preset let a run
that had read a web page install software, or run a script the line downloaded, without a question: `install` was not
among the flags the taint makes a question of.

**As built.**
- `install` joins `TAINT_ESCALATION_FLAGS` (`policy/types.py`). Once a run has read untrusted content, a line that
  installs software (`brew install`, `pip install`, `npm install -g`, `cargo install`, `uv tool install`) or runs a
  script the line downloaded asks, even when the preset or an `allow` rule would let it through; a `preapproved` rule
  still skips the question, as for the other flags of the set.
- A project's own install (`npm install`, `uv sync`, `uv add`) raises no flag and goes ahead as before; a run that has
  read nothing from outside is judged as before. `uv tool list` and `uv tool dir`, which only read, no longer count as
  installing (`_assess_installer` in `policy/shell.py`): only when the words after `tool` that are not options are
  exactly those; any other word, an option's value too (`uv tool --cache-dir dir install x`), still counts.
- Rule replay (`server/rule_replay.py`) reads the same set, so a rule tried on past steps says what the gate would.
- `docs/safety.md` lists installing among what asks after untrusted content.

Checked by `tests/unit/test_shell_policy.py`: each install is allowed in a clean run and asks in a tainted one (they
fail without the change), and a project's own install stays allowed in both; and the unit suite.
