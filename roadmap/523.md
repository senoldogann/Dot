### 523. Installing software or running opaque code asks once the run has read untrusted content

**Status: done (2026-10-22).** An outside code review of 2026-10-22 (its Y3) found that the default preset let a run
that had read a web page install software, or run a script the line downloaded, without a question: `install` was not
among the flags the taint makes a question of.

**As built.**
- `install` joins `TAINT_ESCALATION_FLAGS` (`policy/types.py`). Once a run has read untrusted content, a line that
  installs software (`brew install`, `pip install`, `npm install -g`, `cargo install`, `uv tool install`) or runs a
  script the line downloaded asks, even when the preset or an `allow` rule would let it through; a `preapproved` rule
  still skips the question, as for the other flags of the set.
- The same `install` flag marks a line that decodes a blob and runs it, the local twin of a download run (the review's
  K1, marked critical): the guard reads the code no more than it reads a download, so `policy/shell.py` judges a decode
  as it judges a fetch. `_fed_a_decode` catches a decoder piped straight into a shell or an interpreter (`base64 -d x |
  sh`, `cat x | base64 -d | bash`), as `_fed_a_download` catches `curl | sh`. And a decoder's output on disk — its
  `-o` file and its `>` redirects (`_decoded_writes`) — joins a new `decoded` set in the line's scope, the twin of
  `downloaded`, so running that file later (`base64 -d blob > x.sh; sh x.sh`) is caught by the same `_runs_download`
  and `_fed_a_download` as a downloaded script is (item 385's two-step form). A decoder is `base64`/`base32`/`basenc`
  (and the `g`-prefixed coreutils), `xxd -r`, `uudecode`/`b64decode`, or `openssl`/`gpg` given a decrypt switch; all
  high, with `install`, so untrusted content makes them a question. A decode reaches no network, so — unlike a
  download — running what it wrote does not mark the run untrusted (`fetches` stays false). Encoding (no `-d`), a
  decode written to a file but not run, and a plain file piped into a shell raise nothing.
- A project's own install (`npm install`, `uv sync`, `uv add`) raises no flag and goes ahead as before; a run that has
  read nothing from outside is judged as before. Every `uv tool` command counts as installing, as before: telling its
  commands that only read (`list`, `dir`) from the others needs a reading of uv's options that knows which take a
  value, which the later item below builds.
- Rule replay (`server/rule_replay.py`) reads the same set, so a rule tried on past steps says what the gate would.
- `docs/safety.md` lists installing software and running opaque code among what asks after untrusted content.

Checked by `tests/unit/test_shell_policy.py`: each install, and each line that decodes a blob and runs it, is allowed
in a clean run and asks in a tainted one (they fail without the change); a project's own install, and a pipe that runs
no decoded code, stay allowed in both; and the unit suite.
