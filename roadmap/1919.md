### 1919. DotNext's chat moves the moment a message is sent, not 10-15 s later when the run's first event comes

**Status: done (2026-11-26).** The owner: after he sends a message (the first of a chat or any), nothing moves for
10-15 s until the agent's first thinking or step arrives.

What changed (the app only):
- From the send on, while the message is going out or taken and no run of the chat works yet, one line under the
  stream shows the typing dots and "Starting…", shimmering as the work line does, and the pill says Working with its
  clock from the send. The run's own line replaces it in place once the run exists. A message only waiting for the link
  or behind a held queue shows none, and a refused one loses it at once (its bubble says why). No progress beyond that
  one line is claimed.
- The pill has no Stop in that moment: there is no run to stop yet, and the message itself is the outbox's; Stop comes
  with the run.
- With the steps shown (Show all and Hide successful), the work line also shows while the run has no row to show yet
  (it waits to start, or its model has not answered: the typing dots), so the chat never stands still between steps;
  with them hidden it always showed.

How it was checked: `StreamingLiveUITests.testASentMessageMovesTheStreamAtOnce` against the throwaway daemon, whose
scripted model answers "slow:" only after 8 s: the starting line or the run's line is on screen within 0.5 s of the
send. `ChatUITests.testTheCapsuleClockTicksWithNoEventsAndSaysWhatTheRunDoes` for the pill.
