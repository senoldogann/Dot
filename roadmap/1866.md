### 1866. What recall handed a task is never saved back as a new note; the memory benchmark measures it

**Status: done (2026-11-25).** The study of OpenClaw of 2026-11-25 (`reports/refs-2026-11-25/clawdbot.md`, items 2 and
3) found that its memory marks the text recall put into a session and never extracts it again as a new memory ("a fact
recalled a hundred times stays one fact"), and that a newer fact supersedes the older. Dot measured echoes for audits
(item 1715, `memory_uses.echoed`) but nothing stopped a save of them, and items 1728 and 1729 had measured supersession
only for runs that save a new value, not for one that writes an old value back.

Approach (written before the code): detect the echo exactly, not by a likeness. The store already records every note
a run was handed (`memory_uses`); a save whose words, as words (case, accents, spacing and punctuation aside), are a
handed note's, or hold a handed note of four words or more whole, is that note again. It is not saved, and the model is
told why. Measure first with new benchmark cases, then after.

Measured first (`dotx eval memory`, scripted embeddings, before any change): four new cases E01 to E04 (K01, K03, U03
and U09 again, with the same texts and cosines `bge-m3` measured, so with and without a subject) in which a second run
is handed the old fact as it is saved, the newer fact is saved, and the second run saves the old fact's words again:
the newest came first in 0 of 4 and was among the three best in 2 of 4, the outdated note was shown in 4 of 4. The save
of the same words woke the resting old note (`_saved_again`), and with a subject put the newer one to rest (item
1729's "said now").

What changed (`memory/echo.py`, `memory/supersede.py`, `store/db.py`, `tools/memory.py`, `evals/memory_cases.py`,
`evals/memory_bench.py`):

- `recalled_echo` (pure) and `handed_echo` (reads `Store.handed_memories`, the notes a run was handed that are kept):
  `memory_save` checks it first, before the hold of item 1865 and the save; an echo answers "Not saved: these are the
  words of a note you were handed..." with the note, so the model corrects it with `memory_update` or saves only what
  is new.
- The benchmark saves each fact through the same check; the E cases are a group of their own, so the groups of items
  1728 and 1729 keep their numbers.

After, the same 46 cases:

| group | cases | newest first | newest in top 3 | outdated also shown |
|---|---|---|---|---|
| facts that changed (1728/1729) | 34 | 25 -> 25 | 34 -> 34 | 10 -> 10 |
| facts that did not change | 8 | 8 -> 8 | 8 -> 8 | - |
| old note saved again by a run (new) | 4 | 0 -> 4 | 2 -> 4 | 4 -> 0 |

Design choices: (1) Exact words, not the cosine or the distinctive words of item 1715's trace: a likeness would refuse a
value that changed (`4 CPU cores` and `8 CPU cores` share every distinctive word), and a refusal of a new fact is worse
than a duplicate. Every word counts, one letter or digit too. (2) Containment only for a handed note of four words or
more, since three words ("Prefers tea.") are often said anew in a longer fact. (3) Only notes handed to this run: the
same words a run did not get from recall are a save as before (item 1729's "said again" still wakes a resting note
when the owner says a fact holds again). (4) The tool answers, it does not fail: nothing in the policy changes, and a
yolo or free run asks and is refused nothing new.

Not done: a reworded echo (recall's fact in other words) is saved as before; lessons were already checked against the
saved notes (`kept_lessons`); the configured `bge-m3` run of the E cases was not made (their texts and cosines are the
measured ones of K01, K03, U03 and U09).

Checked: `tests/unit/test_memory_recall_echo.py` (case, spacing and punctuation; the rendered line and a sentence around
it; a changed number, a new fact and a short note inside a longer one are not echoes; only the run's handed notes),
`tests/unit/test_eval_memory.py` (46 cases, the numbers above), `tests/smoke/test_held_notes.py` (a run that searched
for a note and saves its words again saves nothing and is told why), `dotx eval memory`, `dotx eval check`,
`tests/unit/test_freedom_contract.py`.
