### 1790. DotNext's Settings › System › Maintenance: Dot's and the provider programs' versions, and Continue after restart

**Status: done (2026-11-25).** Helper S3 of the settings wave of the iPhone rewrite (the owner's workspace,
`ios-rewrite-2026-11-24/PLAN.md` §25 last bullet, the owner's T3 reference `owner-refs/ref-maintenance.png`).

What must hold:
- Each control maps to what the daemon really has. **Continue after restart** is `[agent] resume` (`safe`/`off`, item
  231), read from `GET /api/status` and written with `PUT /api/agent/resume`, which a phone's key may call; the switch
  is put back when the Mac refuses it or is not reached.
- The Mac row shows Dot's version and each provider program's version with how Dot fares on it, by the daemon's own
  table (item 1673), never a verdict made on the phone.
- No switch that switches nothing: the reference's "Check provider updates" has no daemon setting and gets none here.
  Dot reads each provider's models live when Models opens (so new models appear without a check), and Dot never
  updates a provider's program on its own (Claude Code updates itself; what Dot was measured on is item 1673's table).
  The page's footer says so.

What was built:
- `GET /api/diagnostics/programs` (`routes_about.py`): Claude Code and OpenCode, each found as a run finds it
  (`[providers.*] command`, `DOT_CLAUDE`/`DOT_OPENCODE`, the login shell's PATH), asked `--version` once per request,
  with `supported`/`graceful`/`broken`/`unknown` for Claude Code by `CLAUDE_VERSIONS`, `unknown` for OpenCode (Dot keeps
  no list of its versions) and `missing` when not installed. Read-only; nothing under "Always needs a human".
- The engine: `ProgramsView`, `programs()`, `setResume(_:)`; the page `MaintenancePage` with its Mac row (Dot and
  provider versions, and "Update Claude Code on the Mac with 'claude update'" when one is older than measured).

Checked: `tests/smoke/test_provider_programs.py` (stand-in programs: measured, older, OpenCode, missing; 404 before the
route, seen on a daemon of main), `MaintenanceModelsTests`, the e2e UI test `SettingsMaintenanceLiveUITests` with the
script reading `[agent] resume` = `off` on the daemon's side, shots light and dark.
