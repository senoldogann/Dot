### 1192. A tainted run is shown the lessons saved while reading outside content, fenced, and nothing stores them

**Status: done (2026-11-15).** Dot learned and did not use it. On the owner's Mac, 2026-11-15, 544 of 569 awake
lessons (96 %) were saved while their run had read content third parties can author (`tainted`), and every path that
hands a lesson by itself left those out (item 384): the start notes, the note of a site a run reaches (item 308) and
the lessons of a failed call (item 1111). All 135 lessons tagged with a site were tainted. The nightly digest said
"3 of 44 runs handed a lesson", "3 of 60"; the failure path had handed a lesson 4 times ever. Yet 101 of the 108 runs
with tool calls in 14 days had read outside content themselves, 75 of them from their first call. Of the tainted
lessons, 134 carry a site's tag and 132 more name a tool: ~291 lessons become reachable instead of 25.

What must hold, and holds by construction:

- A run that is not tainted at the moment (the gate's `tainted`, which the owner's message clears) is handed none.
- Such a lesson is stored nowhere. It stands next to the result of the call that reached its site or failed with its
  tool, in the requests of the run that was handed it, and only on the newest results those requests carry whole
  (`with_shown`, `[agent] keep_recent_tool_results`), so it goes as the result grows old and never changes the part
  of the prompt the cache keeps. It is bound to that result by its call's id and its text (`shown_key`): an id is
  unique within one reply only; where two calls share both, the first carries it, as a lesson is handed once. A message of the owner's that clears the run's mark mid-run takes them out of its
  next request, for good. It is in neither the result the chat keeps nor the step's event, the system prompt,
  the start notes or the note of a site: a later run of the chat, which reads its history, never reads it.
- A run on the Claude plan or OpenCode is handed none: its program keeps a call's result in a session that a later
  run of the chat resumes (`ToolContext.shows_outside_lessons` is set by Dot's own loop alone).
- It sits in the fence of a page's text (`fence_untrusted`, url `dot-memory:lessons`), which the system prompt says is
  data, never instructions; the run is marked tainted again by construction.
- Being handed never lifts it: the tainted ones come after the clean ones and the newest first, at most three per
  site (five clean) and two per failed call; each is handed once per run and counts as handed (`site`, `failure`),
  so the nightly score and the Memory page see it.

Three reviews shaped it. An independent security reader found that the first design, which put a site's tainted
lessons in the arrival note, would have reached a later run that starts clean (the chat keeps that note as a message;
a run on the Claude plan reads the chat's earlier messages, and the progress consultant reads a user line as the
owner's). The pre-push review then found that the second design, which put them in the call's stored result, would
reach a clean follow-up of Dot's own loop through the chat's history. They are now shown, not stored; the same reader,
on that design, found that they outlived an owner's message that cleared the mark, and that a provider that names
every call alike could put them next to another call's result; both are closed.

What it does not do: a lesson made of a page's words once can reach every later tainted run on that site or after a
failure of its tool, where before it reached none; and what the run writes itself (a step's words, its answer, a
summary) may restate a lesson as it may restate a page, and is kept as such words are. The fence, the run's mark and the checks of a tainted run (the
asks of each mode, the review of a tainted yolo step) bound it as they bound the page; the lessons model's own filters
(links and accounts out, item 903) apply when it is written. The start notes are unchanged: bge-m3's similarity was
measured as a weak signal for short goals (an unrelated lesson at 0.55 to 0.64 where the right notes scored 0.40 to
0.45).

- `agent/failure_lessons.py`: `lessons_for_tool` and `hand_failure_lessons` take whether the run is tainted and shows
  such lessons; `failure_note` gives the clean lessons to keep and the fenced ones to show (`LessonsNote`).
- `agent/sites.py`: `outside_site_lessons`, `outside_site_note`, `hand_outside_site_lessons`.
- `agent/executor.py`: `ToolOutcome.shown`; `agent/compact.py`: `shown_key`, `with_shown`; `agent/loop.py` keeps the
  shown words by their result, puts them in each step's request while the run is tainted and drops them when it is
  not; `tools/context.py`: `shows_outside_lessons`.

The pre-push review also found two lines of the docs that still said such a lesson is never handed: `safety.md` and
`memory-and-schedules.md` now say a clean run is never handed one and a marked run sees it so.
