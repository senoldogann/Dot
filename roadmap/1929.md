### 1929. Check goals and helper results on a model of another family

**Status: done (2026-11-26).** Set an explicit alternate check model in Settings › Models
(`[models] check_other_family`), empty by default. The setting chooses the recipient of the evidence, which a
switch alone could not do. Recognize model lineages across connectors, including Claude plan aliases and hosted
namespaces. Use the alternate only when its lineage and that of the worker are known and different. An unavailable
alternate cannot silently pass the check to a model of the worker's own family. The worker's current model governs
the choice after a standby switch. Route the existing goal check and give completed helpers one final result check
before reporting, including detached helpers. A scheduled follow-up can satisfy the check when it will run in the
parent’s chat. Keep the action approval and taint review model on its existing role.

Before implementation, a read-only SQLite snapshot joined checker `model_call` events to the worker at that point
(the latest model switch before the event, then the queued model, then the run record for old runs). Of 190
`goal_check` calls, 76 (40.0%) were same-family and 114 (60.0%) were cross-family, including one and five failed
calls respectively. All were top-level; no `review` calls were recorded. The 96 delegated and team parts therefore
have no separately instrumented result check to compare. A parent's assessment of a helper report as part of its
own turn is not separately measurable.

Scripted workers and checkers verified the recorded model of a goal check and a helper result check. The browser test saved and cleared the check model. Ruff, mypy, the freedom contract, targeted Python tests, `dotx eval check` and `npm run check` passed.
