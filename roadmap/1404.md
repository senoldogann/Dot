### 1404. A run's Changes line says how many steps ran that no undo can take back

**Status: done (2026-11-24).** Found by the autonomy audit (gap): undo covers the file tools only (`write_file`,
`edit_file`, `write_notes`; docs/limits.md), so a run that ran commands, drove the browser or the screen or sent a message
had a Changes line that said nothing of them, and a run that changed no file showed no line at all. Verified before the
change: the line (`runchanges.js`, at the head of the side panel's Changes tab, item 841) listed the files of the undo
plan and hid for a run with none.

What changed: `GET /api/runs/{id}/actions` has `outside`, the steps of the run and of the runs it delegated that ran with a
tool the journal does not hold, counted by category (`shell`, `browser`, `desktop`, `message`, `app`) and only the
categories that have any. It is read from the `tool_result` events of the run's family that record the gate's decision
(`Store.ran_steps`: a call the gate refused, or that never reached its tool, has none and is not counted), by the kind of
action each records: `shell`; `browser_input` and `browser_click` (a batched `browser_act` counts the steps it carried);
`desktop_input` and `app_control`; `mcp` (a connected app's tool that may change things); and any step whose action
raised `message_send`, whatever tool it went through, as a message. Opening a page, reading, what Dot keeps in its own
memory or schedules and the delegating itself are not counted. The line says "Dot also ran 3 commands and 2 browser
actions. Undo takes back files only, so it cannot take these back." (`outsideWords`): what ran, never what it did, since a
command may only have read. It stands under the files of the card, and alone for a run that changed no file; a daemon from
before sends no `outside` and gets no line. docs/limits.md and docs/autonomy.md say it.

Checked: `tests/unit/test_outside_steps.py` (the categories, the message flag over the tool, what is not counted; a fixture
run with a helper in the store: a refused call and another chat's run are not counted, an older record counts one step),
`tests/js/runchanges.test.js` (the sentence, singular and plural, an unknown category left out),
`tests/smoke/test_run_outside_journal.py` (scripted runs on a real server: the route, and the card in Chromium at 1280
light and at 390 dark: files and the sentence on one card, the sentence alone, nothing for a run that only read),
`npm run check`.
Not done: the CLI's `dotx undo` does not print the line. A run on the Claude plan sees Dot's tools alone (no built-in tool
of the program, `claude_code/run.py`), so its steps are in the same events and are counted the same.
