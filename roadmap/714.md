### 714. A page's data in one call: its background calls, and its records by selectors

**Status: done (2026-10-27).** **Why.** Dot's browser runs spend nine times as long waiting for the model as on the
tools (the measure of items 696-704), so a turn saved is time saved; and a research run (the morning brief, a watcher)
has no `browser_eval`, so a list of results took it a snapshot and a read of text per page. makecindy/cindy's browser
tools (Apache-2.0) read the page's own XHR calls ("network first") and records by a spec of fields: the ideas are taken,
not their code.

**The change.** Each tab keeps its page's last 50 background calls (`browser/network.py`, `Tab.calls`, kept from the
page's `response` events of type xhr or fetch). `browser_requests` lists them with a number, newest first, filtered by a
part of the address, and reads one's answer whole by its number, JSON written compactly. `browser_extract` runs Dot's
own script (`browser/extract.py`) with a spec: a CSS selector of the records and, for each field, a selector inside one
with `@attribute` to read an attribute. Both are observations, in every mode. Outside `yolo` the values of JSON keys and
address parameters whose names say they hold a secret are hidden, as a script's cookies are (item 533); a field that
takes a secret (`secret_selector`) is never read by `browser_extract`, in any mode; what a login from the password
manager filled in is held back as from every browser tool (`held_back`).

**Checked.** `tests/smoke/test_browser_data.py` in a real headless Chrome: a shop page whose script fetches its items
lists that call with its key hidden and reads its JSON with its session token hidden, and whole in `yolo`; a number no
call has fails saying so; the page's records are read by selectors and an attribute, a missing field is null, a card
field reads hidden, a selector the browser cannot read fails saying so; both tools are a research run's and a task's.
`tests/unit/test_tool_groups.py` and the tests of the tool lists; `dotx eval check`.

The code review of the first push: a call's number was its place among the kept calls, which moved by one with each new
call once 50 were kept, so a number the run had read could name another call; each call keeps the number it was listed
with now (one more than the call before), and a number no kept call has is refused saying so
(`tests/unit/test_browser_network.py`).

The sixth review: an answer that is no plain JSON (behind Google's `)]}'` guard, JSON lines, a form's
`access_token=…`) came as it was, its tokens with it; the guard is taken off, JSON lines are read a line at a time, and
a secret's value is hidden in any other text too (`read_answer`, `tests/unit/test_browser_network.py`).

The seventh review: a value whose key names no secret may hold one (an address with `access_token=…`, a JSON written
as text); every text of a JSON answer is masked as other text is.

The eighth review: the three reads went past the URL rules every other read of a tab holds (item 554), so a tab a
page's timer or a popup led to a forbidden address was read; they are made under `_read_held` now. And the filter of
`browser_requests` matched the address before its secrets were hidden, which let a run read a hidden value letter by
letter from which calls were listed; it matches what is shown. The docs' list of the tools, which a rewrap had run
together into one item, is as it was, with the one new item.

The ninth review (a pass, with nits): an attribute whose name, or whose element's name or id, says it holds a secret
(a CSRF token in a meta tag, a session in a hidden field) reads `[hidden]` outside `yolo`, as such a key of an answer
does.
