### 739. A click that changed nothing is told, and so is what the page says after one

**Status: done (2026-10-27).** **From the owner's runs** (30 days, measured in their database after they found that
Slack's buttons did not answer a click): `browser_act` reported a click as done whatever the page did. Runs repeated
13 clicks that had done nothing (a button behind a dialog on Pinterest and Etsy, Slack's), and after a form was sent
they waited 20 to 30 s for a thank-you text they guessed ("Thank you", "Kiitos"): `browser_wait_text` failed 37 % of
the time since item 699, mostly so, about 21 minutes in 30 days, because a required field had held the form back.

**The change.** A click, a double click, a click at a point and Enter are watched for what they did
(`session._effect`, `driver.page_pulse`): a `MutationObserver` in each of the page's documents (its first ten frames)
counts their changes, and so do the `input`, `change` and `toggle` events no element shows (a box ticked, a field typed
in, a `<details>` opened); the tab counts the requests it starts (`Tab.requests`), the address, tabs and dialogs are
compared as before, and a click whose element took the focus as a field (a text field, a native dropdown,
`driver.holds_field_focus`) changed the page too, so that a run is never told a box it ticked did nothing and clicks it
again. When none of them moved for half a second, the step's line says it is done but the page did not
change, with the fields the page marks invalid and what to try (close what is in front, `browser_eval` with the ref,
item 738); when the page changed, the line names what it says new in an alert or a live region and the fields it newly
marks invalid. Only a step that changed nothing waits the half second; a page that could not be read counts as changed.
Three tests of `test_browser.py` whose pages acted 0.4 to 0.5 s after a click (to test what a wait sees) now act after
0.9 s: within the watch, the click's own line shows the dialog or the new page, which is what a run should see.

**Checked.** `tests/smoke/test_browser_effect.py` in a real headless Chrome: a button with no listener is told as no
change, one that changes the page and one that only sends a request are not; an alert that says "Saved" is named; a
form whose required field is empty is told as no change with "Email" marked invalid, and the page stays where it was.
`test_browser.py` and `test_browser_eval.py` pass. The new tests fail on the code before (the detail was always empty).
