### 1424. "While you were away" covers what Dot did on its own, not only what a schedule did

**Status: done (2026-11-24).** The owner's decision of 2026-11-24 ("do it yourself"): the card listed
`runs.source = 'schedule'` alone (`store/db.py` `_UNATTENDED`, items 466 and 1356), so a reply Dot answered, an agent's
work, a command that ended in the background and what ran in an agent's own chat never showed up in "what happened while I
was away", on the Mac or on the iPhone.

What changed: the store reads an `AwayRule` (`store/models.py`) instead of one source: the runs of every source of a run
nobody watches (`proactive.UNWATCHED_SOURCES`, named once: `schedule` (a schedule's and a campaign's session), `watcher`,
`initiative`, `reply`) with `team` and `background`, **and** the runs of an agent's own chat (a chat bound to an agent,
`threads.agent_id`) under any source that is not the owner's (`prompt.OWNER_SOURCES`: `ui`, `cli`, `review`, `eval`; with
`welcome`, an agent's greeting that opens in front of the owner, and `resume`, a run resumed after one the owner started), the
same no-helper, not-rewound, ended-since-the-moment-or-working conditions as before (`store.unattended_runs`,
`unattended_counts`, `auto_decision_counts`, `unattended_drafts`; the decisions and drafts of such runs and their helpers
count too). **An agent's work (`team`) always has a parent**: only a run sends it (`message_agent`,
`RunManager._launch_delegated`), and the first version of this item required `parent_run_id IS NULL` of every run, so the
card could never list one (the pre-push review found it: the tests had made `team` runs with no parent, which no real run
is). `AwayRule.delegated` names the sources allowed a parent (`team`); such a run is a row of its own unless a run of the
owner's is above it (a source of `owners`, however many runs the work went through, read with a recursive query up the
parents: owner's run, agent, agent is the owner's work; they wait for that run, and for the work in it, which no card
lists), and its approvals and drafts count under itself (`auto_decision_counts`), a helper's under the run that has it. The owner named `reply`, `team` and `background`; I read "what Dot did on its own" as the canonical set of
sources nobody watches, so `watcher` and `initiative` are in too (the pre-push review found a fifth hand-written list that
dropped them): say if the card should list fewer. The rule I chose for the agent's chat, the simplest that lists no run
the owner watched: a run the owner starts from a page, a phone or `dotx run` is theirs and they wait for it, and Dot keeps no
record of who was looking while a run worked (the lease of item 1420 is in memory and has no history, and no per-run
attachment is written anywhere), so "no lease and no browser attached" cannot be read back for a run that is over; the source
says it, and the chat's own unread dot covers a run the owner started and walked away from. A run of a source no rule names
(`notice`, `reflection`, ...) in a chat that is no agent's is not listed. A run is named by its campaign, its schedule, then
(new) its chat's title for a run another source started, whose goal is Dot's own note, else its goal; `AwayRun` carries the
run's `source`. The read mark of item 1356 is untouched (`GET` and `POST /api/away/read`; the card reads from it). The card's
line says "tasks", not "scheduled tasks", since a reply's or an agent's run is no schedule's. `docs/phone.md` (the contract of
`GET /api/away` and the mark, for the app), `docs/daemon.md` (the card and the route's row) and `docs/autonomy.md` say it.
