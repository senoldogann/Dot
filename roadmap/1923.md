### 1923. DotNext's open chat never changes by itself when a newer chat of the bot comes

**Status: done (2026-11-26).** The owner's build 6: while they read one of Dot's chats, the pre-push hook started a
code review chat under Dot and the open screen jumped to it.

Cause: a bot opened from the home (its route names no chat) drew `bot.latest` on every render, so the chat on screen
was whichever of the bot's chats moved last; a newer one (a code review, a chat begun on the Mac) replaced it. Item
1912 keeps Dot's own work from being the latest, but a newer conversation still took the screen.

What was built: `botChatThread` (pure) and a held chat in `BotChatScreen`: the chat the screen showed first is kept
until the owner picks another (from the profile or a new chat) or it is deleted; a newer chat only shows in the list.
A bot's chat list keeps Dot's own work (its schedules', its initiative's, what it sends the agents, the code reviews)
in a section of its own, "Dot's own work", last and apart from the owner's chats, as the web folds it; one that waits
on the owner stands under Needs you. On the iPad's detail column the bot's screen is keyed by its route, so a held or
chosen chat never carries over to another bot.

Checked: `BotsLiveUITests.testANewChatOfDotNeverReplacesTheOneOpen` on a throwaway daemon (`scripts/e2e_bots.sh`): a
chat of Dot open, the test starts a newer one with `POST /api/runs`, the open one stays; red without the change; `ChatListTests.testDotsOwnWorkStandsApartFromTheOwnersChats`.
