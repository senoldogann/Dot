### 681. A file the daemon opens where a run writes too is opened along the path that was checked

**Status: done (2026-10-26).** The whole-project review of 2026-10-26 found that the file tools compared the action
once as a call started (item 181) and then resolved `args.path` again and opened it by name, following links: a
command of the run, which may write the workspace, could swap a folder on the path for a link to `~/.ssh` or to Dot's
own folder between that check and the open, and the daemon, outside the sandbox, read or wrote through it. The undo
journal copied the file at the path the same way, `browser_upload` gave Chrome the path, which it reads when the page
sends it, and the files the daemon makes in the workspace (a crawl's pages, an MCP answer kept whole, an attachment)
were made through whatever link a command left in their folder's place. A named pipe made `read_file` hold a worker
thread for good.

**The change.** `core/held.py` opens a folder one part at a time from `/`, each part with `O_NOFOLLOW` (made when it
is missing, for a write), and a file in it with `O_NOFOLLOW | O_NONBLOCK`, refusing anything but a regular file. The
file tools act on the path they were allowed (`authorized.target`, resolved when the call was checked) and read and
write it that way; the journal's copy of what was there is read the same way, so a link on the path refuses the write;
`browser_upload` copies each file it checked into a new folder of Dot's home (`uploads/`, closed to a command since
item 676; copies older than a day are removed) and hands Chrome the copies; a crawl's pages, an MCP answer and an
attachment are made in folders opened that way under the workspace (which a command cannot move or replace, item 676).
An undo (`undo/restore.py`) deletes or writes a file back in its folder opened that way, and reads what is there to
compare it the same way: the security review of this item found it still followed a link that came between its check
and its write.

`web_extract` reads a file it names, and `show_page` a page it shows by its path, the same way, and the extraction
refuses a file that leads now where the call was not allowed to read; the copies of an upload are sealed from a
command like Dot's other files (the fifth code review).

`list_dir` lists the folder it was allowed, opened the same way, and says a link inside is one and where it leads,
read from the link, rather than entering it (the eighth code review: a folder swapped for a link listed the names of
another; the ninth: the run is told where a link leads).

**Checked.** `tests/unit/test_held_paths.py` (a folder on a checked path swapped for a link: read, write, edit and a
new file are refused, and the file behind the link is unchanged; a named pipe refused at once; an attachment through a
link refused; the browser given copies, a link refused, old copies removed; a listing of a folder swapped for a link
refused, a link in it listed, not entered), the tests of the file tools, the undo
journal, crawls, MCP answers and attachments (2,300 of them), `tests/smoke/test_browser_page_steps.py`.
