### 1937. The night's update syncs the environment to main's lock before it restarts

**Status: done (2026-11-26).** The review of 2026-11-26 (M1): the repair night's update (`repair/night.py`
`_pull_and_restart` → `repair/github.py` `pull_main`) fetched and fast-forwarded the owner's checkout and restarted Dot
without `uv sync`. The daemon runs the checkout's own `.venv` python (`launchd.py`), so a pulled `uv.lock` change (a
Dependabot bump merged without a person) restarted Dot on packages its code was not tested with, and a new dependency
raised `ImportError` at start, which launchd's KeepAlive and the watchdog then restarted all night (six such
ImportErrors were seen).

What changed: `pull_main` records the commit it stood on, fetches, fast-forwards to main's green commit, then runs
`uv sync --locked` in the checkout (up to 10 minutes). A sync that fails puts the checkout back (`git reset --keep`,
which stops rather than lose a change of the owner's), syncs that commit's lock again, and raises `RepairError` naming
both commits and uv's output, so no restart is asked and the owner is told; when the put-back fails too, the error says
so. docs/repair.md says it.

How it was checked: `tests/unit/test_repair_pull_main.py`, real git in a throw-away folder with a stand-in `uv` on
`PATH`: a pull syncs on the new commit; a failed sync leaves the checkout on the old commit, synced, and raises; a
checkout off main is left alone.

  and puts the checkout back instead of restarting when that fails.
