### 1690. memory_save and memory_update name the longest note they take

**Status: done (2026-11-24).** The audit of 2026-11-24 (harness parity) measured 6 of 21 `memory_save` calls of runs on
the owner's Claude plan refused as "the note is N characters long; the limit is 600": the limit (`[memory] max_chars`)
was in no tool description and in no line of any prompt, so a model learned it only from the refusal.

What changed (`tools/memory.py`, `runtime.py`): `build_memory_tools(max_chars)` takes the limit from the config, and
`memory_save` and `memory_update` end their description with "A note holds at most 600 characters; a longer one is
refused, so split it into single facts." Every harness reads the description (Dot's own loop, the door of Claude Code,
OpenCode's bridge).

Checked: `tests/unit/test_memory_lifecycle.py::test_tools_that_write_a_note_name_its_limit` (fails without the
change), `tests/unit/test_opencode.py`.
