### 1715. A run records why recall chose its notes and which of them it echoed

**Status: done (2026-11-24).** The audit of 2026-11-24 (A2, I3 and I4) could not say whether recall picked the right
notes or whether runs used them: the `memories` event held ids and tokens but no scores, `Remembered.tainted_left_out`
was computed and dropped, and a hand-out counted as a use, so the ten notes handed most took 63% of all hand-outs.

What changed (`memory/echo.py`, `memory/service.py`, `agent/loop.py`, `agent/manager.py`, `store/db.py`):

- `Remembered.similarities` (each note taken by meaning, rounded) and `tainted_left_out` go into the `memories` event
  of a run's start, on Dot's own loop and on the Claude plan (both count their start notes there).
- `memory_uses.echoed` (a column added as the others are; NULL until the run ends and for every older row): when a run's
  end is recorded, `echoed_notes` marks each note it was handed 1 when its answer or the arguments of its calls name the
  note's id or carry two of its distinctive words (five letters or more, no function word; one for a note with only
  one), else 0, and logs `notes_traced`. No model is asked; the table survives a deleted chat, as the uses do.

Not done: nothing ranks notes by it yet (the audit's later step, once there are numbers); a run that follows a note in
words of its own is not seen.
