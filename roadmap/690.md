### 690. Secrets are masked in a run's answer, in an error's context, in the terminal's log lines and in a password that looks like a placeholder

**Status: done (2026-10-26).** The whole-project review of 2026-10-26 found four places where a secret passed:

- `RunManager._record_end` masked a run's answer, what it needs and its error with the patterns only
  (`redact_secrets`, `redact_json`), where every step and tool result also masks the secrets Dot holds
  (`redact_known`): a password filled into a page that the model wrote in its answer was stored and told as it stood.
- `dot_error`, the handler of every `DotError`, answered with `exc.context` as it came and logged it at `request_failed`
  for a 500. `McpConnection._context()` puts the raw `url` and `args` there: a key in a URL's query or after
  `--api-key` went to the page and the log.
- The terminal logged the whole `command` at info when a session opened and when an idle one closed.
- `secret_value` asked for a placeholder before it asked for a password, and `_PLACEHOLDER` took `$` + any word, `%word%`
  and `<anything>`: `DB_PASSWORD=$Tr0ngPass1`, `{"password":"$Tr0ngPass1"}`, `%secretkey%` and `<abc12345>` stayed
  unmasked. `redact_json` masked a field named for a secret only when its value was a string, so
  `{"token": ["abcdef123456"]}` stood whole.

**The change.**

- `_record_end` reads the secrets Dot holds (`known_secrets(filled=True)`, off the event loop) and masks the answer, the
  need and the error with `redact_known` / `redact_json`; the end kept for a later store and the campaign's follow-up
  take the masked need too.
- `dot_error` masks the context with `mcp.masking.masked_context` (address, arguments, the secrets Dot holds) and then
  `redact_json` (a field named for a secret), for the response and for the log line, off the event loop.
- `Terminals.open` and the idle close log the command through `redact_known`.
- `_PLACEHOLDER` leaves only real placeholders: a mask or a run of `*`, `.`, `…`, `x`; an environment variable's name
  (`$NAME`, `${NAME}`, `%NAME%`, upper case, digits and underscores); a hint in angle brackets without a digit
  (`<your key>`); a `{{ template }}`; the words none, null, nil, true, false, undefined, redacted, hidden.
- `redact_json` masks every string under a field named for a secret, however deep a list or an object holds it.
- `docs/safety.md` says so.

**Checked.** `tests/unit/test_redaction.py` (the look-alikes of a placeholder are masked, the real ones kept, a list or an
object under a secret field is masked), `tests/unit/test_known_secrets_callers.py` (the two new callers say `True`),
`tests/smoke/test_run_ends.py` (a held value in the answer, the need and the error), `tests/smoke/test_error_context.py`
(the handler's answer), `tests/smoke/test_terminal.py` (the log line of an opened terminal).
