### 761. Text past a NUL byte in a file named as an image is scanned

**Status: done (2026-10-27).** From the notes of items 710-712: the scout's scan took a file named as an image, a
document or a font that holds a NUL byte for what its name says, so it was neither scanned nor named as unread, and words
placed after the NUL were met by no rule.

**The change.** For such a file the scan reads its runs of plain text (24 printable ASCII characters or more) and runs
the text rules over them; when one finds something, the file is also a `disguised` finding as grave as the worst of
them, `high` or `medium` ("plain text in a file named as .png that is not text"): the code review found a long run of
hex in a PDF's stream, a medium finding, would else make a plugin high by itself. The file need not hold a NUL: one that
is not UTF-8 is read the same way. A real image, whose bytes hold no such run that a rule finds, stays clean. The review
and the card see the findings as for any other text. Words in another script than ASCII after the NUL are not read by
this; the scan has no other way to tell them from picture bytes.

**Checked.** `tests/unit/test_scout_scan.py` (a `notes.png` with an instruction to post to a collector after NULs is
`disguised` and `collector`; a real PNG header with picture bytes is clean), and the scout's other unit tests
(59 passed); `ruff` and `mypy` on `plugins/`.
