### 1461. Dot for iPhone draws the web app's own icons: Lucide as vector images, not SF Symbols

**Status: done (2026-11-24).** The owner (2026-11-24, 08:47 and 09:40): the icons are to be SVG, the web app's, not the system's
symbols, and the phone is to have what the web app has. The app drew about sixty SF Symbols; the web app draws Lucide's shapes
(`static/js/icons.js`, ISC licence in `static/js/LICENSE-Lucide.txt`), so the same step was a different picture on the two.

What changed:
- `scripts/export_ios_icons.py` reads icons.js (a small reader of the literals it is written in: `SHAPES` and the `FRAMES` of
  item 849) and writes `ios/Dot/Resources/Icons.xcassets/<name>.imageset/<name>.svg` with a `Contents.json` (single scale, "preserves
  vector representation", template rendering), each shape drawn black through the frame and with the stroke the page draws it
  with (1.75 on the grid whatever the frame, and the half of the stroke a close frame leaves past its edge inside the picture,
  as the page's `overflow: visible` draws it), so that a "+" and a speaker are the same size on the phone as on the Mac. It
  also copies the Lucide licence to `ios/Dot/Resources/Licences/LICENSE-Lucide.txt`. `--check` exits 1 when the files are not what
  it would write.
- Which icons: exactly the cases of `ios/Dot/Core/IconName.swift` (one case a line, in order): a screen can only draw a case, so
  a name the catalog lacks does not compile. 74 icons start it: what the chat list, the chat, the capsule, the inspector and
  Settings draw. icons.js has 51 of them; the other 23 are Lucide shapes the web app does not draw (the bot, the chip, the
  wifi that is off, the circle marks...), kept in `EXTRA` of the script, copied from Lucide v0.577.0 (compared with the package,
  shape by shape) and named as Swift can (`loop` is Lucide's `repeat`, which Swift reserves). The test fails when icons.js gains
  one of them, so that the web app's own drawing replaces the copy.
- `DotIcon(_ name:, size:, pulse:, label:, relativeTo:)` (Features/DotIcon.swift): a template image of the catalog that takes the
  text's colour, grows with Dynamic Type like the words beside it, is decoration unless it has a label, and breathes (an opacity
  pulse, still under Reduce Motion) where an SF Symbol had `symbolEffect(.pulse)`: a step that runs, a reconnecting link, a
  plan step at work, the empty states. `Label(_:icon:)` is a label in a view, `Label(_:menuIcon:)` one of a menu, a context menu or
  a swipe action. Every SF Symbol of `Dot/` is replaced except the three of a notification's actions (`UNNotificationActionIcon`
  takes a system name): the chat list's compose and settings buttons, the composer (plus, send, queue, and a plain square drawn for
  Stop, which an outline would not read as), the capsule's segments (`DockSummary.Segment.icon`), a step's tool (`ToolGlyph.icon`,
  the web's own `toolIconName`: a browser or a page the globe, a command the terminal, a read an eye, a write a file), the
  approval cards, the inspector, the dictation button, the connection line, the cards of the inbox and the away and hand-off cards, the
  settings rows. The Live Activity (`DotLiveActivity`) and the share extension (`DotShare`) are other targets and keep their SF
  Symbols; they do not read the catalog.
- Settings gets an **About** group with **Licences**: Lucide's licence (ISC, and the MIT licence of the icons Lucide took from
  Feather), as the file carries it, to read and to select.

Checked: `tests/unit/test_ios_icons.py` (11 cases: the catalog is what the script exports, every icon is icons.js's drawing or an
`EXTRA` one shape by shape, no extra is also an icon of the web app, the stroke and the frame are the page's, an imageset is a
single-scale template that keeps its vectors, the licence copy is the web app's file, the reader takes icons.js's literals
and refuses a missing constant, a name that is nowhere is refused, the cases are in order and one a line, no Swift file draws a
case that does not exist); `ruff format` and `ruff check`. `ios/DotTests/IconTests.swift` (4 cases) is the part only the phone can
say: every case has an image, and **every icon, drawn through the system's renderer, draws something and draws it all in the
colour it is given** (74 icons, in the system's red, none black): the SVGs the script writes are read by CoreSVG as they are, with no
`currentColor`. `ToolGlyphTests` follow the web's icons for Dot's tools and read another harness's names by their words.
`xcodebuild test` on the iPhone 17 Pro simulator (iOS 26.5), the whole suite: 382 tests, 0 failures (377 before this item).
Screenshots of the list and of a chat at work against a canned daemon (workspace `ios-look-shots/`): the icons read, at the
sizes the SF Symbols had.
Not checked: the context menus' and swipe actions' icons at the size the system gives them (the image says 20 points; a menu
was not opened in the simulator by this item); iOS 18's look; the Live Activity's marks, which stay the system's.
