### 1711. A run's rewrite of the owner's note waits for the owner, and the owner's words keep reaching every run

**Status: done (2026-11-24).** The audit of 2026-11-24 (A2, D1) found that `memory_update` let any run take over a note
the owner wrote or approved: on the owner's Mac a run that had read outside content rewrote two pinned character notes on
2026-11-18, they took its mark, and none of the ~700 runs since was handed them, while the Memory page still showed them
pinned. A run's rewrite of the owner's own `core` note made the run its author, so it no longer went to every run.

What must hold (taint exists so that untrusted content cannot write itself into every later run):

- (a) A note the owner wrote or approved (written by them, pinned, or corrected on the Memory page) keeps reaching runs
  as it stands.
- (b) A run's rewrite of such a note never replaces the owner's words: it becomes a proposal the owner takes or drops
  on the Memory page, marked "From outside content" when the run had read some; it is handed to no run until taken.
- (c) A clean run's rewrite of a note that is not the owner's is written in place, as before.
- (d) Nothing a tainted run writes reaches every run without the owner: its rewrite of a run's note keeps marking the
  note (never a start note), and its proposal reaches runs only when the owner takes it, which vouches for the words
  as the owner's own edit always did.
- What only asks: nothing new. `memory_update` keeps its policy (`persistence`, which asks in a tainted run outside
  yolo and free); a proposal is the tool's answer, never a question or a refusal, so a yolo or free run asks nothing
  new and is denied nothing it was allowed.

What changed (`store/db.py`, `store/models.py`, `memory/service.py`, `tools/memory.py`, `server/routes_data.py`,
`server/views.py`, `static/js/memorylife.js`, `static/js/views/memory.js`):

- Five nullable columns on `memories` (`proposed_content`, `proposed_tags`, `proposed_by`, `proposed_tainted`,
  `proposed_at`), added as the other later columns are; `MemoryRecord.proposed` (`ProposedChange`).
- `Store.update_memory` decides in the write itself: on a note the owner wrote, pinned or corrected it only sets the
  proposal (the newest run's in place of an older), else it rewrites as before. It returns `MemoryRewrite(record,
  proposed)`; `memory_update` answers "Proposed: … waits for them on the Memory page" with the note as it stands.
- `take_proposed_change` (the owner's edit with the proposed words, which vouches for them) and `drop_proposed_change`,
  both refused with 409 unless the proposal is the one the page showed (`at`); `GET /api/memories/proposed`,
  `POST /api/memories/{id}/proposal/take|drop`.
- The Memory page: **Changes tasks proposed** at its head (the note now, the proposed words, the task, "From outside
  content", **Use it** and **Drop**); a note with a proposal says "Change proposed"; a pinned note a task wrote while
  reading outside content says "Not handed to tasks" (pinning does not vouch for words; Edit and save does).

Checked: `tests/unit/test_memory_owner_notes.py` (the audit's two repros, (a)-(d), take, drop, a stale decision; five of
seven fail without the store's decision), `tests/smoke/test_memory.py` (the real `memory_update` tool answers
"Proposed:"), `tests/smoke/test_memory_lifecycle.py` (the routes, 409 on a stale `at`), the tests whose old contract
changed (`test_memory_owner_edits.py`, `test_memory_saves.py`, `test_memory_embed_down.py`), `test_freedom_contract.py`,
`dotx eval check`, and the Memory page in a browser on a throwaway home, computer and phone width.
Not done: a note a run forgets (`memory_forget`) still goes to the trash, the owner's notes too; the owner restores it.
The owner's two pinned notes that are tainted today are not changed by this: the owner vouches for them (Edit, Save).
