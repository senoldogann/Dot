### 1282. A standby model with a small window takes the run over with the tools it holds

**Status: done (2026-11-21).** Dot's own record showed runs that failed with "the model's window is too small for the
system prompt and the tool definitions", ten times. Eight were runs started on a local 64k model (`window` 65 536,
budget 49 152, a fixed prompt of 115 662 tokens for 219 tools) before item 1211 made such a run carry the tools its
window holds. The rest were not: the run's own model had spent its usage window, the same local model was the only
standby, and the move to it measured the prompt with every tool, so the model was passed over and the run failed with
nothing done, though a run started on it would have worked.

What changed: a standby model is measured with the tools its window holds (`held_tokens`, the measure of
`_fit_tools`), and once the run moves there it leaves the others out the way a run started on it does: the owner's
own servers' tools first, the largest first, `finish`, `use_tools` and `ask_user` kept, and the groups, the registry,
the prompt and the tools the run knows of built again for what stays. A model whose window does not hold even those
is passed over as before. A step routed to the fast model or a helper still needs room for every tool, as it is sent
the run's own prompt.

Checked: `tests/smoke/test_helpers.py`
(`test_a_standby_model_whose_window_holds_only_some_of_the_tools_takes_the_run_over_with_those` failed with the
record's error before the change and passes after it), the rest of that file, `tests/unit/test_fit_tools.py`,
`tests/smoke/test_scaffold.py`, `test_model_wait.py`, `test_context_budget.py`, `dotx eval check`.
