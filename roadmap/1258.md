### 1258. The desktop app checks every package hash when it installs Dot

**Status: done (2026-11-20).** Item 694 pinned the versions `uv.lock` recorded and said, in the docs, that a file PyPI
replaces under the same version number is not caught: `uv tool install --constraints` takes the versions and ignores
the hashes (tried then with uv 0.13.4, the uv the app carries). The install and the upgrade of the app now refuse an
artifact whose hash is not one of those.

**The change.**
- `desktop/release.sh` writes `requirements.txt` into the app's Resources (beside `tools`, named in `tauri.conf.json`,
  ignored by git, an empty stand-in from `build.rs` in a development build) with the `uv` the app carries:
  `uv export --locked --no-dev --no-emit-project --no-header --no-annotate`, so every runtime dependency keeps the
  hashes and the markers of `uv.lock`. It builds this version's wheel (`uv build --wheel`, the same build the tag's
  publish runs) and appends `./dotagent_macos-<version>-py3-none-any.whl --hash=sha256:<the wheel>`. A requirement with
  no hash, a path that is not that wheel, or an empty export stops the release. The wheel is copied once and compared
  with the copy in the built app; it is not built a second time. The old `constraints.txt` is no longer written.
- The installer (`installer.rs`), when that file is present and names this version's wheel, makes the environment at
  the same path as before (`runtime/uv-tools/dotagent-macos`, so a launchd job already installed keeps its Python) with
  `uv venv --allow-existing` and then `uv pip sync --require-hashes --default-index https://pypi.org/simple`, run in
  the app's Resources so `./<wheel>` is the wheel the app carries. An upgrade adds `--reinstall`, so packages an older
  app installed without checking hashes are fetched and checked. A file that does not pin this version's wheel, or a
  wheel the app does not carry, stops the install; it does not fall back to `uv tool install`. A development build,
  whose requirements file is empty, still uses `uv tool install`.
- `runtime/bin/dotx` is the link it was: the hashed install puts the script in the environment and the installer points
  the link at it.
- After a failed upgrade the environment is started once, as before. When it does not start, the previous version is
  installed again under the same dependency versions (`uv pip install --constraints` of the requirements file with the
  wheel line left out), and without them only when uv says that version cannot be installed under them. This put-back
  does not check hashes: `uv pip install --constraints` ignores them (tried with uv 0.13.4), and the app carries this
  version's wheel, not the older one's, which comes from PyPI. The install and the upgrade do check them.

**Checked.** On the previous installer the new test
`a_requirements_entry_with_a_wrong_hash_fails_the_install` failed: the install finished (`Phase::Done`) and the command
was `uv --no-config tool install --python 3.13 dotagent-macos==0.1.0`, with no `--require-hashes`. After the change the
same test passes, and `cargo test --lib` in `desktop/src-tauri` passed 93 tests (the crate was compiled on Linux by
leaving out three macOS-only window calls that were put back before the commit; the desktop job runs these tests on
macOS). `tests/unit/test_hashed_requirements.py`, against uv 0.13.4: a requirements entry with a wrong hash makes
`uv pip sync --require-hashes` exit non-zero and say "hash mismatch", the right hash installs the wheel, and
`uv pip install --constraints` installs despite a wrong hash. The checker `release.sh` runs over the requirements file
accepts a hashed file and refuses one that has a line with no hash. `bash -n desktop/release.sh`, `cargo fmt --check`.

Not done: `docs/daemon.md` still describes `uv tool install --constraints`, because an open pull request already has
that file; [Releasing](../docs/development.md#releasing) is the page this change updates. The release script was not
run (it builds and notarizes on a Mac). A real install on a Mac, and that the wheel `release.sh` builds there matches
what a person gets, were not tried here.
