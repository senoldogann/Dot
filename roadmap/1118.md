### 1118. A run whose goal a learned skill was made from reads that skill as its first step

**Status: done (2026-11-10).**

Measured on the owner's store (2026-11-10, last 7 days): 42 of 143 runs of the owner's own (26 of them a schedule's
firing) had a goal word for word the same as a run a learned skill was distilled from, and 3 of the 42 read that skill.
In 136 runs of 3 days the `skill` tool was called 7 times. The instructions list the skill and tell the model to read
a matching one first; the model (deepseek-v4.1-flash) does not. A ranking by meaning alone is no sure sign: over the 50
runs a learned skill was made from, its own skill was the closest by bge-m3 in 15, and of the 11 whose closest skill
stood at 0.65 or more, 9 were right.

What holds: a run of its own (no parent), of a mode that acts (not `chat`), not resumed, whose goal (stripped) is at
least 80 characters and equal to the goal of an earlier run in the `runs` of an active learned skill it is offered,
reads at most two such skills (the newest updated first) through the `skill` tool before its first step: the call and
its result are recorded as any call (the timeline shows it, the read is dated, the run's use is counted for the skill's
retirement, and a skill marked as made from content third parties can author taints the run as reading it does). A
skill whose instructions the run's history already carries is not read again. A goal shorter than 80 characters
("Onaylıyorum") says too little to stand for a task.

The red-team review of the approach (an independent agent) found that tainting from the start could hold a schedule
that sends or posts and ran untainted before: all 42 runs measured were tainted anyway (each read mail or a page), so a
marked skill is read too. A message with tool calls and no model reply is what a move to a standby model already sends,
so no codec meets a new shape. The read does not count as an acting step of the watchdog or a use of tools that turns a
text-only reply into a nudge. A run on the Claude plan or on OpenCode's agent does not go through Dot's loop and reads
a skill only when its model calls for it; none of the 42 runs was one.

Checked: `tests/unit/test_playbooks.py`, `tests/smoke/test_skill_taint.py` (a scripted run of the same goal reads the
skill first, tainted, and the model plays only its own steps), `test_learned_skills.py`, `test_skill_reads.py`.
