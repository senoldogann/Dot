### 623. Dot takes web-research 1.3.1 from PyPI

**Status: done (2026-10-24); needs the owner's look (`pyproject.toml` dependencies, `.github/workflows/audit.yml`).**
The owner's evaluation of the web-research server (7/10, a roadmap of P0 to P2) became its round A, version 1.3.0:
- dates you can trust;
- providers that heal;
- walled pages read another way;
- compact answers;
- the types of sources.

It was released from its repository (`senoldogann/web-research-stack`, pull request #7, tag `v1.3.0`), published to
PyPI by trusted publishing under the owner's account, as 1.2.0 was the same day once the owner added the publisher.

**The independent review of the first push** (REVIEW.md: `pyproject.toml` dependencies and a workflow need a human)
found the server's fetcher checked a host's addresses and then resolved the name again to connect: a DNS answer that
changes (rebinding) could lead its reads to this Mac or the LAN, and 1.3.0's own reads (dates, a walled page's copies)
made that reachable with no address named by a run. Its probes reached a local server and read a token from it. The
fix is the server's, released as **1.3.1** (pull request #8): it connects only to an address it checked in the same
step, on each redirect too; it refuses the IPv6 forms that carry a private IPv4 and the numeric spellings of a host;
its pinned sessions take no proxy from the environment; its workflows pin their actions by commit. Dot takes 1.3.1.

**As built.**
- **The dependency.** `dotagent-web-research==1.3.1` from PyPI: `[tool.uv.sources]` (the repository at a fixed commit,
  item 583) is gone, and `uv.lock` holds the package's hashes. `.github/workflows/audit.yml` exports the whole lock to
  pip-audit, as a requirement with a hash is one it checks. The same lock raises `opentelemetry-api` to 1.45.1
  (Dependabot alert 23), which fastapi and mcp bring.
- **The host lists bind it.** The owner's lists of sites (`[browser] allowed_hosts`, or `blocked_hosts` beyond the
  defaults) bind the addresses a call of the server holds (item 583). Since 1.3.0, two of its features read pages of
  their own accord: the heads of a search's top results for their dates, and another copy of a walled page (the archive,
  another outlet's). While a list is set, Dot starts the server with `WEB_TOOLS_SEARCH_RESOLVE_DATES=off` and
  `WEB_TOOLS_SCRAPE_RECOVER=off` (`mcp/builtin.py`, `host_lists_set`, the one test of "a list is set" that `tools.mcp`
  shares), so it reads no page of its own accord for a date or a walled page's copies. A `web_scrape` with `archive:
  true` reaches `web.archive.org` whatever address it names: while a list is set, that site is judged as an address
  is, and the call is refused where the lists leave it out.
- **What Dot knows of its tools.**
  - The new `web_health` (the state of its search providers) declares itself read-only and runs as a read.
  - `web_scrape`'s new `content_id` names a page the server keeps, to read on from an offset: worked on in the server,
    never sent.
- **The docs.**
  - `docs/extending.md`: the server's tools as of 1.3.0, and the switches with a list of sites.
  - `docs/development.md`: the dependency as it is now, and the audit's whole export.

**Tests.**
- `tests/unit/test_builtin_mcp.py`: the server starts with the two switches off while an allow list, or a blocked host
  of the owner's, is set, and with neither otherwise; the installed server reads the two names Dot sets
  (`WebToolsSettings.from_env`); `archive: true` is judged as a site the call reaches while a list is set. Each fails
  against the code before.
- `tests/smoke/test_builtin_mcp.py`, against the installed 1.3.1:
  - the tools in the server's order, `web_health` among the reads;
  - every string argument judged or known to stay in the server, `content_id` with them;
  - a tool that takes no string named as such.
- `tests/smoke/test_builtin_mcp_page.py`: the tile shows 9 tools.
