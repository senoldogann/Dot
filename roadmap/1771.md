### 1771. DotNext's Models, Scheduled tasks, Rules, Memory and Agents are native, as much of them as a phone is for

**Status: done (2026-11-25).** The owner on DotNext's Settings (2026-11-25): "Why does 'Context, effort and
providers' send me to the web? … Scheduled tasks need an on/off switch of a fitting size so we see at once which is
active. Rules says 'web'. Memory the same. Agents and teams the same." Then the scope cut of 07:30 (PLAN §26, binding):
"show only what belongs on a phone; what is done at the computer has no place there." The test of a feature: the owner,
away from the Mac, needs it to direct, watch, answer or stop Dot's work.

What must hold:
- None of these five pages opens the web page; none offers what §26 leaves to the Mac (chat sizes, providers, the
  night's learning, rules of one's own, the trash, lessons, making agents, their instructions, teams, handoffs).
- Every write is the route the web calls; a refusal to a phone says so with the Mac's place (`PhoneRefused`), and a
  switch the Mac did not take is put back.
- A delete or a forget asks first, as the web does.
- An agent written back keeps what the phone does not show: its tools, its look (a null look would wipe its face) and
  its effort when the new model offers it.

What was built (`ios/Next/Settings/*Pages.swift`, `ModelPicker.swift`, `ios/Next/Agents/AgentsHome.swift`; the old
`AgentPages.swift` keeps the caps):
- Models: the main and fast models, and the code review's model with its reasoning (item 1770), each chosen in the
  §24 picker sheet (owner-refs/ref-model-picker-1/2.png): ✕ and ✓, providers as groups that fold with a count, the ✓ on
  the chosen model, "Default" on Dot's default, a floating "Find a model" field, an Options group with Reasoning. The
  "Context, effort and providers" web row is gone. Dot's default effort and fast mode have no daemon route (the web
  keeps them per browser and per chat, where the composer's chip sets them), so the page has none.
- Scheduled tasks: a switch of the system's size on every row (`POST /api/schedules/{id}/enable|disable`), the name
  opens the edit sheet, the row's menu runs it now (`POST …/run`) or deletes it after a confirmation; no web link.
- Rules: the approval mode tasks start in (`/api/status` `approvals`) with one line of what asks in it, and free mode
  (`/api/policy/free`), which a phone may switch off.
- Memory: the proposed rewrites (Use, Drop), a search, every note newest first with Show more, a note's sheet to read,
  edit its words and tags (`PATCH /api/memories/{id}`) or forget it after a confirmation (`DELETE`).
- Agents (Settings › Agents, the row that opened the web's agents page): the list, an agent's page (role, approvals,
  actions, instructions read), "Chat with …" (its own chat, or `POST /api/agents/{id}/welcome` for its first, then the
  chat opens), and its model (`PUT /api/agents/{id}` with the rest as it was).
- The search finds Agents by its words in both languages; the strings are in Turkish.

Checked: DotEngine's `SettingsDetailTests` (the routes' JSON decodes; the bodies carry every key the daemon requires);
`SettingsLiveUITests` against a throwaway daemon (`scripts/e2e_settings.sh`): the schedule's switch, the code review's
reasoning, free mode off, a note edited, an agent's first chat, each checked on the daemon's side; shots of each page,
light and dark.
