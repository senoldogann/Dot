### 550. The home screen draws Dot's face, at the sizes iOS asks for

**Status: done (2026-10-23).** Asked by the owner: Dot added to an iPhone's home screen still shows the letter "D"
rather than Dot's own logo.

**As built.**
- `static/icons/touch-icon-{180,167,152,120}.png`: Dot's yellow face on its charcoal tile, at the four sizes an iPhone
  and an iPad ask for; `static/index.html` names each at an absolute path, `<link rel="apple-touch-icon">`, so a path
  or a cache of an older page cannot send iOS to the wrong file. The icon and manifest links are absolute for the same
  reason.
- The root names iOS tries by itself stay 180 px files: `apple-touch-icon.png`, its `-precomposed` twin, and
  `apple-touch-icon-180x180.png` with its `-precomposed` twin, all the same face.
- `static/offline.html` names the 180 px icon and the manifest at absolute paths, and `static/sw.js` keeps the 180 px
  icon, the root icon and the manifest in the offline cache.
- `desktop/icons/render.py` renders the four touch sizes and copies the 180 px bytes to the root names, so the icons
  follow the desktop icon when it is drawn again.
- `docs/phone.md` names the four sizes, the absolute paths and the root fallbacks, and says that a web clip added
  before the icon changed keeps the icon it first drew until it is removed and added again (iOS keeps it outside the
  page's cache).

**Tests.** `tests/unit/test_manifest.py`: the page names exactly the four touch icons with their sizes and absolute
paths, each file is the size it claims, the four root names are 180 px, and `offline.html` names the 180 px icon.
`tests/unit/test_server_guard.py`: the launcher's icon paths are public, with Cross-Origin-Resource-Policy
`cross-origin`. `tests/unit/test_static_ui.py`: a reference written from the root ("/favicon.svg") is looked for under
the pages, and every file the page names exists. `tests/unit/test_licences.py` reads the bundled notices. Those unit
test files pass, as do `ruff` and `mypy`. An iPhone itself was not available here: the served icon
was read over loopback and Tailscale (a 180x180 RGB PNG, `image/png`, no auth needed, the guard allowing it), and the
remaining cause of the reported "D" was the web clip's own cache, which the new path and the re-add clear.
