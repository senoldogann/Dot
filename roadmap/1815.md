### 1815. DotNext: the owner's message has the web's actions: Copy, Select text, Read aloud, Edit from here

**Status: done (2026-11-25).** Package W4 of the iPhone rewrite (`ios-rewrite-2026-11-24/P1-gaps.md` §3, PLAN.md §26),
on item 1759's app. Before it the owner's bubble had no action at all (`ChatScreen.swift`'s `.owner` row had no menu);
the web's message sheet (`messagesheet.js`, item 1064) offers copy, select, read aloud and Edit from here (item 282).

What must hold:
- Edit from here calls the web's route (`POST /api/runs/{id}/rewind`, `files: keep|revert`) after the web's question
  (keep the file changes, or undo them too), and the message's words come back to the composer after the newer draft,
  never over it.
- It is offered only where the web offers it: the chat can go back to before the message (`rewindable`), the message
  is the owner's own (not a helper's goal, a resumed run, Dot's note, a reaction's follow-up); greyed, with the reason,
  while a run of the chat works (the daemon refuses then).
- Read aloud speaks on the phone (AVSpeechSynthesizer) in the language the text is written in; nothing leaves the phone.

What was built:
- `OwnerMessageActions` (`Components/MessageSheet.swift`): the system's long-press menu on the owner's bubble with the
  sent time as its header, Copy the text, Select text (a sheet with the words selectable), Read aloud / Stop reading
  (`ReadAloud`, one text at a time), Edit from here with its confirmation and a toast of what it did ("the files put
  back", or that some changed since and were left). One modifier in `ChatScreen.swift`'s `.owner` row.
- The engine's part of package W4 (`DotEngine`): the routes (`Wire/DaemonAPI+Actions.swift`), their models
  (`Contract/ActionsModels.swift`), and the rules, pure and tested (`Sync/MessageActions.swift`: `ownerMessageOffer`,
  `endOffer`, `retryRun`, `modelParts`, `providerTitle`); `RunRecord` decodes `rewindable` and `agent_id`, `RunDetail`
  `resumable` and `cut_off` (optional: a fixture or an older daemon leaves them unknown). `AppModel+Actions.swift`
  makes each call once and hands the screen the failure in Settings' words.

Checked: `MessageActionsTests` (engine: decoding the daemon's own shapes, the offer rules); `ChatActionsLiveUITests`
long-presses a message on a throwaway daemon, taps Edit from here › Keep the file changes and finds the words in the
composer; `scripts/e2e_chat_actions.sh` then reads that the chat has no run left.
