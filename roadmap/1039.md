### 1039. Named browser steps: measured, and not shipped

**Status: rejected (2026-11-07).** The second step of the speed work: more work per model call. 870 of the owner's
1,277 `browser_act` calls in 30 days carried one step, 717 of those a click, mostly into a dialog or the next page,
whose elements have no ref until a new snapshot exists.

**Built (on a branch, not merged).** A step could name its element by role and exact accessible name instead of a ref;
it waited for exactly one such element outside any frame, in fresh snapshots, and acted on it through the ref path (the
secret-field check and every guard of a ref step); a batch went on past a navigation only to named steps with no flag
of the policy, on the same origin, the URL rules enforced right before each, no secret typed on a page the call had not
seen (the red-team review of the design: continuing to another site would have judged spend caps, the pace, the
owner's rules and the approval prompt on the wrong page). The tool's description and the prompt's Browser section said
so, with an example.

**Measured** against item 1040's first baseline (21:05 UTC, the dialog task before the review made its check stricter:
both sides played the same version), the same model and set, 3 attempts each:

| | baseline | named steps | named steps and the prompt's example |
| --- | --- | --- | --- |
| passed | 15/15 | 14/15 (a hyphen, item 1040) | 15/15 |
| model calls a task | 6.0 | 6.5 | 6.5 |
| `speed-apply-dialog` calls | 6.3 | 6.7 | 6.7 |
| single-step acts | 44% | 49% | 45% |
| wall seconds a task | 6.4 | 11.6 | 10.3 (every task slower, the untouched ones too: load) |

The main model did not take the named steps: the dialog task kept its calls and its share of single steps. The change
added 446 tokens to every run's context (26,138 to 26,584), past the budget. It does not beat the baseline, so it is not
shipped (the rule of the speed work, as for the step router).

**What the measures say instead.** On the set a step call is 0.9 s with 118 output tokens; on the owner's runs it is 3.7
s with 596 (step calls of the main model, 30 days), 1.4 s of it to the first token, 100k of 109k input tokens cached.
The owner's time goes to what the model writes: messages and application texts, and 1,077 `browser_eval` scripts in a
month, each written anew. The levers left are on that side: a script the model wrote and checked kept and called again
with parameters (item 893's saved skills), and the model's effort on a browser step; a smaller context saves cost more
than time, as the input is cached.
