### 737. A model's OpenRouter routing: how OpenRouter chooses the provider that serves it

**Status: done (2026-10-27).** **Asked by the owner:** a provider routing setting for each OpenRouter model, as
`[providers.opencode_go] route_overrides` maps a model id to its route. Dot sent no `provider` object, so OpenRouter
chose every model's provider by its own defaults; `:nitro` and `:floor` (item 349, `listed_id`) chose by throughput or
price for one call, and could not name providers, their order, quantizations or a highest price.

**The change.** `config.py`: `OpenRouterRouting` (`sort`, `order`, `only`, `ignore`, `allow_fallbacks`, `quantizations`,
`max_price` with `prompt` and `completion`, each optional) and `OpenRouterConfig.routing`, by model id; a `FrozenModel`
forbids keys it does not know, so a key or a value Dot does not know is a configuration error as it loads.
`defaults.toml`: `routing = {}`, with what it takes and an example. `openrouter.py`: `routing_for` finds a model's
routing, the model's own id first, then the id a variant routes to (as `listed_id`), and `_complete_once` adds it to the
body as `provider` (the fields set alone, `model_dump(exclude_none=True)`), `stream` staying the last key; the shared
`build_chat_body` is unchanged. `provider_errors.py`: `classify_openrouter(..., routed=True)` for a request that carried
a routing: OpenRouter's 404 for a model its privacy settings leave no provider of names the routing too, and its 404
that no allowed provider is left, or none that can handle the requested parameters, names the routing with what the
request asks (a 404 that the model lacks what the request asks, such as image input, is read as before); both stay a
refused access (`ProviderAccessError`), so a run moves to its standby model as after item 361. A request without a
routing is read as before.

**Checked.** `tests/unit/test_openrouter.py`, through the real connector to a stand-in of OpenRouter on this process
(`httpx.MockTransport`; no model is called): a model with a routing sends it as `provider` and one without sends none,
`stream` last in both; a `:nitro` variant takes its model's routing and a variant with its own takes that; an unknown
`sort`, a negative or unknown `max_price` field, an unknown key and a slug list given as a string are configuration
errors, and the example of `defaults.toml` loads; a routed 404 of either kind is a `ProviderAccessError` that names the
routing, through the connector too, and an unrouted one reads as before. Each fails on the code before.
