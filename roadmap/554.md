### 554. The browser and the web tools keep their rules: adopted tabs and popup redirects judged, takeover after a script, stacked encodings capped, private addresses refused, third-party text fenced

**Status: done (2026-10-23).** From the audit of 2026-10-23, the findings of its browser and web areas that a second
reading of the code confirmed (F7, F8, F24 to F28 and F78 to F90). The rules the docs promise for what a run's browser
and web tools may reach, read, and show the model held at the places the audit found open.

**As built.**
- *F7, F24: a tab is judged where it lands* (`browser/session.py`). Every operation that reads a run's tab or acts in
  it asks the URL rules first (`_enforce_landing`): views, find and links, text, screenshots, `browser_act` (before its
  steps as well as after), scroll, wait, upload, a script, a tab switch and the tab that is current after a close. A
  read holds them on either side (`_read_held`). A popup is judged as its chat takes it in (`_leave_refused_popup`:
  reset to a blank page, the opener told), and the tab list does not read the title of a tab on a forbidden address. A
  frame of the page on one is left for a blank page, with a note; a frame that goes there while the page is read fails
  that read. Chrome tells of a popup only once its page answered, and a frame of another site starts navigations its
  own process sends, so the hops of a popup's first redirect and of such a frame reach their server before Dot can
  ask: what they answer is never read.
- *F25: takeover after a script.* Taking a run over (Take over, or from the screen) on a chat in which `browser_eval`
  ran closes the chat's other tabs and opens the current page again from its address (`clean_for_owner`, called by
  `RunManager.take_over` and `take_over_on_screen`): a listener a script left lives in its document, and the owner
  types into one without it. The run's next view says so.
- *F8: stacked encodings.* `web/client.py` reads a body as it comes (`aiter_raw`) and inflates it a piece at a time with
  zlib's `max_length`, gzip or deflate once; more codings, or another, are refused, and the request says `Accept-Encoding:
  gzip, deflate` itself. The SearXNG call reads through it too.
- *F26: private addresses through the browser fallback.* A page read in a scratch tab for the web tools is given back
  only when each document of the way (what Chrome connected to, from the response) and the page it landed on were served
  from public addresses (`BrowserSession._require_public`, `read_page(public_only=...)`, set from
  `[web] allow_private_hosts`); the crawl's reader of the run's own tab holds the landed page to the same rule.
- *F27, F86: the crawl.* A page that cannot be decoded or opened as a PDF is left out with its reason; the reads of a
  level run in a `TaskGroup`, so one that fails cancels the others; a level the page limit cuts goes on at its own depth
  and what it linked to waits for it (and is counted in the addresses left).
- *F28: the fence.* The crawl index's lines that quote pages (addresses, titles clipped to 200 characters, addresses
  left out, robots.txt's) stand in a `<web_content>` fence, as do the links listed for a missing page and the JSON of
  `web_extract`; a crawl that read nothing is untrusted too.
- *F78: host lists.* `host_matches` reads entries as it reads hosts (`browser_host`: Unicode or punycode, a trailing dot,
  a numeric address).
- *F79: the pool.* `BrowserPool.retire_other` closes the session kept for the mode the main one is switching into
  (`POST /api/browser/mode`).
- *F80: docs.* The browser page says `browser_fill_login` is the one other way a password reaches a page, with its limits.
- *F81: card expiry dropdowns.* The field marking reads a `<select>`; a `select` step into one is refused outside yolo,
  screenshots cover it, a script is kept off its page, and the view does not mark the chosen option.
- *F82: Incognito.* `_let_go` empties it whatever the context, unless a Chrome holds the folder.
- *F83: the teach binding.* A recording keeps at most 400 steps and the skill writer is told when it is full.
- *F84: import-chrome.* `import.lock` in the profile folder (`flock`): the import holds it exclusively while it swaps
  files in, Dot's own Chrome holds it shared while it starts; each refuses at once under the other.
- *F85, F88, F89: search.* An Anthropic answer without a search result is an error, so the ladder climbs on; Ollama's
  429 benches the rung; the answer memory is keyed by the rungs and keeps the count asked.
- *F87: `web_extract`* ends at its own time with the extractions made; the sources not reached are listed.
- *F90: PDF pages.* A page with no width or height is refused as `InvalidValueError`, not divided by.
- Docs: `browser-and-computer-use.md`, `runs.md`, `safety.md` say all of the above where it was promised otherwise.

**Left.** F24's structural fix, holding each new target until its guard is up (`Target.setAutoAttach` with
`waitForDebuggerOnStart` beside Playwright's own), is not made: it is a second client of a handshake Playwright runs,
and what it would add is the hop's request not being sent, never what is read. F83's forgery stays possible (the page
can call the binding): the cap bounds it, the owner reads the steps and the skill, and the docs say so; an isolated
world for the recorder is a rewrite of it. F26 judges what a page was served from, not the request a redirect of it
made Chrome send. F78 does not refuse an entry no host can be read from at load: it names nothing.
