### 962. A run that read outside content does not put a project's change live unchecked

**Status: done (2026-11-03).** **Found** by the pre-push review of a note from a chat of Dot's own initiative to the
owner's chat (item 963): a yolo run that read content third parties can author ran `fly deploy`, `wrangler deploy`,
`firebase deploy`, `vercel --prod` or `netlify deploy --prod` (the shell guard's `release` flag and nothing else)
without the review model's check or the owner's question, though a push to main or a merge of a pull request (`upload`)
had both. The owner chose on 2026-11-03 to close it in the policy.

**What must hold (the approach, before the code).**
- A step that puts a project's change live (`release`) reaches beyond the Mac as an upload does: in a run that read
  outside content it is treated as every other flag of `TAINT_ESCALATION_FLAGS` is. In yolo the review model checks it
  first (`checked_when_tainted`, item 525) and its refusal stands; in the other modes a preset or a rule of the owner's
  that would let it through asks (`source: taint`), as for an upload.
- Nothing changes for a run that read nothing from outside, nor for a chat of Dot's own initiative, whose release asks
  in every mode already (item 850).

**What only asks.** The shell guard's reading of a command is unchanged: a deploy command it does not name `release`
(a script of the project's own that deploys, say) is not caught by this, as the docs of the guard say of what it does
not read.

**Built.** `policy/types.py` `TAINT_ESCALATION_FLAGS` holds `release`, and `_TAINT_CHECKED_FLAGS` takes it from there.

**Checked.** `tests/smoke/test_taint_check.py`: a yolo run that read outside content has `fly deploy` checked by the
review model, whose refusal stands; a run that read nothing does it. `tests/unit` policy tests.
