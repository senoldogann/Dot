### 2090. The lint of a skill Dot writes

**Status: done (2026-11-28).** Owner 2026-11-26, from Uber Engineering's "How Uber Evals 1 Million Agent Skill
Invocations a Month": a skill a later run can follow and check itself against has numbered steps, one objective and a
check each, and a table of failures and fixes, where "try again" is no fix.

Measured first, read-only on the owner's store (2026-11-28): 125 learned skills, 1,081 numbered steps; 699 steps (65 %)
say no check of their own, 167 (15 %) chain a second objective with "then", and none of the 125 has a table of
failures and fixes. The learned skills are written in English and Turkish, so the lint reads both.

What must hold: the lint never refuses, rewrites or retires a skill; it only says what a skill lacks. What it reads are
words, so it is a measure, not a gate: a step that says "confirm" is counted as checked whatever it confirms.

What changed:
- `skills/lint.py`: `lint_skill(text)`, pure, the rules `no_steps`, `step_without_check`, `step_with_two_objectives`,
  `no_fix_table`, `retry_is_no_fix`, with English and Turkish words.
- A learned skill is linted as it is written: the `playbook_written` event lists what it lacks under `lint` (and the
  log line counts it).
- `dotx skills lint [NAME]...` lints the skills named, or every skill and active learned skill, and exits 1 when one
  lacks something.
- Docs: `docs/harness.md` "The lint of a skill", a line in `docs/extending.md`.

How it was checked: `tests/unit/test_skill_lint.py` (each rule, a Turkish check word, a retry-only fix),
`tests/smoke/test_learned_skills.py` (the event carries the lint), `tests/unit/test_cli_parser.py`; the lint run over
the owner's 125 learned skills read-only for the numbers above.
