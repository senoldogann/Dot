### 915. A request of its own sent while the chat works starts at once in a chat of its own

**Status: done (2026-11-01).** **Asked** by the owner (2026-11-01): of the proposals drawn from DeepSeek Harness's
"Super-agent" article, the router first. The article splits a router, which talks to the person and hands work out,
from workers, which do it, so that a new request never waits for the work under way; with one session, a model left to
decide handed work out in none of five runs, and a request took about twice as long. Dot's chat was that one session:
a message sent while its run worked waited in the chat's queue until the run ended.

**Built.**
- `agent/busy.py`: the fast model (`[models] fast`) is asked one question, the request under way and the new message
  in fences, and answers `separate_request` with a yes only when the new message clearly stands on its own. A doubt, a
  model that fails or does not answer in 12 seconds, or no verdict is a no.
- `RunManager.start_beside`: in a chat of Dot's own with the owner where a run works (not an agent's, a campaign's, a
  delegated run's, a team's, which works as the team, or one held by a ✋), a message judged a request of its own starts at once in a chat of its own, with
  the choices it was sent with, and the run at work gets a `started_beside` event.
- `POST /api/threads/{id}/queue` asks it first for a message with no agent, no one-message level and no picks, and says
  `beside_run_id` and `beside_thread_id`, also to the same message sent again with its key; the rest is queued as before.
- The chat shows *Started in a chat of its own* with the request's words, a link to its run (`besideLine`), on the run's
  page and in the history of the chat; the composer's toast says so, with Open.
- A run that ended while the fast model answered leaves the chat free: the message is queued there and starts at
  once. The queue says *Sending…* while the fast model is asked.
- `[agent] busy_parallel` (true; false queues every message). Evals leave it off: an attempt sends none, and a test of
  the queue means the queue.

**Left for later.** A message that comes by iMessage still waits in the queue (its chat is the channel's); the answer of
the new chat is not yet repeated in the chat at work.

**Checked.** `tests/smoke/test_busy_parallel.py`, a real server and its queue route, the run at work held by a gated
model: a request of its own starts at once in another chat, the chat at work has the line, the fast model was shown
both messages; one that is part of the work is queued, as is one the fast model failed on and one with picks, which is
not asked about; the same message sent again with its key says the same chat; a team's chat at work keeps its message in the queue; with
the switch off every message waits and nothing is asked. The queue's own tests are unchanged.
