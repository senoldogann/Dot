### 652. The button that adds a reaction shows on the message the pointer is on

**Status: done (2026-10-25).** The owner asked that the smiley under each of Dot's messages show only when the pointer
is on the message: under every message of a long run it was one more mark to read past.

**The change.**
- `app.css`: with a pointer (`hover: hover` and `pointer: fine`), `.react-button` is transparent until the pointer is
  on its message (the answer, a message said in a run, a turn before the run), the keyboard is on it, or its palette
  is open. It keeps its place, so nothing moves when it shows.
- The reactions that stand still show as chips, always.
- A touch screen has no pointer to rest, so it shows the button always: hidden there, a reaction could not be given.
- `docs/runs.md` says so.

**Checked.**
- `tests/smoke/test_reactions_page.py`, wide in Chrome: the button is unseen with the pointer away, seen on the
  answer, and stays seen while its palette is open with the pointer away. On a phone in WebKit it is seen at once.
  The 18 tests of the file pass.
