### 1669. A helper's report wakes a chat whose newest run a restart or the Claude plan's limit ended, never your Stop

**Status: done (2026-11-24).** A helper that ends while no run works in its chat starts a run that reads its report
(item 1351), but only when the chat's newest run ended done. An autonomous chat whose lead was cut by a restart of Dot,
or ended by the Claude plan's usage limit, then waited for the owner's next message with the report unread, though
nothing of the owner's had ended it (R-f H2 of 2026-11-24).

What changed (`agent/manager.py`, `agent/helper_reports.py`):

- `wake_for_helpers` also wakes a chat whose newest run did not end done when `_wakes_after` allows it: the daemon's own
  end cut that run off (`cut_by_restart`: a stop, a restart or a crash), or its `run_finished` error is of the kind
  `plan_limit` (`plan_limit_of`, item 1206) and the plan's window has reset, or the plan named no reset time.
- A window that resets later sets one timed wake for the chat (`_wake_at`): 30 s after the reset it tells the chat its
  helpers' reports as a helper's end does (the run at work reads them, or a run is started). The daemon's end cancels
  it; the reports stay kept in the store, so the next start tells them.
- The owner's Stop, the emergency stop and every failure of the run's own still leave the reports to the owner's next
  run, as before.

Checked:
`tests/smoke/test_helper_wake.py::test_a_helpers_report_wakes_a_chat_whose_newest_run_a_restart_or_the_plans_limit_ended`
(seven cases: a stop of the daemon, a crash, the plan's limit with a passed reset and with none named wake the chat; the
plan's limit with a reset ahead sets the timed wake and starts nothing; the owner's Stop and a failure start nothing).
With the old condition put back four of them fail, and the timed wake's case too. `uv run dotx eval check` passes.
Not done: an OpenCode Go usage window (`ProviderWindowError`) that outlasts `[agent] quota_wait_s` is stored as a
`lasting` failure, which is not told from other failures, so it does not wake the chat.
