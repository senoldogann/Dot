### 535. Eighty-four more plugins, each tried as Dot reaches it

**Status: done (2026-10-22).** Asked by the owner, with four screenshots of another agent's plugin marketplace: as many
plugins as can be added, those of the screenshots and more, each one known to work.

**As built.**
- `mcp/catalogue.py` gains 84 services (142 in all), and Customize › Plugins lists 159 (78 before):
  - 50 sign in with the owner's account, among them Vercel and Dropbox, which turned Dot away before;
  - 10 are open to all: grep.app, Svelte, Astro Docs, Nuxt UI, OpenAI Docs, AWS Knowledge, Socket, Excalidraw,
    Kiwi.com and CoinGecko;
  - one takes a key at its address: Apollo GraphOS (`x-api-key`);
  - 23 start on this Mac: 15 with no key (DuckDB, MarkItDown, Time, shadcn/ui, Magic UI, Next.js DevTools, Shopify
    Dev, Xcode's own `xcrun mcpbridge`, XcodeBuildMCP, Kubernetes, Azure, AWS, Firebase, Convex, Snyk) and 8 with
    one (MongoDB, Pinecone, PagerDuty, HubSpot, Mailgun, Kagi, Alibaba Cloud, DingTalk), each key kept in Dot's `.env`
    and handed to the server in its environment, never in its arguments.
  From the screenshots: Sourcegraph, Vercel, MongoDB, DuckDB, Apollo GraphQL, Alibaba Cloud, DingTalk and the Chrome
  DevTools, Playwright, Postman and Context7 Dot had; Redis waits (below); the rest are skills and agents of that
  agent's own, or apps of China's market with no MCP server to reach.
- **How each was tried.** One that signs in went through Dot's own sign-in as far as the service's page: the MCP
  library's OAuth client, with the metadata Dot registers with (`_client_metadata`) and its callback on 127.0.0.1,
  found the authorization server, registered Dot and was shown the sign-in or consent page; nothing signed in.
  Buildkite's, WordPress.com's and beehiiv's pages stand behind a check of the browser that a browser passes; Tally's
  address is `api.tally.so`, as `mcp.tally.so` answers a POST with a 301 the client does not follow. One open to all,
  and every one started on this Mac, was started by `dotx mcp list` in a throwaway home (each server with a HOME of its
  own there, a key a placeholder) and listed its tools; Xcode's bridge lists its 53 without Xcode open, and Kubernetes
  needed a placeholder kubeconfig.
- **Left out, with why** (the catalogue's docstring): Canva ("Unsupported client"), Semgrep, Replicate and Otter (an
  issuer with a slash the address lacks, which the library refuses), Gamma (no callback on 127.0.0.1), Railway
  (registration turned off), PlanetScale, Make and Coda (a client with a secret only), Asana, Box, HubSpot's and
  PagerDuty's own servers, Smartsheet, Zendesk, Xero, Render and DocuSign (no registration), QuickBooks (it refuses a
  client that is no browser), Storyblok's open server (no tools), Bright Data's (a schema nested past what Dot reads),
  Postgres MCP Pro (it fails to start with the current MCP library), the open servers of Gorgias and Retell (by their
  tools, Gorgias's is its own team's, and Retell's calls take a key it names no way to pass), and six deprecated
  packages. HubSpot and PagerDuty come in by their local servers. Redis, ClickHouse, Neo4j and Qdrant start, but each
  takes an address and a user besides its password, which the page would keep as secrets: they wait for settings of
  the catalogue that are not secrets (the pre-push review found it). Square lets Dot register, but its tools take
  payments and no flag marks a payment made through an MCP tool yet: it waits for that flag.
- **DuckDB** keeps a database in memory, which its server opens only to read and write (it refuses one in memory to
  read alone, tried). A query reads and writes the files it names and may attach another database; its query tool is
  declared as one that acts, so the policy weighs each query, and the server's own tool to switch databases is left
  out (`--allow-switch-databases`).
- **The first start.** `npx` and `uvx` fetch a package on its first start, which took 52 seconds for Firebase alone and
  more than five minutes for MongoDB with forty others at once, on a cold cache; a server has 60 seconds. The try that
  adds a server started on this Mac now gives it `FIRST_START_S` (five minutes, `first_try` in `server/routes_mcp.py`);
  the server kept keeps its own limit, as a start of the daemon waits for every server, and finds the package cached.
- **Marks.** 35 logos from gilbarbara/logos at the commit the others came from, 15 symbols of Simple Icons 16.35.0
  (HubSpot's and Sanity's for their wordmarks, Next.js's as gilbarbara's file holds a `<use>`, DuckDB's in black as
  its yellow does not show on the white tile), and letters or an icon for the 30 with no logo (Cal.com among them: its
  symbol is its wordmark, too small to read in a tile, as its screenshot showed); the folder's LICENSE names each.
- **Checked again later.** `tests/smoke/test_catalogue_reachable.py`, marked `internet`, checks the whole catalogue by
  read-only requests, without registering anything: a service that signs in answers 401 and its authorization server
  registers a client without a secret (Supabase, GitLab, Miro and Heroku do without saying so) with PKCE S256, one open
  to all answers its `initialize`, one at an address with a key is there, and a package is on its registry, not
  deprecated, with a program to start. 141 cases pass.
- `docs/extending.md` lists them, what each server started on this Mac uses (a kubeconfig, `az login`, `~/.aws`, an
  open Xcode, the files a DuckDB query names), why Redis, ClickHouse, Neo4j and Qdrant wait, and the first try's five
  minutes.

**Tests.** `tests/unit/test_mcp_connect.py`: the try that adds a server started on this Mac waits five minutes and the
server kept does not, one at a URL is left as it is; a catalogue's command is `npx`, `uvx` or `xcrun`.
`tests/unit/test_plugins_directory.py`: each listing's ways name catalogue entries, each logo is a safe SVG named in the
LICENSE; Vercel is tried. `tests/smoke/test_catalogue_reachable.py` as above.
