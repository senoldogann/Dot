### 614. What Dot learns is not lost to a model that answers in words, or leaves a field out

**Status: done (2026-10-24); needs the owner's look (`agent/review.py`).** Checking that the self-improvement works,
item 613's numbers and the owner's log showed that the learning roles lost their work to the shape of an answer:

- The harness's step, run by hand on the owner's Dot, failed at once: "the review model did not call propose_harness".
  The review model (`ollama:gemma4:cloud`) had written its answer as JSON in a code fence instead of calling the tool.
- The log held 74 unusable answers of `write_playbook`: 21 of them left the description out (`description: Field
  required`), and 11 called no tool. Nine skills were lost. Claude models answered `propose_lessons` in text 13 times.

**As built.**

- **A skill without its description keeps the first sentence of its "When"**, cut between words to 200 characters,
  which says the goals it fits as the description would (`PlaybookDraft._description_from_when`). A description the
  model wrote is kept. Without "When" the answer is still refused and asked again.
- **A learning role's answer given as text.** When a model calls no tool and its whole text is one JSON object (in a
  code fence or not, or a call that names the tool, `{"name": ..., "arguments": {...}}`), the object is read as its
  call, validated as a call is, and logged (`review_answer_from_text`). This holds only for the roles that write or
  judge what Dot learns: lessons, skills (write and revise), the owner section, the outdated and merge judges, the
  skill overlap judge, and the harness's proposer, composer and experience writer (`_TEXT_ANSWERS`).
- **Gates still need the call.** The roles that let an action happen answer by their call alone: the review of a step,
  the goal's verdict, the advice to a run at work, a rule drafted from the owner's words, the answer selected, and the
  vetting of lessons. A model reading a page could quote the page's JSON, and a quote is no verdict. Words around a JSON
  object are no answer for any role.
- **The docs.** `docs/extending.md` (learned skills) and `docs/harness.md` (the harness's roles) say it.
- **The independent review (REVIEW.md: `agent/review.py` needs a human).** It found no way to make a gate take a text,
  and three faults of the text path, fixed:
  - the code fence's pattern backtracked on blank lines: a fence followed by 32,000 of them and no end held the
    daemon's loop for four seconds, quadratic in their number. The fence's first line now ends at its first line
    break with only spaces and tabs before it, and a text longer than 100,000 characters (a verdict is a few thousand)
    is not read;
  - the text was parsed with `json.loads`, which a nesting past the interpreter's recursion crashed (the writer's run
    recorded "playbook crashed"); it is read by the strict parser of a tool call's arguments, `parse_json_object`;
  - the description taken from "When" was cut at character 200, inside a word: a secret straddling the cut would keep
    its first part, as the masks match a secret whole. It is cut between words, and a first word past 200 characters
    leaves the description out (asked again).

**Tests.** `tests/unit/test_review_lenient.py` (+8, two of them over several inputs):

- the description from "When" (two sentences, blank, long, kept, refused without "When"), and cut between words;
- a skill answered as bare, fenced and wrapped JSON;
- JSON among words still asked again, and each of the six gates refusing a bare, a fenced and a wrapped answer;
- a fence that never ends, after line feeds, CRLF, spaces or tabs, refused in under a second;
- a text past 100,000 characters, and a nesting of 10,000, no answer;
- the writer keeps a fenced answer at the first ask.

Each fails against `review.py` before (the four fixes of the review were each checked so: the old line put back, the
test fails).
