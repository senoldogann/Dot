### 750. A name that fits two running copies of an application, and bringing the right copy forward

**Status: done (2026-10-27).** **Found** by the review of computer use the owner asked for: Dot's own Chrome is the real
`/Applications/Google Chrome.app`, so the owner's Chrome and Dot's are two apps with one name and one bundle id.
`find_app` broke a tie only with the Chromes of Dot's browser (`chrome_pids()`, which holds the pid of every browser
session, so both once an `own` and a `user` session exist, or neither) and otherwise raised "use the pid or the bundle
id", which the bundle id cannot satisfy; it raised even when the conversation already worked in one of them. Bringing a
running application forward fell back to `open -b <bundle id>`, which Launch Services may resolve to the other copy.

**The change.** `apps.find_app` (and `require_app`, `open_app`) breaks a tie in order: the pid the thread works in
(`state.pid`, or the batch's application for an `activate` step), then the one of Dot's browser when only one is; else
it raises "use the pid of the one you mean" with every candidate and its pid, and whether a Chrome Dot works in.
`apps.activate`, when another running copy shares the bundle id, asks the running process (`NSRunningApplication` by
pid, unhidden, activated) to come forward, and starts through `open -b` only a process that no longer runs; one copy
alone keeps `open -b`, which brings an application forward from Dot's background process, where the process's own
activation may be refused (macOS 14 and later); `desktop_open_app` no longer asks Launch Services to
reopen a window for an application whose bundle id another running copy shares.
What is in front, or has a window on screen, does not break the tie: the code review of the change found that it moves
between a batch's review and its run, which could then resolve the name to the other copy. An `activate` step brings
forward the copy its inspection resolved (`_activate` resolves with the same arguments and refuses another pid).

**Checked.** `tests/unit/test_desktop_apps.py`: each rung of the order, a thread pid that fits no candidate, the error's
wording, a path that fits two copies, `_pick_app` with a thread's pid, and activation by pid with `open -b` left for a
process that is gone and for an application of which one copy runs. They fail on the code before.
