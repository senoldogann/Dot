### 1319. The web tools' "public only" rule is applied before the browser sends a request, and watch_video walks its link's redirects first

**Status: done (2026-11-22).** (a) The rule that the web tools reach the public internet only was applied to a page the
browser had already fetched (`_read_page` read what Chrome connected to, `_renderer_for` the address the tab landed on):
the request to a private address, a redirect hop to `127.0.0.1`, a picture at the metadata address, had gone out already.
(b) `watch_video` checked the first host of a link; yt-dlp then resolved and followed the redirects by itself.

(a) In Dot's own Chrome, `BrowserSession` keeps the pages a web tool holds to the rule (`_public_only_pages`): the
scratch tab of `read_page(..., public_only=True)`, and the run's tab for the duration of
`open_url(..., public_only=True)`, which `web_crawl`'s renderer now asks for when `[web] allow_private_hosts` is off.
Every request of such a page the tab's Fetch guard reaches (`_answer_paused`: first request, each redirect hop,
resources, those of a frame Chrome keeps in the page's own process) and the first request of every frame it does not
reach (the context's route, `_on_request`) is answered after
`_not_public`: the host's addresses are looked at (`web.addresses.unread_or_non_public`, kept 30 s per host) and a request
whose host is, or resolves to, a private, loopback, link-local, shared-carrier or metadata address is failed as blocked by
the client before it is sent; so is one whose address cannot be read (no answer, no address, over 5 s): what is not known
to be public is refused. A refused navigation is kept as a refusal, so the call ends in the `ForbiddenUrlError` the other
refusals end in, with the address and why. The check after the read (`_require_public`, the connection Chrome made) stays.
One limit, measured (2026-11-22, `test_a_redirect_out_of_a_frame_of_another_site_is_not_reached_by_the_rule`): a frame
of another site is a target of Chrome's of its own, which the tab's guard does not reach, and the route sees only its
first request, so a public page can make a redirect hop of its frame a private address, and the check after the read
(the page's own address and the connection Chrome made) does not look at it. The docs say so (`docs/safety.md`,
`docs/runs.md`); a service worker's requests are not looked at either, and whether the route sees them is not verified.
Closing it needs a Fetch session on every frame target before that frame's first request, which Playwright's
`new_cdp_session(frame)` gives only after the frame exists; it is not in this item.
Nothing else changes: a tab of the browser tools is in no such set, `browser_open` passes no `public_only`, and in attach
mode (whose requests Dot does not answer) only the later check applies. A public host that cannot be resolved by Dot is
now a refusal ("not known to be public") instead of Chrome's name-not-resolved error, for these reads only.

(b) `watch_video` follows the link's redirects through the checked `WebClient` (`_hops_are_public`: one GET, one byte
read) before yt-dlp starts, and refuses the link when any hop connects to a non-public address, and when the chain could not be
walked to its end (more than the client's six hops, a hop the rules on addresses turn away, a hop that cannot be
reached: `WebError.hops_followed` says whether the failure was the link's own first request or a later hop); with
`allow_private_hosts` on nothing is probed. Only a failure in transit of the first request (a timeout, a connection that
cannot be made) is logged and leaves the link to yt-dlp, as before: no redirect was seen then. A site that answers the
probe with a status, an error page included, is no failure of it. A
pinned direct URL for yt-dlp is not possible (a site's extractor needs the page's own address), so this is the
redirect-chain pre-check, not more: the addresses an extractor takes out of the page are still yt-dlp's to open. Closing
that would take a checked proxy for yt-dlp, which is not in this item.

Checked: `tests/smoke/test_browser_public_only.py` on real Chrome with local servers that record what they were asked (a
private page, a redirect hop to a private address and a picture at one are never requested; a public page is read; an
unreadable name is refused, with the resolver told to have no answer, so no query leaves the Mac; a hop out of a frame of
the same site is never requested, and one out of a frame of another site is, as the limit above says; `read_page` with
the rule off and `browser_open` still reach 127.0.0.1; the run's tab is held only while the crawl renders, and let go
after; six of the nine fail with `_not_public` made to answer "public" for everything), `tests/unit/test_unread_addresses.py`
(literals, mixed answers, no answer, a late answer, an empty host), `tests/smoke/test_watch_video.py` (a link whose second
hop is on this Mac is refused and yt-dlp never started, the same link without it goes to yt-dlp as written, a first
request that cannot connect leaves it to yt-dlp, a chain of seven public hops before the loopback address and a second
hop that cannot be reached are refused, the two last failing without the change; `allow_private_hosts` probes nothing) and `tests/unit/test_web_private_reads.py`.
