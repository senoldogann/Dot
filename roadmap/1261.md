### 1261. A screenshot the model sees carries the snapshot's refs

**Status: done (2026-11-20).** The code review of 2026-11-19 (its top ten, item 9) found that a browser screenshot
sent to the model has no ref labels, so the model cannot connect what it sees in the picture to the refs in the aria
snapshot it acts on.

`browser/labels.py` draws a small box, the element's ref, at the top-left of each interactive element whose box meets
the viewport, at most 40, in the order of the latest snapshot. An element outside the viewport is not marked, and
neither is one that only lays the page out. The boxes of a frame are counted from where the frame stands. The picture
`Screenshot.data` keeps is the page with no marks, and that is what is stored for the owner; `marked` is what a model
is sent, including a vision model that describes the picture for one that cannot see. Nothing is marked when the tab
has no snapshot yet, and the model is then sent the plain picture.

Checked: `tests/smoke/test_browser_ref_labels.py` (a page's visible refs are marked on their boxes, a heading and an
element below the viewport are not, the raw picture has no marks, and a crowded viewport keeps the first 40).
