### 1561. The freedom contract is a test: a table of every kind of tool decided under yolo and free mode, every tool and every place that asks seen

**Status: done (2026-11-24).** The owner's word of 2026-11-24 10:28 (improve Dot, never break yolo mode and free mode; item
1560 is the page) had no check: the policy tests decide hand-written actions one by one, so a tool whose classification
changed, a tool added later or a new place that asks the owner would bring a question into a yolo run and no test would say so.

What changed: `tests/unit/test_freedom_contract.py` (macOS only like the other tests of the registry, so
`tests/unit/conftest.py` lists it).

- **A table of calls of every kind of tool**, each prepared by its own tool (`RegisteredTool.prepare`, so the action is
  what the tool classifies and not a hand-written `ActionInfo`): shell (a read, a write and a delete in and outside the
  workspace, `curl`, an upload, `git push`, a push to main, a deploy, a secret read, `sudo`, an install, mail), files (write
  and edit in the workspace, the home folder, the system, Dot's own folder and a protected place; there is no tool that
  deletes a file, a deletion is a shell line), the browser (navigate, click, type, submit a form, a message sent with Enter, a
  post, a payment, an upload, a vault login, a script), the desktop (click, type, open an app, AppleScript, mail), the web,
  mail and calendar, schedules, memory, the owner's lists, delegation and teams, the office, campaigns, the terminal, waits,
  drafts, the phone, a site's recon, the run's own tools, meetings, the typed judge's tools and three tools of a fake MCP
  server. The browser, the desktop, the vault and the MCP server are stand-ins that answer what a classification reads (a
  snapshot line, the control under a step, a login, a hint); the shell guard and the file classification are the real ones.
- **A real `RunGate` on a real store decides each row in every way a run can stand**: yolo and free; yolo and free in a chat of Dot's
  own; yolo and free after outside content; free over `ask`, `auto` and `supervised`; yolo alone in the owner's chat (also
  after outside content), in a chat of Dot's own and in a run nobody watches. The broker of the test cannot wait: a question
  raises at once and is counted. Where the contract names an ask (a payment, a message or mail or a post in yolo in the
  owner's chat; a message, a post or a release in a chat of Dot's own) the owner is asked and nothing else; everywhere else
  the call goes through unasked and, when the policy would have asked, one record decided by `yolo` says why. The same table
  runs under the balanced and the cautious preset, and with owner's rules that ask about every step and hand every deletion
  to them.
- **Every tool of the registry has a row or says why it has none** (`NOT_APPLICABLE`, empty today: every tool has a row,
  the registry built with the desktop, the phone, the code reader and the typed judge on).
- **Every place of the source that asks the owner is named** (`KNOWN_ASKS`, the gate's own three): a walk of the source's
  syntax finds each call of the approval broker's `request`, `keep` and `leave`, the method taken as a value and
  `getattr`, and the modules that import the broker's class (the review of the first push found the alias spellings); a new
  one fails.
- **A scripted run through the real loop** (the real shell and file tools, a browser that presses nothing): in free mode,
  over a run in yolo and over one in `ask`, it ends done with no `approval_requested`, no pending question and no `ask_user`,
  and two `approval_auto` records say why the post and the payment would have asked; with free mode off, the same run in yolo
  asks only about the post and then the payment, after the shell, the file and a click that asked nothing.
- **The gate adds no wait**: no approval, kept step or left question is awaited and no sleep longer than none is awaited, for
  every row, in every way that asks nothing.
- What stands as a refusal and no question is pinned: a research run, the pace of a site, the review model's check of a run that
  read outside content, and a secret carried out (refused in yolo, recorded in free mode).
- The exceptions are compared with the engine's own flags (`_OWNERS_FLAGS`, `_INITIATIVE_FLAGS`).
