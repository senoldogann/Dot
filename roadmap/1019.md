### 1019. Pushes are signed again: the signing library takes the project's page as the subject

**Status: done (2026-11-07).** **Found** by Dot's own record (11 times, kind daemon): `push_watch_ended:
VapidException("Missing 'sub' from claims. 'sub' is your admin email as a mailto: link.")`. Item 992 made the VAPID
subject the project's page (`https://github.com/senoldogann/Dot`), but py_vapid checks the subject with a pattern that
takes an https: address without a path only. Every push raised `VapidException` while it was signed, before it was
sent; the error is not a `PushError`, so it ended the push watch, and the phone heard nothing until the daemon started
again. The test of item 992 faked pywebpush's `webpush`, so the library's signing never ran in it.

**Built.** `notify/push.py`: the daemon's key signs with py_vapid's `no-strict` setting, which asks only that a subject
is there; the subject stays the project's page, an https: contact as RFC 8292 allows. Docs: `docs/phone.md`.

**Checked.** `tests/unit/test_push.py`: the real pywebpush signs a push (only the post to the push service is a fake)
and the signed token carries the project's page as `sub`; it fails without the change with the `VapidException` of
the record. On the owner's iPhone once deployed: a notification arrives, or `push_failed` names Apple's reason.
