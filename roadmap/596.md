### 596. A file address the browser refuses says how to see the page Dot made

**Status: done (2026-10-23).** The owner's Dot built a page in its workspace (`ai-herald/index.html`) and tried to open
it as `file:///Users/…/workspace/ai-herald/index.html`; it was told only "scheme 'file' is not allowed; only http and
https open", and the owner asked whether Dot should not be able to open what it made on this Mac.

The refusal stays: a page opened from disk could lead the browser to any other file of the Mac (a key, a password
store) and its text would reach the run past the rules on reading files (`[policy] sealed_paths`). A server of this
Mac on another port than Dot's own already opens as any site.

**As built.**
- `checked_url`, the address check of the browser tools and of `web_fetch`, gives a refused `file:` address what to do
  instead (`_local_file_hint`): read the file with `read_file`, which the rules on files judge, and, for a page of Dot's
  workspace, write its path in code in the answer, which makes it the answer's button to the file: the panel beside the
  conversation shows its text (an HTML file is never drawn there), and the owner opens the page in their own browser.
  Another refused address keeps its words.
- It names no server of this Mac: a server opens as any site, and a folder a page named would bring the files around
  it within the browser's reach, `~/.ssh` among them, past `[policy] protected_paths`, which the sandbox does not hold
  (the first round's review).
- `docs/browser-and-computer-use.md` says it.

**Tests.** `tests/unit/test_own_interface.py`: a page of the workspace is refused with the scheme's reason, `read_file`
and its path to write in code, what the panel shows and where the page opens; a key of the home folder with the reason
and `read_file` alone; neither names a server; an address of another scheme gets none of it.

Later item (proposed to the owner): Dot opens a page of its own workspace by itself, on a preview that serves that
folder alone, a link out of it refused, with nothing else of the disk reachable.
