### 1670. The process groups a crashed Dot left at work are ended when it starts again, and named to the run that goes on

**Status: done (2026-11-24).** Dot starts a shell command, a terminal session, a Claude Code program and a code-mode
script each in a process group of its own, so that a Stop ends the whole group; nothing wrote those groups down. A crash
or a `kill -9` of the daemon left them at work, adopted by `launchd`, and the next start closed the runs as cut off but
ended none of their processes: a `claude -p` kept spending the plan, a loop kept writing, and no Stop reached them.

Proved first, on a throw-away Dot (`DOT_HOME`, `DOT_LOG_DIR`, `DOT_CHROME_DIR` in a fresh `mktemp` folder; a scripted
model; a stand-in daemon process that runs a `RunManager` with a run whose `shell` call is `sleep 6137`, killed with
SIGKILL; then a second process that does the next start's `RunManager.recover()`):

- before: `sleep 6137` (pgid 54655) was the stand-in's child; after the SIGKILL its parent was 1; after the next start's
  `recover()` (one run closed as cut off) it was still there, and the probe ended it itself.
- after: the same; then `recover()` logged `orphan_group_stopped kind=shell pgid=68630 run_id=... signal=SIGTERM`, and
  no `sleep 6137` was left. With `terminal_open` and `trap '' HUP; sleep 6137` (a plain `sleep` in a terminal ends with
  the terminal's hang-up when the daemon dies) the session outlived the daemon too, and the next start ended it
  (`kind=terminal`).

What changed (`process_groups.py`, `core/paths.py`, `tools/shell.py`, `tools/waits.py`, `terminal/session.py`,
`tools/terminal.py`, `claude_code/run.py`, `codemode/runner.py`, `codemode/tool.py`, `agent/manager.py`,
`agent/resume.py`):

- `record_group` writes one file per group under `process-groups` in Dot's home (`0600`, named for the pgid): the pgid,
  the leader's start time to the microsecond as the kernel has it (`proc_pidinfo`, no `ps`), the run, the kind, the
  start of its command, and the Dot process's pid and start time. `forget_group` removes it when Dot ends the group or
  is done with it: the shell command's end, the terminal session's close, the code's end, `_end_program` of the Claude
  Code program. `run_command`, `Terminals.open` and `RunPlan` take the run's id for it.
- `stop_orphans`, from `RunManager.recover()` after the runs of the processes that are gone are closed: each group whose
  Dot process is gone (pid and start time) and whose run is not at work gets SIGTERM, then SIGKILL after 3 s, and is
  logged (`orphan_group_stopped`). Only while it is still the group written down (`is_orphan`): a living leader of that
  pgid that started at the same microsecond, or, with the leader gone, members that all started after it (a pgid is not
  given out again while a member of its group lives). A file of a group that is gone, or that is unreadable, is removed.
- B2: the run that goes on from a run whose groups were ended (a resumed run, a resumed helper of item 1668) is told in
  its note: "Work it had going in the background outlived the Dot that started it and was stopped when Dot started
  again; it no longer runs, so start it again if it is still needed", one line a group (`stopped_line`).

Nothing under `policy/` changed: this ends only processes Dot itself started and wrote down.

Checked: `tests/smoke/test_orphan_groups.py` (a stand-in Dot that records a `sleep` group is SIGKILLed: `stop_orphans`
ends that group and no other, leaving a group of a Dot that lives, one whose run works, and a file whose pid now leads a
later process; the rules of `is_orphan`; each kind written down while it works and forgotten after: a shell command, a
terminal session, a code-mode script, the Claude Code program's end) and `tests/unit/test_resume.py` (the note's
line). The terminal's forget taken out turns the smoke test red. The suites of the touched code pass
(`test_terminal*.py`, `test_code_mode.py`, `test_claude_code_run.py`, `test_run_id_in_shell.py`, `test_wait_until.py`).
Not done: the real `claude` program was not killed through this path (no model call): its recording is read in the code
and its forgetting is tested with a `sleep` through `_end_program`. A pid reused by a group Dot starts between a
process's reaping and its `forget_group` would lose that new group's file (named for the pgid); the window is the time
between `wait()` and the next line. A command that leaves a process in the background of its own (`nohup x &`) after
its shell ended is not written down, as Dot does not end it while it lives either.
