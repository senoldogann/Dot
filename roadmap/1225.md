### 1225. A run changes its model only when its credits or limits are spent

**Status: done (2026-11-19).** The owner, 2026-11-19, with two screenshots: a run on Claude Haiku 5.5 that declined
its goal was moved to OpenCode's GLM 5.3 Flash, and they want no such move. A run moves to a standby model when its
credits run out (and its usage window, quota or rate, the limits each provider has); otherwise, when the agent cannot
go on, it asks what it must ask or the run ends.

- Undone: #980 and #983 (item 1211's move of a declined goal to the standby models). A run whose model ends it saying it
  cannot ends with that answer, its needs included.
- `agent/loop.py` `_cannot_answer`: the standby models take a run over for spent credits, a spent usage window, a
  spent quota (not a 402 for a model the plan lacks) and a rate limit, and for nothing else. A content filter's stop
  (item 437), replies with nothing (item 789), a refused key or access and a missing key end the run on its own model,
  saying why. A step routed to another model (`[agent] step_router`) still goes back to the run's own model.
- Tests: the filter, empty-reply and declined runs end on their own model with no switch and no request to the standby
  model; the spent-quota switches are unchanged. Docs: `docs/models.md`, `docs/runs.md`.
