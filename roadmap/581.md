### 581. MCP tools named in words in the menus, and Dot's own icon for a server of no service

**Status: done (2026-10-23).** The owner's screenshot of the slash menu: every tool of web-research stood as
`web-research / mcp__web-research__web_crawl_results`, the name the model calls it by, beside a plug; they asked for
names that read, and for Dot's icon on the ones that have no logo.

**As built.**
- **Names.** The slash menu names an MCP tool as the row of a call to it does (`toolWords`, item 513): its server's name
  as a title, then what it does ("Web Research · Web crawl results", "Tavily · Search"). The palette names a tool by
  the name the model uses (`mcp__<server>__<tool>`, mcp/naming.py), so the old rule, "the server before the tool unless
  the tool's name begins with it", never held and every tool read as the raw name. The letters still find a tool by its
  server's name and by the model's name (`find`, which `filterGroups` reads beside the label).
- **Dot's icon.** A server of no service (`mark` null: web-research, which comes with Dot, and the servers added by
  hand) wears Dot's own icon (`/icons/icon-96.png`) where it wore the plug: in the slash and at menus, on its chip in the
  composer and on its tile in Customize › Connectors. It is its own tile, as an application's icon is (`markTile`,
  `data-icon`/`data-mark` `dot`), on no ground and no ring. A service of the catalogue with no mark of its own keeps the
  plug on a tile of its colour (item 542): its name is no one else's to draw.
- `docs/daemon.md` says both.

**Tests.** `tests/js/slash.test.js`: the tools of the palette, by the model's names, read "Tavily · Search", "Context7 ·
Resolve library id" and "Web Research · Web crawl results", and are found by "crawl", "web-research" and
"mcp__context7". `tests/smoke/test_composer_picks.py`: a server of no service wears Dot's icon in the at menu, on its
chip (before the palette arrives too) and in the slash menu, whose tools are found by their words.
