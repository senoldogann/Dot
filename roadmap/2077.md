### 2077. Recall reads back a run whose chat was deleted, and says a record it cannot find may be deleted

**Status: done (2026-11-28).** Dot's record held `recall: no record of Dot's has that id` four times. The calls the log
still kept were of real ids: `run_mwqdf5bz_c647ce` and `run_mwqe4it3_083004`, two code review runs of 2026-11-21 whose
chats the owner had since deleted, and `sch_mwu19u1y_c7d4e6`, a schedule a run had deleted an hour before. A run that
came back to old work found those ids in earlier words and was told no record of Dot's had them, the answer it gets for
an id it made up, though the run ledger of item 1323 keeps the numbers of every run deleted with its chat.

What changed:
- `Store.get_deleted_run` reads the ledger's row of a run (`DeletedRunRecord`: source, model, status, when it started
  and was deleted, its parent run and its chat's schedule); no words of the run, as the ledger keeps none.
- `recall` of a run no longer kept reads it from the ledger: the run was deleted with its chat on that day, its goal,
  answer and steps are gone, and what the ledger keeps. Those are Dot's own values, so nothing is fenced.
- A record that is gone without a trace (a deleted schedule, chat, thing to do or approval, a run deleted before the
  ledger was kept) is still an error, which now says it was deleted or the id is not one of Dot's.
- docs/runs.md says so.

How it was checked: `tests/smoke/test_recall.py::test_a_run_whose_chat_was_deleted_is_read_back_from_the_ledger`
fails without the change and passes with it (the run's goal and answer stay out of the answer, the deleted chat's id
gets the new error); the file's other tests, `tests/unit/test_run_statistics.py`, ruff and mypy pass.
