### 1912. DotNext's Dot no longer wears an unread mark for its own work

**Status: done (2026-11-26).** The owner's test of build 6: "the Dot logo always shows as an unread message", even
after opening it.

Cause, on the owner's store (read only, 2026-11-26): 226 of Dot's chats were unread, 216 of them the pre-push hook's
code reviews (`source = review`) and 9 schedule chats; a bot's mark counted every unread chat it holds, and a tap on
Dot opened its chat that moved last, which is nearly always the newest review, so the chats the owner reads were
never the ones that kept the mark. The web folds those chats under sections of their own (`sidebar.js`
`CHANNEL_SECTIONS`: Dot's work, the agents' work, code reviews).

What was built (DotEngine `Bots.swift`): `isConversation` (pure) leaves out the sources the web folds (`initiative`,
`schedule`, `team`, `review`); a bot's unread count counts only its conversations, and the chat a tap opens is its
latest conversation (its latest chat when it has none). Asks still count from every chat: work that waits on the owner
marks Dot. The work stays among Dot's chats.

Checked: `BotsTests.testDotsOwnWorkNeitherMarksItUnreadNorIsWhatATapOpens`, red without the change.
