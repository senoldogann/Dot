### 1270. The unit tests run on Linux, where a cloud agent works

**Status: done (2026-11-20).** The owner develops Dot with cloud agents too, on Linux, where the unit tests could not
run: a run of `pytest tests/unit` died in `tests/conftest.py` on `os.O_EVTONLY`, and once past it 219 modules failed to
load on AppKit, Quartz or ApplicationServices. Pull request #1012 had cut the tools' path to the browser window; this
takes it over to the end, from a session that stopped there.

- `policy/paths.py` reads `O_EVTONLY`, `tools/notes.py` `O_SEARCH` and `O_NOFOLLOW_ANY`, `core/held.py` `O_SEARCH`, when
  they open a folder, not at import (macOS's behaviour is unchanged).
- The pure parts that loaded a framework for a name are moved where the framework is not: `INTERACTIVE_ROLES` and
  `DESKTOP_ACT_TOOL` to `desktop/types.py`, the key chords to `desktop/chords.py`, the models of a Snapshot and its
  shortcut's words to `desktop/snapshot_models.py`, `AutomationState` to `connections/states.py`.
- The adapters import the framework in the function that asks macOS: the permissions, the PDF readers, the photos,
  the Mac's connections, the voice app's look, the app of a document, Dot's window after a capture, the doctor's
  capture check, the initiative's idle time. The runtime makes the desktop session, the Snapshots service and the
  desktop's tools in the functions that build them, the browser's window asks the applications when it does, and Watch
  makes its screen at the first viewer. The QR code is imported by its route on the event loop's thread, as its module
  binds a Core Graphics function as it loads.
- What still needs macOS is left out on Linux, by AppKit's absence rather than the platform's name:
  `tests/unit/conftest.py` lists the modules (the desktop's own, and those whose tests read paths as macOS's kernel
  names them, the shell guard's among them; a name that is gone stops the collection), and the tests marked `macos`
  in modules whose other tests run anywhere (those that read a macOS-only open flag, or run `osascript`, `plutil`,
  `launchctl`, `zsh` or `sandbox-exec`); the search's cancel test needs ripgrep and says so.
- The gate's Linux job runs the unit tests, so a module that loads a framework for a name fails there.

Measured on the gate's Linux: before, 3,259 tests collected and 149 modules failed to load (219 with `O_SEARCH`
stubbed, as the session before counted); after, every module loads and 5,449 tests run: 5,304 pass and 145 are left out
as needing macOS. macOS still runs all 7,198.

Checked: the unit tests on macOS; the same on a Mac with PyObjC and macOS's open flags hidden; the unit tests on the
gate's Linux runner; mypy, ruff.
