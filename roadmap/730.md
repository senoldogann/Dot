### 730. The daemon gives the memory it freed back to macOS

**Status: done (2026-10-27).** The owner's daemon showed a physical footprint of 543 MB (peak 626 MB) after 8 hours
of runs; started fresh it holds 184 MB. `vmmap` put the growth in the heap: Python's arenas (VM_ALLOCATE, 350 MB, 310
of them compressed) and malloc's small and large regions. Serving the web UI does not grow it (opening the six largest
chats four times: 185 -> 191 MB, flat), and a read of the code for collections that grow per run found none but the
cache of `vault/masking._forms`, which had no bound: every cookie value of every site a script ran in passes through
it. A step builds and drops megabytes (the conversation sent to the model, often 200,000 tokens, its JSON, tool
output), and macOS's malloc keeps the blocks freed, dirty, for later: they count in the footprint Activity Monitor
shows.

**The change.** `core/heap.py`: `dotx daemon` starts itself again at once with `MallocSpaceEfficient=1` (`os.execv`,
the same process id, so launchd and Dot.app's launcher keep it), under which malloc gives freed pages back. The
variable is read when a process starts; a macOS that does not know it ignores it; the MCP servers and the desktop
helper inherit it. `_forms` keeps the forms of the 2,048 values masked last.

**Measured** (M4, macOS 26.6, Python 3.13). A process that built and dropped 120 conversations of 400 messages: 1.1 GB
kept without the variable, 9 MB with it (`MALLOC_LARGE (empty)` 872 MB dirty went). Forty runs of fourteen steps in one
chat, in one runtime, with a model that reads a large file each step and thinks 3 KB a reply: 170 MB at the end without
it, 150 MB with it, and 27.4 s against 22.9 s. A daemon started on a copy of the owner's database: 184 MB without
items 729 and 730, 132 MB with them.

**Checked.** `test_heap.py`: the process starts again with its own arguments and the variable set, once.

**Not done.** Python's arenas stay where a long-lived object pins them; what pins them in the owner's daemon was not
measured (it needs a look inside the running process). The peak of a step falls with a smaller conversation: the
context budget is the owner's question (item 396 set it to the most a window allows).
