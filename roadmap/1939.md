### 1939. A review model whose key is missing no longer crashes a long run

**Status: done (2026-11-26).** The review of 2026-11-26 (wave 1, #7; A1-01 of 2026-11-19): `_checkpoint` in
`agent/loop.py` caught only `ProviderError`, so a run that reached its checkpoint (every `checkpoint_steps`, 40) while
the review model's key was missing (an expired sign-in, a removed key) died on `MissingSecretError`, a `ConfigError`,
although the docstring says a run is never stopped for a judge that failed. `_consult` (the watchdog's consult rung)
likewise crashed instead of ending the run as stalled with the problem stated, as its docstring says.

What changed: both catch `ConfigError` beside `ProviderError` and do what their docstrings say: the checkpoint logs
`checkpoint_failed` and changes nothing; the consult ends the run as stalled with "The review model could not give a
second opinion: <why>". docs/autonomy.md says it.

How it was checked: two tests in `tests/smoke/test_progress_watchdog.py` with a review model whose provider raises
`MissingSecretError`, both red before the change (the run failed with "no API key for openai"): a run with checkpoints
ends done, and one that climbs to the consult rung ends stalled saying why. `dotx eval check` and the freedom contract
pass.
