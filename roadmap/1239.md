### 1239. A phones file the daemon cannot read keeps it from starting anything

**Status: done (2026-11-19).** `docs/phone.md` says a `phones.json` the daemon cannot read keeps it from starting, and
`PairedPhones.load` refuses such a file. The code review of 2026-11-19 (finding K4-01) found it read only as the
server's context was built, after the daemon had bound its address, cut off and resumed runs, opened the iMessage
channel and started the scheduler: the error then stopped them all part way, left the running mark, and launchd started
it all again, every time. The file is read first now, before the instance lock, the running mark, the address and the
runtime.

Checked: `tests/smoke/test_daemon_refusal.py` (a broken `phones.json` ends `dotx daemon` with the file named, before it
makes its database or its running mark; before the change it went on to bind the address), `tests/unit/test_phones.py`.
