### 713. A run waits for a spent quota instead of failing

**Status: done (2026-10-27).** **Measured** in the owner's logs: Ollama Pro answered "You used all included Pro usage"
to hundreds of calls from 12 to 15 October, and OpenCode Go "Go usage limit exceeded" 24 times; with no standby model
that could take over (the owner's list starts with the main model itself, and its second one runs on the same Ollama
plan), each such run failed. Cindy (`docs/product-rules/usage-limit-auto-continue.md` of makecindy/cindy, Apache-2.0)
waits for a subscription's reset and goes on: the idea is taken, not its code.

**The change.** In the loop, when no standby model takes the run over and the error says the quota or the rate is spent
(`_spent`, the reasons `unavailable_reason` gives for them; spent credits are not waited for, as Cindy does not wait for
an API key's: the owner has to buy them, and is told at once), the run waits for `[agent] quota_wait_s` (6 hours by
default) as it waits for a model out of reach (`model_wait_s`, item 158): it asks the same step again when the provider
named a time (`retry_after_s` of the error, not the router's pause, which holds a cooldown of its own when nothing was
named), else every 10 minutes, at least a minute and at most half an hour apart. The `model_waiting` event carries
`spent`, and the timeline says "cannot answer (usage window spent)" or "(rate limited)". A quota still spent at the end
ends the run with the provider's own words. A refused key or access, a model the plan does not include and a missing key
end the run at once, as before. Anthropic's spent prepaid balance and OpenCode's `CreditsError` were read as a spent
quota; they are spent credits now (`ProviderCreditError`), which the whole gate showed: a run would have waited six
hours on an empty balance.

**Checked.** `tests/unit/test_provider_errors.py` (spent credits told apart from a spent window);
`tests/smoke/test_model_wait.py`: a spent quota for two calls waits, says so with its reason, and the run
goes on and ends done; a quota that stays spent fails the run with the provider's words once the wait is over; a refused
key never waits; the rate limit with no quota wait fails at once, as before.

**Not done.** A call outside a run (a lesson draw, the reflection, the goal check) still fails on a spent quota; the
next reflection draws what it missed (item 687).

The third code review: the wait for a quota and the wait for a model out of reach were timed from one moment, so a
connection that broke while the quota was waited for (a Mac that wakes, a network that drops) was timed against
`model_wait_s` from the start of the whole wait and ended the run; a wait for a spent quota now goes on through a
broken connection, timed from its own start (`spent_since`), checked by
`test_a_connection_that_breaks_while_the_quota_is_waited_for_does_not_end_the_wait`.

The fourth code review found OpenAI's credit and spend codes still read as a spent quota: a list of what does not come
back kept missing one. The rule is turned round: a run waits only for what is known to come back by itself, a rate
limit, a subscription's usage window (`ProviderWindowError`, OpenCode Go's `GoUsageLimitError`) or a quota whose
provider named when it comes back; any other quota ends the run at once, Ollama's monthly plan among them, which does
not come back within six hours anyway. Checked by `test_a_quota_that_does_not_come_back_soon_ends_the_run_at_once` and
`test_a_quota_whose_provider_named_when_it_comes_back_is_waited_for`.

The fifth review: spent credits are never waited for, even with a time named (`ProviderCreditError` first), and a
named time counts only when it falls within `quota_wait_s` (a month's plan that names next month is not waited for);
`docs/models.md`'s line on a run with no standby model says what is waited for first.

The seventh review: a gateway that names a time on every answer (`Retry-After: 60`) made a month's plan look like a
quota that comes back; a named time decides nothing now, it only spaces the asks of a wait. A run waits for a rate
limit and a subscription's usage window alone.
