### 1725. DotNext's engine reads a chat whole: the work log with its four tool modes and folds, the asks of the dock, the composer's and the queue's rules

**Status: done (2026-11-24).** Wave N2 of the iPhone rewrite, the engine's part (`ios/DotEngine`, pure and tested).

What was built:
- The transcript (`Sync/Transcript.swift`): tool rows with their arguments, output, screenshots and kind (read, edit,
  command, search, wait, web, screen, helper; Dot's and the Claude plan's names), the plan as a checklist, the helpers of
  a run as one group, the asks left where they were asked with what was decided and who decided (this phone, elsewhere,
  the review model, nobody in time), a failed run's one-line cause, the Claude plan's usage limit with its reset time,
  reaction targets (`answer`, `step-N`), no owner's message for a run that follows a reaction. A finished run's steps,
  plan and passing words fold to one line with its duration and tally; the owner's words, Dot's notes and the asks stay
  out of the fold; a failed fold is drawn open.
- The four tool modes as a table and a pure filter (PLAN.md §13 S6), written on `ToolCallMode`:

  | What | Show all | Hide successful | Hide all | Zen |
  |---|---|---|---|---|
  | command, read/edit, wait, search, web, screen step (succeeded) | row | hidden | hidden | hidden |
  | the same, still running | row | row | hidden | hidden |
  | a failed tool | row | row | row | hidden |
  | helper group | card | card | card | hidden |
  | reasoning | not drawn: the daemon stores none | | | |
  | plan | card | card | card | hidden |
  | interim prose | shown | shown | shown | hidden |
  | the run's answer, run error, usage limit, asks, the owner's words, Dot's notes | shown | shown | shown | shown |

  "Response streaming" off drops the words being written: an answer shows once whole.
- `Sync/ChatRules.swift`: one duration shape (`DurationParts`, §19), the ask dock's entries (kind, whole text and
  target, options, "always allow" only where item 866 allows it, stable oldest-first order, phases pending / submitting
  / queued offline / answered elsewhere / expired / refused / retry, an ask answered here never "answered elsewhere"),
  the composer's buttons (Send / Queue / Steer / Stop / confirm an edit, with the other way), `/` and `@` completion, the
  queue's edit (save, unchanged, gone, empty; the live draft kept), reorder, the chat's one phase ("Waiting on you" over
  "Working"), the follow rule of the scroll, short helper titles.
- `Sync/Markdown.swift`: an answer's blocks (headings, paragraphs, lists, tables, code, quotes, rules).
- A helper's own `run_finished` on the stream ends it in the view (the capsule no longer counts a finished helper); an
  accepted queued message follows the edits of its queued words, so its overlay goes once its run shows.
- The outbox: "always allow" (`remember`), reactions and the chat's model choices; the API: models, failsafe, a tool's
  screenshot, a run's actions and changes.
