### 1800. DotNext's chat list: select several, pin and delete them together, a Pinned section on top

**Status: done (2026-11-25).** The owner's test on his iPhone (PLAN §23): the list needs multi-select, a bulk delete,
pin and unpin with a Pinned section, swipe actions and a context menu.

Before: each row had a swipe to pin and to delete and a context menu (rename, pin, delete), one chat at a time; a
pinned chat stood first in its section (`ListProjection.ordered`) with no section of its own.

What must hold: the same daemon routes the web's list uses (`PATCH /api/threads/{id}` `pinned`, `DELETE /api/threads`),
through the outbox, so a tap made offline goes when the link is back; a chat with a run at work is never sent to be
deleted (the daemon refuses the whole request with 409 then), and the confirmation says it is kept; nothing invented the
daemon does not have (there is no archive: none is offered).

What was built (`ios/Next/App/Live.swift`): the list is `ChatListView(scope:selection:)`, self-contained (all chats, or
one bot's: Dot's own or an agent's), so the bots home of PLAN §27 can show it inside a bot's profile; `ChatsTab` only
puts it beside the open chat.
- **Select** in the bar, or **Select** on a row's menu (that row checked): rows take a check circle, a tap checks a row
  and opens nothing; **Select all / Deselect all** and **Done** in the bar; the bottom bar (the tab bar hidden) has
  **Pin** (or **Unpin** when every checked chat is pinned), the count, and **Delete…** with one confirmation for all of
  them, leaving out the chats at work.
- `chatListSections`: **Pinned** first, whatever the chat's state (its status word still says it), then Needs you,
  Working, Recent.
- The swipes and the context menu stay (pin/unpin, delete with the owner's confirmation setting, rename).

Checked: `ChatListLiveUITests.testSeveralChatsArePinnedAndDeletedTogether` on the simulator against a throwaway daemon
(`ios/Next/scripts/e2e_chats.sh`), which reads on the daemon that the two chats were deleted.
