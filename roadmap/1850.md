### 1850. The iPhone app is tested on GitHub's macOS runners

**Status: done (2026-11-25).** About ten helpers built and tested DotNext (`ios/Next`, its engine `ios/DotEngine`) on
the owner's Mac (10 cores, 16 GB) behind one Xcode lock (`/tmp/dotnext-xcode.lock`) and waited 30 minutes and more
each. The repository is public, so GitHub's macOS runners cost nothing in money; they cost time, as the account runs
five at once and the gate's macOS jobs share them.

What must hold: every pull request that changes `ios/**` (or the workflow) gets the engine's tests, one build of
DotNext and its tests, the String Catalog check and the chat's and Settings' tests from that build; a push to `main`
that changes them, every night, a run asked for and a pull request labelled `ios-full` get every UI test and Settings
end to end against a throwaway daemon of the same commit too; one check named `ios` passes only when all of them did;
a run holds two macOS runners at most, so three of five stay free for the gate; a test that passed only on its retry
is named in the job's summary; the result and every screenshot can be fetched with `gh run download`; the token
can only read; each action is pinned by a commit (zizmor passes).

What was built: `.github/workflows/ios.yml` on `macos-26` with Xcode 26.6 (the image's default, iOS 26.5 simulators).
Jobs `engine` (`swift test`), `build` (XcodeGen from Homebrew, `xcodebuild build-for-testing` signed ad hoc, so the app
has its app group as on the Mac, then `scripts/check_strings.sh`; the products go to the next jobs as an artifact),
`tests (chat)`, `tests (controls)` and `tests (rows)` two at a time (`max-parallel: 2`, after `engine` and `build`;
`test-without-building` on an iPhone 17 Pro; each test of `SettingsControlsUITests` has a part of its own, as it takes
16-27 minutes there; a pull request without `ios-full` runs `chat` alone, the matrix chosen by the event), `e2e`
(after the tests, so alone, whatever they gave; skipped on a pull request without `ios-full`;
`scripts/e2e_settings.sh` with `uv` and the daemon of the checkout, its folders under a TMPDIR of each try's own so
that each try's daemon and xcodebuild logs, and the first try's result, go to the artifact; tried once more when the
first try fails, as the UI test runner sometimes does not start there; the script now fails on
`xcodebuild test`'s own status too, which its pipe into `sort` had dropped), `ios`. Each test job uploads its
`.xcresult` and the attachments exported from it (`xcresulttool export attachments`: a failure's screenshot, and what a
test attaches to be kept) for 7 days, and `scripts/passed_on_retry.py` writes each test that failed and then passed
on its retry to the job's summary ("passed on retry: <test>") and as a warning. A passing test keeps no screenshot,
so the owner's shots of every scene stay `scripts/shots.sh` on the Mac.
No cache: DotEngine is a local package and the app has no remote package, so there is no lock file and nothing for SPM
to fetch; a restored DerivedData is rebuilt anyway, as a fresh checkout gives every source a new time.
ios/Next/README.md "CI" says how to read a run.

Measured on the runner (probe runs 45564864764 and 45569714390, Xcode 26.6): `engine` 1-2 min, `build` with the
String Catalog check 2-3 min, `tests (chat)` 10-12 min (31 unit and 10 UI tests), `tests (rows)` 17 min,
`tests (controls)` 24 min, `e2e` 15 min (8 of 8 checks of the daemon's side ok); a simulator's boot takes about 2 min
of each. Found on the way: Xcode 26.1 fails at the asset catalog (Xcode 26.6 builds it); `StringCatalogTests` reads the
catalog at its source path, so the test jobs check the code out too; the UI test runner failed to start once ("Timed
out waiting for AX loaded notification") in `e2e`, and XCTest's launch of the app timed out once in the pull
request's first run (45578426723, `tests (rows)`): the test parts now install and open the app once before the tests
and run a failed test once more (`-retry-tests-on-failure -test-iterations 2`); a test that fails twice fails.

The pull request's first whole run (45583593058: up to five macOS runners at once) took 58 minutes, 10 of them
queued; `ChatUITests.testSlashOpensTheCommandsPanelFilteredAsTheOwnerTypes` failed its first run there and passed its
retry, and so did `SettingsLiveUITests` in `e2e`, while every write it made reached the daemon: both are left to the
tests' owner. The two-runner cap and the pull request's short run followed (the lead's review: an iOS run holding four
or five runners for about 50 minutes stalled every other pull request's gate).

Checked: zizmor and actionlint on the workflow; `passed_on_retry.py` on run 45583593058's result (it names the slash
panel's test); the runs above and the pull request's own run.
