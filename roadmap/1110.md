### 1110. The repair night goes on after a merge

**Status: done (2026-11-10).** Asked by the owner: "how are self-repair and self-improvement doing: as we want, or still
simple?" Measured in the owner's Dot: 19 sessions in eight nights, seven merged; 167 problems in the book, 154 open and
153 never tried, 46 of them seen often enough to be handed out; the plan's five-hour window 22 % used; one session a
night whenever it merged. A merge ended the night (`repair_night`), so that Dot would not go on in a process whose code
on disk had changed after the owner's checkout was pulled: with `sessions_per_day = 10`, a night that fixed something
fixed one thing.

Now a merge, a session's or a second look's, does not end the night and does not touch the owner's checkout: the
night goes on to the next problem, each session on a checkout of its own of the new main, while the day's sessions,
the night's time and the plan's window last. Once it is over, if it merged anything, the owner's checkout is pulled
fast-forward (when it is on main) and Dot restarts once idle, once; a checkout off main or a pull that failed is told to
the owner. A session ends `merged` with the note that the pull comes at the night's end (`merged_unpulled` is no longer
written; the page still reads it in older sessions).

Checked: `tests/smoke/test_repair_night.py` (two problems, both merged in one night, one restart; on the old code the
night stopped after the first), the repair tests.
