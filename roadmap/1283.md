### 1283. A search of a path that is not there says so, as list_dir does

**Status: done (2026-11-21).** Dot's own record showed `search_files: ripgrep failed` eight times. Each one was a path
the model gave that was not there: a file it guessed in a worktree that did not hold it, a folder (`web`,
`src/dotagent/config`) it took for one, a worktree removed since. ripgrep ends with 2 and says "No such file or
directory (os error 2)" of the path, and `search_files` (and `find_files`) reported that as a failure of ripgrep's own,
where `list_dir` and `read_file` say "path does not exist" / "file does not exist". The model's wrong guess was not
told apart from a ripgrep that does not work, in the answer the model reads, in the record and in what runs learn.

What changed: when all ripgrep said is that the path it was given is not there, `search_files` and `find_files` fail
with "path does not exist" and the path. A file gone from below the path while it was read, a pattern ripgrep cannot
read and any other error still fail as "ripgrep failed" with what ripgrep said. What the run's sandbox refuses
(os error 1) is shown as before, so the sandbox tells no more of what is there than it did.

Checked: `tests/unit/test_search_unread.py` (the lines of ripgrep 15 and of older ones),
