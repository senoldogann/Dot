### 689. An agent may be given an MCP tool connected after the daemon started

**Status: done (2026-10-26).** The whole-project review found that `agents_router` froze
`known = frozenset(ctx.runtime.registry.tools)` when the router was built. The Apps routes call `refresh_mcp_tools`
after a server is added, removed or switched, which changes the registry in place, so `GET /api/tools` missed the new
tools and `_checked` refused an agent that named one with a 422 until the daemon was restarted.

**The change.** The router reads the registry's tools at each request (`known()`), for the list of tools, an agent
made or saved, and the agents a template makes.

**Checked.** `tests/smoke/test_agents.py`: a tool that joins the registry after the server is up is listed and may be
given to a new agent, and once it leaves, it is not listed and is refused again. `docs/agents-and-campaigns.md` says
the list is read at each request.
