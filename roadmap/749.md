### 749. A desktop batch stops when a step brings another application to the front

**Status: done (2026-10-27).** **Found** by the review of computer use the owner asked for: `desktop_act`'s description
promises that a batch stops "when the screen surprises you (a dialog, a different application)", and nothing did.
`_remeasure` noted whichever application was in front after each step as the one the next keyboard step expects, so
`[click a link in Mail, type "..."]`, where the click brings Safari forward, typed into Safari.

**The change.** After each step but the last, `DesktopSession._run_steps` compares the application in front with the one
before the step. When another application came forward that is neither the batch's own nor the result of an `activate`
step, the batch stops with "<App> came to the front after step N; look at the screen before going on" and the steps
after it are reported skipped, as for the other stops. An application in front all along, the batch's own application
coming forward (a click on a window that was behind), and a front that cannot be told do not stop it.

**Checked.** `tests/unit/test_desktop_batch_front.py`: a click that brings Safari forward in a Mail batch stops it after
step 1 with the two others skipped (also when Finder was in front at the start); Mail coming forward, a front that
stays, an unknown front and an `activate` step go on. The first and third fail on the code before.
