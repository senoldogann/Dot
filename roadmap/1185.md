### 1185. Retry under an answer

**Status: done (2026-11-15).** A chat assistant lets an answer be asked for again; Dot had Edit from here (item 282),
which rewinds the chat and leaves the message in the box to be sent by hand. Under the answer of a message of yours that
the chat can go back to before (as its message has Edit from here), on the chat's page of that run, there is now Retry,
an arrow in a circle in the answer's foot, and on a phone a row of the message's sheet (item 1064, which lends every
button of the foot).

- It asks as Edit from here does, because what the turn changed on the Mac stays unless taken back: "Retry" keeps the
  file changes, "Undo the file changes and retry" takes them back, Cancel does nothing.
- Then `POST /runs/<id>/rewind` and, at once, `POST /runs` with the message's words and files and the composer's
  choices, in the same chat, or as a new chat when the rewind left no run (the chat's first message). The page goes to
  the new run. No new endpoint: the two calls are the ones the composer and Edit from here already make.
- The composer's choices are read before the rewind (their read may reach the daemon for the models), so a failure there
  leaves the chat as it was. Anything that fails after the rewind (the network, a choice the daemon refuses) leaves the
  message and its files in the box of the run the chat ends with now, as after Edit from here, and the failure is told:
  nothing is lost.
- The picks of the first send (an account, a skill, a plugin, item 318) are not sent again: the rewind does not return
  them, as Edit from here does not put them back in the box either; the docs say so.
- The chat keeps one line: no versions of an answer are kept to switch between. Keeping them means a tree of runs in the
  store, and a run that acted on the Mac cannot be undone by showing another branch; that is for the owner to decide.

Checked: `tests/smoke/test_chat_retry.py` (Chrome at 1280 px: a chat of two turns, the second retried, the first kept;
WebKit as the owner's iPhone: a chat's first message retried from the sheet, as a new chat; a send refused after the
rewind leaves the message in the box; a models read that fails leaves the chat as it was, a check that fails on the old
order).
