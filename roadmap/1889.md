### 1889. A model's no is asked once with the scope, then stands: the owner restarts on a model of their choosing

**Status: done (2026-11-25).** Backlog item A0, which the owner approved on 2026-11-25. The owner uses Dot for
authorised security research (bug bounty programs, responsible disclosure), work a model sometimes reads as harm. Their
local item 1366 answered that by sending a refusal back twice as "not an answer", by opening the third try with words
that make the model go on past its no, and by moving the run, unasked, to a model kept because it refuses less. None of
that is carried over: it argues with a model's judgement instead of giving it what it lacked, and it hides from the
owner which model did the work. This item gives the model the context once, openly, and leaves the choice of another
model to the owner. It is built on the scopes of items 1887 and 1888 (pull request #1126), whose branch it starts from.

What must hold:

1. A technical block is not a judgement. A reply the provider's content filter stopped, and replies that stay empty
   after the nudges, move the run to its standby models (`[models] standby`), each once, as a spent quota does; with
   none left the run ends as before (the filter's words, `RESULT_EMPTY_REPLIES`). Item 1225 kept these on the run's
   model; the owner's word of 2026-11-25 moves them.
2. A refusal of in-scope work is asked again once, openly, on the same model. In scope means the run's goal names a
   host a scope covers (`dotagent.scopes.authorising`: `[recon] owned_hosts`, `[recon] scopes`, `scopes.toml`), or the
   goal is the owner's own words (a run they started in the app, with `dotx run`, or from their phone). The note says
   what it is: the program's scope and rules, the owner's words, and that the work is finding and reporting, not
   exploiting; and that a second no stands and is not argued with. Once per run.
3. A refusal that stands is the run's end: no further note, no model hop. The run fails with the model's own words
   under `PREFIX_MODEL_REFUSED` (the ending `model_refused`, which no schedule retries), the event `model_refused` says
   so, and the run's page offers one action, **Restart on…**, whose menu is the composer's model menu. The model picked
   starts a new run of the same goal in the same chat (`POST /runs/{id}/restart`), and the old run's event
   `restarted_on_model` records it as the owner's choice. A refusal outside scope (a run Dot started on its own, a
   delegated part) stands at once, the same way.
4. Up-front routing: `[models] kinds` maps a task kind to a model, `security` the only kind for now. A run started
   with no model chosen whose goal names a scoped host and speaks of security work starts on that model. Settings ›
   Models › Roles has a **Security research model** row ("Default model" for none).

What only asks: nothing new. The restart is an offer on the page, never a question; a yolo or free run asks nothing it
did not ask before.

Kept: item 1761 — a message the Claude plan's safeguards flagged is a lasting failure, never tried again on the same
model. Its end now carries `PREFIX_MODEL_REFUSED`, so its page offers the same restart.

The detector (`dotagent.agent.refusal.looks_like_refusal`) reads only the opening of a final answer, for a sentence
that declines the task itself, in English and Turkish; a reply that names a limit it worked around is work.

Found by the review of the first push and fixed here, as this branch carries items 1887 and 1888 (pull request #1126):
`dotx scope add` escaped only a backslash and a quote, so rules of several lines wrote a `scopes.toml` that could not
be read back and stopped every scan; every control character is escaped now and the file is read back before the add
is reported. A `scopes.toml` that cannot be read covers no host for the grounds of a refusal and the routing of a
security task (`authorising_if_readable`, logged), while the port scan and `security_scan` still stop on it. The
program's name and rules reach the model quoted, on one line, as recorded, never as Dot's own words. The docs say who
writes a scope. The restart is refused for a run that did not end on a refusal and on the model that declined it, and
the note is given once per run across a resume (`LoopState.refusal_asked`). The second review: the Turkish patterns tie the no to the request itself ("bunu", "bu isteği", help refused), so "Maalesef VPN olmadan taramayı yapamam; pasif denetimi yaptım" is work; and a scopes text that would not read back is refused before it replaces the file.
