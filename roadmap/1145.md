### 1145. An ambiguous edit names the lines of its text

**Status: done (2026-11-13).** **Found** by Dot in its own record (`edit_file: the text occurs <n> times; add
surrounding context or set replace_all`, five times, kind `tool_error`): a LinkedIn draft and a decision page in the
workspace, and three runs whose events are gone. Sending a text that occurs twice is the model's own slip, which no
edit tool prevents, but the error told it only how many times the text was there: to widen it, the run had to read the
file again to find where.

**The change.** The error carries `at_lines`, the line where each occurrence starts (the first 20), counted as the
replacement counts them, CRLF files too. Numbers only, so a failed edit of a third party's file still names none of
its text (item 494).

**Checked.** `tests/unit/test_edit_file_ambiguous.py`: a text found on lines 2 and 5 is refused naming `[2, 5]`, in a
plain, a CRLF and a third party's file, the file left as it was; on the code before it the error had no lines.
