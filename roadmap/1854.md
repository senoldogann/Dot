### 1854. A run a restart cut off goes on by itself, unless what was cut may have paid, sent or posted

**Status: done (2026-11-25).** Taken from the study of OpenClaw (`reports/refs-2026-11-25/clawdbot.md`, item 1,
`src/gateway/session-restart-resume.ts`), on the owner's word of 2026-11-25. Dot already resumed on its own, when the
daemon starts (`[agent] resume = "safe"`, item 248), a run of the web UI cut off at most `resume_within_s` before; but
only when every call that was cut while it ran only read. A run cut in a command, a write or a click waited for the
owner's Continue, and so every deploy waited for the runs to end (`dotx service restart --when-idle`, item 1310).

The approach, written before the code:

What must hold:
- A run the owner stopped (Stop, Ctrl-C, the emergency stop) is never resumed: its ending is not a cut-off
  (`cut_off_by`), as before.
- A run is resumed once: a resumed run that a restart cuts again waits for the owner, as before.
- A call that reaches beyond the Mac (a payment, a message or mail, a post, an upload or data sent out, a release:
  `SENT_OUT_FLAGS`, the set for which the scheduler never tries a task again, which now holds both) and was cut while
  it ran may have been done; going on could do it twice, so such a run waits for the owner. So does a call whose kind
  Dot cannot tell (an unknown tool, arguments its tool refuses, a click classified by the screen, and a `browser_act`
  click, classified by the element of the tab's last snapshot, which the daemon that starts does not hold: classified
  again, a click on "Pay now" would raise nothing): it may be one of those.
- The resumed run keeps the run's approval mode, taint, ledger, plan and proof checks (item 1853): it goes through the
  same gate, which it neither loosens nor tightens. Nothing new asks in `yolo` or free mode.

What may ask: nothing new; the resumed run asks what its mode asks.

What was built: `resumes_on_start` (`agent/resume.py`) no longer asks every cut call to only read; it holds back a run
only for a cut outward call or a cut call of unknown kind. The note of a run the daemon resumed by itself opens with
the words OpenClaw found to work: Dot restarted while it worked, check the state of what was in progress (files,
processes, helpers, outside actions) before repeating any of it, then go on. The sources stay those of the web UI and
the phone: a schedule's run is still tried again by the scheduler (item 1206), a channel's run waits (its answer goes
back to the channel only from the run its message started), and a run of `dotx run`, an eval or a code review waits.
The docs (`docs/autonomy.md`, `docs/runs.md`, `docs/daemon.md`, `defaults.toml`) say that a restart no longer loses
the work of such runs; `--when-idle` stays for a restart that should not cut a step in the middle.

Checked: `tests/unit/test_resume.py` (the new rule, the outward and unknown cases, the note), the resume smoke tests,
`tests/unit/test_freedom_contract.py`, `dotx eval check`.
