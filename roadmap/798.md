### 798. A finding that comes back becomes a check, not another comment

**Status: done (2026-10-28).** **Asked** by the owner: "O halde şimdi bu sistemi uygulamaya başla. Lütfen ne yaptığımı
bilerem aşama aşama ilerle test ederek." The first step of the system the owner approved was the review→check loop:
the review guide was prose, so a finding that returned had no guard that failed when it returned.

- **The guide names checks.** `REVIEW.md` has a "Checks made from reviews" section: every repeated finding names a
  test, and the section says to add it in the same pull request as the finding. The first three are the secret field
  the user gave (and the page's secret refused), the left question that notifies the user, and the default run
  ceiling.
- **A test keeps the registry honest.** `tests/unit/test_review_rules.py` parses the section and fails when a name
  points at a missing file, a missing test function, a bullet without a check, a duplicate, or a rule that says
  nothing. Deleting a guard is a red gate, not a quiet regression.
- **Measured.** `uv run pytest tests/unit/test_review_rules.py` passes; the three named tests exist; the full unit
  suite stays green. The guide is read by `/code-review` and the Reviewer agent, so the loop is part of the review,
  not a separate document.
