### 921. The repair night: Claude Code fixes Dot's problems, and Dot merges or waits

**Status: done (2026-11-02).** **Asked** with items 919 and 920. The owner wants Dot to report its problems and gaps
straight to Claude Code, and the fixes merged without their approval once the tests and the code are right
(`[repair] merge = "on_pass"`, set on their Mac). What must hold whatever a session does is in Dot's code, not in the
brief or in the session's environment:

- Dot reads the files a change touches, from the branch and from GitHub. A change to a path of REVIEW.md's "Always
  needs a human" is never merged.
- Dot merges, only with every check passed and only while the head is the commit it looked at. The session has no way
  to GitHub by default (item 919's environment): Dot pushes its branch through the review hook and opens the pull
  request. That default is not a boundary: the session has a shell and can set it back, and no sandbox can take the
  Keychain's GitHub sign-in from it and leave Claude Code its own (the second review). What holds:
  - GitHub's protection of `main` refuses a push of a commit whose checks have not passed, for admins too, so the one
    way in is a pull request whose checks passed;
  - Dot reads `main` on GitHub and takes a print of the owner's checkout (its `git status`, commit, git config and
    hooks) when a session begins, before it merges and after a session it merged nothing for: either changed by no
    doing of Dot's stops the night, merges, pulls and restarts nothing, and is told (`main_moved`). A session runs with
    the owner's rights and could write outside its own checkout (the sixth review); what it might change elsewhere on
    the Mac is not checked, and the docs say so;
  - the gate's own sources need the owner whatever REVIEW.md says (`PROTECTED`: REVIEW.md, CLAUDE.md, AGENTS.md,
    CONTRIBUTING.md, `.claude/`, `.github/`, `src/dotagent/repair/`, the scheduler), and REVIEW.md's list is read
    from `main` on GitHub, so that no change merged on its own loosens the gate for the nights after it (the third
    review);
  - the repair night's own errors in the log are never a problem of the book;
  - Dot's dependencies (`pyproject.toml`, `uv.lock`, the npm and Cargo manifests and locks) need the owner too, and
    only the hook's own review passes a push (a `.pass` mark a session left is removed first), and every command Dot
    runs ends with what it started however the night ends (the seventh review).

  A whole night is bounded (two hours: its rounds and checks waits are cut to it, and none starts past it; a push
  through the review hook already under way has half an hour of its own), so that a restart asked meanwhile never
  gives up on it; a merge whose pull then fails is still a merge (the fourth review). A problem a stopped daemon left
  *being fixed* is open again at the next night, and `/usage` is read through its model (the eighth review). The
  checkout's print holds the contents of its changed and untracked files, and is read after every session that
  merged nothing, a failed one too; a pull request's files are read from GitHub every page (the ninth review). Dot
  pushes from the owner's checkout, never the session's, after fetching main, so that the hook's reviewer reads the
  owner's REVIEW.md and settings and the current main (the tenth review). The session is given its item number:
  Dot takes it with the repository's `scripts/next_item.py` and its own sign-in, as the session cannot reach GitHub
  (the eleventh review). The hook's review is read from the path it names, relative to the owner's checkout, and a
  problem whose pull request is open waits for the owner rather than getting a second one (the twelfth review).
- The session's environment holds no API key, and no folder of the owner's Dot.

**Built.**
- **`repair/night.py`.** `repair_night` reads the record into the book, then, while the day's sessions are not spent
  and the plan's window has room (`leave_room`, by `claude -p /usage`, Claude Code's own report read with no model
  call, as Codync reads it):
  - makes a checkout from `origin/main` and runs a session with `brief`, which fences the evidence as data;
  - reads the last line (`READY:`, `NO FIX:`, `NEEDS OWNER:`);
  - checks the branch's files, pushes it through the review hook (a review that stops it goes back to the same
    session, `--resume`), opens the pull request, checks GitHub's files, waits for its checks, and hands the failed
    ones back with the end of their logs, fenced; a session that holds a failure not its own gets the checks run
    again (`rounds` in all);
  - merges and pulls the owner's checkout when it is on main, or leaves it for them;
  - tells the owner, keeps the session and the plan's window, and removes the checkout.

  A merge ends the night (pulled into the owner's checkout or not), and when it was pulled the restart is asked for
  then: going on in a process whose code on disk changed, and
  past the bound the restart waits for the night's work, was the review's finding. A failure the session could not end
  on (the emergency stop, a defect) leaves its problem as it was.

  A session the window refused is no try and no session of the day's. Once another account is signed in (the owner's
  switcher moves to the next account at a limit), the night goes on with it; otherwise it ends. The emergency stop
  ends it before the next session. Each session works on a branch of its own, deleted when it opened no pull
  request.
- **`repair/github.py`.** git and `gh` by argv:
  - a checkout of its own;
  - the branch's items, commits and files, the push through the hook (its review read when it stops the push), the
    pull request opened;
  - the files and checks of a pull request, with `gh pr checks` exiting 8 or 1 read as its list, "no checks
    reported" as none, and any other failure raised;
  - a failed check's log, and its run again;
  - the merge, and the fast-forward pull;
  - `human_paths` reads REVIEW.md's list.
- **The scheduler.** It starts the night at `[repair] time`, the daemon's alone, and names it in its night's work, so
  that a restart waits for it. `repair_now` starts one by hand.
- **The page.** `GET /api/repair`, `POST /api/repair/now`, and Settings › Rules and memory › Self-repair: the account,
  the problems, the sessions, Run now.
- **`[repair]`.** Off with no `repo`; `merge = "ask"` by default. `docs/repair.md`.

**Checked.** `tests/smoke/test_repair_night.py` plays whole nights on a real git repository (a bare origin and the
owner's checkout), with stand-ins of `claude` and `gh`, without a model or the network:

- a fix that changes `src/dotagent/policy/` waits for the owner and is not merged;
- the session had no GitHub token, `gh`'s sign-in in an empty folder and no credential helper, and Dot pushed the

- the review hook stopping the push sends its review back to the same session, whose next commit is pushed and
  merged;
- a session that pushes its commit to main itself stops the night, merges nothing, and tells the owner;
- a session that writes a file in the owner's checkout outside its own stops the night before any merge;
- a mark of a passed review a session left for its own commit is removed, and the hook reviews the push;
- a session that wrote in the owner's checkout and whose push then failed stops the night all the same;
- a merged branch is deleted by Dot on GitHub and here (`gh`'s own deletion fails on a branch a worktree holds);
- a change to `src/dotagent/repair/` waits for the owner though the test's REVIEW.md does not list it;
- no defect lets the problem go and tells nothing;
- the plan's window refusing a session ends the night, and the next one asks nothing until it resets;
