### 2040. Several secrets on one card, on the phone and on the web

**Status: done (2026-11-27), not merged until the independent security review and the owner have seen it.** The owner's
ask (SR1, after another app's card that asks App Store Connect's Issuer ID, Key ID and .p8 file in one card): the
agent draws the inputs a task needs, asks them on one card, and uses the secrets safely.

What changed:
- `ask_secret` takes `fields` (2 to 4) instead of `name` for things that go together: each field's name (the
  environment variable its commands read), its words and its kind: `secret` (a box that shows no letter), `text` (one
  that shows them, an id the owner copies) or `file` (a key file picked; UTF-8 text, at most 16 KB, its text in
  `$NAME`). The one-`name` call stays as it was. A field the chat holds already is not asked again.
- The kind changes the box alone: every value is held 24 h, at least 8 characters, masked as before; a file's text is
  masked whole and line by line (lines of 16 characters or more; a PEM's first and last lines are no secret).
- The daemon puts each field's limits in the card (`min_chars`, `max_chars`); the phone and the page read them.
- `POST /api/approvals/{id}/secret` takes `{answers: [{name, value}]}` for a card of several: every field once, held
  all or none in one write of the chat's file (`save_secrets`), taken back in one write if the card was answered
  otherwise. An older client's `{value}` on such a card is refused with a word to update.
- DotNext and the web draw the same card: each field's words and `$NAME`, its box or file picker, Save securely once
  every field holds a value, Decline. A card of one value is unchanged, its short-code path too.

Decided after two independent reviews (a security red team and an API/product reviewer), recorded with their dissent
in the item's PR: no unmasked kind (a run could read any value with `echo`), a file as content not a path (a guarded
folder or a cross-chat leak), no persistent vault, no "use the saved one", no `optional`/`hint` in this slice. The vault
is its own item, with its own red-team review.

How it was checked (on this Mac, the fast checks): `tests/unit/test_held_secrets.py` (fields held together, one bad
field holds none, taken back in one write, a card answered by its fields alone, a file's lines masked),
`tests/smoke/test_ask_secret.py` (a real server: a card of three fields, an older client's value refused, every value
reaches the command, the key printed whole and by line masked, no value in an event or a file but the chat's own),
`tests/js/secretfields.test.js`, DotEngine's `ChatRulesTests`, one DotNext build-for-testing and the String Catalog.
On GitHub: the web's browser test at 1440 x 900 and 390 x 844 and DotNext's
`ChatUITests.testACardOfSeveralSecretsTakesEachFieldAndWaitsForTheKeyFile`.
