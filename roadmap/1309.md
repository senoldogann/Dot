### 1309. A retired Ollama cloud model is remembered, its replacement is named, and the doctor says which role names it

**Status: done (2026-11-22).** Ollama's service answers HTTP 410 for a cloud model it retired ("minimax-m2.7 was retired on
November 9, 2026. Try glm-5.3-flash:cloud."). Item 1195 left such a model out of the model list and logged it, but the
replacement the words name was never offered, every refresh of the list asked the dead model again (eight events in the
log), and nothing said that the configuration still names it.

- `llm/ollama.py`: `RetiredModels` remembers each retirement for 6 hours by server and model (`RETIRED`, shared by the
  process); `suggested_replacement` reads the model after "Try" in the service's words; `list_models` does not ask a model
  remembered as retired, forgets those the server no longer lists, and logs `ollama_model_retired` with `use`; a call
  of a retired model (`_details`) is remembered too; `OllamaProvider.retired()` gives the entries.
- `GET /models` gives Ollama's `retired` entries (`model`, `use`, `message`, `since`; the field is empty for the other
  providers).
- `dotx doctor` has a row `ollama model <name>` for each retirement the process knows: it fails when a role of the
  configuration (`main`, `vision`, `fast`, `review`, `helpers n`, `standby n`) names the model, saying which and what to use;
  otherwise it passes and says the model is gone and what to use. Nothing is rewritten. The rows come after the checks of
every role, helpers and standby included: `dotx doctor` runs in a process that knows no retirement until a model is asked
about, so a model that only those two roles name was missed when the rows were built before them.

Not done: a schedule's own model is in the store, which the doctor does not read, so a schedule that pins a retired model is
not named (its firing fails with the service's words, which hold the replacement); the page of Models shows no new line
(the API has the entries). Found while testing: the shipped `defaults.toml` names the retired `ollama:minimax-m2.7:cloud`
for `main` and `review`; an owner who does not set them in `config.toml` gets the new doctor row failing. Left as it is: the
choice of a new default is the owner's.

Checked: `tests/unit/test_ollama_retired.py` (the replacement read from the words, the TTL with a fake clock, the dead
model probed once across refreshes and again after the TTL against a stand-in server, a removed model forgotten, a call
remembered, the doctor rows with and without a role naming it, the models API entry), the doctor tests
(`tests/smoke/test_doctor.py`: through the doctor's own checks against a stand-in Ollama server, a model that only
`helpers` and `standby` name gets its row, naming both).
