### 1074. A delegated run stands under its chat, which works while it does

**Status: done (2026-11-09).** The owner's screenshot of 2026-11-09: a row "Work order wo_…: Dr…, web · delegated by
another run, Working 1m" stood in the sidebar as a chat of its own, while the chat that gave the order showed as ended:
"subagent sohbetleri sol sohbette görünmemeli, ana sohbet working olarak devam etmeli".

Why: the sidebar nests a delegated run under the row of the run that delegated it, among the runs at work
(`nestRows`). A work order's attempt outlives the lead's turn that gave it (item 907), so once that turn ended the
attempt had no parent among the rows and stood as its own row, "delegated by another run".

Now each row of a delegated run carries the chat of the run at the top of its delegations (`ActivityRow.root_thread_id`,
`server/activity.py`). The sidebar (`placeWork`, moved to `nesting.js`) puts a delegated run whose parent works no more
under that chat, which stands at work (its creature working) while the run does; the home's Today strip lists no
delegated run as its own row.

Checked by `tests/js/nesting.test.js` (the attempt under its chat, the chat at work, no row of its own),
`tests/smoke/test_activity.py` (the row's chat) and the sidebar's browser tests (`test_side_working.py`,
`test_working_rows.py`).
