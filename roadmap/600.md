### 600. A page Dot made in its workspace is shown whole, with the files beside it that it names written in

**Status: done (2026-10-24).** The owner asked whether Dot should not be able to open what it made on this Mac, and
approved a preview of a page with its own files (2026-10-24, "herşeye onay veriyorum"). `show_page` showed a page by its
path (item 598) as the file holds it, and a shown page is sandboxed and loads nothing of this Mac (`PAGE_HEADERS`), so a
page that keeps its styles, scripts or pictures in files beside it was drawn without them.

The approach. What must hold: a shown page stays what it is, sandboxed, with an opaque origin and nothing of the Mac to
load; no new address of the daemon, no change to the guard. So the files are written into the page when it is shown,
and only files `read_file` reads without a question. What only asks is not needed here: nothing the run could not read
reaches the page.

**As built.**
- `tools/page_files.py` `with_its_files`: the page's start tags and style blocks are read with Python's HTML parser, at
  the places they stand in the text. A linked style sheet becomes a style block (its `media` kept), a script's file its
  text (its other attributes kept, `</script` in it escaped), and the files a tag shows or plays (`img`, `source`,
  `audio`, `video` and its poster, `track`, `input`, SVG's `image`) and the pictures and fonts a style uses (`url()` in
  a sheet, resolved from the sheet's folder, in the page's style blocks and in a tag's `style`) `data:` addresses of
  their kind. The page's text and the edits are joined once.
- A file is written in only when it is one `read_file` reads without a question: in the workspace once its links are
  followed, neither protected nor Dot's own (`classify_path` is `workspace`), not kept from a crawl or an MCP answer
  (item 494). A web address, a `data:` one, a fragment and a path from the root are left as written.
- And only while the page with it stays one page (500,000 characters): each file is measured before it is read (its
  `data:` address, or its text) against the room left, less a margin for what escapes add, and one that would not fit
  is left out and the page shown without it, as item 598 showed it. A page that still comes out longer (a file that
  grew while it was read) is shown as written. A sheet a style imports (`@import`) is not written in (a shown page's
  styles load from no `data:` address) and is named. The tool's answer names the files written in, those left out and
  those that did not fit.
- A file is read as it was judged: opened without following a link, and judged again by the path the kernel opened
  (`F_GETPATH`), so a file swapped for a link to a protected one, or its folder for a link to a protected folder,
  after it was judged is not read; `read_file` keeps that race for a later item. A path that cannot be read (a NUL in
  it, a file this process may not open) is left out and named, not an error of the tool.
- The pattern of `url()` and `@import` bounds every run and takes no parenthesis in a name, so a style of unclosed
  `url(` is read in linear time: the regular expression holds the interpreter, and with it the daemon, while it runs.
- What a script loads by itself (a module's imports, a fetch) does not load: the sandbox's limits stand. The refusal of
  a `file:` address of a page (item 598) says the files beside it are written in.
- `docs/runs.md` says it, and the tool's description.

**Tests.** `tests/unit/test_page_files.py`: a site with a style sheet (with a picture and a font of its own folder's
neighbours), a script that holds `</script>`, a style block, pictures by `img` and SVG `image`, and a picture one folder
up in the workspace, all written in; a web address, a `data:` address and a fragment left; a protected picture, a
crawl's, a missing one and one through a link out of the workspace left out and named; a tag's `style` with a picture;
a picture larger than a page left out wherever the page names it, and the page shown, one page long, with the rest; a
sheet a style imports named; a page that comes out longer shown as written; 400,000 characters of unclosed `url(` read
in under two seconds; a large picture named forty times measured and never read; a file swapped for a link, and a folder
swapped for a link, after they were judged, not read; a NUL in a link and a picture that cannot be opened left out.
