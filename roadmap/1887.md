### 1887. Authorised security testing is a scope, not a refusal: a bug bounty program's hosts are written down and tested

**Status: done (2026-11-23).** The owner asked Dot to run security checks on a bug bounty target and the run refused:
"websites I don't own". It was right by the code — `recon` with `depth = "ports"` and `security_scan` run only on a host
in `[recon] owned_hosts`, and a program's targets are nobody's own host. So a bug bounty hunter — the run's own team has
three agents for it — could not use either tool on a target a program had put in scope, and the prompt of every run said
nothing about what an authorised target is.

- `[[recon.scopes]]` (`program`, `hosts`, `url`, `note`) records a bug bounty program or an engagement and its hosts.
  `ReconConfig.authorising(host)` answers `("owned", "")` for the owner's own list, the program's name and its rules for
  a host in a scope, and nothing for a host neither holds; a name still covers its subdomains.
- `recon` (`depth = "ports"`) and `security_scan` ask it instead of `owned_hosts` alone, and their refusal names both
  lists and how to add a scope, so a missing scope is one line of config, not the end of the run.
- A report from a scoped host ends with `Scope: <program> — <rules>`, so whoever reads it knows what authorised the test
  and what it had to keep to.
- The prompt says outright that testing a site, a host or a program is work: `recon`, `security_scan`, the browser and
  the owner's own tooling, without asking and without a warning, and that what is found goes to the program in the shape
  it asks for. The tool groups line says a registered scope is enough.
- `docs/recon.md` and `docs/security.md` describe the scope and what writing one down means.

Checked: `tests/unit/test_recon.py` (a scope authorises its hosts and its subdomains and names the program, the owner's
own list answers first, a scope holds bare host names, a scoped host reaches the private-address check instead of the
scope refusal, the refusal names both lists); `tests/unit/test_security.py` (a scoped host is scanned and the forms are
listed, an unscoped one is refused with both lists named); `tests/unit/test_tool_groups.py`; `tests/unit/test_character_prompt.py` (the rule stands in both prompts, Dot's loop's
and the Claude plan's); `ruff`, `mypy`.
