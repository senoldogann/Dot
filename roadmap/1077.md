### 1077. The files a chat made show as they are, from the Changes tab and from their names in the answer

**Status: done (2026-11-09).** Asked by the owner, with a screenshot of the Changes tab: the HTML, PDF, text and
Markdown files Dot made should show cleanly there, and a file named in the conversation (tagged, or a word ending in
`.md` or another suffix) should open its preview when clicked.

Before: the Changes tab opened a file only on its diff; the panel showed an `.html` file as code; a file opened from the
answer only when named in code by its full path (`~/…` or `/Users/<you>/…`), while Dot often names what it made by its
name (`README.md`).

Now:
- Each row of the Changes tab has an eye that shows the file as it is now beside the conversation (a page drawn, a
  PDF's pages, a Markdown file formatted, a text), without opening the diff.
- A web page (`.html`, `.htm`, up to 10 MB) is drawn as a browser draws it: the daemon keeps a copy in `looks/` as it
  keeps Quick Look's drawings (macOS's Quick Look draws no HTML: `qlmanage -p -o` writes only a `.url`) and serves it
  under the same sandbox (`LOOK_HEADERS`), and the panel frames it sandboxed with nothing allowed: no script of it runs
  (the pre-push review: a script may take its own frame to another site, which a frame's sandbox with `allow-scripts`
  allows, and draw a false page in Dot's panel) and no refresh moves it; it reaches no server, nor the pictures and
  styles beside it on the disk. A page that draws itself with a script shows without what the script draws.
  **Source** shows its HTML as code.
- A file named by its name or the end of its path opens too: in code with a suffix files have, in words a document's
  (`md`, `html`, `pdf`, `txt`, `csv`, `docx`, `xlsx`, `pptx`). The daemon finds a relative path in the workspace: the
  workspace's own, else the newest file (no link) outside hidden folders whose path ends so (among the first 20,000 entries).
  What it finds is judged as every path the panel shows (`located_file`), so a link in the workspace to a hidden or
  outside file is refused as before; `..` is refused.

Not done: a file a message names outside the workspace by its name alone opens nothing (the panel says there is no
such file in the workspace); the run's summary card above the Changes tab keeps its names as text.

Checked by `tests/smoke/test_changes_panel.py` (wide and light, phone and dark: the eye, the page drawn with its script
run in a sandboxed frame, its source, a name in words and one in code in the answer) and `tests/unit/test_previews.py`
(the newest of two, a path's end, a hidden folder, `..`, a link to a hidden file).
