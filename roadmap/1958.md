### 1958. A login refused on another host says the one step the owner takes for it to fill there

**Status: done (2026-11-26).** The owner's Apple Developer run of 2026-11-26 (run_mwxgc0a9_95badb, 261 s, 38 calls,
then run_mwxgssp4_e1839b, 322 s, 53 calls) began in Dot's Chrome and moved to Safari after a problem there; the owner
asked to find and fix that problem if it was Dot's.

What failed in Chrome, from the run's events: `browser_open developer.apple.com/account` landed on Apple's sign-in at
`idmsa.apple.com`; `browser_fill_login` with the vault's login of `appstoreconnect.apple.com` was refused, as the site
rule says (items 493 and 1208: a login fills on its own host or a host under it, and two hosts that end alike say
nothing of one owner). The run then typed the Apple ID itself, looked for Chrome's AutoFill (a reload, an arrow key, a
click at a pixel, seven screenshots in 90 s), went to Safari's AutoFill through the desktop tools, met the sheet that
asks for the Mac's password and stopped; its answer blamed the Mac's password. The owner gave that password in the
chat and the second run signed in through Safari's AutoFill.

Dot's part: the rule held as designed, but the refusal sent the run to "tell the owner that the site signs in on that
page", not what the owner does about it, and with Dot's vault there is one way only: the vault keeps one website a
login, so a login of its own for `idmsa.apple.com` with the same username and password (App Store Connect's own sign-in
form is in a frame of `idmsa.apple.com` too, item 1342, so a login of `appstoreconnect.apple.com` fills nowhere on
Apple's sign-in). Fixed: the refusal names the host the site signs in on and the owner's one step by where the login is
kept (`_owner_adds` in `vault/hosts.py`): in Dot's vault, a login for that host in Settings › Vault with the same user
name and password; in 1Password, the host added to the item's websites. It still names no wider site (1208), and only
the owner adds a host; nothing a run can call does.

Left to the owner: a login of Dot's vault that names more than one site (one record, several hosts, as 1Password's
items do) is a change of the vault's records and of its form, which touches what a password is filled on; it waits on
their word.

Checked: `tests/unit/test_vault.py::test_a_login_refused_on_another_page_sends_the_run_to_its_own_site_and_proposes_no_wider_one`
(the step for each place a login is kept, the host named, and still no wider site).
