### 899. The deep review of 2026-11-01: what eight reviewers found, fixed

**Status: done (2026-11-01).** **Asked** by the owner (2026-11-01): "Tüm projeyi derinlemesine review ettir haiku veya
sonnet kullanarak. Ardından bulguların hepsini düzelt, test et, birleştir." Eight Sonnet reviewers, two at a time, each
one area read statically (the agent core; the server; the tools; the scheduler, watchers, initiative and trading; the
store and memory; the web UI; the browser, iMessage, MCP and the model router; the desktop shell). Every finding was
read again in the code before it was fixed; what was not fixed says why.

**The taint model.**
- A campaign session's answered question vouched always (`_decide_for_session`): now as any run's (`can_ask_user`,
  item 508). The answer's `said`, what the review model takes as the owner's instruction, held the question the run
  wrote (which a page may have written): now the owner's words alone (`_answer_said`), in a run at work, in the goal
  of the run an answer starts once the asker has ended (the question stays in what its model reads first), and in the
  instructions of a campaign's next session.
- `memory_save`, `memory_update` and `todo_add` marked by the taint as it stands: the owner's "go on" cleared it and a
  note quoting the page was saved clean. Now by `ever_tainted` (also given to OpenCode's tool context).
- A schedule a tainted run made fired clean for good: `ScheduleOptions.from_outside`, set from `ever_tainted` and kept
  in its own column (`schedules.from_outside`, added to an existing database), starts every firing tainted as a
  watcher's run does, kept through the owner's edits.
- An MCP call that failed without the server's answer gave the model the server's message and stderr tail unfenced:
  now fenced and untrusted (`_lost`); an error of Dot's own words (a timeout) is raised as before.
- A Markdown link whose words name another address showed one site and opened another: the host it goes to is said
  beside its words (`linkWords`).

**What the owner approves.** `create_agent`'s card showed the name and role only: now its tools, model, refusals and
instructions. `schedule_create`'s card cut the goal at 600 characters: now the whole goal. An agent may not be named
Dot (the tool and `POST /api/agents`; one named so before is still changed), and the words of one a run makes are
masked of the secrets Dot holds.

**Scheduler, watchers, trading, initiative.** A firing is written only while its schedule is still on and due at that
time, with the goal and times it was found with (`claim_schedule_fire`): an edit, switch-off or delete made meanwhile
stands, a one-time schedule's edit at its own time too. A recurring schedule that cannot
fire backs off as a one-time one does; one skipped for its time passing after such failures says why. A watcher writes an item down as
soon as its run starts, so a failing line or tell cannot start a second run. One trading exit that fails no longer
loses the tells of those that sold. A thing of Dot's own whose start failed in any way is open again, not "doing".

**Store and memory.** Saving the words of the owner's or a pinned note again keeps its time; deleting a chat keeps the
owner's lesson saves; a vector is written only while its note has those words, and a restore replaces a stale one;
the migration takes the write lock first; a pruned tainted run counts as having read outside content
(`read_outside`, `outside_reads`); a note that holds for a while is not merged by hand; a deleted agent's queued
messages go with it.

**Server, UI, desktop.** Two asks of one loop at once make one schedule; a held secret is let go whatever kept its card
from being answered; the browser switches write the config before they take effect; the office pages a long run's
history; an older status read that answers late shows nothing; the desktop window follows a daemon that comes back at
another address or with another token.

**Not changed, and why.** Making the yolo answer vouch for nothing (item 508 chose otherwise, and its test says so) and
not counting a run by hand toward switching a schedule off (item 458 counts it, documented): both are designs, not
slips. An exit under the minimum size is marked failed: it cannot be sold, and the owner is told. The browser routes'
check of runs at work before a change is not held under a lock against a start (a narrow window, left). The
`_refresh_memory_index` read at every open (a cost, not a fault). The installer's upgrade that a quit does not stop and
its children killed by pid alone (`installer.rs`, which always needs the owner's look): its own item.

**Checked.** The unit suite (6,557), the gate's smoke suite (1,196), `dotx eval check`, `npm run check`, `cargo fmt`,
`clippy` and `cargo test` (88), the office and approval browser tests; new tests for the memory mark after a cleared
taint, the fenced MCP failure, the link's host, and a marked schedule kept in the store and firing tainted.
