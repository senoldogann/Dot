### 741. What a script's page sent is said with its value

**Status: done (2026-10-27).** **From the owner's runs** (30 days): of 628 `browser_eval` calls, 421 called a site's
own API with the page's session, and 125 of them were POSTs that sent mail through a webmail's API and messages
through Slack's. All of them were of yolo runs whose goal asked for it, and the owner wants no question in yolo; but
the run's record named none of it: a script is one click of medium risk, and what it sends goes by no flag.

**The change.** While a script runs and the page settles after it, the session notes the requests its page sends
that are not reads (not GET, HEAD or OPTIONS), by method, host and path, without their query, and counts them
(`session.run_script`, `ScriptRun.sent`); the value says them (`[the page sent, while it ran: POST
api.example/send (×2)]`, the first ten, inside the page's fence, with the secrets of the chat held back) and the
log has a line (`browser_script_sent`, how many and to which hosts). Nothing is held back or asked about, in any mode:
the run, the owner reading its record and the review model that reads its steps see where a script sent something.

**Checked.** `tests/smoke/test_browser_eval.py` in a real headless Chrome: a script whose page POSTs twice to one
address and reads a page says `POST <host>/api/send (×2)`, its query left out, and a script that sends nothing says
nothing; the rest of the file passes. The new test fails on the code before.
