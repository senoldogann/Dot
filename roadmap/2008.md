### 2008. The browser as the last resort: what a week of browser use was, and a run told to go straight to its page

**Status: done (2026-11-27), prompt part.** The biggest saving (mail of an account that is neither Gmail nor Outlook)
waits on the owner's choice of how Dot reads it.

The owner asked (2026-11-27, from Grok Bot's habits) that Dot use an API, an MCP server or a connector before the
browser, and give the browser a narrow brief when it is needed. Measured first, read only, from the owner's store over
the seven days to 2026-11-27 (counts only):

- 1,243 browser calls in 1,187 model steps, about 7,450 s of model time and 2,935 s of tool time. 41 runs used it: 20
  of 33 schedule runs, 13 of 70 chat runs, 6 team runs, 2 others.
- By site, in steps: the webmail of the owner's own domain 298 (about 2,100 s), Fiverr 279, digiahub 115, Braintrust
  114, x.com 84, jobexio 50, witted 50, an events calendar 36, Google's sign-in 22, Stripe 16.
- Was there a tool for it? The webmail: no. `mail_search` and `mail_read` read Gmail and Outlook only (OAuth), and that
  account is neither, so a quarter of all browser steps read and answered mail through a web page. Fiverr, Braintrust,
  digiahub, jobexio and witted offer a seller no API: the browser stays, and Dot's learned skills are already kept per
  site and handed first for the run's site. x.com: Dot has no X API tool (the API is paid). The schedules' own goals
  name the webmail page. The prompt already ranked the channels (shell and files, APIs and MCP, web, browser, desktop).
- Overhead: 312 of 442 `browser_act` calls had one step; 52 `browser_new_tab` and 56 `browser_switch_tab`, mostly a
  run juggling tabs it opened itself (a click that opened a tab stopped the batch 11 times in 30 days); 33 times a run
  opened a page again that it had open; 16 snapshots right after an act; 47 calls failed (15 of them `browser_wait_text`).
- Log-ins: 46 calls (`browser_logins`, `browser_fill_login`, `browser_create_login`, `browser_captcha`), about 4 %;
  `ask_user` was used twice. A run that meets a wall only the owner can pass asks them to Take over, which main has
  (`POST /api/runs/{id}/takeover`, then `/handback`); the "Computer: action needed" card is the follow-up pull request #1191
  names, not rebuilt here.

What changed: the Browser section of the system prompt tells a run to start on the page the work is on by the direct
address it was given or found (never a guessed one, as the Web section says), to work in one tab (a new tab only for a
page kept beside another, never a page again that it has open), and to take a snapshot after an act only for what the
act's result did not show. `delegate`'s `goal` asks, for browser work, the address to start on, when to stop and what to
report. The task prompt grows by about 79 tokens and the tool schemas by 32
(`tests/fixtures/prompt_surface/summary.txt`); a first wording took 103. The first step's budget
(`tests/smoke/test_context_budget.py`) is raised by 100, and its system budget by 100, saying why.

Not done, for the owner: a mail source for an account that is neither Gmail nor Outlook. Recommended: read the account
from Mail.app when it is set up there (no new credential); otherwise IMAP with the password Dot's vault holds, which is
a credential's new use and needs the owner's yes and a security review.

How to measure after: the same counts over the seven days after the deploy (browser calls and steps per site, new and
switched tabs, pages opened again, snapshots right after an act).

Checks: `tests/unit/test_prompt_surface.py`, `tests/smoke/test_context_budget.py`, `tests/unit/test_freedom_contract.py`
(nothing new is asked or refused), `dotx eval check`.
