### 981. A phone does not take away an allow rule that stands before a preapproved one

**Status: done (2026-11-05).** **Found** by the security audit of 2026-11-05 (the owner's ask; run-1 lead
`dotagent/server/routes-data:rules:phone-removes-allow-rule-shadowing-preapproved`): a phone's key may not widen for
good what runs do without asking (item 678), and the rules routes judged a change by the changed rule alone: switching
off or deleting an allow rule was let through as narrowing. The first rule that fits decides, and an allow rule turns to
a question for a run that read outside content where a preapproved rule does not: with an allow rule above a
preapproved one that fits the same steps, a phone that took the allow rule away let those steps through unasked, for
good.

**Built.** `server/routes_data.py` `uncovers_preapproved`: switching off or deleting an allow rule with an enabled
preapproved rule after it is refused from a phone (403), as a move of any rule is. Docs: `docs/phone.md`.

**Checked.** `tests/smoke/test_phone_limits.py` (a phone is refused both for an allow rule above a preapproved one, and
let through once none follows it), `tests/smoke/test_rules.py`.
