### 568. A chat left and come back to while its run works shows each message once

**Status: done (2026-10-23).** The owner, again: "on the phone, the desktop and the web the agent writes the same things
two or three times in the chat". Item 567 had dropped a reply that the answer repeats; read against a week of the
owner's runs, the replies the answer repeats were 49, and the comparison before item 567 already dropped 47 of them, so
two or three of every message came from somewhere else. It is the page: a run's page keeps what it read of the stream
(item 426) and, coming back to the run, draws that at once and follows the stream on after the last message's id. A
piece of a thought or of a message being written is live only and has no id (0); when the page was left while the model
was thinking or writing, as it mostly is with a model that thinks at every step, the stream started again from the first
event, and every message, tool group and answer of the run was drawn a second time, a third after a second return. The
same code serves the browser, the desktop app and the phone.

**As built.**
- `views/run.js`: the stream goes on after the highest id among the kept messages, the last stored event read, not
  after the id of the last message kept.
- `docs/daemon.md` says it.

**Tests.** `tests/smoke/test_answer_once.py`: a run writes a message, then thinks while the page follows it; the reader
goes to Settings › System and back, twice; once the run ends, the message and the answer are each in the chat once. It
fails without the change (the message twice after the first return).
