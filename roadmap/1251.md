### 1251. The review model reads the whole of what an action does, in parts when it is long

**Status: done (2026-11-19).** The code review of 2026-11-19 found two ways the review model approved what it had not
read (K3-01, K3-02):

- An action whose target or body passed 12,000 characters got `escalate` without the model being asked. In `auto` that
  asks the owner, but yolo's taint check stops only at `deny`, so in a tainted yolo run such a step ran unread.
- An MCP call's arguments reached the review, the owner's rules and the card as 300 characters of the summary; a
  schedule's goal as 600. The whole call ran.

Now the review reads a long action in overlapping parts of 12,000 characters (2,000 shared between neighbours; a field
short enough for one part is shown whole in each), one question each, asked side by side; the strictest answer decides
(deny, then escalate, then approve). Past eight parts (about 82,000 characters) it still hands the action to the owner
unasked, and yolo's taint check refuses such a step with how to go on (split it), instead of letting it run. An MCP call
longer than the summary shows carries its whole arguments, secrets masked, in `ActionInfo.body`, as a page's script does
since item 985; the summary, which is a schedule's whole goal, is read whole too, not cut to 1,500 characters in the
middle (the pre-push review found the first version left schedules as they were). Autonomy is unchanged: yolo still asks
nothing, and a step the model reads and does not refuse runs as before.

Checked: `tests/unit/test_review_target.py` (a 32,000-character command read in four parts, every name of it seen; a
100,000-character script handed on unread; the strictest part decides), `tests/smoke/test_taint_check.py` (a
200,000-character step refused with "split it" in a tainted yolo run, a short one still done), `tests/unit/test_mcp_pure.py`
(the link past the 300 characters is in the body).
