### 1462. Dot for iPhone: agents are bots, not letters

**Status: done (2026-11-24).** The owner, after using the build on his phone "Proma" (2026-11-24, 08:47): "the other bots must have a
bot icon too, not a letter in different colours, and the same in the chat area". Every agent but Dot wore a disc with a gradient
in a hue taken from its id and its first letter (`Avatar`, `hue(of:)`): "J" in pink, "S" in tan, a colour the agent never chose,
on the agents strip and the chat list's rows, and nothing at all in the chat itself, where the web app's line "starts with the
face of who works" (items 843 and 859).

What changed:
- One `AgentAvatar` (Features/AgentAvatar.swift) draws every agent: Dot wears its own face (`DotGlyph`), every other agent
  Lucide's `bot` (item 1461's icon, drawn as a template) on one neutral disc, the theme's raised ground and a hairline (a
  stronger one under Increase Contrast), whatever its id: no hue, no initial. The ring round it stays (`StateRing`, item 1460:
  it turns once in four seconds while the agent works, amber and still while it waits for the owner). `Avatar`, `hue(of:)` and
  their gradient are gone, and so is the `cornerDownRight` icon that only the helper rows used.
- Where an agent shows: the agents strip, the chat list's rows (both layouts), the inbox's rows (item 1442), the new-chat hero
  for an agent, the inspector's helpers (the bot, ringed while the helper works, where a branch mark stood), the design
  gallery, and **the chat itself**: the first line of an agent's since someone else spoke (its answer, or a message it wrote
  along the way) has its face at the leading edge and the lines that follow line up with its words (`AgentLane`, 28 pt);
  steps, a card it asks and a note are not someone else speaking, so the two lines on either side of them are one voice;
  the owner's message starts a new turn and is not given a face. At the accessibility text sizes there is no room for a lane and
  the face stands over the first line. The Live Activity (`DotLiveActivity`) draws no avatar, so it has nothing to change.
- The pure rules are in `Core/AgentLook.swift`: `AgentLook.face(ofAgent:)` (Dot for Dot or for a chat with no agent, the bot for
  every other id), `AgentLook.words(name:state:paused:)` (VoiceOver says "Research, working", "Research, waits for you", a
  paused agent "JobHunter, paused", one at rest its name alone: the strip's chips say it), `AgentSummary.state` (blocked is
  waiting, a run in hand is working; the strip had this rule in a private function) and `SpeakerRule.wearsFace(at:in:)`.

Checked: `ios/DotTests/AgentLookTests.swift` (8 cases: Dot's face and the bot's, no agent is told apart by its id, the words
VoiceOver says, an agent stands as its newest run does, and four of whose line wears the face: the first since the owner spoke,
the owner's next message gives the next line the face again, steps/cards/notes between two lines are no one speaking, a chat
that opens with the agent). `xcodebuild test` on the iPhone 17 Pro simulator (iOS 26.5), `DotTests`: 390 tests, 0 failures (382
before this item). `scripts/export_ios_icons.py --check` and `tests/unit/test_ios_icons.py` (11 cases) pass with `cornerDownRight`
gone.
Not checked: the look against the owner's eye on the phone (the screenshots of the pass that closed this branch are named in the
pull request); VoiceOver itself (the words are tested, the chip's label is set from them, no screen reader was run).
