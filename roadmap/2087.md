### 2087. main's smoke gate: the iMessage progress test no longer races the runner's speed, and a failed test leaves no run behind

**Status: done (2026-11-28).** Gate run 46131559515 on main failed two tests of `tests/smoke/test_channel_routes.py`,
the second with "The run failed. Internal error: IndexError: pop from an empty deque". Neither is a product bug:
- `test_a_run_that_works_longer_than_a_moment_tells_what_it_does_while_it_works_and_then_answers` asserted that the
  first message of progress, sent by the half-second timer, already lists both of the run's steps. On a loaded runner
  the second step came after the timer, so the first message told only the command, which item 618 means it to: a
  message tells what was done since the one before. The test now waits for the run to reach the gate after its two
  steps and checks that the messages of progress together tell each step once, in order, and the thought once.
- When that test failed, its `finally` cleared the scripted model while its run was still working; the run's next call
  found no turn, crashed with the empty deque, and its failure was told on the next test's channel, so
  `test_a_run_that_ends_in_a_moment_tells_only_its_answer_whatever_it_did` read it in place of its own answer. Both
  tests now stop and wait for their runs before clearing the model, and start only once no run is at work. The
  scripted model counts its calls (`Replies.asked`).

How it was checked: both failures reproduced locally by firing the timer before the steps (`progress_first_s=0.01`):
the same two failures as on CI, the deque crash included; with the change, the step check holds and the second test
passes. `test_channel_routes.py` and `test_channel_router.py` passed three times in a row with `-n 3`.
