### 704. Files go into a file field the page hides, without a click

**Status: done (2026-10-26).** **Measured:** 8 of 37 `browser_upload` calls in the owner's month failed. Six named an
`<input type=file>` that the site had moved off the screen or put under an icon (poolia.fi, finitec.fi, lokki): Dot
clicked it to open the file chooser, and the click waited eight seconds for an element it could not reach.

**The change.** `driver.upload_files` looks for the file field first: the element itself, else the one file field
inside it (a label that wraps a hidden field), and gives it the files with `set_input_files`, no click. Otherwise the
element is clicked and the chooser it opens is given the files, as before. A field beside the element is not taken (the
review of the first push): it may belong to another control than the one the run named.

**Checked.** `test_browser.py`: a field off the screen under an icon, a field hidden in its label, and a button in a box
of two fields that opens the second's chooser all get the file; a field beside a button that does not open it gets
nothing. Without the change the first fails as the owner's did (`Locator.click: Timeout 8000ms exceeded`).

**Not done.** A LinkedIn upload failed on a disabled button and on a chooser that never opened; neither is this.
