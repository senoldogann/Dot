### 1341. terminal_open and wait_until are in the prompt of a run on the Claude plan from the start

**Status: done (2026-11-23).** Self-repair found it in Dot's record: `terminal_open: Invalid arguments for
terminal_open`, three times in three runs on `claude_code:sonnet` on 2026-11-22 and 2026-11-23.

On the Claude plan Dot's tools are deferred (item 1053): the model sees their names only, until it looks one up, and
the prompt tells it to look a tool up before its first call (item 1201). The shell's description sends the model to
`terminal_open` (a command that runs past `timeout_s`) and to `wait_until`, and it called them by their names alone:
three of the seven calls of `terminal_open` in two weeks came with no argument at all (35 output tokens, refused for a
missing `command`), and `wait_until` came with guessed names (item 1340) or none. Each was a refused call, a turn lost,
or a fall back to `shell`. A probe with Claude Code 2.1.330 and an MCP server of two tools showed both sides: a tool not
looked up was called with an argument name the model made up (`mode` for `quokkafish_mode`), and a tool the server
lists with `_meta` `anthropic/alwaysLoad` had its definition in the prompt without a look-up.

  550 tokens) in every such run's prompt. An OpenCode door marks none: OpenCode puts every tool in its prompt.
