### 618. A run started from iMessage tells what it does while it works

**Status: done (2026-10-24).** The owner asked, of what Dot shows on iMessage, for "the agent's command running, its
thinking and the live flow: whatever we can show, we should show it in the richest way." Until now a run started from
the phone was silent until its answer: a run that works for a minute looks like a run that does nothing. iMessage cannot
edit a message it has sent, so "live" cannot be one message that grows; it is a few messages that do not flood.

**What must hold, and what only tells.**

| What must hold | Held by |
| --- | --- |
| no message before the run has worked 15 s; then at most one every 30 s, and six in all; none after the answer; a run that ends sooner sends only its answer | `Progress.due_at` and `message` (the limits, on the router's clock); the router drops a run's state at `run_finished` |
| a secret Dot holds is not told, whatever a cut would do to it | the arguments of a call (`redact_json`) and a thought (`redact_known`) are masked before they are worded and cut, and the whole message once more as it goes (`_say_progress`) |
| what a tool answered is not told | the router follows `run_started`, `assistant` and `tool_call` only; `tool_result` is not among its kinds, and the words are made from the call's tool and arguments |
| a page is told by its host alone, a file by its name, a command by its first 60 characters | `step_words` (`_host`, `_file`, `_command`) |
| only what a message of a channel started is told | `_followed`: the run is the root of its delegations, is in the channel's chat and has the channel as its `source`; a run typed in the chat's page, one in another chat and a delegated run are none of these |
| nothing is told to a channel that is off or has nobody paired, nor kept for it | `_tell_progress`: not `_reachable`, then `Progress.forget` |
| the owner can have only the answers | `[channels] progress = "off"`, live (Settings › Channels, `POST /api/channels/progress`) |

What only tells: the lines' words, their number (eight a message), and how repeated steps are counted.

**As built.**
- `channels/progress.py` (new): `step_words(tool, args)` words a call in the page's own terms: a command is `$ ` and its
  first 60 characters (white space single, a cut marked `…`), `read notes.txt`, `wrote summary.md`, `edited main.py`,
  `searched the web: <query>`, `read a page: example.com` (`web_fetch`, `web_extract`), `crawled a site: …`,
  `opened a page: …` (`browser_open`), `used the browser`, `used the desktop`, `handed work to a helper: <goal>`, `used
  the skill <name>`, a phrase for the tools that have one (`looked in a folder`, `kept a note`, …) and `used <tool in
  words>` for any other (an MCP tool by its server); the end, a question, the plan, the groups of tools, the help and
  the reading of a terminal say nothing a phone needs and are not told. `first_sentence` is the first sentence of a
  thought as one plain line of at most 160 characters. `Progress` keeps what a run did since its last message (the same
  step again straight after is counted, `×3`; at most 200 steps; a message holds the newest eight and counts the earlier
  ones) and its newest thought, and says when the next message may go and what it says: `Working for 45 s:` and the
  lines, the thought (`💭 `) last, and only when it is new.
- `channels/router.py`: `WATCHED_KINDS` has `run_started`, `assistant` and `tool_call`; `_follow` makes the lines (the
  store is asked once for a run, the answer kept until `run_finished`); `_tell_progress` sends a message when one is
  due, after an event and when the loop's wait ends (`_held_for` counts the next due time, so a run that has nothing new
  to say after 15 s still speaks at 15 s); `_say_progress` masks, keeps within the channel's size and sends. The
  router's windows go by an injectable clock (`time.monotonic` by default) instead of `time.monotonic()` called in
  place, which is what lets a test give the time; the limits are constructor arguments for tests (`progress_first_s`,
  `progress_apart_s`).
- `config.py` `ChannelsConfig.progress` (`"steps"` or `"off"`), `defaults.toml` (with its comment), `config_edit.py`
  (`ChannelsSetting`), `channels/service.py` (`progress`, `set_progress`, the view's `progress`), `channels/views.py`,
  `server/routes_channels.py` (`POST /api/channels/progress`, the config file written first as the iMessage switch's is,
  and the switch put back when it cannot be), and the card of `views/channels.js` (the **Progress messages** switch).
- Docs: `docs/channels.md` (how it works, what leaves this Mac), `docs/safety.md` (what leaves this Mac),
  `docs/daemon.md` (the route).

**Left out, and limits.**
- Six messages at 30 s apart end at 165 s: a run of twenty minutes is silent from about three minutes on, until its
  answer. That is the limit the owner set; raising it is `MAX_MESSAGES`.
- Only `thinking` is a thought. The text a model says beside its tool calls (`assistant.text`) is not told; a model that
  does not think has commands and tools only.
- The steps of a delegated run are not told, only the delegating (`handed work to a helper: …`).
- A message of progress is not an answer: no link is added, and it is not cut with the line that says the rest is in
  Dot.
- Nothing here changes the policy, the shell guard, the approvals or the sandbox.
