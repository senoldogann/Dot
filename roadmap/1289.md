### 1289. A question that asks the user for a secret is refused, and the run asks on the card

**Status: done (2026-11-21).** The owner's word of 2026-11-21: a Stripe sign-in wanted the verification code his phone
had just received, and the run asked for it with `ask_user`, so the question - and the code he would have typed as its
answer - sat in the chat: "secret sorma pop up'ı açılması gerekiyor sohbette, sormadı". The card (`ask_secret`) was
there all along; nothing told the model to use it, and `ask_user` took a secret as readily as any other question.

`tools/meta.py` reads a question before it is left: a noun a person names a secret by (a verification, one-time,
sign-in, 2FA or SMS code, an OTP, a password, an API or private key, a token, a card's CVV or PIN, in English, Turkish
and Finnish) together with a verb that asks for the value (what/which/have/get/know/use/write/type/enter/send/give/
share/tell/paste/reply with, and the Turkish and Finnish forms of give/write/send/tell). The verbs are whole words and
the nouns are stems, so the suffixes of Turkish and Finnish are the same secret ("şifreni yazar mısın?", "salasanan
annatko?"); a code or a key is only one with the word that makes it one (a bare "code" or "kod" is none: "should I
write the code in Python?", "which promo code?", "what is the error code?"). It only ever adds a refusal, never one
taken away: it asks on the card for "should I write the password reset page first?" too, where a card costs the user a
step and a secret in the chat costs more, and a question that names no secret ("did the verification code arrive?",
"is the promo code applied?") stays a question. A question that is refused is refused before it is left, and the run is
told what it asked for, which name to give the card and what the label and `why` should say. The system prompt says the
same in both styles: a code only the user can read is asked for with `ask_secret`, never with `ask_user`.

The way out of the card for a code too short to hold was half done: the code the user typed as the card's message
reached the run's words but not its instructions, so the page's one-time-code field refused it outside `yolo`. It is
now the user's own words, as the answer to a question is, and the result tells the run to type it in.

Checked: `tests/unit/test_secret_question.py` (the Stripe question and ten more read as what they are, in three
languages and their suffixes, "can I have", "may I have" and "do I use" among them; six questions about a secret that
ask for no value stay questions; `ask_user` refuses and names the card; a code typed on the card becomes the run's
instructions), `tests/unit/test_lean_prompt.py` (the rule in both styles, and the lean prompt still under half the full
one).
