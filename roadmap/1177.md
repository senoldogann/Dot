### 1177. A dropdown is chosen on a page whose library replaces `Array.from`

**Status: done (2026-11-14).** Dot's record showed `browser_act failed with an unexpected error (ValidationError)` four
times, each a `select` step on a job application form (likeit.fi's `Application.jsp`, TalentAdore): "N validation errors
for Dropdown, options.0: Input should be a valid dictionary or instance of DropdownOption, input_value='ref: <Node>'".
The script that reads a native `<select>`'s options called `Array.from(element.options, mapper)`. Those pages load a
library that replaces `Array.from` with its own (Prototype.js's `$A`), which ignores the mapper and hands back the
`<option>` elements themselves; Playwright returns a DOM node as the string `ref: <Node>`, so every `select` on such a
page failed, and the runs fell back to typing into the field or gave the form up.

- `driver.py`: `_DROPDOWN_SCRIPT` reads the options with a plain indexed loop, which no page script replaces.

Checked: `test_browser.py::test_a_dropdown_is_chosen_on_a_page_that_replaces_array_from` selects an option on a page
whose script replaces `Array.from` the way Prototype.js does: without the change it fails with the same
`ValidationError` as the record; with it the option is chosen and the view shows it selected. The other dropdown tests
of `test_browser.py` pass as before.
