### 1244. Firecrawl Local in the MCP catalogue

**Status: done (2026-11-19).** The owner asked for Firecrawl's local edition
(https://docs.firecrawl.dev/quickstarts/firecrawl-local): one Rust program, installed with `cargo install
firecrawl-local`, that scrapes, crawls and maps the web as Markdown from this Mac with no key and no account. Its `mcp`
command serves those tools over standard input and output, so the catalogue names it as a server started on this Mac
(`firecrawl-local mcp --public-only`), beside the cloud Firecrawl, and the Firecrawl plugin offers both ways.
`--public-only` refuses localhost and the private network, as `web_fetch` does unless `[web] allow_private_hosts`
(the pre-push review: Firecrawl's own page says an agent steered by a page's hidden words could open an internal
address). The tools are the npm package `firecrawl-mcp`, which the program runs with `npx`: `FIRECRAWL_MCP_PACKAGE`
pins it (3.40.0, the newest a week old), and `package_of` reads it there, so the pinning test and
`scripts/catalogue_versions.py` see it as every package `npx` starts (item 695). The program itself has no registry to
pin by, as Xcode's bridge has none: the one found on the login shell's `PATH` runs. `FIRECRAWL_CLOUD=search` sends
only its search tool to Firecrawl's cloud: by default a page that refuses this Mac is fetched there, and its address
would leave for Firecrawl (the second pre-push review).

Checked: `tests/unit/test_mcp_connect.py`; by hand on the owner's Mac, with 3.40.0 and `--public-only`, the server
started, listed its 30 tools, refused `http://127.0.0.1` ("a private address; private targets are off") and scraped a
public page to Markdown with no key.
