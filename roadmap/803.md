### 803. The interface has a map an agent can read, and it cannot drift

**Status: done (2026-10-28).** The video's feature map is a list of what the app can do, written before an agent is
asked to change it. Dot had 28 view files and no single page that said what each one was for; a reviewer had to read
the JavaScript to learn that `controls.js` is the light/dark control page and `settings.js` is the shell, not a page.

- **`docs/dot-ui.md`.** One row per view file: the page, the file, and what it is for. The map names the shell
  (`settings.js`), the home page (`runs.js`), one run (`run.js`), and the settings pages around them.
- **Three smoke anchors.** The map names `tests/smoke/test_harness_page.py`, `tests/smoke/test_memory_page.py` and
  `tests/smoke/test_rules.py`, the pages with the most wiring and the clearest failure a person sees.
- **The map cannot drift.** `tests/unit/test_ui_map.py` parses the table and fails when a view file has no row or a row
  has no file; it also checks that the three smoke files exist and contain a test function.
- **Measured.** `uv run pytest tests/unit/test_ui_map.py` — 2 passed; the table has 28 rows, one for each of the 28
  view files.
