**Status: done (2026-11-26).** Since item 1886 a pull request runs no macOS job: what only macOS shows is first seen on
main's own runs. The lead asked that such a red run be seen at once and that the owner's live Dot be updated only from a
commit whose macOS runs passed.

What must hold: one issue, "main is red on macOS", open while main's newest commit failed a macOS run, naming the runs
and jobs that failed, and closed once a commit passes; a check that tells whether main's newest commit passed (green),
failed (red) or has a run still to come (pending), so an update waits on green.

What was built: `scripts/main_macos_green.py` (stdlib and `gh`). `verdict` is pure: red when a finished run did not
pass, pending while the gate has no run or one is not finished, else green; it reads the commit's newest runs of

`report` opens the issue, comments on the open one while red, closes it when green, and leaves it while pending. A job
`main-health` ends each macOS workflow's run on main and runs `report` (it may write issues); its own run, not finished
while it runs, is read from its other jobs (`--this-run`); it waits for every other job of the run. The gate's verdict
is its run of the commit; the iPhone app's is its last run of a push to main, whatever its commit, as ios.yml runs only
for a push that changed `ios/` (a later commit that did not touch the app does not make a red one green).
docs/development.md and CLAUDE.md say to run `check` before updating the owner's Dot.

checkout and restarted Dot: with item 1886 that was code no macOS test had seen. A night that merged now waits for
