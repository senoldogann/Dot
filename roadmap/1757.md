### 1757. DotNext's engine reads and writes Settings: the settings routes, the proof of the key, the diagnosis by hop, the search, the pair link

**Status: done (2026-11-25).** Wave N3 of the iPhone rewrite, the engine's part (`ios/DotEngine`), for item 1759's
Settings.

What must hold:
- A route the phone reads is decoded from the daemon's own JSON (`server/views.py`, `config.py`, `store/models.py`);
  a field the engine does not name is ignored, so a daemon that adds one breaks nothing.
- The key is never sent to an address before it proved it holds it: `expectedProof` is the daemon's HMAC
  (`server/guard.py`: HMAC-SHA256 over "dot daemon proof\n" + nonce, keyed with the hex SHA-256 of a phone's key),
  checked against values the daemon's own Python computes.
- A refusal says the daemon's words: Dot's errors are `{"message", "context"}` (`server/app.py`); the engine read only
  `{"detail"}` (FastAPI's own shape), so every refusal of the daemon reached the screens without its words. Now both, and
  `refusedToAPhone` reads `context.phone` of a 403.
- A stray link or QR fills nothing: `pairingStart` takes only `dotnext://pair` with an https tailnet address and an
  8-character code, or a tailnet address alone.

What was built (`Contract/SettingsModels.swift`, `Wire/DaemonAPI+Settings.swift`, `Settings/`):
- The routes: `/assistant`, `/health` (sent without the key), `/status`, `/phone`, `/phone/push-settings`,
  `/models/main|roles`, `/code-review` (read), `/budget` (item 1731), `/usage`, `/schedules` (+ enable, disable, the whole
  `PATCH` with every key written, nulls included, as the daemon requires them), `/rules`, `/memories/search`,
  `/memories/proposed` and a proposal's take and drop (item 1711, with the `at` shown), `/reactions/settings`,
  `DELETE /failsafe`; the probes (`probeHealth`, `probeStatus`, `proveKey`).
- `diagnose` (pure): the probes into five hops, the first failure explaining the rest (no network, the `.ts.net` name
  unresolved = Tailscale off on the phone, nothing answers = the Mac asleep or its Tailscale off, connection refused =
  Dot not running, TLS, a daemon error, the key refused, the proof mismatched); `traceId`.
- `searchSettings` (pure): every word of the query begins a word of the title, path or synonyms; title matches first;
  case, accents and the Turkish dotted and dotless i folded.
- `settingsFailure` (pure): unreachable, key refused, refused to a phone with the daemon's words, Dot too old (FastAPI's
  "Not Found" of an unknown route, not a missing item), other.
- `PairingFailure.tooManyPhones` (the 422 of `check_room`), told apart from a refused code.

How it was checked: `swift test` in `ios/DotEngine` (`SettingsTests`, `SettingsFailureTests`, `PairingQRTests`,
`PairingLinkTests`: 16 tests, each red before its code); the proof's expected values computed by the daemon's Python;
the routes exercised end to end by item 1759's e2e against a throwaway daemon.
