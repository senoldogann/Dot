### 873. An agent a run makes gets the tools it names, never every tool

**Status: done (2026-10-31).** **Asked** by the owner, after the review of Dot against an agent-template article
(0xRafy, "GrokBot Templates", 2026-10-02): its rule for a good agent is one job and no leftover tool, since every tool a
role does not need is a way to go sideways.

What the owner's Dot showed (its database, 2026-10-28 to 2026-10-31): the four agents Dot made (JobHunter, Growth
Lead, Content Studio, Community & Launch) had `tools = []`, which for Dot's run means every tool, though the prompt's
Team section said "each with only the tools its role needs". `agent_tools` gave an empty list the maker's bound, and
Dot's bound is none.

- `tools/team.py`: `agent_tools` refuses a call that names no tool ("name the tools its role needs in tools, ..."),
  as it refuses a tool the run lacks; the maker's bound is no longer a fallback. The argument and the tool's
  description say the tools are named one by one, one job each; the result names them.
- `agent/prompt.py`: the Team section says "each with one job and only the tools its role needs, named one by one".
- `docs/agents-and-campaigns.md` says so. An agent made before keeps its tools; the owner trims it in the editor.

**Checked.** `tests/unit/test_team.py::test_an_agent_a_run_makes_gets_only_the_tools_named_each_one_the_run_has`;
`tests/smoke/test_create_team.py` and `tests/smoke/test_team.py` name tools in their scripted calls.
