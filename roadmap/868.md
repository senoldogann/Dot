### 868. A thing of Dot's own whose run left the owner a question waits for the answer, and is not done twice

**Status: done (2026-10-31).** **Asked** by the owner, with two screenshots of one task in two chats: "ajan izin
beklerken bazen aynı sohbeti tekrar başlatıyor; otonomide bunun da önüne geçelim".

What the owner's store showed. At 14:16 a run of Dot's own initiative fixed ten preview pages. Its step that put them
live waited 15 minutes and expired. It then left the question "may I put the fixes live?" and ended `failed`. The
initiative counted that as a failed try and put the thing back on the list. At 14:52, with the Mac idle, it started
the same goal in a new chat. The owner answered the first chat's question at 15:02. From then on, two runs put the same
site live side by side (`vercel build --prod` in one, `vercel deploy` in the other).

**What holds.**
- A thing is not started while its chat holds it. Its chat holds it when one of its runs is at work, whatever
  started it, when a question or kept step that its runs, or the runs they delegated to, left for the owner is
  still unanswered, or when a run that went on from the thing's ended and its end is not settled yet (only an idle
  tick settles it, the one that may change the list). This holds for the oldest thing and for an urgent one on a busy tick. The check reads only; it
  changes nothing on the list.
- The run that left a question is a counted try, as any end but done is. A thing that waits is not let go for its
  tries. Once the wait is over, the limit holds as before: the question was answered or skipped, or the step's time ran
  out.
- A later run of the chat can go on from the thing's run. It is a resume, the run the owner's answer to a question
  started, or the run their answer to a kept step started. Each carries the goal of the run it goes on from as its own,
  alone or followed by what was answered (`goes_on_from`). A message the owner writes is a goal of its own and is no
  sign the thing was done (item 715).
- The end of such a run is the thing's, settled as one of its own runs' (`_settle`). Done marks the thing done, counts
  the try and tells the owner. Failed is a counted try, and the thing may be tried again or let go at its last try,
  with the owner told. Stopped by the owner lets the thing go. A new question waits again.
- A thing whose last try left a question is let go once the wait is over and the owner is told, as after any last try.
  So is a thing tried as often as a lowered limit allows, which was let go without a word before.
- The thing is read again after that end is settled, so a counted try is not written over when the thing starts.
- How this changed in review:
  - The first push did not count the try and did not settle the end of the answer's run. The first pre-push review
    found that a skipped question, or an answer's run that failed or was stopped, started the thing again in a new chat
    with no try counted.
  - The second push knew an answer by the words that open it. The second review found two gaps: the run an answered
    kept step starts, and an urgent thing on a busy tick while the answer's run worked. The rule is now the goal the
    run carries, and any run at work in the chat holds the thing.
  - The third review found that on a busy tick an urgent thing whose answer's run the owner stopped, or that failed,
    started again before an idle tick settled that end. A run that went on from the thing now holds it until its end
    is settled.
  - The fourth review found that a thing whose last try left a question was let go without a word once the wait was
    over, and that the end of an answer's run done was neither counted nor told. Every end now goes through `_settle`,
    and every let go through `_let_go`, which tells the owner.

**Where.**
- `store/db.py`:
  - `count_left_in_chat(thread_id)`, the questions and kept steps left in a chat's runs and their families;
  - `_family_of(seed)`, the recursive head shared by the four queries of a run family.
- `agent/manager.py`: `goes_on_from(run, earlier)`.
- `proactive/initiative.py`:
  - `_chat_of(todo)` reads the thing's chat (`_ThingsChat`: the runs that went on, whether one works, whether one
    waits), and `_urgent_todo` and `_next` read it;
  - `_next` settles the end of the newest run that went on with `_settle`;
  - `_tried` keeps a thing that waits to do;
  - `_let_go` lets a thing go and tells the owner, from `_tried` and from `_next`.
- `docs/proactive.md` says so.

**Checked.** `tests/smoke/test_initiative.py`, on a scripted model:
- a run of Dot's own, the thing's last try of two, leaves a question and ends failed: the thing stays to do, its try
  counted, and is not let go;
- the next tick of an idle Mac starts nothing;
- the owner's answer starts a run in the same chat, and once it ends done, the thing is done with that run's answer;
- no other run was made;
- the owner skips the question:
  - with a try left, the next tick tries the thing again, that try is the second, and the owner is told it was done;
  - at its last try, the thing is let go, the owner is told, and no run starts;
- the end of a run that went on from the thing's:
  - the answer's run failed: the thing is tried again in a chat of its own, with one try counted;
  - it failed at the last try: the thing is let go, and the owner is told;
  - the owner stopped it: the thing is let go, and no run starts;
  - a kept step's answer started it, with or without a note, and it ended done: the thing is done, its try counted,
    and the owner told;
- an urgent thing on a busy tick, and any thing on an idle one, is not started while a run is at work in its chat: an
  answer's, a resume, or a message's;
- on a busy tick an urgent thing is not started while the end of its answer's run, stopped or failed, is not settled,
  and its tries are as they were.
