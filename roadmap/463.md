### 463. A schedule made in an agent's chat runs as that agent

**Status: done (2026-10-21).** The second part of item 462's split (item 449 has the plan of the nine): a schedule made
in a chat starts its runs as that chat's follow-ups do (item 291), and since item 462 a schedule can run as an agent,
but one made in an agent's chat still ran as Dot, with every tool and without the agent's instructions. **As built.**
`chat_options` (`tools/schedule.py`), which gives a schedule made by `schedule_create` or by `/loop` the options of its
chat, carries the agent of the run that made it (its chat's top run), and `_opening_options` (`server/routes_runs.py`),
which a new chat sent with a loop asks the scheduler with before its run starts, carries the request's agent, which a
campaign never has. The model names no agent: it is the chat's, the owner's choice, as the chat's approval mode is, and
the chat's approvals go with it ahead of the agent's own (a yolo chat's schedule stays yolo). Schedules made before this
keep running as Dot. Tests: `tests/unit/test_schedule_choices.py` (a schedule made in an agent's chat names it, with the
chat's yolo; one in Dot's chat names none), `tests/smoke/test_chat_loop.py` (a new chat with an agent sent with a loop
makes the loop's schedule the agent's; both fail without the change). `dotx eval check` passes (a tool changed). Docs:
`docs/runs.md`, `docs/memory-and-schedules.md`.
