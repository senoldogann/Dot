### 579. A campaign follows the browser mode unless its start names a Chrome

**Status: done (2026-10-23).** The owner chose Dot's own Chrome in Settings › Browser, and campaigns still opened their
own Chrome ("My Chrome"): a campaign started without a choice took `[agent] campaign_browser` (`"attach"`) and kept it
in its record, so every session of it worked in the Chrome the owner has open, signed in as they are, whatever the
browser mode said. The owner's Dot found it and changed the code in the owner's checkout; this item brings that change
to `main` with the test it needed.

**As built.**
- `RunManager.start_campaign`: a campaign started without `--browser` (the web UI never sends one; the CLI and the API
  only when asked) is stored with no Chrome (`browser` NULL), and each of its sessions works in the daemon's browser
  mode of the moment (`campaign_browser`, `browser_of` → `BrowserPool.session_for(None)`), as every other run does: a
  change in Settings › Browser reaches its next session. The check that the owner's Chrome answers runs at the start
  when that mode is `attach`: the mode the daemon works in now (`runtime.browser.mode`), which Settings › Browser
  switches while it runs, as the sessions read it, not the one it started with. `--browser own` or `--browser attach`
  (or `browser` in the API) still pins the campaign.
- `Store.create_campaign` takes `None`. `[agent] campaign_browser` stays a setting, so that a `config.toml` that sets
  it still loads, but nothing reads it now (`defaults.toml` says so).
- An eval keeps off the owner's Chrome as before: `eval_config` set `campaign_browser = "own"` for that, which a
  campaign no longer reads, so it sets the browser mode itself to Dot's own (headless as before); an eval's other runs,
  which took the owner's mode, keep off it too. `docs/harness.md` says so.
- `docs/agents-and-campaigns.md` and `docs/command-line.md` say it; the CLI's help, the API's model and the docstrings
  too.
- On the owner's Mac (by hand, not by this change): the four campaigns that had been pinned to `attach` were set to
  follow the mode, their old values kept in `workspace/social-agent/campaign-browser-backup.json`, and two scripts of
  theirs that reached the owner's Chrome on port 9222 were moved aside.

**Tests.** `tests/smoke/test_campaigns.py`: a campaign started without a Chrome keeps none in its record and its
session's brief names the daemon's (Dot's own in the tests' configuration); it pinned the old default before. With the
daemon switched to the owner's Chrome while it runs (closed in the test), such a campaign is refused before it is
stored, and switched back to Dot's own it starts (fails when the start reads the mode the daemon started with).
`tests/unit/test_evals.py`: an eval of an owner whose mode is `attach` works in Dot's own Chrome, headless (fails
without the change to `eval_config`). The unit and smoke suites pass.

Not changed: a campaign pinned on purpose keeps its Chrome; `[agent] campaign_browser` is not removed (an old
`config.toml` would no longer load).
