### 2026. Dot's own tools keep the seal of a run nobody started: no daemon-side read or write of what its sandbox seals

**Status: built (2026-11-27), waiting on the owner's look (it touches `src/dotagent/policy/`).** The owner approved it on
2026-11-27, as the follow-up of item 2016: the sandbox of a run nobody started holds the processes it starts, but Dot's
own file tools (`write_file`, `edit_file`, `read_file`, the search tools, `generate_image`, `watch_video`, a page shown
from a file, a file the web tools read, a browser upload, a pipeline record) run in the daemon's process, outside it, so
in yolo or free mode such a run still read Dot's token or changed its configuration through them.

## Approach (written before the code)

What must hold: for a run nobody started (item 2016's `RunGate.unattended`), while `[shell] sandbox_unattended` holds,
every step whose tool names a file it reads or writes in the daemon's process is refused, in every approval mode, yolo
and free mode included, when the file is one the sandbox seals for that run's processes:

- read or written: Dot's own files (its keys, token, settings, database, browser profiles, journals) and `[policy]
  sealed_paths`;
- written: what Dot loads and runs (its code, plugins, skills, playbooks, emergency stop), and anything in Dot's home or
  its logs but the workspace.

The set is the sandbox's own, built once with it (`Seal`, `policy/sandbox.py`), so the two cannot drift. The check is
one place every tool goes through: the gate (`RunGate._keep_seal`), before the policy decides and before any question,
on the step's target when the step is a read or a write, and on the files a step reads besides its target
(`ActionInfo.reads`: a browser upload's files, the files `web_extract` and the other web tools read). The tool resolves
each path as it does today (links followed, the kernel's spelling), and the file tools keep refusing a path that leads
elsewhere when they run (item 681). A refusal is a policy event of its own (`seal`), told to the run as any refusal is.

What only asks: nothing; nothing new asks, in any mode. A run the owner started is not touched: its gate has no seal.

What it does not cover: a tool that reaches Dot's files without naming a path (the memory tools write the store through
their own API, `skill_save` writes a skill through its own, a schedule is written by the scheduler); these are Dot's own
features with their own rules. Apple Events, as before.
