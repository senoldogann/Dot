### 1014. The Claude plan's models take a reasoning level and fast mode

**Status: done (2026-11-07).** **Why.** The owner's word of 2026-11-07: on their Claude plan (item 1013) they could
not pick the model's reasoning level or fast mode, as on the other models, and saw two models only.

**Built.** `llm/claude_code.py`: `fable` beside `opus` and `sonnet` (the aliases `claude --help` names); the models'
reasoning levels are Claude Code's own (`EFFORTS`: low, medium, high, xhigh, max), and Opus has fast mode
(`offers_fast_mode`). `claude_code/run.py`: the run's level goes as `--effort`, fast mode as `--settings
{"fastMode":true}` (the one settings source a run reads, `--setting-sources ""` keeping the rest out). A plan without
extra usage runs fast mode off (measured on 2.1.318: `fast_mode_state` off, `extra_usage_disabled`); the run's answer
then says so. The run's level, or the configured default when it chose none, is rounded to Claude Code's levels and
always sent (`run_effort`), so what the composer shows is what runs; fast mode goes to a model that has it alone
(`run_speed`). Docs: `docs/models.md`.

**Checked.** `tests/unit/test_claude_code.py` (the level and fast mode reach the program, neither when the run has
none; Opus alone has fast mode; the off reason read and said); a real call on the owner's plan (Opus, `--effort low`,
fast mode asked: the model ran, fast mode off for extra usage).
