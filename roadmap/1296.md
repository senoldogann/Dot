### 1296. A navigation a redirect cuts off is read where the tab stands, not failed

**Status: done (2026-11-22).** `Page.goto` that Chrome cut off (`net::ERR_ABORTED`: the page the tab was on, or the
page the request was sent to, started another navigation before the first committed) was a hard failure of
`browser_open` and of the reads of the web tools, while the tab was often already on the real page, unread.

`driver.navigate` now returns a `Navigation` (status, `redirected_to`). On `ERR_ABORTED` it waits (bounded: 2 s for
a main-frame commit it has not seen, 5 s for DOMContentLoaded), reads the tab's address and, when the tab stands on a
real page (not blank, not `chrome-error://`, and not where it was unless a main-frame commit was seen meanwhile), returns
success naming it; `_load` adds the note "the page redirected to X" and goes on to the unchanged settle and
`_enforce_landing`, and `_read_page` goes on to its own URL-rules and public-only checks of the landed address (it
fails, saying so, when the landed page's response was never seen, rather than invent a status). When the tab stands on
no page it sends the navigation once more whatever `navigation_attempts` says, and a second cut raises as before. Every
other failure is retried and raised as before; a request the URL rules refused still arrives as `BlockedByClient`, not
as a cut.

Checked: `tests/unit/test_navigate_cut.py` (eight tests on a stand-in tab: a cut onto a real page, onto the page it was
on, onto the error page, onto nothing; two cuts raise; transient and hard failures and a download as before) and
`tests/smoke/test_browser_cut_navigation.py` on real Chrome against a local site whose page sends the tab on while
Dot's next navigation waits for a slow server (the call reads the page the tab is on with the note; an ordinary open has
no note; a redirect to a blocked host is refused on the way and the retry reads the page asked for).
