### 781. The aggressive toolkit: a form's payloads, a script's selector, a click's second way, and the deep-OS map

**Status: done (2026-10-28).** **Asked:** the owner's list of 2026-10-28, its four points, "especially 2": a
`browser_execute_js` that makes a three-step click one step; a security module that generates SQLi, XSS, login-bypass
and default-credential payloads and tries them on forms; an agent loop that retries a failed action with another
method before returning to the user; and a Deep-OS fast-path map from a UI task to its CLI or AppleScript.

**What was there first.** Item 776's recon had read the list and built the passive audit and the owner's port scan,
and stopped there: its roadmap said a payload/exploit generator and a C2 framework are "the parts of an attack chain,
not a tool a run needs", and it sent no payload. The other three points were partly there: `browser_eval` (item 263)
already runs a script with the elements of refs (item 738), so the JS click existed without the name; `browser_act`
(item 739) already said when a click left the page unchanged and named `browser_eval` as the way round it, but the
model had to take that way; the prompt already preferred a command to a click, and `shell` and `apple_script` ran
one, with no map of which command.

**What changed.**

- `security_scan` (item 781a): reads a page's forms and tries a small, read-only set of payloads on them — SQL
  injection, reflected XSS, a login bypass and default credentials — with `depth = "forms"` to list them without
  sending anything. The host must be in `[recon] owned_hosts`, every form action must stay on that host, hidden
  fields (a CSRF token) go back as the page gave them, attempts are capped, and the report names the sign, not the
  page. It is a check of an owner's form, not an exploit and not a scanner for someone else's site: no WAF evasion, no
  session, no payload that writes, drops or takes. That line is the one item 776 drew, kept: a form's question is a
  tool a run needs; an attack chain is not.
- `browser_eval.selector` (item 781b): the script gets the first element a CSS selector matches, so
  `browser_eval(script="(el) => el.click()", selector="button[aria-label='Send']")` is the Fast-Track click a
  snapshot, a find and a step would take three calls to reach. `refs` and `selector` are one or the other.
- `browser_act.retry` (item 781c): a click whose batch left the page unchanged is tried once the other way before the
  result returns — the same ref gets the pointer sequence a script sends, then the page is read again and the step's
  line says it was retried. A click that moved the page is never sent twice; a failed step is left alone.
- Deep-OS (item 781d): the built-in skill `deep-os` and [Deep-OS](docs/deep-os.md), a map from a Mac task to the
  command that does it — Wi-Fi by `networksetup -setairportpower`, volume and dark mode by `osascript`, screen by
  `pmset`, ports by `lsof`, processes by `pgrep` — with the destructive commands that wait for the owner's word and
  what to do when a command fails. No new tool and no new permission: `shell` and `apple_script` already run the
  line, and the policy still judges it.

**Checked.** `tests/unit/test_security.py` (8: a refused host, forms without a payload, the four findings, the
cross-host form, the cap, the parser), `tests/unit/test_browser_retry.py` (2), the selector and the real retry in
`tests/smoke/test_browser_eval.py` (17, with Chrome: the synthetic click on a page that ignores a real one), the
group and budget smoke tests, and the whole unit suite. The context budget went up by 600 tokens for the new tool and
the two browser fields (21,984 measured), and the group line now names `security_scan` in `recon`.

**Limits.** The scan is a quick check: it sees the forms a page serves a visitor, not a signed-in area, and a clean
result is not a verdict. The tool's payloads are a fixed, short list; a deeper assessment (sqlmap, Burp, a WAF's
bypass) belongs in a terminal, on a host the owner is allowed to test. The retry reaches a synthetic click, not a
button that waits for a custom event (some of Slack's) — `browser_eval` with the event still does that.
