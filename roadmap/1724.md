### 1724. MCP servers are not started lazily: measured, and kept as they are

**Status: decided (2026-11-24).** The audit of 2026-11-24 (A3, improvement 4) counted `playwright`, `chrome-devtools`,
`deepwiki` and `rea-mcp` started 84 times each in six days of the owner's log and called by no run (`github` 46 starts,
one call), and asked whether a server should start on a run's first call of its tools instead.

Measured:
- The owner's log (2026-11-18 to 2026-11-24): 31 `daemon_started`; the other 53 starts of each server are `dotx`
  processes that open their own runtime (runs, evals, the night's work). `open_hub` starts every enabled server at once
  (`mcp/hub.py`), once per process, not per run; 0 restarts, 0 failures in the window.
- A start in a throwaway home: Playwright's server (`npx -y @playwright/mcp@0.0.83 --no-webmcp`, npm's cache warm)
  answered with its 25 tools in 2.76 s, then 1.62 s and 1.43 s, about 140 MB in three processes as it started; idle
  ones on this Mac hold 4 to 6 MB resident. deepwiki (HTTP) connected in 0.88 to 0.96 s. The servers start in parallel,
  so a process waits for the slowest, not their sum. `chrome-devtools` (`--autoConnect`) was not started, as it would
  reach the owner's Chrome.

Why not lazily: a run's tool list is built from each server's listing when the runtime opens (`build_mcp_tools`), the
gate reads each MCP tool's annotations (read-only, destructive) from it, and the instructions carry what the server said
of itself. Starting on first use needs those from somewhere before the server runs: a kept copy of the last listing,
which would let a server's changed tools or annotations be judged by an old copy until it starts, and a server that
can no longer start would show as connected until a run calls it. That is a change of what the gate reads, for about
two seconds of a process's start and a transient 140 MB; the smallest safe change is none. What saves the most is the
owner's: switching off `playwright` and `chrome-devtools`, whose work Dot's own browser tools do (A3 counted 0 calls of
either), on Settings › Connectors.

Checked: the measurements above (scratch home, `open_hub` on the worktree's code); docs/extending.md says when servers
start and what an unused one costs.
Not done: no code change; the owner decides on switching the two servers off.
