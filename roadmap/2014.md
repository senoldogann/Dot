### 2014. The small window's compaction fixture takes the cards tool, and the tool's schema is shorter

**Status: done (2026-11-27).** Item 1967 (#1191) added `show_cards` to the `pages` group. `main` went red:
`tests/smoke/test_scaffold.py::test_a_small_window_cuts_the_budget_and_the_tool_output_and_the_run_compacts_to_stay_inside`
saw two compactions one step apart (`min(gaps) > 1` was 1), because the full tool surface that fixture forces carries
the tool's schema at every step.

Measured: the schema was 3,689 characters, about 1,150 tokens, in the full surface. A run on the default surface
(`[agent] tool_surface = "auto"`) is not affected: a model whose window cut the context budget gets the grouped surface
(`surface_for`, `agent/scaffold.py`), where the `pages` group is off at the first step and is turned on by
`use_tools`, so a small window there keeps the room it had. Only this fixture, which sets `full` so that tools fill the
small window, pays for it.

What changed:

- The schema leaves out what the tool checks itself: the length of a text, a post, a cell and a path, and the bounds of
  a number (`WithJsonSchema`; pydantic still rejects them with its message), and the tool's description names the
  sizes that matter. 3,689 to about 3,000 characters; in all 34,696 tokens measured for the first step of a fresh
  home against 34,884, and tools 25,292 against 25,480.
- The fixture's window goes from 54,000 to 55,000 for the rest, as for each tool group that joined the full surface
  before it (the comment in the test lists them; item 1973 did it for the Safari tools). `tests/smoke/test_context_budget.py`
  takes the measured numbers: 34,850 in all and 25,400 for tools.

Checked: `tests/smoke/test_scaffold.py` (12 passed), `tests/smoke/test_context_budget.py`,
