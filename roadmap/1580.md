### 1580. A Claude Code program that ends before its result says how it ended, and programs cut in one second are said in one line

**Status: done (2026-11-24).** Measured on 2026-11-24 at 10:44:04.01 to .03: five `claude` programs that Dot's daemon had
started (four long helpers of 67 to 371 steps each and the owner's chat run) ended within 20 ms of each other, no tool call
of theirs failing before. The daemon (up since 07:53) logged only `run failed: Claude Code ended before it answered` for
each, with `stderr: ""`, kind `passing`; the macOS log showed the programs' connections closing together, which points to
a kill from outside, and nothing in Dot says so. The cause was not found, and Dot had nothing to find it with: `follow()`
turned the closing of the output pipe into one `ClaudeCodeBroke` with `{run_id, inited}`, and the exit code of the program
was never read.

What changed (`claude_code/cut.py`, `claude_code/run.py`, `core/errors.py`):

- The pipe that closes (and an input that breaks) is a `ClaudeCodeCut`, a `ClaudeCodeBroke` of its own (still a passing
  failure, the same words), and the runner then reads how the program ended: it gives the program up to 2 s to have its
  exit (`exit_seen`: a program killed from outside has it within milliseconds), then ends what is left of its group, as it
  did before. The error's context and one log line (`claude_code_program_cut`) carry `returncode`, `signal` (the name for a
  negative code, and for `128 + n`, which is how Claude Code itself ends on SIGTERM: measured on 2.1.331, a group SIGTERM
  gave 143 and a group SIGKILL gave -9), `exited` (false for a program that was still running when its output closed, which
  Dot then ends itself), the last 2 KB of stderr, `inited`, `steps`, `silent_s` (the seconds since the last line it wrote:
  `_Quiet.wrote`, which only a line moves, unlike `heard`), `claude_session` (not `session_id`, which `redact_json` masks by
  its name) and `cut_at` (`HH:MM:SS`, the owner's clock).
- `claude_code_programs_ended_together` is one line, with the run ids, the signals, the codes and the spread in
  milliseconds, when two or more programs of this process were cut inside one second (`EndedTogether`: the first cut opens
  a window, the others join it, and the window's end writes the line once, so five programs are one line, not four).
  Dot's own ends are never counted: `_end_program` marks the program it ends while it is still running
  (`mark_ended`), a program that did not end by itself has no exit of its own to count, and a program that ended after its
  result is no cut.

Checked: `tests/unit/test_claude_code_cut.py` (the signal behind an exit code, including 143 and 137; the context, with its
error stream cut to the last 2 KB; the window: three cuts in 20 ms are one line with their ids and signals, one alone and
two a second apart say nothing, a late cut opens a window of its own, the window closes by itself; Dot's own ends and a
program that did not end are not counted; the exit a program is given a moment to have) and
`tests/smoke/test_claude_code_run.py` with the stand-in program that kills itself with SIGKILL and with SIGTERM and that
crashes with exit 1 (the run fails with the program's exit in its context, in the event and in the `run failed` line; two
runs cut together are one line; a Stop that ends the program is no cut).
