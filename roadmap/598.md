### 598. A page Dot made in its workspace is shown drawn, by its path, rather than as its text

**Status: done (2026-10-23).** Item 596 told a run that tries to open a page of its workspace as a `file:` address to
write the page's path in code in the answer, whose button shows the file's text beside the conversation (an HTML file is
never drawn there), while the owner opens the page in their own browser by hand: the "Open on the Mac" of the panel
leaves a page out, since it would run. The owner's page (`ai-herald/index.html`, 56 KB) holds its styles and scripts and
loads one library from cdn.jsdelivr.net: `show_page` draws such a page, in the conversation and full size. But
`show_page` took the page's HTML alone, and `read_file` gives a file in numbered windows of the tool's output (12,000
characters), so a run would have read the page in five parts and written its 56 KB out again.

**As built.**
- `show_page` takes the page by its `path` instead of `html`, one of the two (`tools/pages.py`): a file of the workspace
  whose suffix is `.html`, `.htm`, `.xhtml` or `.svg` (`PAGE_SUFFIXES`), read whole and kept as a page given as HTML is
  (`page_file`). It must lie in the workspace once its links are followed (`expand_path`, `within`), not among the
  files a crawl or an MCP answer kept there (`holds_third_party`, item 494), be text in UTF-8, not empty, and no longer
  than a page (`PAGE_MAX_CHARS`); anything else is refused with what was wrong and nothing is kept.
- The call is classified as a read of the file (`read_action`, as `read_file`'s): a protected place in the workspace is
  a read of secrets, which the policy asks about. Like `read_file`, the tool is a path tool (`make_path_tool`): it is
  classified again as it starts and refused if that differs, a link moved while the call waited, and it reads the file
  where it was judged (the authorised `target`), not its path resolved once more. The run reads nothing of the page;
  it is drawn for the owner alone, sandboxed as every shown page (item 521), and the files beside it do not load.
- A run cut off in such a call is not resumed on its own as one that only read (`agent/resume.py`): a second call
  would show the page twice, as a page given as HTML would (item 552).
- `_local_file_hint` (`tools/browser.py`): a refused `file:` address of such a page in the workspace tells the run to
  give its path to `show_page` (`use_tools` with the group `pages` turns it on), which draws it in the conversation
  and whose Open shows it full size in the owner's browser, and what loads there: scripts and styles from the hosts of
  `LIBRARY_HOSTS` alone, pictures only written into the page, and the files beside it not at all. The names come from
  their constants (`SHOW_PAGE_TOOL`, `USE_TOOLS_TOOL`, `group_of`, `LIBRARY_HOSTS`, `PAGE_SUFFIXES`).
- Any other file of the workspace keeps its path in code, which the panel shows (a PDF, a picture or a document drawn,
  a text as text); the words no longer speak of a page.
- The path of the address is read with `..` taken away (`posixpath.normpath`), item 596's PASS nit: a path that climbs
  out of the workspace gets `read_file` alone.
- `docs/runs.md` and `docs/browser-and-computer-use.md` say it; the tool's description names the path.

**Tests.** `tests/unit/test_page_by_path.py`: the owner's page is shown by its relative path and an SVG drawing by its
absolute one, each kept whole, and a page given as HTML as before; the call is a read of the file, of secrets in a
protected place; a path out of the workspace (by `..`, by a link), a crawl's page, a file that is no page, a missing, an
empty and a too long one are refused and nothing is kept; a call with both the HTML and a path, or neither, is refused;
a link judged a safe read and then pointed at a protected file before the call runs is refused, and nothing is kept.
`tests/unit/test_resume.py`: a run cut off in a `show_page` call that read its file is not resumed on its own.
`tests/unit/test_own_interface.py`: a page of the workspace (`index.html`, `About.HTM`, `feed.xhtml`, `chart.svg`) is
refused with `read_file`, its path for `show_page`, the group that turns it on, its Open and the hosts it loads from,
and no path to write; a PDF of the workspace with its path in code; a key of the home folder, and a page whose path
climbs out of the workspace, with `read_file` alone; none names a server.
