### 1961. DotNext shows an answer's links and files in its words, and a table's long cells inside their rows

**Status: done (2026-11-26).** The owner, on build 8 of item 1935: the file cards and the link row under the answer are
too much, and a table's wrapped cells drew over the next row.

What changed:
- An answer's references are in its words (`Components/AnswerInline.swift`): a link shows its site's own icon (a globe
  until it is fetched) before its words, a bare address its short form instead (`inlineLinkLabel`: a GitHub pull
  request or issue `#1012` after the GitHub mark, a repository `owner/repo`, any other site its bare domain); a file
  named in a code span or in the words (the web's rules, `prose.js`) is its name after its kind's symbol, a link to its
  preview sheet (`dotfile:` address, opened by `AnswerBody`). The marks are drawn at the words' size, in one `Text`, so
  they wrap and select with the words; every mark (the site's icon, the GitHub mark, the file's and the globe's
  symbols) is a decorative image drawn at the app's own text size, so VoiceOver reads the words alone, and a
  reference whose words are several runs (a fade step, an emphasis) draws its mark once (`markStarts`). A site's icon is asked for only once
  the answer is whole (never for a half-written address) and for at most 48 sites a launch; a `dotfile:` address
  opens only a path the web's rules take for a file. Nothing is listed under the answer any more: item 1935's file chips, sources
  chip and link rows, and the engine's `answerLinks`/`answerFiles`, are gone; the preview sheet and Safari's in-app
  view stay.
- A table (`TableGrid`, a `Layout`): each column takes its widest cell on one line when the table fits the reading
  column; otherwise the widest columns wrap first to a shared width that makes it fit (`tableColumnWidths`, at least 96
  pt a column), and a table still too wide scrolls sideways. Each row is as tall as its tallest cell at those widths, so
  a wrapped cell (a code span too) never draws over the next row.

How it was checked: `swift test` (`InlineReferenceTests`, `TableColumnTests`); `AnswerInlineTests` (a bare address
shortened, a written link's words kept, a file's sheet address, one mark per reference through the fade); `ChatUITests` on `n2-chat`, whose answer
now holds a GitHub pull request, a written link, a file and a table of long cells: the links and the file are links in
the words (`#1012`, the written words, `ci-notes.md`), nothing is listed under the answer, the file opens its sheet
and Open on Mac; the long cell wraps, shares its row's top and ends above the next row, at the default size and at AX3,
on an iPhone 17 Pro (the Mac was loaded; the SE and Pro Max widths are left to the nightly run, the rule is width-free:
`TableColumnTests` covers a 343 pt column).
