### 2106. Send now on a queued message stops the run and starts it at once

**Status: in progress (2026-11-28).** The owner's words of 2026-11-28: a queued message sent "without waiting" must take
effect at once, not wait for the run at work. Before, the queue's Send now (DotNext) and Steer (web) steered the message
into that run (`POST /queue/{id}/steer`), which reads it at its next step and goes on.

What must hold:
- `POST /api/queue/{id}/now` (`RunManager.send_queued_now`) puts the message first in the queue and stops the run of this
  process at work on the chat; that stop starts the message as the chat's next run (`_follow_queue`) instead of holding
  the queue as a stop does. The rest of the queue follows it as before.
- The message starts once: through the queue's claim (`Store.claim_queued`), whether the stop or the run's own end gets
  there first. Nothing is lost: the message stays in the queue until its run has started.
- With no run at work, it starts at once; a hold of a stop or of a crash goes with the press, a hold for a free task of a
  chat with several (item 2012) stays. A run a `dotx` command drives is refused with 409, as a steer of it is.
- `POST /queue/{id}/steer` stays as it was (older phones, the web's ⌘⇧Enter with the box empty).
- No new ask in any mode: a stop and a start the owner pressed for (`tests/unit/test_freedom_contract.py`).

How it was checked: `tests/smoke/test_queue.py` (sent now with a run at work, over HTTP; sent now with a held queue; the
page's Send now at 1280 and 390 px, light and dark), DotEngine `SyncTests.testAQueuedMessageSentNowStartsItsOwnRunAndTheOverlayGoesOnceItShows`,
`uv run dotx eval check`, `tests/unit/test_freedom_contract.py`.
