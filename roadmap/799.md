### 799. A failed run becomes a draft eval task, and the score has a weekly baseline

**Status: done (2026-10-28).** **Asked** by the owner: "O halde şimdi bu sistemi uygulamaya başla." This is the second
step of the approved plan: an eval task is data in `catalog.py` with a reference solution, so the first real failure
needs a draft before it can become a task, and the model's score needs a repeated measurement rather than one run.

- **`dotx eval from-run RUN [--out PATH]`.** Reads a saved run and its events, and writes a Markdown draft with the
  goal, the ending, the step and token count, and the tool names that failed. Tool arguments are left out, so the draft
  can be read before it is shared; the result is clipped at 1,000 characters. The default is
  `<home>/evals/drafts/<run>.md`; the draft tells the reader how to turn it into a catalog task and then run
  `dotx eval check`.
- **`src/dotagent/evals/drafts.py`.** `draft_from_run` is pure (a `RunRecord` and its events in, Markdown out), so it is
  tested without a store; `save_draft` writes the file and makes its folder.
- **CLI wiring.** `EvalFromRunCommand` is part of the command union, the parser takes `RUN` and `--out`, and the eval
  dispatcher opens the store, closes it in a `finally`, and prints where the draft went.
- **A weekly score.** `scripts/weekly-eval.sh` plays the catalog once, finds the report before and after, and runs
  `dotx eval report` on them; docs/development.md says to schedule it from cron or a Dot schedule.
- **Measured.** The draft tests pass (3), the parser test passes, the script test passes; `dotx eval from-run
  run_mvsal2os_3ac051 --out /tmp/eval-draft-run.md` wrote a draft with the goal and 74 steps and did not include tool
  arguments; ruff and mypy are clean.
