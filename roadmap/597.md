### 597. Under a run's answer, one line of what it changed on this Mac, with Review and Undo

**Status: done (2026-10-23).** The owner showed another app's end of a session, "Edited 6 files" with each file's
added and removed lines and Undo and Review, and asked whether Dot should show such a thing, without becoming a code
editor: the aim is an agent like Grok's or OpenAI's, better than them. Dot had what such a line needs (the undo
journal, `GET /api/runs/{id}/actions` and `POST /api/runs/{id}/undo`, the side panel's Changes tab, item 368), but the
page showed no way back since the Actions tab left at the owner's word (item 364).

**As built.**
- `runchanges.js`: under the answer of the page's run, once the answer is in, one line read from the run's undo plan
  (`GET /api/runs/{id}/actions`): what its file tools did in words ("Created a file and changed 1"), the files by name
  (three, then "+N"), each a button to the file beside the conversation, **Review**, which opens the Changes tab and
  its diffs, and **Undo**. A file the run created is one the undo deletes; one it changed, one the undo restores. The
  run's own notes (`write_notes`) and a file as it was before the run are left out; a run that changed no file shows
  nothing.
- **Undo** reads the plan again when pressed, so a file the owner changed since the line was drawn (here, in the
  Changes tab or in an editor) is no longer the run's to take back; it asks first, saying what goes back, what is
  deleted and what stays (a file changed since the run, which the plan calls a conflict, apart from one that cannot go
  back for another reason), then takes back each file that is as the run left it (`POST /undo` with its path), and draws
  the line again from the plan after, also when a file could not go back; the page's Changes tab and Files card read
  the files again too (`onUndone`). Once this card's Undo took the run's files back, the line says so; a run whose
  files are as they were otherwise says nothing. Whether the run and its helpers have ended (`ended`) is read when Undo
  is pressed, which says so and waits when they have not: Undo is off only when no file can go back. A second press
  while the first reads the plan or asks is let go, so a double click asks once.
- While the answer is written in (item 366), the line waits with the foot until the words are all in: `timeline.js`
  marks the answer `data-revealing` meanwhile, and one rule hides both, where the foot was hidden by its own style.
- What the owner does says what went wrong (`attempt`, a toast): the plan not read when Undo is pressed, a file not
  taken back. Only the line's own reading as the answer comes keeps quiet (in the console), the Changes tab having the
  files all the same.
- A copy of the answer leaves the line out (`clipboard.js`): it is Dot's account of the run, not what the run said.
- Not an editor's list: no line counts and no diff on the line, which the Changes tab has; a command's own writes are
  in no journal and so not on it. A run's card is the page's run's alone: the earlier turns of a chat keep theirs in the
  Changes tab.
- `docs/daemon.md` and `docs/autonomy.md` say it.
