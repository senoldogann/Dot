### 526. Copies of the database, made while the daemon runs and kept where the owner says

**Status: done (2026-10-22).** Asked by the owner, after the home folder was lost: the database is to be copied all the
time, kept somewhere safe, and the copies must not weigh on the Mac.

- **Where it stood.** Nothing copied `dot.sqlite3`; `dotx prune` only deletes. A lost home folder took every chat, run,
  note and agent with it.
- **The copies.** While the daemon runs, `store.backup.keep_backups` copies the database every `[store]
  backup_every_hours` hours (1), at once when no copy is younger, and only when the database or its write-ahead log was
  written since the last copy (`changed_since`), so an idle Mac makes none. `make_backup` uses SQLite's online backup in
  one step: a copy made in several restarts from the first page whenever another connection writes in between, as the
  daemon's do (the pre-push review found it), and in WAL mode one step reads a snapshot and holds back no write, so runs
  go on while it copies; the copy is checked (`quick_check`), compressed (gzip, level 6) and kept as `dot-<UTC
  time>.sqlite3.gz` (0600, in a 0700 folder), written under a hidden name and renamed once whole. The uncompressed copy
  is a hidden file of Dot's home (0600), removed once compressed; both hidden names hold the process's id, so two copies
  at once never share one, and what a copy cut off left (older than an hour) is cleared by the next.
- **What is kept.** `thin_backups` keeps the newest `backup_keep_hourly` (24) copies and the newest copy of each of the
  last `backup_keep_days` (14) days; it only ever looks at files named as copies.
- **Where.** `[store] backup_dir`, `<home>/backups` when empty. The docs say to point it at an external disk or at
  iCloud Drive to keep the copies off the Mac, as `<home>/backups` goes with the home folder.
- **Seen and made by hand.** `dotx backup now` makes a copy at once and thins the folder; `dotx backup list` lists the
  copies; `dotx doctor` has a backups row that says how old the newest copy is, and late only when the database changed
  since it (a quiet night makes no copy, and is no fault). A copy that fails is logged (`backup_failed`) and tried again
  ten minutes later, a failure to list the folder too; a file shaped as a copy's name but holding no time is not taken
  for a copy; the loop ends only with the daemon. Copies turned off are the owner's choice, and the doctor's row says
  "off" as a pass.
- `docs/configuration.md` says all of it, and how to go back to a copy.

Checked by:
- `tests/unit/test_backup.py`: a copy is the whole database, checked, compressed and private, with nothing half-written
  left; a copy finishes while another connection writes all the time; there is no copy of a database that is not there;
  thinning keeps the newest hourly copies and one of each recent day and leaves every other file alone; a copy is made
  again only when the database changed; the doctor's row; the daemon's loop copies at once when no copy is there.
- `tests/unit/test_cli_backup.py`: the commands are parsed, `dotx backup now` copies and `dotx backup list` lists.
