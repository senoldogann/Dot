### 1302. A program that is handed a command line by an option of its own is judged by that line

**Status: done (2026-11-22).** The review of the shell guard on commit 688f63322 found that `sqlite3 db '.shell CMD'`,
`vim -c '!CMD'`, `emacs --batch --eval '(shell-command "CMD")'` and `tar --use-compress-program=CMD` were `low` and
allowed in balanced, while the same CMD under `bash -c` is `high`: the guard read the generic `-c`/`-e` value of a
program it does not know (`_given_lines`) and nothing of these programs' own options.

`_carried_lines` (policy/shell.py) takes the line each known program is handed and judges it with `_assess_all`, as
`bash -c` is: for `tar`/`gtar`/`bsdtar` the value of `-I`/`--use-compress-program`, `--to-command`, `--info-script`,
`--new-volume-script`, `--rsh-command` and the `exec=` of `--checkpoint-action`; for the vim family the shell escape of
an Ex command given with `-c`, `--cmd` or `+` (a `!` at the start or after a range or a word and a blank, so `!cmd`,
`:!cmd`, `+!cmd`, `r !cmd`, `%!cmd`, not the `!` that ends `q!` and `w!`); for `sqlite3` the `.shell`/`.system` line
and the `|command` of `.import`, `.output`, `.once` and `.read`, in its arguments and on its input (a here-document, a
pipe); for `emacs` and `emacsclient` the string of each `shell-command` form of the Lisp given with `--eval` and
friends, and any other form that starts a program (`call-process`, `start-process`, `make-process`) as unknown, since
its program and words are not read. A program with its own reading no longer goes through the generic `-c`
reading; the verdict of `vim -c 'set nu'` and the others without a shell escape is the one it had.

The approach: the guard asks by the structure of each program's option (which option carries a line, how a bang or a
dot command is told), and the docs list what it does not read (`vim -S`, `emacs -l`, `sqlite3 .read file`, `:call
system()`, `:terminal`). Plain `sqlite3` queries, `vim`/`emacs` without those options and ordinary `tar` keep their
verdicts (`tests/unit/test_shell_guard_ordinary.py`).

Checked: `tests/unit/test_shell_guard_programs.py` (46 handed lines, which all ran unasked before, are `high` and asked, like
the `bash -c` baseline that heads the 47 of its list; 47 harmless or plain lines keep `safe`/`low` and `allow`; it
fails without the change), `tests/unit/test_shell_guard_ordinary.py`.
