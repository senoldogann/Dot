### 513. MCP sessions that went quiet, tools named in words, a Working that folds, and Auto for agents

**Status: done (2026-10-21).** Reported by the owner.

- **Tavily failed though its key was set.** Four searches sent at once at 22:36:10 failed in under a second with "the
  MCP server closed the connection". The session had been quiet for 17 minutes, and its connection broke on a TLS
  handshake its client failed. The connection made again 3 s later served every later call. A session reached at a
  URL that was quiet for `_QUIET_CHECK_S` (60 s) is now pinged first (`McpConnection._answers`), under the
  connection's lock, so the calls that come wait for the new session rather than fail on the old one.
  - A call whose connection broke is still not repeated, as the tool may have done part of its work. The exception is
    a tool the server declares read-only (`readOnlyHint`), which is called once more on a new connection, with a
    warning (`mcp_call_repeated`).
  - The error's context names a log only for a server Dot starts.
- **Tool names in words.** `toolWords` in `tools.js` names Dot's tools by what they do ("Edit file", "Update plan",
  "Use skill"). An MCP tool is named by its server, as a title, and what it does, with the server's name taken off the
  tool's own (`mcp__tavily__tavily_search` reads "Tavily · Search"). Any other tool reads in words of its name. The
  words are no longer monospace, and their title is the tool's own name.
- **Working did not fold.** Folded, Working kept the open chat in sight (item 202), so with only the open chat at work
  a fold changed nothing. Folded, it now hides every row and keeps its count, and a search shows the chats at work it
  finds.
- **No Auto on an agent's page.** Item 495 gave the home's box and a chat's dock Auto, and the agent page's box kept
  `MODES` (Task, Chat, Research) and no commands. It has `MESSAGE_MODES` now, starts on Auto and takes `/auto`,
  `/task`, `/chat` and `/research`. The daemon already settled Auto for an agent's run (`routes_runs.start_run`). It was
  never the agent's approvals.
- **SearXNG.** Not changed here. The owner's own instance (`services/searxng`, launchd `dev.dotagent.searxng`, set up
  by a run) answers first on the auto ladder while `[web] searxng_url` is set, and its engines time out (bing, yep).
  Taking it out is a change to the owner's config and launch agents, so it was asked first.
