### 1228. Google's models in Dot: a Gemini API key, an Antigravity account, and tool schemas Gemini reads

**Status: done (2026-11-19).** The owner, 2026-11-19: Google gives free Gemini models on an API key from AI Studio, and
wanted them in Dot beside the other providers — in the AI services page, in the model picker, and usable by a run. The
same evening a chat on the Antigravity route stopped with two Gemini refusals of Dot's own tool schemas: "Unknown name
`gt`", then "`required[0]`: property is not defined".

- `llm/google.py`, `config.py`, `defaults.toml`, `llm/router.py`, `doctor.py`: the `google` provider, on the Gemini
  API's OpenAI-compatible route (`https://generativelanguage.googleapis.com/v1beta/openai`) and a key from
  aistudio.google.com in `GOOGLE_API_KEY`. `dotx auth set GOOGLE_API_KEY` stores it; `dotx models google` lists what the
  key reaches (22 models on the owner's free-tier project); a model is called `google:<model>`.
- `llm/antigravity.py`: the `antigravity` provider, the Gemini models of a Google Antigravity account over Cloud Code
  Assist, with the account's login read from disk and the thought signature carried back with each tool call.
- `tools/schema.py`: a bound pydantic drops into a field's own metadata (a field with both an `Annotated` validator and
  `Field(gt=...)` becomes `{"gt": 0}`) is written as `minimum`/`maximum`, so no provider meets a keyword it cannot
  read. Gemini refused the whole request over one such key.
- `llm/antigravity.py` (`_schema`): under `properties` the keys are the names a call passes, not keywords — a parameter
  called `title` was dropped as if it were the schema's own `title`, and the `required` list then named a property that
  was not there.
- `server/static/js/providers.js`, `views/keys.js`, `static/icons/providers/google.svg`: Google in the AI services page
  with the Gemini mark, its key row and the models it brings; both providers carry a name and a mark in the model
  picker (Antigravity has no key at all, so it has no row in AI services); `cli_setup.py` and `agent/helpers.py` know
  their key names, so `dotx setup` offers the Gemini key and a standby model can name one.
- `tests/unit/test_tool_schema_bounds.py`: the bound is `minimum` and the Antigravity route keeps a `title` argument.
  `tests/unit/test_antigravity_codec.py` covers the Cloud Code request and reply.

Checked: one real run on `google:gemini-3.5-flash-lite` answered (goal check reached, 22.5K tokens in, 104 out); the
Antigravity route took the whole 111-tool task registry (HTTP 200 where it had been 400) and answered with a
`web_search` call; on the owner's key `gemini-3.5-flash-lite` and `gemini-3.1-flash-lite` answer, while
`gemini-3.1-pro-preview`, `gemini-4-carbon` and `gemini-4-neon` come back 429 with no free quota; all 111 tool schemas
now have every `required` name among their `properties`.
