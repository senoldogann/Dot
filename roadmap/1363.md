### 1363. The goal check may read the lines of a file the run wrote before it decides

**Status: done (2026-11-23).** From the same reading of GLM-5.4 and the agent-team write-up
(`workspace/glm-54-loop-dot-cikarimlari.md`, move P0-1): GLM's second pass reuses the first pass's cache and adds one
sliding window of its own; Dot's goal check had the cache (the digest, the plan and the facts) and no window at all. The
digest says that a file was written and how large the call was, never what the file holds, so a check that could not tell
from it whether the answer was true had two ways out: trust the claim, or send the run back to read what it had just
written. On 2026-11-23 `agent/review.py`'s goal check was a single question with `achieved`, `continue`, `blocked` or
`scheduled` and no tool of its own.

What changed: the check may answer `inspect` (item 1363). `agent/goal_read.py` holds `GoalRead` (a path, a first line, at
most 120 lines) and `read_written`: it reads only a file the facts list among the files the run wrote or edited, at most
4000 characters, each line at most 300 after the mask, a file over 2 MB refused, and the whole answer masked as the
facts are (`redact_secrets`). The file is opened the way the daemon opens its own (`core/held.py`: no link followed along the
path, one name of one regular file), and a path is matched as it was written, never through a link, so a file the run
wrote and then replaced with a link to a guarded one, a folder swapped for a link, a hard link and a pipe are refused;
`held.py` now opens a step with `O_SEARCH` where the kernel has it and `O_DIRECTORY` alone where it does not, so the
module works where the unit tests run on Linux.
`agent/review.py` carries `reads` in `GoalVerdict` and the rule in its system prompt; a verdict with `inspect` and no
read, more than two, a read on a decision, a second inspect after the evidence, or an inspect where the check may not
read, is a protocol error and the model is asked again. `agent/loop.py` asks the check once more with what the files
hold, and never more than once. A campaign's claim (`tools/campaign.py`), which asks the same question but has no run's
facts behind it, is told that inspect is not available.

Checked: `tests/unit/test_goal_read.py` (thirteen tests: the named lines of a written file, a file the run did not write
is never read, a file swapped for a link, a hard link and a folder swapped for a link, too large, the line cap and the
mask, a secret longer than a line's share masked before the cut, the shape of inspect and of a decision, a check that
may not read, the prompt with and without evidence, the second ask with the evidence, one ask for a decision). The two
smoke tests that pin this prompt are updated with it: `test_run_limits.py` reads the rule as it now stands, and
`test_context_budget.py` rises by 150 for the hand-over line item 1362 adds to the prompt and to `delegate`'s
description (30,305 measured on the gate's runner, system 8,758, tools 21,377). `ruff`, `mypy` and the unit tests of
the touched modules pass.
Not done: the check cannot run a command (only read what the run wrote).
