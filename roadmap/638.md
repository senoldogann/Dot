### 638. Web-research 1.4.7 in Dot: Google's Chrome fallback is held too, and Chrome asks for no keychain

**Status: done (2026-10-25).** The independent security review of item 637 found three things in web-research 1.4.6.
Item 637 closed one of them in Dot (F2: the server now starts in its own folder) and stated the other two as limits
until 1.4.7. The dot-0b session released 1.4.7 (web-research PR #16, on PyPI), and this item pins it with the lock.

**What 1.4.7 brings, one commit each (as its author measured).**
- **F1: Google's Chrome fallbacks are held to the address guard.** These are the installed Chrome, headless or
  visible, that the search takes when Camoufox cannot start. On 1.4.6 a page's script there reached a private address;
  on 1.4.7 it reaches nothing (`tests/test_google_chrome_guard.py`, against the installed Chrome).
- **F2, a second layer:** Camoufox's fetch runs as `-P -m camoufox fetch` (`-I` on Python 3.10), in an empty folder of
  its own.
- **F3: an older Camoufox cache is left alone.** A non-empty `~/Library/Caches/camoufox` without `.0.5_FLAG` is said
  to hold an install this camoufox does not use. `camoufox_path` is not called, so it is not deleted, and no fetch
  starts.
- **The keychain.** The Chrome `_start_chrome` runs gets `--use-mock-keychain` and `--password-store=basic`. The
  "Keychain Not Found" dialog the owner saw on 2026-10-25 came from a security reviewer's reproduction that started
  this Chrome inside sandbox-exec. Now no such Chrome asks macOS for the owner's keychain.
- **Dates and speed.**
  - DuckDuckGo's dates become a result's date (weight 0.45; `strict_dates` still reads the page).
  - The search's Camoufox keeps a page for the next search and is shut down when idle. Its author measured 2.6 GB
    freed at 35 s with the idle time at 20 s. The first search went from 13.8 to 3.3 s, the median from 3.72 to
    0.71 s.

**The change.**
- `pyproject.toml`: `dotagent-web-research==1.4.7`. `uv.lock` moves that package alone; its hashes were checked
  against PyPI's. Its dependencies are 1.4.6's, and fpgen stays 1.3.0, so the fingerprint model in the owner's Python
  environment stays.
- `docs/safety.md`: the two limits that waited on 1.4.7 are gone. It says what 1.4.7 does instead: Google's
  fallback is held, the old cache is left alone, and Chrome has a keychain of its own.
- `docs/extending.md` and `docs/development.md` name the version.

**Checked.**
- Dot's web-research tests, unit and smoke, on the installed 1.4.7: 105 passed. They include the server's schemas
  against what Dot judges, and the switches Dot sets.
- The installed package was read for each fix: the fetch command `('-P', '-m', 'camoufox', 'fetch')`,
  `--use-mock-keychain` in `google_search.py`, and the guard held in `_search_headless_chrome`.
