### 587. One gate for every text Dot learns

**Status: done (2026-10-23).** The harness audit of 2026-10-23 (items 587 to 589) read how the learned parts meet in the
system prompt and found that the texts Dot learns are checked by four gates that disagree: the harness components'
(`harness/components.py`), the lessons' (`agent/lessons.py`), the learned skills' (`agent/playbooks.py`, `_WITHHELD`)
and none at all for Dot's lines of the owner section (`agent/reflection.py`, `_describe_owner` masked secrets and cut
sizes). A habit with a hidden 76-character instruction in variation selectors was adopted and stood in the prompt while
its owner saw one plain line; `evil.example/collect`, `data:`, `javascript:`, a Cyrillic *er* in a scheme,
`hxxp[:]//evil[.]example`, `/Users//ada`, `~ada` and a fullwidth key all passed the components; the lesson check and the
component check disagreed on a fullwidth e-mail address; a habit could hold a fake `# Trust and safety` heading or a
`[system note]` line; and a Dot line that began `(you said)` was indistinguishable from the owner's own, which the
prompt says outranks the others. This entry was written before the code, as item 540 asks: what must hold, where it is
held, and what only asks. The code follows it.

**What must hold, and what only asks.**

| What | What must hold | Held by | What only asks |
| --- | --- | --- | --- |
| A text a page wrote does not take over a prompt | no learned text stands in a prompt except with the owner's say, and none outranks the rules of trust and safety | the owner's adoption of a version (`auto` never adopts a proposal from a run that read outside content, item 392); the lead of the habits and of the tool guidance, which say that the rules of the prompt win; the prompt's own order | the gate: it refuses a text by the names it can read |
| The owner's mark means the owner | a line marked `(you said)` is the owner's own | the prompt builder puts the mark on the owner's lines only (`owner_prompt_lines`) | the gate refuses a Dot line that wears the mark, at the night's write and again when the prompt is built |
| One question, one answer | the same text gets the same verdict wherever it is learned | one module, `core/learned_text.py`, and no pattern of the same question anywhere else | which questions a kind of text is asked (below) |

**Decisions.**

- **H1, which rule.** The first of the audit's two options: refuse every default-ignorable code point, plus the line and
  paragraph separators (Zl, Zp), on top of the categories refused before (Cc, Cf, Cs, Co, Cn). The second option, to
  allow only printable categories, would let through exactly the characters of the audit: variation selectors, the
  combining grapheme joiner, the Mongolian and Khmer selectors are marks (Mn), the Hangul fillers are letters (Lo), the
  Braille blank is a symbol (So). Python has no property for the first, so `_IGNORABLE` lists its ranges (checked in a
  test against the `regex` module, which has the property), and the Braille blank, which is no ignorable, is listed by
  itself. A habit with an emoji written with its variation selector is refused; the owner can write the emoji without
  it.
- **M1, one module with four readings.** `core/learned_text.py` reads a text as written, in NFKC, with a small table of
  Cyrillic and Greek look-alikes put for Latin letters (and what prints nothing left out), and with the defanged
  spellings put back (`[.]`, `[dot]`, `[:]`, `[at]`, `hxxp`); every question is asked of every reading. No dependency.
  It finds schemes, `www.`, `data:` and the other addresses that act without slashes, `//host`, a host with a path or a
  port, a numeric address that is not a local one, a host named bare on a known top-level domain, e-mail addresses,
  home paths in any spelling, account names, secrets, characters that print nothing, and lines that imitate the prompt.
- **A bare host, and the domains that are also words.** The list of top-level domains is in code, in two parts. A host
  on `_ALWAYS` (the generic domains that are no common word, `example` and `onion`, and the country codes that are no
  file extension or word) is a host wherever it stands. A host on `_AMBIGUOUS` is also a file's name or a word
  (`README.md`, `main.py`, `build.sh`, `Safari.app`, `item.id`, `user.name`, `logger.info`, `window.top`), so it is one
  only with a port, a path or a third label. That keeps the habits a Mac agent needs (`Read README.md before you edit`)
  and loses `evil.md` bare; the docs say so.
- **Naming a site is not going there.** A lesson of a run that read outside content and the description of a learned
  skill may name a site bare (`On x.com the view counts are not in the page`): browser runs are always tainted, and a
  rule that dropped every lesson that names a site would end what Dot learns of the web. They are asked for an address
  to go to alone (a scheme, `www.`, a path, a port, `//host`, `data:`, `javascript:`, a numeric address). A habit, a
  line of tool guidance, a line of the owner section and a step of a skill are instructions every run follows, and are
  asked for the bare host too. `finds_link(text, naming=False)` is that difference, and the only one.
- **L4.** `lesson_problem` is the gate without the link and the account name (a lesson of a clean run may name a site
  and an account), so a fullwidth e-mail address, `ada[at]example[.]org`, `/Users//ada` and `~ada/` are found as in a
  habit, and so are a character that prints nothing and a line that imitates the prompt. `outside_problem` asks the link
  (naming a site allowed) and the account name of a lesson of a run that read outside content, in every reading.
- **L5.** A line that starts like a Markdown heading (any), like a bracketed, parenthesized or angled system, developer,
  assistant, user, tool, Dot, harness, note or instruction tag, or like `System:`, `Developer:`, `Assistant:` or
  `Human:` is refused. A rule that only talks about them (`A system note is how the loop talks`) stays.
- **H2.** `vetted_dot_lines` runs every line the owner writer returns through the gate and refuses one that holds the
  owner's mark anywhere, in any reading and any case or spacing; a refused line is dropped and logged
  (`owner_line_refused`, with its number and why, never the line), and the night goes on. The old masking of secrets in
  those lines goes: a line with a secret is refused whole. `owner_prompt_lines` asks the gate again when the prompt is
  built, with the patterns of secrets only, so that a line an older Dot stored (the reflection writes the lines only on
  a night with runs) never reaches a prompt. The owner's own lines are not checked; the prompt marks them.
- **L8, lines.** A text's lines are counted at every break `str.splitlines` knows (a carriage return, a line and a
  paragraph separator among them), so five lines are five wherever they end; the separators are also refused outright.

**Review round 1 (2026-10-24).** An independent security review of 587 to 589 found that the guards of the loop, the

the fix, as item 540 asks: *what must hold is made structural, and the net is a net.* The structural part: the gate is
asked of a text **whenever it is used**, not only when it is written (I4), the owner's mark is refused in **every**
learned text (N3), every text a model writes into the harness goes through the gate (N6), and a night that refuses every

rule that a habit never overrides trust and safety.

**Pre-push review, round 3 (2026-10-24).** One Important and one Nit (the Nit is item 589's).

- **The writer was asked for what the gate drops.** `_OWNER_SYSTEM` asked for "the tools, sites and applications they
  use", and the gate (H2) refuses a host named bare, an address and an `@handle` in a line of the section, so "Reads the
  news on bbc.co.uk and codes on github.com" was dropped at night (`owner_line_refused`) and left out of every prompt,
  stored lines included; with every line of a night so, the old ones stayed and were filtered out all the same. The
  part of the section about the sites the owner uses emptied, and `docs/memory-and-schedules.md` still promised it.
- **The decision: the rule stands, and the writer and the docs follow it.** The other way, to let the section name a
  site as a lesson does (`addresses=False`, then `finds_link(naming=False)` and `finds_handle`), was not taken, for the
  reason the rule was made: a line of the section is an instruction every run reads at the start, as a habit is, and a
  domain in a line every run reads is the instruction surface the gate closes (a page that reached the notes or the
  goals could have the writer put an address there for a run to go to). A lesson may name a site because browser runs
  are always tainted and a rule that dropped every lesson that names one would end what Dot learns of the web (the
  decision above); the section has no such cost. A name carries the same to the model: "the BBC" tells a run what
  `bbc.co.uk` would, and it is how the owner would say it. So the writer is asked for the tools, services and
  applications by their names (`"GitHub"`, `"the BBC"`, `"Linear"`), never by a domain, a web address, an `@handle` or
  an e-mail address, and told that a line that holds one is dropped, whatever else it says; the memory doc says the same
  and that the owner's own lines are never checked, so a site written by its domain there stands. The gate is not
  loosened.
- `agent/review.py` (under "Always needs a human"): the words of `_OWNER_SYSTEM` only (the tools, services and
  applications by name, and one rule of what is dropped). Nothing else of the file changes; no policy file is changed.
  `defaults.toml` says "by their names" in the comment of `owner_chars`.
