### 467. A run never reads the value of a password, code or card field, outside yolo

**Status: done (2026-10-21).** The fourth of the nine ideas taken from OpenBot (item 449 has the plan): the values of
secret fields kept out of what the model reads. Until now Chrome's snapshot printed the value of a filled password,
one-time-code or card field (`textbox "Pass" [ref=e3]: hunter2`), a search of the page found it, the changes view after
a step showed what the owner typed in a takeover, and a screenshot showed it too. **As built.** One definition of a
secret field, the one Dot refuses to fill by: the page's marking, a `password` input or an `autocomplete` token of
`SecretKind` (`browser/safety.py`: `secret_selector`, `hides_secrets`). Pure parts (`browser/snapshot.py`):
`filled_fields`, the text box, search box, spin button and combo box lines with a ref whose value is on their line or,
as Playwright 1.63 prints a field with a placeholder, on a `text` line under it (the critique's catch: the design's rule
missed that form); `hide_values`, which shows `[hidden]` on both and keeps the name, the ref and the placeholder. Page
parts (`browser/driver.py`): `capture_lines` hides before the lines are rendered, searched or compared, so the view,
`browser_find` and the changes view never see the value; `secret_refs` asks each filled field of the snapshot by its own
ref, all at once, with a short timeout after a count: a field that cannot be asked (gone since the snapshot, its frame
closed, too slow) and a ref of another shape count as secret, with a structured warning, and there is no cap of fields
(the critique). The design's first ask of each frame, whether it held a marked field at all, was taken out at the second
review: what a page is like after the snapshot cannot answer for it, as a payment frame added and taken away in between
leaves no trace (Playwright drops a frame that went from the page's list), while a field asked by its ref is the one the
snapshot showed, or is gone and hidden. `screenshot_jpeg` covers the marked fields of every frame that is still
attached; the selector names the inputs and text areas the driver's field marking reads, so the screenshot and the lines
hide the same fields. Not in yolo (the owner's rule and item 443): `hide_secrets` is required on every view of
`BrowserSession` and the tools give `hides_secrets(ctx.approvals)`, so a yolo run is shown every value and pays no
probe. What is left as it was, said in the docs: `browser_eval` can read a value and is judged as any step, the live
Screen view, desktop screenshots, a password field turned into text with no marking. Measured (median of 15 snapshots):
a page with a password and a code field 10.4 ms without masking and 13.1 ms with it, a page of three ordinary filled
fields 4.3 and 6.6 ms, a page of sixty 4.7 and 34.4 ms. Tests: `tests/unit/test_snapshot_mask.py` (Chrome's real
snapshot of such a page kept as golden text, so a Playwright that prints fields otherwise fails a test of the gate; the
fields found on their line and under it; the value hidden on both and the rest kept; a search that finds no value; a ref
written into a name and a quoted key; the four modes; the selector's kinds; a field that cannot be asked or went since
the snapshot hidden, an ordinary field kept, a marked one hidden, yolo asking nothing),
`tests/smoke/test_secret_masking.py` (a real headless Chrome: a password, a code and a card field with placeholders and
a card field in a frame of another origin; the view, searches, the changes view after the page changed values, the text
and the links of the page, none with a value; the screenshot's pixels covered on the four, not on an ordinary field;
yolo shown every value; sixty filled ordinary fields kept; the browser tests fail without the placeholder rule), the
browser tests of the session given the new argument. Docs: `docs/safety.md`, `docs/browser-and-computer-use.md`,
`docs/daemon.md`.
