### 633. The Agents page names Dot's newest chat on its card, and the cards' ages keep up with the clock

**Status: done (2026-10-25).** The owner, with a screenshot of Your agents (fourteen cards, each saying "No chats yet"):
"No chats yet doesn't work dynamically: I talk to some agents all the time, and it still says No chats yet."

**What was found.** This was read on the owner's own daemon, read-only through its API.
- **Dot's card.** `GET /api/agents` built Dot's summary with `latest=None` (`server/routes_agents.py`). Its card said
  "No chats yet" always, over the owner's 138 runs with Dot in eight chats.
- **The other thirteen cards.** They were right: no run of the owner's has an agent.
  - Reviewer and Competitor Watch learned lessons from runs that are not there any more. Their chats were deleted, and
    `delete_threads` deletes a chat's runs with it.
  - Dot made Social Media Manager in a chat whose Instagram schedule runs as Dot. Item 463 lets no run's model hand a
    schedule to an agent; the owner can, in the schedule's Agent field.
- **The ages.** A card's "just now" was written once, when the list was read, and the list is read again only when a
  run starts or ends. Left open, the page said "just now" for an hour.

**The change.**
- `Store.latest_dot_run` gives the latest run of Dot's newest chat, with the chats and their latest runs that the chat
  list has:
  - runs a person, a schedule or a channel started, not a delegated one, none a rewind took out;
  - a chat is Dot's as that list says whose a chat is, by its latest run: not an agent's, not a campaign's, not one
    with a team. Their own cards name those chats. A chat whose latest run is an agent's after Dot's is the agent's
    (the review's nit: the first version judged each run alone).
- `GET /api/agents` gives it to Dot's summary with its chat's title.
- Dot's face works on the card while that run works, as an agent's does.
- The ages of the agents' and the teams' cards are written again every minute while the page stays open.
- `docs/agents-and-campaigns.md` says it.

**Tests.**
- `tests/unit/test_agents.py`: Dot's newest run is its own chat's, and not one of these after it: an agent's, a
  helper's, one in a chat with a team, or a campaign session's. A newer one counts until a rewind takes it out. A chat
  whose latest run is an agent's after Dot's is not Dot's; this fails against the first version, which judged each
  run alone.
- `tests/smoke/test_teams.py`: the list names Dot's newest chat by its title beside an agent's.
- `tests/smoke/test_agents.py`, in the browser:
  - Dot's card names its newest chat, and not "No chats yet".
  - With the page's clock moved ten minutes and the list kept from being read again, Dot's "just now" becomes "10m ago".
    This fails without the ticking.
