### 982. A drag is judged where it lets go

**Status: done (2026-11-05).** **Found** by the security audit of 2026-11-05 (the owner's ask; run-1 lead
`dotagent.desktop.actions.inspect_step:drag-destination-unjudged`): a `desktop_act` drag was read and judged at its start
point alone (`inspect_step`); its end was resolved only as it ran, checked for the failsafe corner. A file of Finder
dropped on a page went with no flag (a low-risk step any preset lets through, a run that read a page included), and a
drop on a password manager or on Dot's own window was neither refused nor asked, though docs/safety.md says those are
never controlled outside yolo. `browser_upload`, which gives a page a file the same way, carries `upload`.

**Built.** `desktop/actions.py` `inspect_step` reads a drag's end point too, as `StepContext.drop`;
`desktop/safety.py` `assess_step` judges a drop on a password manager, Dot's window or Chrome's grant as a step there
(refused outside yolo), the control it lets go on as a click, and something taken out of Finder into another
application as an upload (medium, `upload`, which a run that read outside content asks about); `refuse_secrets` refuses
a drop on a password manager in every mode. Docs: `docs/browser-and-computer-use.md`.

**Checked.** `tests/unit/test_guard.py` (a Finder drag onto a browser is an upload, onto a password manager, Dot's window
or Chrome's grant is high risk and secret access, within Finder no upload; a drop on a password manager is refused; it
failed before the change), the desktop unit tests.
