### 2030. A swipe on a message quotes it and does not pull the chat back

**Status: done (2026-11-27).** The owner, on a real iPhone: swiping a message (Dot's or their own) to quote it left the chat.

Root cause: iOS 26's navigation pulls a pushed screen back from a swipe to the right anywhere in it (the content pop
gesture, `UINavigationController.interactiveContentPopGestureRecognizer`), which the swipe on a message is. The swipe to quote
(item 1972) was a pan that began alongside every other gesture (`shouldRecognizeSimultaneouslyWith` always true), so both
ran: the message was quoted and the chat went back, or the pull-back won.

Rules:
- The swipe's pan and the navigation's pull-backs (the edge's `interactivePopGestureRecognizer` and iOS 26's
  `interactiveContentPopGestureRecognizer`) never run together, and the pull-backs wait for the swipe's pan to fail
  (`shouldBeRequiredToFailBy`). The pan fails at once for a start less than 32 pt from the screen's edge, for a pull that is
  not to the right and for one that is not more across than down, so a swipe from the edge, a scroll and a swipe to the
  left still go to the system. The chat's own scroll still runs beside the pan.
- On the web (a phone width) quoting is a button of the message's foot and its sheet, not a touch gesture, so there is
  nothing there to conflict with.

Checked: `ChatUITests` pushes a chat fixture over a root (`-DotNextPushed YES`, "Fixture home"): a swipe from mid-screen on the
owner's message and on Dot's quotes it and the chat stays open; a swipe from the screen's edge goes back to the root. The
build and the test run on GitHub (`ios.yml`).
