**Status: done (2026-11-20).** `full` was the default "until evals show that groups help" (item 524). Measured now, on
the eval catalog (47 tasks, one attempt each, `opencode_go:deepseek-v4.1-flash`, run from this branch and from `main`
side by side, reports `20261120-145335` and `20261120-145340` in `evals/`):

| | full | grouped |
|---|---|---|
| passed | 46 of 47 | 47 of 47 |
| input tokens | 5,736,716 | 3,237,575 (−44%) |
| a pass costs | 4.7 steps, 123.0 k tokens | 4.6 steps, 69.6 k tokens |

The one task `full` failed (`find-first-error`) is one attempt, not a verdict; the point is that grouped does not lose
a task and spends 43% fewer tokens. On the owner's Mac 188 of the 205 task runs in its database (counted with a query of the `tool_groups` events, 2026-11-20)
started grouped already, since a run of more than 128 tools does so whatever the setting: the default now says what the
Mac does. A model that turns a group on with `use_tools` or by calling one of its tools gets it for the rest of
the run (item 524); `full` and `auto` stay settings.

Changed: `defaults.toml`, `docs/runs.md`, `docs/extending.md`, and the tests that pinned `full` or read what a first
step carries: `test_tool_groups`, `test_eval_choice` (the default), and `test_scaffold`, `test_mail_calendar`,
`test_team`, `test_context_budget` (the budget is that of every tool offered) and `test_browser_settings`, which now ask
for `tool_surface = "full"` themselves, since their subject is not the surface.

Checked: the unit tests (7,218), the smoke tests that need no browser (1,407 passed) and `dotx eval check`. Not measured: other models than deepseek-v4.1-flash, and one
attempt a task is a thin sample; `dotx eval run --repeat 3` is the way to widen it.
