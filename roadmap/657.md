### 657. Settings › Web search: the order of the engines, their keys, and a try of each

**Status: done (2026-10-25).** This is the page of item 655, under Models beside AI services.

**The page.**
- **Asked in turn** lists the engines web_search asks, numbered, each with what it is and whether it is ready.
  - A row moves up or down, and Turn off takes it out; a search keeps one engine at least.
  - When an engine is not ready, the row says what it lacks: a key, the Ollama or Anthropic key in AI services, a
    SearXNG address, the web-research server, or Dot's own browser.
- **Not asked** lists the rest, each with Add, which puts it at the foot.
- **A search API's key** is saved there in Dot's `.env`, as AI services saves a model provider's key. It is never shown
  again but its last characters, and Remove takes it out.
- **Try** asks one engine one search ("Dot web search test") and says how many results in how many seconds, or why it
  failed. An engine that lacks something is not asked at all.
- **Live.** An order and a key hold from the next search, with no restart.

**The routes** (`server/routes_websearch.py`):
- `GET /api/web/search`;
- `PUT /api/web/search/order` (empty refused, each engine once, written as `[web] search_order`);
- `POST|DELETE /api/web/search/keys/{engine}` (only the four APIs' variables, one change of the key file at a time);
- `POST /api/web/search/try/{engine}` (not the browser rung, which opens a window).

**Test.** `tests/smoke/test_web_search_settings.py`, in a real browser, wide and light, and on a phone and dark. A test
of its own, which reaches nothing, does the following:
- adds Tavily;
- moves it up, and the order and the config file hold it;
- saves its key, which the page never shows and `.env` holds, and Tavily is ready;
- tries Exa, which says it needs a key and is not asked;
- on the phone, keeps inside the screen and removes the key.

**The reviews.** The pre-push review found that a key from the environment was said to come from the Keychain (the
page compared `"env"`, the source is `"environment"`), and that the route kept a copy of the rule of whether the
web-research rung exists; it uses `tools.web.web_research_runs` now. The independent security review found nothing.
The route that saves a key does what Settings › AI services does, and the owner should look at it as at that one.
