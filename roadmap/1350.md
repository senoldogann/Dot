### 1350. A message from the home starts a chat of its own on the model picked, and a message for a model that cannot answer is refused by name

**Status: done (2026-11-23).** The owner's report: "I opened a clean Dot, picked a different model in the composer, sent
my message. Dot continued in an old project chat that had been left over, did not start with the model I selected, and
showed an error."

Root cause, two parts, both reproduced in Chromium on a throw-away home with one finished chat from another day (the
scripted model, a second one `deep` picked in the box):

- **The home went on in the chat of the latest activity.** Items 1245 and 1279 made the home's box a message to "Dot's
  home chat", which `Store.dot_home_chat` names as the newest chat whose latest run is Dot's, however old and whatever
  it held, and `whereTo` in `views/runs.js` sent the message there with that chat's `thread_id`: a box that looks new
  (empty, "Message Dot") continued an unrelated chat. Recorded before the change: the run of the message had the old
  chat's `thread_id`, and with the old chat's run still at work a message queued or steered into it, where the model
  picked is dropped (a steer joins the run under way).
- **A model that cannot answer was taken and failed after the start.** `POST /api/runs` and the queue only parsed the
  reference; a model whose provider has no key started its run and chat, which ended "The task failed: missing API
  key" (`MissingSecretError`, `secrets.py`), in the old chat the owner had been put in, with the message stranded in a
  failed run.

What changed:

- **The home starts a chat** for every message to Dot (`whereTo`); only an agent the owner picked has one lasting
  chat, as before (item 1233). A chat is gone on in from its own page (**Open your chat with Dot**, the sidebar),
  where the box is that chat's. The run records the model picked: checked in the run's own record.
- **A refusal before anything starts** (`RunManager.check_model_answers`, called by `start_picked`, `start_for_agent`,
  `start_for_team`, `start_campaign` (Keep going), a message into an agent's own chat and `queue`, the last on the
  model the message will run on, the agent's own when it names none, so the pages, the phone, `dotx run`, the share
  sheet's `POST /api/runs`, a channel and a queued message that drains meet it; a schedule's firing is not asked, but a run that lands in an agent's own chat
  with no agent named is judged by the agent's model as a message there is): a
  model whose provider has no key, whose program (OpenCode, Claude Code) is not installed, or that Ollama's service
  retired is refused with `ModelUnavailableError` (HTTP 422; `model`, `problem`, `fallback`): "openai:gpt-5.5 cannot
  answer this message: no openai key is set. Send it on ollama:x, the default model, or fix the model in Settings ›
  Models." Nothing is made by a refusal, so the words stay in the box (a channel tells the owner), and the home's and
  a chat's box show a button that sends the same message on the default model (`modelrefused.js`, `refusedModel` in
  `errors.js`). A model its provider merely does not list is not refused.
- **A steer says it keeps the model**: a message sent into a run at work while the box names another model tells that
  the model waits for the next message (`intent.keepsModel`).
- Left as it is on purpose: Dot opening at the chat screen it was on last (item 810) shows that chat and its history,
  and the box there is that chat's.
