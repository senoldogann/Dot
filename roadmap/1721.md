### 1721. A shown page that names media by a web address is refused with why, a page too long says how to shrink, and the pages of one step keep the call order

**Status: done (2026-11-24).** The audit of 2026-11-24 (A3, D2 to D4): a page with `<img src="http://…">` or
`<video src="http://127.0.0.1:50899/…/final.mp4">` drew a broken picture and an empty player (the page's policy loads
pictures, sound and video only from `data:` and `blob:`), while `show_page` answered "is shown to the user"; 2 of the
owner's 18 pages did, and the run remade them with `data:video`. A page over 500,000 characters was refused with the
limit alone. Five `show_page` calls of one step drew in a different order each run, as the calls ran at once and each
page took its place when its call ended.

What changed (`tools/page_files.py`, `tools/pages.py`):

- `remote_media(html)`, a pure function: the web addresses (`http:`, `https:`, `//host`) of the pictures, sounds and
  videos a page names in its tags (`img`, `video` and its `poster`, `audio`, `source`, `track`, `input`, SVG `image`),
  its `srcset` and its icon link. `show_page` refuses a page that names any, before it is kept, with the addresses and
  how to write them in (a workspace file by its relative path, or a `data:` address). What its styles name is not read:
  a sheet or a font of another host (Google Fonts) leaves the page in its fallback fonts, as before, and a background
  picture is its ground, not what it shows (the pre-push review's second round: refusing those cost a page that showed
  fine). The page's policy (`server/guard.py`, under "Always needs a human") is unchanged:
  pages run untrusted scripts, and fetching a page's media for it would have Dot fetch addresses a page names.
- `too_long(name, chars)`: a page too long, given as html or by its path, is refused with its length and how to shrink
  it; a file named by its path is written in as base64 as well, so it takes the same room (the brief's "images by file
  or URL rather than base64" does not shrink a page: a URL does not load, a file is written in).
- `show_page` is not parallel-safe: Dot's own loop runs the pages of one step one after the other, in the order of the
  calls.

Checked: `tests/smoke/test_pages_in_order.py` (a scripted run shows three pages in one step with the store slowed for the
first two, then a page with a `<video>` by a web address: the pages stand in the call order, the video page is refused
with `ok: false` and not kept; without the change the order came out reversed and the video page was kept, both seen
failing once), unit tests of `remote_media` and of both refusals in `test_page_files.py` and `test_page_by_path.py`, the
browser tests of the shown pages.
Not done: a run on the Claude plan or OpenCode calls each tool through the bridge as the program sends it, so the order
there is the program's; nothing on the screen changed (a refused page is never drawn), so no new screenshots.
