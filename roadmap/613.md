### 613. A run's core note stands for every run only once the owner pins it; a switched-off step says off

**Status: done (2026-10-24).** The owner asked to make sure that the self-improvement works and is of use. On the
owner's Dot, a week of numbers (`dotx stats --days 7`) showed:

- **Core notes no rule let go.** Four notes went to almost every run, 198 or 199 of 201. One was the owner's own. The
  other three had been written by runs and tagged `core` by them: about a thesis template, a job search and a thesis's
  hours. A `core` note was handed to every run, never rested, was never proposed to be forgotten and was never merged
  (`prompt_memories`, `resting`, `rested_since`, `proposable`). So whatever a model once tagged `core` went with every
  run for good, whatever its goal: in the prompt of a run about a table for two, and in its tokens.
- **The harness's step was off**, and the page and `dotx stats` said "last went well 2026-10-21", because it had run
  once.

**As built.**

- **What stands.** A note stands for every run (`stands` in `memory/service.py`) when it is tagged `core` and is the
  owner's own: one they wrote, or one they pinned (item 584's pin). A run may still tag a note `core` to ask that it
  stand. Until the owner pins it, it is a note of a run's like any other:
  - it is handed when it fits the goal (by similarity, with embeddings on, as `inject_min_similarity` says);
  - it rests after `rest_days` unused;
  - it may be proposed to be forgotten;
  - it may be found outdated by a newer note.
  Merges still leave `core` notes alone.
- **The tool says it.** `memory_save`'s `tags` says that `core` asks that the note be handed to every run, and that it
  is once the owner pins it.
- **The Memory page** marks a run's `core` note no one pinned *Core once pinned*, with a title that says what pinning
  does.
- **Off says off.** "The nightly self-improvement" says *off*, and when it last went well if it ever did, while
  `[harness] step_time` is `off`: on the Memory page's How learning fares, and in `dotx stats`.
- **The docs.** `docs/memory-and-schedules.md` (the start notes, resting, the proposals, how learning fares).

**Not changed, and why.** The owner's notes that runs tagged `core` keep their tag. Pinning one makes it stand again,
and the page marks which they are. Nothing of the owner's is rewritten.

**Tests.**

- `tests/unit/test_memory_taint.py`: a run's core note is not handed to a run it does not fit, and is to one it fits;
  the owner's and a pinned one are handed to every run. It fails against the code before.
- `test_memory_ranking.py`, `test_memory_lifecycle.py`, `test_reflection.py`: a run's core note rests, is proposed,
  has a rest date and may be outdated; pinned, it stands (these said the opposite).
- `test_learning_health.py`: off after a step ran.
- `tests/smoke/test_memory_page.py`: the badge on the one note it fits.
