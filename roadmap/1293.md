### 1293. The shell environment filter holds back more of the variables that carry a secret

**Status: done (2026-11-21).** The filter of `child_env` (`tools/shell.py`) removed a variable from the environment of the
commands of a run when its name held `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `CREDENTIAL` or `AUTH`. A personal
access token (`GH_PAT`), a password under another name (`MYSQL_PWD`, `DB_PASS`), a DSN, a cookie, a session, a webhook
and the address of a database with its password in it (`DATABASE_URL`) went through to every command.

`tools/env_filter.py` now decides (`hides_secret(name, value)`), by name without regard to case: `TOKEN`, `SECRET`,
`PASSWORD`, `PASSWD`, `CREDENTIAL`, `COOKIE`, `NETRC`, `BEARER`, `WEBHOOK` anywhere; `KEY`, `AUTH`, `SESSION` anywhere;
`PASS`, `PAT`, `PWD`, `DSN` as a word of the name (so `PATH`, `COMPASS` and the working folder's `PWD` and `OLDPWD` are
not caught); a name ending `_SK` or `_PK`; `DATABASE_URL`, `REDIS_URL`, `MONGODB_URI`, `AMQP_URL` and
`CELERY_BROKER_URL`; and any other name ending `_URL`, `_URI` or `_PROXY` (`HTTPS_PROXY`) whose value has
`user:password@` in it. A short list of ordinary names is kept though a weak part stands in them (`SSH_AUTH_SOCK`, `XDG_SESSION_*`, `TERM_SESSION_ID`,
`ITERM_SESSION_ID`, `SECURITYSESSIONID`, `GPG_TTY`, `KEYCHAIN*`, `GIT_AUTHOR_*`, `HOMEBREW_NO_*`, `PATH`, `PWD`,
`OLDPWD`), but never when the name holds a strong part (`KEYCHAIN_PASSWORD`). A prefix of that list (`KEYCHAIN`,
`XDG_SESSION_`, `GIT_AUTHOR_`, `HOMEBREW_NO_`) excuses only the weak part it holds: what follows it is read as any name
is, so `KEYCHAIN_PASS`, `KEYCHAIN_PWD`, `KEYCHAIN_KEY`, `XDG_SESSION_KEY` and `GIT_AUTHOR_KEY` go, as the old filter
held them back. `[shell] pass_env` still lets a name through.

Two decisions the item's text left open. `SSH_AUTH_SOCK`, `GIT_AUTHOR_NAME` and `GIT_AUTHOR_EMAIL` were dropped by the
old filter (`AUTH` is in them) and are now given to commands, as the item asked for `SSH_AUTH_SOCK`; the docs said the
agent's socket was withheld on purpose (item 555), and now say it is given. A name ending `_SK` or `_PK` goes by its name,
not by its value (a secret key's value, `sk_live_...`, has no `://`).

Checked: `tests/unit/test_env_filter.py` (a table of 81 ordinary names that stay and 65 that go, of addresses by value,
`pass_env` for each name that goes, and a login environment passed through `child_env`), `tests/unit/test_osascript_env.py`
and `tests/unit/test_restart_when_idle.py`, which use `child_env`.
