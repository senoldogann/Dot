### 1953. A helper ends at its open pull request, and the checks are watched in the background

**Status:** done (the words of two prompts and a tool's description; the effect is measured after the deploy).

The run review of 2026-11-26 (problem 10) found the coding helpers waiting for CI inside their runs. Measured on the
owner's store (read-only, the 76 `delegate` runs of the week, 2 524 M input tokens): 8 138 shell calls took 29.0 hours;
**382 of them were `gh pr checks` or `sleep` calls and took 9.27 hours, in 37 of the 76 runs**. Each poll of a Claude
Code helper reads about 200 k tokens of context again, and the wait keeps a session, and the plan's 5-hour window, open
for nothing.

What Dot has for this, found before choosing: `wait_until` waits in code (item 887; the helpers used it 195 times for
12.8 hours too), watchers look at mail, the calendar, GitHub notifications and named checks the owner configured (a check
is the owner's `[checks]` entry, which a run cannot add), and a command started with `terminal_open` and `background`
tells its chat when it ends, starting a run in it when none works (item 229). The last one is the notification that
fits: no model turn and no token while it waits, and the result reaches the chat. A delegated run has no chat of its
own to be told in (item 1760), so the parent, which has one, is the one that watches.

- `agent/prompt.py: _DELEGATED`: a helper whose part ends in a pull request ends its run once it is pushed and open,
  names its address, says its checks are pending, and runs no `gh pr checks` loop, no `sleep` and no `wait_until` on
  them.
- `tools/delegate.py`: the `delegate` tool's description tells the parent to watch the checks with `terminal_open`
  (`background`) and `gh pr checks <number> --watch`, and that its chat is told when they end.
- `tools/shell.py: BACKGROUND_HINT` names a pull request's checks among the commands that go to the background (the
  sentence is left out of a run that has no chat, as before).

Not done, with the reason: no new watcher kind (a `pull request` watcher would be a model of its own: state, the token's
scope, a poll) before the words are measured; the number to look at after the deploy is the shell hours of `gh pr checks`
and `sleep` calls in helper runs (9.3 h in a week) and the helpers' input tokens.

No ask and no denial changes in yolo or free mode: nothing of the gate or the policy is touched
(`tests/unit/test_freedom_contract.py`). The prompt surface was written again (`scripts/prompt_surface.py`): only the
two tool descriptions changed, the system prompts of the five kinds do not carry the helper's lines.
