### 804. A table, a block of code and the HTML of an answer read clean on a phone

**Status: done (2026-10-28).** **Asked** by the owner: "tablo, kod satırları, ve diğer olası her şeyi düzgün ve temiz
göstersin" in the iMessage channel. `channels/text.py` (item 617, 627) made a table one row to a line, its cells joined
by ` · `: on a phone's narrow screen a row of three or four cells wraps into a run of words that no column holds
together. A block of code ran straight into the words before and after it, as Messages draws no box around it, and the
HTML tags, entities, footnotes and backslash escapes a model writes into Markdown reached the phone as they were.

- A table of two columns is a line to each row, `• first: second`; one of three columns or more is a card to each row,
  its first cell after a bullet and each other cell under it as `Header: value` (an empty cell left out), with a blank
  line between the cards; one of one column is its header and a bullet to each cell; a table with no header words
  joins each row with ` · `, as before (`table_lines`).
- A block of code has a blank line before and after it; one indented under a list item stays with the item.
- The tags of HTML (a list of names, so `x < y` and `<custom>` stay) go and their words stay; an entity with its
  semicolon reads as its character; `[^1]` reads `[1]` and the line of its note starts `[1]`; a mark after a backslash
  is the mark, held like a code span so it is never read as emphasis or a list.

**Checked.** `tests/unit/test_channel_text.py`: two, three and one columns, a short row, a table with no header, code
apart from the words and under a list item, tags, entities, footnotes, escapes; the earlier expectations of a table
and of code changed with them.
