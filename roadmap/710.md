### 710. The plugin scout finds, checks and reviews plugins for the gallery

**Status: done (2026-10-27).** The owner: the plugins and skills should keep up with the best and most accepted the
world makes, a system that lives and grows; "with the right planning, and skip no step". Decided with them: nothing
installs itself, the scout looks every night, skills and plugins first (MCP servers later).

**Research** (2026-10-26): Anthropic's marketplaces are the catalogues to read (`claude-plugins-official` lists 315
plugins and pins the commit of each kept elsewhere; `anthropics/skills`, `knowledge-work-plugins`); skills.sh ranks by
installs but has no interface; and agent skills are a supply chain under attack (an audit of ClawHub found 341 malicious
skills of 2,857; another found critical issues in 13 %). So: known sources, rules before a download, a pinned commit and
the hash of what was read, a scan, a review, and the owner's click.

**The change.** `plugins/scout_sources.py`: the leads of Anthropic's marketplaces (tier a; the community one tier b), of
the makers the gallery takes from (tier a) and of GitHub's topics (tier b), and the rules on what GitHub says of a
repository (MIT or Apache-2.0, 90 days old, not archived, pushed within a year, 200 stars for tier b).
`plugins/scout_scan.py`: the scan of exactly the files an install keeps. `plugins/scout_review.py`: the review model's
verdict in one tool call (risk, refuse, does, why in the owner's language), the skills fenced, never lower than the
scan; and the fit to the owner's recent goals. `plugins/scout.py`: one night, bounded in leads, updates and time; a
plugin unusable by its own files (a link, a skill it lists without a `SKILL.md`) is remembered, one that failed for the
night's reasons tried again. `plugins/scout_types.py`: what is kept (key-value store, bounded). The model call's purpose
is `scout`.

**Measured on the real thing** (real GitHub, real catalogues and archives, a stand-in reviewer): a look of five took 17
requests and 8-12 s and proposed four. It found two faults the fixtures had not: a catalogue that lists a skill folder
with no `SKILL.md`, and a skill that holds another `SKILL.md` among its resources; both are handled and tested. The
scan's rules were tuned on Anthropic's, Hugging Face's, Supabase's and Superpowers' skills: a maker's own CLI install, a
credentials file named by its own AWS skill, a Slack webhook in an alerting skill, "never publish without asking the
user" and an ngrok tunnel of a migration skill read as medium or nothing, not high.

**The review of the first push:** an update's key was kept before its review, so a review that did not come lost the
update until the repository moved on (now kept once reviewed, or once its files are found unchanged); an update did not
pass the rules (it does now: a repository whose licence changed or that was archived has none proposed); a fit that fell
back to words said nothing (`scout_fit_by_words` now); a plugin whose files could not be read (`OSError`) ended the
night (it counts as failed, and the others go on); and the night now ends at its next plugin when the emergency stop is
engaged (`ScoutStopped`, nothing kept). `merged` lays what a night found over the state as it is when it ends.

**The review of the second push:** the bounds cut the candidates by position, so a few nights' finds pushed out a plugin
the owner had installed from a proposal (the gallery lost it, its updates and the dedup with it): each state is bounded
on its own now, and an installed one is never pushed out by new finds. A catalogue's `repo` went into GitHub's addresses
unchecked, and one the gallery's model refuses ended every night: it is checked against the repository pattern where it
is read and by the lead's own model, and a `ValueError` of one lead fails that lead alone. Tested in
`test_scout_sources.py` and `test_scout_night.py`.

**The review of the third push** (the third BLOCK; the owner chose the structural option): the plugin's name, publisher
and source, the files an update changes and the path and words of each finding stood outside the fences, and each is the
authors' to choose. Now one fence holds all of them and each skill has its own; outside stand only Dot's words, the
rules met with how many times, and the owner's words. Tested in `test_scout_review.py`: a word planted in each of the
eight places is found eight times, never outside a fence, and both tests fail on the code before.

**The review of the fourth push:** the leads were chosen before what was looked at was read, so a catalogue's plugins
without skills or refused by the rules (most of the official marketplace's 315 are connectors without skills) were taken
again each night before any other, with their requests, and a few nights would have proposed nothing while saying so. A
plugin the catalogue pins at a commit looked at is now left out before any request, and of the rest a night takes first
those taken longest ago (`seen`, kept with the state), so those one night has no room for come first the next. Tested in
`test_scout_night.py`; both tests fail on the code before.

**The review of the fifth push:** a plugin was known by the source that named it, so one skipped under a GitHub topic
came back under a new id once another topic named it at a newer commit: a candidate now keeps its folder (`path`), and a
plugin is known by its repository and folder, among the gallery's, the installed ones and the candidates, whichever
source names it. An update was checked by the rules of a maker's repository, so one of a community plugin never met the
200 stars: it is checked by the tier the plugin was installed from. Tested in `test_scout_night.py`; both tests fail on
the code before.

**The review of the sixth push:** the updates looked for were the first installed plugins by name, each night the same,
so those after `updates_per_night` never had one looked for (a fix of a hole among them too): they are taken as the
leads are, those looked at longest ago first (`seen`), and only those of the gallery or of a proposal, the others having
no skills to compare. Tested in `test_scout_night.py`, which fails on the code before.

**The review of the seventh push:** the review model read only each `SKILL.md` and the names of the other files, so a
harmless one that says "run scripts/setup.py first" passed with a `setup.py` that sends the owner's data away by words
no rule of the scan names. It now reads the text of the files beside each skill, the scripts first, in the same fences;
a file too long for its budget is named to it as not shown and is an `unread` finding, which keeps the risk from being
low. Tested in `test_scout_review.py` and `test_scout_night.py` (the code before had no text of those files to give).

**The review of the eighth push:** the docs said a night without a token stays within GitHub's 60 requests an hour,
which a night with several plugins installed did not, and the rest of it met 403s counted as failures: GitHub's count of
what is left is read from each answer, and the night ends when two are left, or when an answer says they ran out ("out
of GitHub's requests"), what it did not reach coming first the next night; the docs say what a night takes. A plugin
named with one letter made an id the candidate refuses, and failed each night: an id has two characters at least. An
update whose newest commit no longer had a skill Dot installed failed each night: it is unusable at that commit, and
looked at once. A plugin the review refused is not proposed again, which the docs now say. Tested in
`test_scout_sources.py` and `test_scout_night.py`; each fails on the code before.

**The review of the ninth push:** the key of an update looked at held the new commit alone, so after a Revert the update
from the version put back counted as looked at, and none was proposed until the repository moved on: the key holds the
installed commit too. A new plugin skipped or refused shared the bounds of the settled ones, and once pushed out was
proposed again: those the bounds push out stay declined (`declined`, its repository and folder, the last 5,000). Tested
in `test_scout_night.py`; both tests fail on the code before.

**The review of the tenth push:** each maker's repository is the gallery's too, and a lead of the whole repository was
left out whole, so a skill a maker added was never proposed, though the docs said Dot looks there: a whole repository is
never known whole, and the skills of a repository the gallery, an installed plugin or a candidate holds are left out one
by one, the rest proposed. Tested in `test_scout_night.py` (fails on the code before).

**The review of the eleventh push:** the tenth push's change left a plugin of a whole repository (a maker's, or a GitHub
topic's) known by its skills alone, and the ninth push's `declined` held only its folder, so once pushed out of the
bounds its skills were proposed again. A plugin declined is now kept by its folder and by each of its skills, and the
skills held of a repository include those: one place, `_held`, decides for both kinds of lead. Tested in
`test_scout_night.py` (fails on the code before); `defaults.toml` says updates are looked for of the plugins installed
from a proposal too.

**The review of the thirteenth push:** whether a file is text was read from its name, so a script named `setup.png` was
neither scanned nor shown to the review, nor said unread. A file is now text by what it holds (UTF-8 without a NUL,
`scout_scan.text_of`), whatever its name; text in a file named as an image, a document or a font is a high finding
(`disguised`), and it is scanned and shown as any other. Tested in `test_scout_scan.py` and `test_scout_night.py`, which
fail on the code before. Anthropic's, Hugging Face's, Superpowers', Supabase's and Cloudflare's skills scanned again on
2026-10-27: still at most one high finding (the same packed archive of Anthropic's own).

**The review of the fourteenth push:** whether a file was shown whole was read from the length of the text read, so a
file cut at the bytes read (four-byte characters, the last one cut in two) could pass as shown whole: it is read from
the file's size on disk now. The scan read the first 2 MiB of a file: it reads every byte. Tested in
`test_scout_review.py` and `test_scout_scan.py`, which fail on the code before.

**Checked.** `test_scout_sources.py` (the trimmed catalogues, each rule with its twin), `test_scout_scan.py` (each rule
and a twin written as a good skill writes it, hidden Unicode shown by its codes), `test_scout_review.py` (verdict,
floor, no verdict is an error, timeout, fences, the fit), `test_scout_night.py` (a night end to end: proposed, refused
by the review and by the rules, unusable, without skills, already in the gallery, an update with its changed files,
nothing looked at twice, one failure leaves the others, out of time; the proposal installs through the gallery's own
check; an update whose review did not come is tried again, an update refused by the rules, one unreadable plugin leaves
the others, the stop ends the night, and `merged` keeps the owner's decisions), `test_scout_review.py` also that a
fallback to words is logged.
