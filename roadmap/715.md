### 715. Dot works for the owner on its own while the Mac is idle

**Status: done (2026-10-27).** **Asked by the owner:** sessions that go on for ever; when the goal needs no step,
Dot, which knows them by now, goes and does other things for their good, on its own. Their choices: fully free (their
own approval mode, `yolo` for them), no limit, while the Mac is idle. makecindy/cindy's companions (Apache-2.0,
`docs/product-rules/cindy-bots-runtime.md` §6.3 and `teammate-authority.md`) do it with a list and events rather than a
bare timer that wakes a model to invent work, and they never take a companion's own goals as the owner's word: the
ideas are taken, not their code.

**What must hold.**

- Off until the owner switches it on; the emergency stop holds it; one of its runs at a time; nothing while a run of
  the Mac works or while the owner uses the Mac (`CGEventSourceSecondsSinceLastEventType`, `idle_minutes`).
- Its goals are Dot's words: `RunManager.start_own` starts a run of `INITIATIVE_SOURCE`, whose goal gives the review
  model no instruction (`_register_run`, as the background notice's of item 229). In `ask` and `auto` what reaches
  others still asks the owner; in `yolo` nothing asks, as the owner chose.
- What a tainted run put on the list is done by a tainted run (`todos.tainted`, `RunOpening.tainted`): in `yolo` the
  review model's check of item 525 refuses a message, a post, a payment or an upload that no word of the owner's calls
  for. The run that looks for work takes the taint of the runs whose words its record quotes, as the morning brief does.
- No loop: a thing is not listed twice (30 days after it ends), a run tries it `attempts` times at most, then it is let
  go and the owner told; the look for work comes every `look_every_hours` at most, a research run that changes nothing
  but the list.

**The change.** `todos` in the database; `proactive/todos.py` (the list, its switch in `kv`, the card's view and
actions); `proactive/initiative.py` (`Initiative`, a part of the scheduler's tick); the tool `todo_add` (a write of
Dot's memory to the policy, so a research run has it; its own group `todos`); `[initiative]` settings; `GET`/`PUT
/api/initiative` and the list's routes; the **On its own** card on Schedules (`initiativecard.js`); the source is
unattended where a schedule's and a watcher's are (`loop`, `prompt`, `progress`, `manager`).

**Checked.** `tests/smoke/test_initiative.py` on a scripted model: switched off, or with the Mac in use, nothing starts;
switched on and idle, the oldest thing is done in a chat named after it, with no instruction for the reviewer, marked
done with the answer's first line and told; a failing thing is tried twice, then let go and told; a thing a tainted run
listed starts tainted; with nothing listed, a research run looks and lists what it found, and the next tick does it;
the API switches it, lists, refuses a duplicate in other spacing and case, drops and takes up again; the card in
Chrome at 1280 and 390 pixels. `tests/unit/test_tool_groups.py` (the group `todos`), the unit tests, `dotx eval check`.

**The code review of the first push.** The look's record quoted the titles of the newest chats, a watcher's among them
(a mail's subject), and the titles of things a tainted run had listed, into a run that starts untainted: a planted line
could come back as an untainted thing to do. The record names only the chats a person started and counts, without
quoting, the things that came from such content. The day's count of its runs is read from the store, not kept in
memory, so a restart does not count from none; `docs/runs.md` lists the new tools. Checked by
`test_the_record_of_a_look_quotes_no_words_a_third_party_wrote` and
`test_the_runs_of_a_day_are_counted_from_the_store_across_a_restart`.

The second round: a resumed run kept its goal as the owner's words, and a later run of a chat of Dot's own took the
goals of the chat's earlier runs, Dot's among them, for the owner's instructions; the goals of runs of Dot's own, of
resumes and of the notices of item 229 are never instructions now (`_NOT_THE_OWNERS_WORDS` in `agent/manager.py`: a
resume of the owner's run keeps the owner's words through the run it resumes, which its chat holds). A start that fails
takes its empty chat with it and holds the next ten minutes; the day's runs are counted in SQL
(`Store.count_runs`). Checked by `test_its_goals_stay_dots_words_in_the_later_runs_of_its_chat_and_a_resume` and
`test_a_start_that_fails_leaves_no_chat_and_is_not_tried_again_at_once`.

The third round: the look wrote back the whole state it had read before it started, the switch with it, so the switch
the owner turned off while it started was turned on again; the switch and the time of the last look are each written
in one update that keeps the other as it stands (`switch_initiative`, `note_look`), checked by
`test_the_owner_switching_it_off_while_a_look_starts_keeps_it_off`.

The fourth round: a thing whose run a crash cut off was taken up again at every start with its try uncounted, so a thing
that brings Dot down was never let go; a crash counts a try now (`cut_off_by` tells it from a shutdown, which, with the
emergency stop, counts none), and a thing tried as often as a lowered `attempts` allows is let go instead of holding the
part of the list that is read
(`test_a_thing_whose_run_a_crash_cut_off_counts_a_try_and_one_a_shutdown_cut_off_does_not`,
`test_a_thing_tried_as_often_as_a_lowered_limit_allows_is_let_go`).

The fifth round: the card said that what reaches others asks first, which `yolo` does not: it says so, or that `yolo`
refuses it; and when macOS cannot say how long the Mac has been idle, which keeps every start back, the card says so
(`idle_readable` of `GET /api/initiative`).

The sixth round: a thing was compared with the oldest 500 of the list only, so after some weeks a thing done lately
could be listed again; its normalised title is kept (`title_key`, indexed) and compared in SQL (`Store.same_todo`). A
thing whose chat the owner resumed was done a second time in a new chat; a later run of its chat now has it, and done

Checked by `test_a_thing_is_not_listed_twice_however_long_the_list_grew` and
`test_a_thing_whose_chat_the_owner_resumed_is_left_to_that_run`.

The ninth review (a pass, with nits): only a resume of a thing's run takes it over, not another message of the owner's
in its chat; and a thing whose run ended while the daemon went down is settled as any end (let go when the owner stopped
it), a crash alone counting a try.
