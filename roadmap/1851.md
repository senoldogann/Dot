### 1851. The orphan-groups test keeps a Dot home of its own, which no other pytest worker writes into

**Status: done (2026-11-25).** `tests/smoke/test_orphan_groups.py::test_each_kind_of_start_is_written_down_while_it_works_and_forgotten_after`
failed on `main`'s gate (2026-11-25, `assert ['12085.json'] == []` after the code-mode start) and passed alone. The
cause: the gate runs the smoke tests with `-n auto` and one `DOT_HOME` for every worker, and `process_groups_dir()` is
that home's. Any other worker's shell command, terminal or code-mode script writes its group's file into the same
folder while it works, so a test that reads the folder empty saw another worker's file; the module's fixture also
deleted the others' files, and another worker's runtime, on its recovery, could end the stand-in dead Dot's group
before the first test did.

What changed: the module's autouse fixture gives each test a `DOT_HOME` of its own (`monkeypatch.setenv`, a fresh
`tmp_path_factory` folder); the stand-in Dot inherits it through `os.environ`.

Checked: the old module failed at once with a loop writing a file into the shared folder beside it, the new one passed
with the same loop; the module 3 times under `-n 4` with `test_note_trace.py` and `test_helper_wake.py`, green.
