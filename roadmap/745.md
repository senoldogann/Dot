### 745. A `browser_upload` of a custom "choose file" control reaches its field

**Status: done (2026-10-27).** **Measured:** in the owner's runs of the last 30 days, 8 of 57 `browser_upload` calls
failed with "uploading the files failed | Locator.click: Timeout ...ms exceeded", on job-application forms: a custom
"choose file" button, a field kept hidden.

**How a ref reached the chooser.** Item 704: the element if it is a file input, else the one file input inside it,
else a click that waited for the element to be visible, stable, uncovered and enabled before it could open the file
chooser, and failed after `action_timeout_s` when a button was redrawn all the time or under a layer.

**The change** (`driver.upload_files`), in the order it tries, each a way that cannot give the files to another
control than the one meant:

1. the field the element is, or holds (as before);
2. the field of its label (`for`, or the one it wraps), or the one an id in its `aria-controls` names
   (`_CONTROLLED_FIELD_SCRIPT`): files set without a click;
3. a click, and the chooser it opens takes them; a click that times out waiting for the element (not one that went
   through and opened nothing) is made once more with `force=True` and a two second wait for the chooser, only when the
   element itself is the topmost at its middle (`_ON_TOP_SCRIPT`, `elementFromPoint`): `force` skips the check that
   another element would take the click too, and a forced click on a button under a layer would press the layer (a
   bar that sends a form, a cookie banner) (`_chooser_files`);
4. when no chooser opens, the file field of the page if it is the only one (`_only_file_field`): with one field there
   is no other control the files could be for. A page with several keeps the 704 rule: a field beside a button that
   opens nothing is not taken.

Nothing of the tool's checks changes: which files may be uploaded (the workspace, or any in `yolo`, copied and checked
as before), the click's risk and flags, the landing check, the page the upload brings up marked untrusted.

**Not done.** A field next to the button, or the nearest in its form, on a page with several fields is still not taken:
a resume could go into the cover letter's field. The runs' failures that were such pages remain failures, with the
error that says what the click waited for.

**Checked.** `tests/smoke/test_browser.py::test_a_control_that_names_its_field_or_never_holds_still_or_opens_nothing_still_uploads`
in a real headless Chrome: a `div role=button aria-controls` on a page of two fields (no click, under 3 s), a button
that never stops moving (CSS animation) whose chooser takes the files, and a button that opens nothing on a page with
one field. It fails on the code before; the 704 test (a field beside a button on a page of several is not taken) still
passes.
