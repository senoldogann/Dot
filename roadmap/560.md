### 560. The docs say what Dot does: auto's review model on messages, what leaves the Mac, a lost phone, the home folder

**Status: done (2026-10-23).** Asked by the owner: a last, deep review of the whole project before calling it ready. A
review of the code and the docs by part (twenty auditors) found these places where a page under `docs/`, the README or
SECURITY.md says something the code does not do or leaves out what a user needs. An independent check read the code
for each before it was kept. The code's own findings are items 551 to 559 and 561, and each fixes the lines of the docs
its change touches.

**As built.**
- `docs/safety.md`:
  - A message or a post in your name waits for a yes in every mode that asks: yours in `supervised` and `ask`, the
    review model's in `auto`. It said "your yes" everywhere, which `policy/engine.py`'s `route_for` and
    `tests/unit/test_guard.py` contradict; `docs/autonomy.md` and the README had it right. `docs/extending.md` said the
    same of an MCP tool that sends.
  - What leaves this Mac now lists OpenCode Zen's free models, whose providers may train on what they get. It also
    lists what the mail and calendar tools ask of Gmail, Google Calendar and Microsoft Graph, the requests of 1Password's
    `op`, and the plugin gallery's download from GitHub. It said it listed everything.
  - Removing `SSH_AUTH_SOCK` keeps a command from being told where the SSH agent listens, not from reaching it: the
    socket is a file in a fixed place that the sandbox does not close.
  - The locations of `[policy] protected_paths` are kept from a run as far as the policy sees: the file tools refuse
    them, and so does the shell guard for a command line whose words reach one. What a script reaches by itself is
    not seen, which the page's note on the guardrail said further down and this line now says where it promises.
- `README.md`: the memory's embedding model is a requirement whatever provider runs the models (Ollama's `bge-m3`,
  OpenAI's, or none with `embed_enabled = false`). It was listed under Ollama alone, and `dotx setup` with another
  provider left notes that could not be saved. The way to keep a run's conversation on the Mac names the helpers, the
  standby models and the embeddings, as `docs/safety.md` does.
- `docs/phone.md`: how to cut a lost phone off. Its token is the installation's own and does not expire. Take it off
  the tailnet, delete `<home>/api-token` and restart for a new token, `tailscale serve reset`, and the name out of
  `[server] reach`.
- `docs/configuration.md`: the home folder's table names `vapid-key.pem`, `plugins-data/`, `playbooks/`, `evals/` and
  `daemon.running`.
- `docs/models.md`: OpenCode's sandbox switch is in Settings › Rules (there is no Settings › Sandbox).
- `docs/extending.md`: Remove plugin refuses a plugin of `[plugins] dirs` with 409, as `routes_mcp.py` and
  `docs/daemon.md` say; Redis's gallery plugin has no logo.
- `docs/harness.md`: the scoring set is the eval tasks of `[harness] scoring_tasks` (runs kept as tests are left for
  later, as the page's end said); the selector is built but the step does not call it yet, so `[harness] selector`
  has no effect.
- `docs/daemon.md`: the side panel's tabs are Changes, the plan, the agents and the screen; there is no actions tab.
- `SECURITY.md`: only the latest release is supported, and a fix ships as a new version. It said there were no
  releases.

Two findings of a second, independent audit are in it too: the overclaim about `[policy] protected_paths` and the
local-model recipe of the README. One finding is left to item 557, which fixes it with the code: the "Reflection above"
of `docs/memory-and-schedules.md`.

**Tests.** Prose only. The links and anchors it adds resolve (`runs.md#mail-and-calendars`,
`extending.md#1password`, `extending.md#customize--plugins`, `phone.md#dot-on-the-phone`).
