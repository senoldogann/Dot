### 628. A keychain file that is not there is refused, and no test reaches the login keychain through it

**Status: done (2026-10-24).** Item 621's agent (the vault) found, while probing, that `security` does not fail on a
keychain file that is missing. It reads and writes the login keychain in its place. Its probe put a dummy vault item
(`dot-vault`, `vlt_x`) in the owner's login keychain, then removed it, and its Keychain layer now refuses a missing
file.

The same hole was in the tokens of the accounts signed in (item 422, `oauth/keychain.py`). `tests/smoke/conftest.py`
points `DOT_KEYCHAIN` at a file that does not exist, and its comment said that keeps every test away from the owner's
login keychain: true of a read that finds nothing, false of a write.
- **What was found.** A look for the test addresses of the repository (`<provider>:<address>`, `dot-oauth`, no value
  read) found one such item in the owner's login keychain: `microsoft:someone@example.com`, made on 2026-10-19.
  - No test of today's tree writes that account. It was an earlier test's.
  - It is the owner's to remove (their Keychain); they are asked.

**As built.**
- `Keychain._run` refuses a keychain file it names that is not there ("the keychain file is not there") before any
  process starts. This holds for every call: the slot's lookup, the prompt that writes and removes, and the reads.
- A path that is not whole (`accounts.keychain-db`) is refused when the Keychain is made: `security` looks for such a
  name under `~/Library/Keychains`, and the check above would look in the working folder.
- `tests/smoke/conftest.py` says what holds now.
- `docs/development.md` says it beside the keys' isolation.

**Tests.**
- `tests/unit/test_keychain_file_missing.py`:
  - a save, a read and a forget through a missing file each raise, and no process is started (process creation is
    stood in for, and fails the test if called);
  - a file that is there is asked.
  - The first test fails against the code before.
- The keychain and OAuth unit tests (33) pass, and so do the sign-ins' smoke tests with their own keychain file
  (`test_oauth_accounts.py`, `test_mail_calendar.py`: 12).
