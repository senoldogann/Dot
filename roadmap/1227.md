- **How the work is done** (`store/models.py` `ObjectiveWorkflow`, `store/db.py` column `workflow`, `tools/objectives.py`):
  an objective gains `sources`, `rules`, `evidence`, `exceptions`, `next_step` and `record`, each optional. An older
  database gets the column with `{}`; its objectives read with none. A run that read outside content may set the next
  step, never the rest. `objective_text` and the look for work and brief (`proactive/work.py`) read them. The tool's
  description is the teaching mode: take the parts from the owner's words and two or three real cases, ask only for a
  part none shows, and none of it for a one-off task. No new system: it is the objective, extended.
- **The ledger** (`pipeline/ledger.py`, pure): three tables (Clients, Actions, Outcomes) in a marked block of the record
  file; the rest of the file is never touched, and a file with none gets it at its end. An action is begun before it
  goes out and ended sent, failed or uncertain with what showed it; begun or uncertain blocks a new try until looked at;
  sent is never begun again under its name; only failed is tried again (tries counted). A client paused or
  do-not-contact gets no action. Outcomes need a date and a source and are kept once. `compare` counts, per way of
  acting, the clients reached, those who answered after the send and those won, and `summary` says when too few to tell.
- **The record file** (`pipeline/record.py`): each change reads, changes and writes the block under a lock file beside
  the record, through `atomic_write` (noted for `dotx undo`); a refusal writes nothing; a block whose markers or columns
  were broken is neither read nor written.
- **The tools** (`tools/pipeline.py`, group `pipeline`): `pipeline_view` (any mode), `pipeline_client`,
  `pipeline_begin`, `pipeline_end`, `pipeline_outcome` (task and chat), each weighed as a file write by where the record
  is. A run that read outside content cannot lift paused or do-not-contact.
- **A reply starts its work** (`tools/replies.py`): the run item 926 hands a reply to is told to read the record first,
  keep the reply as an outcome, and begin its answer there. No new trigger: the schedule that reads the inbox is the
  event source, and the guard against twice is item 926's (once per sender in 12 hours) plus the ledger's.
