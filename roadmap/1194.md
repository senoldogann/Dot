### 1194. The installer resets its steps after a new choice with a fill, as Rust 1.100's clippy asks

**Status: done (2026-11-15).** Dependabot's #947 raises the desktop shell's Rust from 1.99.1 to 1.100.0, whose clippy
refuses the loop that set the installer's steps back to waiting when the person chose another model or key
(`needless_range_loop`, `src/installer.rs:1845`; the only finding, run 43344986715). It was the reason the desktop
checks went red on main on 2026-11-13, before item 1189 pinned the toolchain.

- `desktop/src-tauri/src/installer.rs`: `inner.states[MODELS_STEP..STEPS.len()].fill(StepState::Waiting)` in place of
  the loop over the same indexes. `states` and `STEPS` both hold four entries and `StepState` is `Copy`: the same steps
  are set to the same state, and an index out of range panics as it did.

Checked: `cargo fmt --check`; `cargo clippy --all-targets -- -D warnings` on 1.99.1 (pinned) and on 1.100.0;
