### 725. The shell guard asks before the upload and publish tools it knows by name

**Status: done (2026-10-27).** From the outside review of 2026-10-27 (its finding 1): after a run read outside content,
`git push`, `scp` and `curl -T` asked, while `aws s3 cp`, `rclone copy`, `docker push`, `npm publish`, `twine upload`,
`cargo publish`, `gem push`, `hg push` and `lftp -e 'put …'` went through without a word, as `runs <command>`, low risk
and no flag; a package published to a registry asked nothing even in a clean run, though a public post is one of the
things Dot does not decide alone.

**The approach (item 540).** Nothing here must hold: the kernel's part stays what it is (the sandbox keeps a run out of
Dot's own files and the sealed stores, not out of the owner's others), and a program can send anything out under a name
the guard does not know. What changes is what only asks: the guard asks by the names it can read, as it does for `git
push`, and the docs say what it does not read. No spelling is chased: a tool is known by its name and the words that
make it send, found among its words wherever its options put them (`npm --registry r publish`), and a tool not in the
table is the limit the docs already state.

- **A public post** (`public_post`, medium; asked in every preset, as the docs promise for public posts): a package
  published to a registry anyone reads, `npm`/`pnpm`/`yarn`/`bun publish`, `cargo publish`, `twine upload`, `uv
  publish`, `poetry publish`, `flit publish`, `hatch publish`, `gem push`, and an image pushed, `docker`/`podman`/
  `buildah push` (and `docker buildx build --push`).
- **An upload** (`upload`, medium; asked once the run read outside content, as `git push` and `scp` are): `aws s3
  cp/mv/sync` and `aws s3api put-object`, `gsutil cp/mv/rsync`, `gcloud storage cp/mv/rsync`, `az storage … upload`,
  `rclone copy/copyto/move/moveto/sync/bisync`, `hg push`, `svn commit/import`, `croc send`, `wormhole send`, and
  `lftp`, `smbclient` and `tftp` whatever they are told (each can put a file from its own commands).
- **Not read, and said so:** a name looked up (`dig`, `nslookup`, `host`) carries out what the line puts in it, and
  `openssl s_client` sends what it is given; the docs name them with the limits, as reading them would ask at each
  lookup.

**The reviews of the first push.** The pre-push review: a verb was looked for among all the words of a line, so `docker
run image echo push` and `hg log -k push` were taken for a publish and a push; and a copy down from a bucket asked as an
upload, which the docs did not say. The independent review: an option between a service and its verb (`aws s3 --profile
p cp`), the tools' own abbreviations and aliases (`npm pub`, `gem pu`, `hg pus`, `wormhole tx`), the other ways to push
a build (`--push=true`, `-o type=registry`) and verbs the table did not name (`rclone rcat`, `rclone serve`, `az storage
fs file upload`, `svn copy` to a URL) went through. A table of the verbs that send was a list of spellings to chase, so
the structure changed: a publish verb is looked for where the tool's verb stands (its first word, or its first after the
values of the options before it), with the shortest abbreviation the tool takes; an upload tool asks for any verb but
those that only read (`_UPLOAD_READS`, the storage services' reads), and when which word is the verb cannot be told (an
option of unknown kind before it) it asks; the options the tools' own lists say take a value (`--profile`, `--config`)
are read as such. A copy asks in either direction, and the docs say so; a package published through an interpreter
(`python -m twine`) is a limit the docs state.

**The review of the second push:** the options that make a build push (`--push`, `-o type=registry`) were looked for
among all the words of a `docker`, `podman` or `buildah` line, so `docker run -e PUSH=true app` and `docker run img
./release.sh --push` asked as a publish, which no rule of the owner's can quiet: they are read among the options after a
build's verb alone (`build`, `buildx build`, `image build`, `compose build`), `--push=false` is none, and an output
pushes by the value of `-o` or `--output`.

**The review of the third push** (a pass, with nits taken): `rclone link`, `gsutil signurl` and `aws s3 presign` stood
among the verbs that only read, though each makes a link anyone can open to a private file: they send now, asked once
the run read outside content.

**The review of the fourth push** (the third BLOCK; the owner chose the structural fix): `az storage` alone still sent
by a list of the verbs that send, so `az storage blob generate-sas`, a link anyone can open, went through while `rclone
link` asked: `az storage` is now as the others, a send unless a verb that only reads stands among its words (`list`,
`show`, `exists`, `download`, `url`, `stats`) and none that sends does.

**The review of the fifth push:** an option's value that is a reading verb (`az storage container set-permission -n
list`) made the line a read: the verbs of `az storage` are read before its first option alone.

**The review of the sixth push** (a fifth BLOCK; the owner's choice): `gcloud storage objects` and `buckets` stood among
the reads, so every verb under them, making a file public included, went through; a list of the verbs that only read let
through, round after round, a verb a group hid (`az` before, `gcloud` now). The storage services of `aws` (`s3`,
`s3api`, `s3control`), `gcloud` and `az` now have no reads: every command of theirs asks once a run read outside
content, `aws s3 ls` too, and a run that read none is not asked.

**The review of the seventh push:** the service was looked for in the command's first word, and gcloud puts its release
track first (`gcloud beta storage cp …`, `gcloud alpha storage buckets add-iam-policy-binding …`), which no longer
asked: the track is read past.

**The review of the eighth push:** the service was still looked for where the command's first word stands, which past
gcloud's release track and an option the guard does not know (`gcloud alpha --billing-project p storage cp …`) was told
wrong. The service is now any of the command's words: never too few questions, and a value named like a service (`az
group create -n storage`) asks too, once the run read outside content.

**Checked.** `tests/unit/test_shell_senders.py`: each tool of the table, with its options before its verb, is asked
about as the table says, after outside content and (a publish) in a clean run, and its twin that only reads (`npm view`,
`docker pull`, `rclone ls`, `hg pull`, `svn update`) is not, while every command of a cloud storage service asks (`aws
s3 ls` too, `gcloud beta storage`); `dotx eval check`.
