**Status: done (2026-11-07).** **Why.** The owner's ask of 2026-11-07: the nightly learning's proposer and composer
should use Opus on their Claude plan, not Anthropic's API. Until now a model of the plan answered only a run, whole
(item 1013); every single call of Dot's was refused, so the roles could not use one.

**What must hold.** A role's question is one call with no tool at all: `claude -p --output-format json` with `--tools
""`, `--setting-sources ""` (no hook, no CLAUDE.md), `--strict-mcp-config` and no MCP config, no slash command,
`--permission-mode dontAsk`, `--no-session-persistence`; the environment of item 1013's run (no API key, no
secret-named, `DOT_*` or `GIT_*` variable); the question on the program's input and the system prompt in a 0600 file of
a private folder of the call, removed as it ends, never in the arguments `ps` shows. The init line must list nothing but
`StructuredOutput` (or nothing for a text answer), the measured built-in plugins aside, else the call fails. A used-up
window fails the call with when it resets (`ProviderWindowError`); nothing switches model. A conversation, a picture or
more than one tool is refused: only a run, whole, has those.

model's one tool and the result carries `structured_output`; a harness proposal came back in 3 s within its bounds.

(`flatten_json_schema`), so `habits` came back as the text `"null"`: the call's schema allows null in each field
(`answer_schema`), as an API does, and Dot's own validation of the answer holds it.
