### 917. Import from Chrome: the sign-ins of a profile of the owner's Chrome copied into one of Dot's from a dialog

**Status: done (2026-11-02).** **Asked** by the owner, with a screenshot of another app's "Import from Chrome" (from a
profile of their Chrome, with its cookies, into a new profile or one there is): a profile made by picking the cookies of
their Chrome directly would be a more visual and better setup.

The import was `dotx browser import-chrome [--profile] [--replace]` only, into the profile in use: a command to type,
the name of a Chrome folder to know ("Profile 1"), and a profile to switch to first.

- `browser/chrome_import.py`: `chrome_profile_titles` (the names Chrome shows, from its `Local State`), `cookie_count`
  (read-only) and `chrome_is_open`. `browser/profiles.py`: `name_for_import`. `browser/readable.py`: the check that
  counts the cookies Chrome reads, moved out of `cli_browser.py`, which the command and the daemon share.
- `GET|POST /api/browser/chrome-import` (a profile whose cookies cannot be counted is listed with why, `uncounted`,
  not left out with the others) and `POST /api/browser/profiles/{name}/check` (`routes_browser.py`): the
  import is the command's, all or nothing; into a new profile that goes again when it fails, into one there is only
  with `replace` when it holds sign-ins, never Incognito; refused while Chrome is open, and while runs are active when
  the profile is the one in use or is to be.
- Settings › Browser › Profiles: **Import from Chrome** opens the dialog (From, Into, Tasks use it), which looks again
  every 3 seconds while Chrome is open, then imports and checks, each said in a toast.
- `docs/browser-and-computer-use.md` says so.

**Checked.** `test_browser_settings.py::test_settings_browser_imports_the_sign_ins_of_a_chrome_profile_into_a_profile_of_dots`
on a throw-away Chrome a real Chrome wrote on the mock keychain (no Keychain asked): the dialog at 1280 and 390 wide,
the import into a new profile named after Chrome's name, now in use and on the system keychain; a profile that holds
sign-ins says it is replaced and is refused without `replace`; the check reads the cookie; a Chrome that holds its data
directory leaves the cookies uncounted and the import refused. `test_chrome_import.py`: the names, the count, a broken
Local State, the new names.
