### 1466. Dot for iPhone: helpers that go on after their run ended are shown

**Status: done (2026-11-24).** The owner (2026-11-24, 10:44, with three screenshots): "5 agents work but the app does not show them
because the session ended". The chat's header said "Done · 1 min ago" and the capsule over the composer showed nothing while five
helpers still ran. The cause, found in the code: `ChatState.line` began with `guard isWorking else { return .idle }`, so once the
chat's own run had ended the line was idle and the capsule said nothing, although the daemon lets the helpers a run that ends done
started go on (`_detached` in `src/dotagent/agent/manager.py`, item 1351: "its chat is told when they end"). And the phone read the
helpers' list only when the chat opened or refreshed and followed the events of the run that works only, so after the run ended
the count never went down either.

What changed:
- **The line** (`ChatState.line`): a chat whose run is over but whose helpers are live is `.helpersInBackground(count:)`; with none
  live it is idle; while the run works it is as before (waiting on the helpers it waits for, helpers in the background after a
  message released the run from its wait). The capsule's helpers segment shows "5 helpers" (the count of the live ones, the accent,
  its icon breathing) and opens the Run sheet at the helpers (item 1467 orders it, the ones at work first).
- **The header and the status card** (`HelperWords.header`): "5 helpers working" under the chat's title instead of "Done · 1 min
  ago", "5 helpers in the background" while the run goes on, as before; the run sheet's status card says the same. "Done · 3 steps ·
  35s" under the last message is the run's own and stays.
- **The watch** (`ChatSession`, `Core/HelperWatch.swift`): while the chat is open and a helper is live the session asks for the
  list of helpers (`GET /api/threads/{id}/helpers`, one small request, nothing else) every 8 seconds (`HelperWatch.seconds`), reads
  the chat whole when a helper that was live has ended (its report may have started a run in the chat, which `catchUp` follows with
  the run's stream) and stops when none is live. With no link it asks nothing and keeps the last count; the capsule draws that count
  dimmed and VoiceOver says "last known" (`DockSummary.Segment.dimmed`). The app coming to the front (`kick`) and a message of the
  lifecycle stream (`lifecycle`) read the chat at once, as they did, and that read starts the watch again; leaving the screen or the
  app going to the background ends it. The app only reads: no ask, no wait, and never more than one small request in eight seconds
  per open chat while a helper is live. The run sheet's status card stacks its three parts at the accessibility text sizes (it was
  built for one line of words: "5 helpers working" broke in the middle of a word beside the step count).
- **The list of chats** (`ThreadRow`): the daemon's list of chats (`GET /api/threads`, `ThreadSummary` in `src/dotagent/store/models.py`)
  has no field of helpers: its `latest_status` is the newest run's, and `as_shown_thread` changes only that. The daemon is not changed
  by this item. The row says what the phone itself last read of the chat's helpers (`NativeStore.helperCounts`, filled by each read of
  a chat's helpers, the open chat's and the reading ahead's, in this run of the app only, never from the disk), and only while it was
  read at the chat's newest run (`ListHelpers`): "5 helpers working" under the words, the ring turning, the chat among the working
  ones. A chat the phone has not read in this run of the app, or whose helpers ended while it was off the screen, reads as before
  until the chat is opened or read ahead; a daemon field for it is the clean fix and is not done here.

Checked: `ios/DotTests/HelperWatchTests.swift` (the line: a run ended done with five live helpers is `.helpersInBackground(5)`,
ended with none live is idle, working is as before, a helper that ends by the list or by its own event lowers the count; the header's
words; the capsule with the count, dimmed with no link or while Dot is out of reach; the row of the list; the rule of the watch: every
8 s, only while one is live, only with a link, the whole chat when one ended) and `HelperWatchSessionTests` (a session against a
scripted daemon: it asks for the helpers again and again and for nothing else while none ends, the count goes 3, 2, then the chat is
idle and the asking stops, a helper that ended makes the chat follow the run its report started, with no link nothing is asked and the
count stays until the link is back, a chat the app left asks nothing): 21 cases. `xcodebuild test` on the iPhone 17 Pro simulator
(iOS 26.5), `DotTests`: 420 tests, 0 failures (390 before items 1466 and 1467, which add 21 and 9).
