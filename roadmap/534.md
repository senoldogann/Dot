### 534. Reading the clipboard asks, as a read of a protected location does

**Status: done (2026-10-22).** The audit of how Dot keeps the owner's passwords from a run (the owner asked whether it
is sure) found three ways a run reads the clipboard without a question in any preset: the `desktop_clipboard_read` tool
(low risk, no flag), `pbpaste` (on the list of commands that only read), and an AppleScript that returns `the
clipboard`. The clipboard is where a password sits for a minute after the owner copied it from their password manager,
which is what the manager is for: a run that read it then hands the password to the model, whatever Dot does for the
fields of a page.

**As built** (on item 531's flag `protected_read`, which a read that may reach a secret carries):
- `desktop_clipboard_read` is a medium-risk observe with the flag `protected_read`, so the aggressive preset asks,
  balanced asks (the flag joined its list), cautious asks. Its description tells the model it will be asked.
- `pbpaste` is no longer one of the commands that only read: the guard finds it a read of the clipboard
  (`policy/shell.py` `_reads_the_clipboard`), `pbpaste | head`, `$(pbpaste)` and the rest alike.
- An AppleScript or a JXA script that names the clipboard is judged the same way, as a tool of a run (`apple_script`)
  and as an `osascript` line of the shell: `the clipboard`, `clipboard info`, their raw events (`«event JonsgClp»`,
  and the `<<event …>>` spelling), JXA's `theClipboard` and `clipboardInfo` however they are called
  (`app.theClipboard()`, `(app.theClipboard)()`, `app.theClipboard.call(app)`, `a['\x74heClipboard']()`), any
  pasteboard (`NSPasteboard`, Carbon's `PasteboardCreate`) and `pbpaste` however the script runs it. A script that
  only puts text there is not told from one that reads it, so it asks too: three reviews each found a line that hid a
  read behind a write (`copy` in a string, a comment, the same line) and the approach was reconsidered after the
  third; the guard does not read strings, so a script that only names the words in one asks as well, and `run script
  "…"` is caught the same way.
- The line is scanned whole, as it is for a protected path (`_universal_findings`): any line that names `pbpaste` (in
  any letter case: this Mac's file system does not tell `PBPASTE` from it, and behind a wrapper the guard does not
  look through: `time -l pbpaste`, `arch -arm64e pbpaste`, `ssh -o ProxyCommand=pbpaste`), any line that runs
  `osascript` and names the clipboard anywhere (a pipe, a here-document, a here-string, a variable, a glued `-e'…'`),
  and any line that names a pasteboard (`python3 -c` or `swift -e` with `NSPasteboard`) asks; a line that only talks
  of one (`grep pbpaste notes`, `which pbpaste`) asks too, the price of reading names.
- Putting text on the clipboard (`desktop_clipboard_write`, `pbcopy`) asks nothing more than before. A yolo run asks
  nothing (item 443). `docs/safety.md` and `docs/browser-and-computer-use.md` say so.

Checked by `tests/unit/test_clipboard_reads.py` (each read asks in all three presets and carries `protected_read`, not
`destructive`; the writes carry no such flag; the desktop tool's action, prepared as a run would). They fail without the
change.

Not built: a script in a file (`osascript r.applescript`: the guard calls it uninspectable and, in the aggressive
preset, allows it as it allows any high-risk step without a flag), a name that the line or the script builds as it
runs (`printf 'pb%s' paste | sh`, `app['the' + 'Clipboard']()`), a script typed into a session (`osascript -i`, then
`terminal_send`), and a paste of the clipboard into an application that the run then reads back (`⌘V`, `keystroke
"v"`, `desktop_act`'s `key` step, then `desktop_read`; `paste` as the run's own step puts the run's text there), all
said in `docs/safety.md`; and a page that reads it (`navigator.clipboard.readText()` asks Chrome's own permission).
Considered and left: a deny of the pasteboard's Mach service in the sandbox profile (`com.apple.pasteboard.1`),
which stops `pbpaste` and `osascript`'s `the clipboard` for the shell, a terminal and `apple_script` whatever the
line says, and also stops `pbcopy` and a script's write inside the sandbox, which this entry promises it leaves as
it was; a later item can weigh the two. Found on the way, not this item's: the guard compares a command's name
exactly, so `RM -rf ~/x`, `SUDO` and `SECURITY` are judged as unknown commands (allowed in the aggressive and balanced
presets) on this Mac's case-insensitive file system, as `PBPASTE` was; here the line's own scan covers the clipboard,
and item 538 folds the name for every command.
