### 790. Dot's own initiative keeps a thing the emergency stop cut off

**Status: done (2026-10-28).** **Asked** by the owner, from the review of every module. A review of `proactive/`
found, each checked in the code:

- **The STOP file seen by the run let the thing go.** docs/proactive.md says a run the emergency stop ended leaves its
  thing to do; the code knew the stop of every run ("Emergency stop: every active run was stopped.") but not the words
  of a run that saw the STOP file as it worked ("Emergency stop: …"), and marked that thing "You stopped it." and
  dropped it. Every ending that begins with "Emergency stop: " leaves it to do.
- **A store failing at the first tick left things "being done" for good.** The recovery of what a stopped daemon was
  doing marked itself done before it worked; one error left the rest as being done until the next start. Each thing is
  recovered on its own, and the recovery is marked done once the list was read.
- **A run started before its thing was marked.** A daemon that died between the two left the thing open with a run
  going, and the next start began it again. The thing is marked as being done (with no run) first, and open again with
  its last run's id if the start fails; the recovery already makes a thing being done with no run to do again. What
  remains is the moment between the start and the line that names the run: narrower, not closed.

**Not changed:** the gap between its runs (`gap_minutes`) is kept in memory, so a restart while the Mac is idle may start
the next run sooner; a watcher whose store write fails after its run started may start it again at its next look.
Both are rare and cost a run, not a loss.

**Checked.** `tests/smoke/test_initiative.py` (a run that saw the STOP file leaves its thing to do), the watchers' and
the brief's tests.
