### 813. The Trading page chooses the schedule a move of the market wakes

**Status: done (2026-10-29).** **Asked** by the owner after the fresh start of Dot's store: the Trading page said
*[trading] wake_schedule names no schedule (sch_mvrgr39u_cc823a): no run is woken.*, true (the paper shift's schedule
was in the store set aside), and only the config file could change it.

- `PATCH /api/trading` takes `wake_schedule`, a schedule's id or `""` for none, kept in the config file as the other
  settings are (`config_edit` writes it); an id the store holds no schedule for is refused (422), so the setting names
  a schedule that is there when it is set.
- Settings › Trading › Watching has **Wake on a move** under its lines: the schedules (one switched off says so) and
  None; a schedule that is gone stands as *A schedule that is gone* until another is chosen, and a choice is drawn from
  the daemon's answer; a refused one (a schedule deleted meanwhile) leaves the picker on what is kept, with the reason
  beside it, and a schedule made since the page was read is offered when the picker is opened again. The lines say to
  choose there, not to write the config file.
- The owner's own config: the id of the gone schedule was cleared (`wake_schedule = ""`), so the page says no schedule
  is woken instead of the red line.
