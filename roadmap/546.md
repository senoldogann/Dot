### 546. Skills & MCP names what the run used, not every skill and server Dot has

**Status: done (2026-10-23).** Asked by the owner: the side panel's Skills & MCP area is there to list the skills and
MCP servers the agent used in that session, not the whole palette.

**As built.**
- `static/js/contextpanel.js`: `usageOf(tool, args)` reads a skill from the `skill` tool's name and a server from the
  name between `mcp__` and the tool's own (`mcp__server__tool`); `addUsage(list, usage)` lists each once in the order
  it was first used and counts its calls, and a skill and a server of the same name stay two rows. A skill read in
  parts counts once, at the call that begins it (no `start`, or `start` 0), not once per part.
- `static/js/contextpanelview.js`: `skillsSection` starts hidden and takes the root run's successful tool calls through
  the `onTool` the timeline calls as the run works and as its history is replayed; each row opens Customize › Skills or
  Connectors, wears a hammer or a plug, and says "used once" or "used N times"; the summary counts the skills and the
  servers. The palette the section used to read is no longer read by the panel.
- `docs/daemon.md` says the section lists what the run used and stays out of sight until it uses one.

**Tests.** `tests/js/contextpanel.test.js`: `usageOf` reads a skill and a server, and nothing of Dot's own tools (an
`mcp__` word inside a shell command is not a server), and a skill read in parts counts once, at its first part;
`addUsage` keeps the first-use order, counts the calls and keeps a skill and a server of the same name apart.
`tests/smoke/test_context_panel_page.py`: a run that used no skill and no MCP server has no section.
`tests/smoke/test_side_panel.py`: its scripted run, which uses neither, shows Recap and More, and More is the section
that scrolls on its own. `npm run check` (biome, tsc and the 77 JS tests), `ruff` and `mypy` pass.
