### 1940. An OpenCode run that hangs ends: a silence watch, and the time limit kept by the clock

**Status: done (2026-11-26).** The review of 2026-11-26 (wave 1, #8; CC-02 of 2026-11-19): a run on OpenCode's agent
(`opencode/run.py`) read its session's events with no time limit and checked `run_max_minutes` only when a step ended,
so a server that hung mid-stream left the run "working" for good; the outside watchdog only told the owner. Claude
Code's runs have had a silence watch since item 1013.

What changed (`_Follow`):
- `[providers.opencode] silence_s` (600 s): the run waits for its next event at most until the silence is spent, and a
  session silent that long while no tool works for it (a call `running`, OpenCode's or one of Dot's) and no permission
  waits on the owner fails the run ("OpenCode's agent said nothing for N s while no tool worked for it, so Dot ended
  it"); the agent is stopped as for any failure.
- The time limit is kept by the clock too: once `run_max_minutes` is spent with no step ending, the agent is told once
  (as at a step's end), and a run whose agent has still not ended five minutes later (`_LIMIT_GRACE_S`) is over and
  ends failed as a limit, as one that goes on two steps after being told does.
- docs/autonomy.md says it.

How it was checked: `tests/smoke/test_opencode_run_ends.py`: a silent session fails the run, a call at work holds the
silence off until it ends, and a run past its time limit with no step ending is told once and then over; with the
other OpenCode tests.
