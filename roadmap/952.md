### 952. Recurring work goes on in one chat

**Status: done (2026-11-03).** **Asked** by the owner: the same or recurring work should use the same chat; a chat
made each time confuses. Measured over a week: 32 chats of messages to agents (Growth Lead alone five or more, each
titled with its brief), 15 of Dot's own initiative (*Looking for work to do for you* four times), and a chat for each
session of a campaign after the first.

**Built.**
- `agent/manager.py` `delegate`: the work sent to an agent (message_agent, assign_work, a returned order's next
  attempt) goes to the agent's one chat, named after it, which every piece continues: its run reads what it did
  before. While a run works there, the next piece takes a chat of its own (`_agent_chat`), so that two sent at once
  still run side by side (the chat is chosen and claimed under the agent's lock, so that two pieces sent in one step
  do not both take it); a chat made for work that did not start goes again.
- A run that goes on in such a chat reads the words of the run before it there, so it starts as tainted as that run
  ended (`carried`, item 257's way), the agent's run whatever its sender is: one that read a page leaves its chat's
  next run tainted.
- `proactive/initiative.py`: a run of Dot's own initiative goes on in the chat of the same name it used last, once no
  run works there: the looks for work are one chat.
- A campaign's sessions after the first go on in one chat of the campaign's, named after it, not a chat each.
- `store/db.py` `latest_thread`.

from a tainted one starting tainted),
