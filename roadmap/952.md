### 952. Recurring work goes on in one chat

**Status: done (2026-11-03).** **Asked** by the owner: the same or recurring work should use the same chat; a chat
made each time confuses. Measured over a week: 32 chats of messages to agents (Growth Lead alone five or more, each
titled with its brief), 15 of Dot's own initiative (*Looking for work to do for you* four times), and a chat for each
session of a campaign after the first.

**Built.**
- `agent/manager.py` `delegate`: the work sent to an agent (message_agent, assign_work, a returned order's next
  attempt) goes to the agent's one chat, named after it, which every piece continues: its run reads what it did
  before. While a run works there, the next piece takes a chat of its own (`_agent_chat`), so that two sent at once
  still run side by side (the chat is chosen and claimed under the agent's lock, so that two pieces sent in one step
  do not both take it); a chat made for work that did not start goes again.
- A run that goes on in such a chat reads the words of the run before it there, so it starts as tainted as that run
  ended (`carried`, item 257's way), the agent's run whatever its sender is: one that read a page leaves its chat's
  next run tainted.
- `proactive/initiative.py`: a run of Dot's own initiative goes on in the chat of the same name it used last, once no
  run works there: the looks for work are one chat.
- A campaign's sessions after the first go on in one chat of the campaign's, named after it, not a chat each.
- `store/db.py` `latest_thread`. The store keeps an agent's chat to one run at work whichever process starts it (a
  helper's chat is still its own and checked by its process alone), and refuses to rewind a chat to before work an
  agent did there: that work's runs keep no place in its history, and a rewind would cut their words and leave them
  counted as the next work's history (the pre-push review of item 953). A chat deleted takes its runs with it, the
  work they did in an agent's chat among them, whose words stay there: that chat keeps their mark (`thread_taints`),
  which the next work there takes until a message of the owner's own in that chat clears it, every other run there
  starts marked till then, a kept step's answer, a reaction's follow-up, a resume and a background command's notice
  among them; the words stay, so that a reader of the chat (`read_agent_chat`, `read_chat`) is marked and no lesson is
  saved from it (`skill_save`, item 893) whatever the owner wrote since (the pre-push reviews of items 956 and 955); a campaign's next session
  goes on from the newest run of its chat, as the rest do.

**Checked.** `tests/smoke/test_delegate.py` (the agent's chat, a new one while it is at work, a run that goes on
from a tainted one starting tainted, another process's run refused there, no rewind past an agent's work),
`tests/smoke/test_work_orders_for_real.py` (a returned order's second attempt in the first's chat),
`tests/smoke/test_initiative.py` (two looks, one chat, the second tainted after the first read a page), `tests/smoke/test_campaigns.py` (the session chat's name).
