### 1268. The database has a version, copied before it changes and refused when newer

**Status: done (2026-11-20).** A store from an older Dot was given the columns added since at every open, each added
only where it was missing. Nothing said which version wrote a database: a change that was not a new column had no
order to run in, nothing copied the database before it changed, and an older Dot opened a newer database and wrote to
it. Taken over from a session that stopped before writing it.

- `PRAGMA user_version` holds the schema's version, `SCHEMA_VERSION = 1` (`store/db.py`). `_MIGRATIONS` lists the steps
  in order; step 1 is every column and index added before versions (`_add_missing_columns`, unchanged).
- At an open, a database below the version is copied first with the copy of the backups (item 526: SQLite's online
  backup, `quick_check`, gzip, 0600) into `<home>/backups-before-upgrade`, then takes its pending steps and its new
  version in one `BEGIN IMMEDIATE` transaction, rolled back on any error; the version is read again inside it, so the
  daemon and a `dotx` command opening at once do the steps once. A new database is made at the version with no copy.
- A database of a later version is refused (`StoreError`, with the version found and the one supported) before any
  table is made or written.
- `test_store_schema.py` pins a digest of the tables, columns and indexes of each version: a change of the tables
  without a new step and version fails there, and an old database migrated has the same tables as a new one.
- The tests that make "a store from before X" by dropping columns now set its version to 0, as such a store has.

Measured on a copy of the owner's database (320 MB, version 0): the first open made a 91 MB copy and migrated in
11.7 s, `quick_check` ok, its chats read; the next open took 0.03 s.

Checked: `test_store_schema.py` (new database, an old one copied and migrated with its rows and its copy restorable,
a newer one refused and left unchanged), the unit tests, the copy of the owner's database.
