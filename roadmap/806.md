### 806. The pictures and files the owner sends on iMessage are read

**Status: done (2026-10-28).** **Asked** by the owner (the first of the proposals for the iMessage channel): a picture
sent to Dot was only told *Dot does not read attachments yet*, and words with a picture ran without it.

- `channels/inbox.py` reads the files a row brought, as the rows of `attachment` and `message_attachment_join` name
  them (`_files_of` in `imessage.py`, which a database without those tables or columns reads as files not known): only
  from `Attachments` beside Messages' database, `..` read before the place is judged, links resolved and the file
  opened with `O_NOFOLLOW`, a regular file of at most 20 MB, the first ten of a message. A photo of an iPhone (HEIC,
  HEIF) and a TIFF are drawn as PNG by ImageIO (`core/photos.py`, moved from `tools/files.py` where item 556 had it). A
  voice message, a video and a sticker are not read.
- The intake accepts a message with a file, words or none; the channel reads the files, waiting up to 15 s
  (`FILES_WAIT_S`) for one Messages is still bringing down, and hands the words and the files to the router
  (`Receive` takes both). Only files: the run is told so (`FILES_ONLY_NOTE`); part not read: `UNREAD_NOTE`, as before,
  and the answer's first line; nothing to run: the owner is told it is on its way, or what Dot reads.
- The router keeps the files as uploads (`store_attachment`) and starts or queues the run with them, as the composer
  does; a file the upload refuses counts as not read, and a message left with nothing to run starts nothing.
- The copy of a row that one Apple ID keeps twice is told by its words and its files' names, so a picture alone runs
  once. Dot's own picture is told by the minute after it sent one, as before, and for an hour by the name of the file
  it sent (`OWN_PICTURE_NAME_S`): a copy that comes late would else run on Dot's own picture, now that a picture alone
  is a command.
- A stop the owner sends after a message whose file is still coming ends the wait at once (`_stop_after`), so `/stop`
  is not held behind it.
- The files past a message's first ten count as not read, so the run and the owner are told. While the emergency
  stop is engaged the files are not kept, as no run starts. The language of item 805 is heard only from a row the
  owner may have written: one that may be a run's own (a send at that moment, Send Later) changes nothing.
- `docs/safety.md` says what the channel reads of a message now.
