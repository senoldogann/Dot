### 1303. An awk program that prints to a target it works out while it runs asks

**Status: done (2026-11-22).** The review of the shell guard on commit 688f63322 found that `_AWK_WRITE` only saw a
redirect target that starts with a string literal, so `awk 'BEGIN{printf "x" > ENVIRON["HOME"] "/.zshrc"}'` was `safe`
and `awk '{print | "sh"}'` was `low`: awk wrote a file or ran the text it printed under names the guard never read.

`_awk_redirect_targets` finds each `print` and `printf` statement of the blanked program (its strings and regular
expressions replaced by marks) and takes the text that follows its `>` or `>>` at the top level of its parentheses, up
to the end of the statement: a `>` that compares (in a pattern, a condition, between parentheses) is not awk's
redirect. A target that is one string literal (or one in parentheses) is judged as a redirect to it is
(`_assess_redirects`); any other target is unknown, which every preset asks about as for other writes it cannot place.
A pipe to a command that is not one literal was unknown already; a literal command is judged as the line it is, and one
that is a shell or an interpreter with no script or code of its own (`_reads_code_from_input`: `sh`, `bash -s`,
`python3 -`, also behind the wrappers `_run_by_wrappers` reads through: `env sh`, `exec bash`, `nohup sh`, `env -S 'sh
-s'`) is unknown too, since it runs what awk prints. `_AWK_WRITE` is gone.

The approach: awk's grammar decides what is a target (a `>` in a `print`), not a list of function names; the verdict
of a program that prints to standard output, reads files or writes to a literal path does not change. One idiom asks
that did not: `print > "out/" $2 ".txt"` (a target built from a literal and a field), as the field can climb out of the
folder; `print > "out.txt"` does not.

Checked: `tests/unit/test_shell_guard_awk.py` (38 computed targets and shell pipes ask, 32 of which were allowed before; 51
ordinary programs keep their verdict, `test_a_pipe_into_a_shell_is_read_through_the_wrappers_in_front_of_it` for the
wrappers), `tests/unit/test_shell_guard_ordinary.py`.
