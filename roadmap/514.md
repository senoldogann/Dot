### 514. A page's own tools stay out of a run

**Status: done (2026-10-22).** The security review of Dependabot's playwright update (#506) noted that the Playwright
MCP server of the catalogue, started as `npx -y @playwright/mcp@latest` and so never pinned by the lock, now offers the
tools a page registers through WebMCP to the agent by default, as `webmcp_<tool>`: their names, descriptions and code
are whatever page the server opens, a prompt-injection surface. **As built.** The catalogue starts the server with
`--no-webmcp` (`@playwright/mcp` 0.0.83's own help: "do not collect or expose the tools that a page registers through
the WebMCP API"); the service is still recognised by its package, as a flag is no part of it (`service_of`). A server
added before keeps the arguments it was added with; the owner's home had none. Tests: `tests/unit/test_mcp_connect.py`.
Docs: extending.md.
