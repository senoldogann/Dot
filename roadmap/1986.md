### 1986. A code review whose chat was deleted starts in a new chat instead of failing

**Status: done (2026-11-27).** Dot's record held `command_failed: the Dot daemon refused the call` seven times in five
days: each a `dotx run --review --thread thr_…` of the pre-push hook, answered `404 thread not found`. The hook keeps
each branch's review chat (`.git/claude-review/thread-<branch>`) and continues it in the branch's next review; the owner
had deleted those chats since (on 2026-11-27 at 05:07 one deletion took 209 review runs with their chats). The review
then failed on its first model, the one the owner chose in Settings › Models › Code review, and the hook handed the
change to the next model of the plan, so a cleared Code reviews list cost each branch its review on the chosen model.

What changed: `dotx run --review` whose `--thread` chat is gone starts the review in a new chat, writes so to standard
error (`the chat thr_… is gone; the review starts in a new chat`) and logs `review_chat_gone`; the hook reads the new
chat from the run's last line and keeps it, as it does after a first review. A review reads the change from its files,
not from the chat, so nothing it needs is lost. Both paths do it: a run handed to the daemon asks
`GET /api/threads/{id}/view` first, a run in the command's own process asks its store. A run that is not a review still
fails on a chat that is gone, now as `NotFoundError` ("the Dot daemon has nothing that the call names", the daemon's
answer in its context) instead of the generic refusal.

The other record of the same words, a `422` on `proof` (2026-11-25), was a `dotx` newer than the daemon still running
before its restart; nothing changed for it.

How it was checked: `tests/smoke/test_cli_handoff.py::test_a_review_whose_chat_was_deleted_starts_in_a_new_chat` fails
without the change with the record's own error and passes with it; the file's other tests, ruff and mypy pass.
