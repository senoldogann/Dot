### 1143. A note a run corrects holds from the correction

**Status: done (2026-11-13).** `memory_save` takes `valid_days` for a fact that is true only so long, and the note runs
out that many days later (item 306). `memory_update`, which the model is told to prefer over forgetting and saving
again, took no time at all and kept the note's old `expires_at`: a trip moved by a week was corrected in words, and the
note still ran out on the old day. `memory_update` now takes `valid_days` too, counted from the correction. Without it
the note keeps the time it had, so a lasting note stays lasting and a timed one keeps its day. The owner's note and a
pinned one keep their time, as when a run saves their words again. Both are judged in the same statement that writes
the text, so a pin made while the rewrite waits on the embedding still holds. The owner's edit on the Memory page does not change the
time.
